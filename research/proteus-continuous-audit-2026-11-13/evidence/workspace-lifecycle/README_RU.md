# Удаление вложенного сохранённого worktree при cleanup родителя

Подтверждённая проблема P1 на Core `89997df995df7c39b713e16aba216ecb19c8f497`.

## Область действия
Необходимы два уровня worktree-задач, то есть **max_depth≥2**. Фактический fixture использовал **max_depth=3**. **Default max_depth=1 не затронут этим сценарием**, поскольку второй уровень задачи недоступен. Это не утверждение о проверке всех остальных сценариев default-конфигурации.

## Результат и контроли
- Чистый parent + незакоммиченный leaf: оба task завершаются успешно, leaf сначала сообщает о сохранении checkout, но cleanup parent удаляет вложенный checkout и файл; в leaf branch файла нет.
- Dirty parent + незакоммиченный leaf: checkout и файл остаются.
- Чистый parent + закоммиченный leaf: checkout удаляется, но файл сохраняется в Git branch.

Три исходных запуска использовали настоящий stdio server, TaskTool, ProcessAgentControl и Git cleanup. Последовательное воспроизведение не требует гонки. Запись результата и model/workflow/policy являются тестовыми fixture. Реальная модель, Desktop, пользовательский harness, полный Rust gate и нагрузочные проверки не запускались.

`verify.py` повторно проверяет сохранённые доказательства без запуска агента. Обычный режим должен проходить; `--expect-fixed` должен падать на инварианте сохранения незакоммиченного результата. Падение здесь подтверждает баг, а не исправление.

Production patch отсутствует. Для исправления нужно запретить удаление ancestor с retained descendant worktree либо изменить layout на стабильный общий owner-root с сохранением семантики base commit.

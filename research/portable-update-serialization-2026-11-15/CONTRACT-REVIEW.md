# Independent source-level transaction review

Read portable.py's main/assembly metadata/archive flow and portable_state.py's publication boundary. Verdict: the proposed local advisory-lock design is coherent for cooperating portable.py invocations targeting the same stable destination. Exact patch and synthetic test code still need review before execution. No project code/tests were run.

Parsing, argument validation and selection of components can remain outside the critical section. Moving base.resolve and the existing operational body into _update(args, selected), with a nullcontext for --plan and update_lock(PORTABLE) otherwise, puts destination-derived reads before copying and replacement into one serialized transaction. The lock must span ready-record read, stage copy/assembly and validation, publication, cleanup, and archive. archive reads live PORTABLE, not stage, so ending the lock at publish would leave an inconsistent archive window. Existing plan returns before mutation and need not acquire a lock; its documented intention-only output is not a coherent concurrent snapshot guarantee.

Use one persistent lock inode in the destination parent, outside the renamed destination tree; do not unlink the file on release. Include --full and --reuse-binaries even where read/assembly steps differ. Exceptions must release the lock through the context manager. Advisory fcntl behavior has a Linux/POSIX cooperating-writer scope, not a universal platform or filesystem guarantee.

Default base=PORTABLE then allows a waiting second partial update to read the first update's completed state. An explicitly selected external base still deliberately replaces from that chosen snapshot; serializing cannot turn it into an incremental merge of current destination. External base changes and noncooperating writers remain out of scope. Publication followed by archive is serialized, not an atomic all-or-nothing combined outcome: archive failure after successful publication does not roll back the already published tree in current code.

Probe-based controls may demonstrate lock coverage and release but do not independently reproduce lost updates. A bounded actual-main synthetic interleaving/serial-equivalence control can support that stronger property if its fixtures and synchronization are reviewed. Neither test substitutes for production builders, live installation or archive-failure recovery qualification. No new framework or broader transactional state is needed for this narrow contract.

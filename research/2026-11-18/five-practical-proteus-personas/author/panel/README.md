# Счётчик рядов: интерактивная панель Proteus на Rust

Панель считает готовые ряды от **0 до 999**. Нажатие «+1 ряд» прибавляет один, «−1 ряд» вычитает один, «Сбросить» возвращает ноль. На нуле кнопки уменьшения и сброса недоступны; на 999 недоступно прибавление. Счётчик живёт в памяти одного экземпляра расширения: хранилище или привязка к чату не предусмотрены.

## Что копировать

Откройте штатный checkout [Proteus-desktop-extensions](https://github.com/Proteus-harness/Proteus-desktop-extensions/tree/ef064381d2194d95faef2b85f6cc3a1c34c6b975). В его **новую** папку `packages/row-tally/` положите содержимое `example/`: `Cargo.toml`, `extension.json`, `src/main.rs` и `src/panel.rs`. Не создавайте ещё один уровень `example`. Корневой Cargo.toml уже включает `packages/*` и предоставляет зависимость `proteus-extension`. Указывать новый член workspace вручную не надо. Пример привязан к **protocol 4**; сам крейт SDK этого checkout имеет версию **0.1.0**, не 4.0.

- `panel.rs` содержит число, три перехода и UI на настоящих SDK builders.
- `main.rs` связывает public `Extension::render/action` с состоянием; `render` передаёт дерево только своей панели. Не нужно пересчитывать счётчик в обработчике рисования.
- `extension.json` объявляет только боковую панель, `dependencies.core: false` и нужные ей возможности. Идентификатор, имя каталога, `[[bin]].name` и имя внутри пути `bin/row-tally` согласованы.

## Проверка сборки

В корне checkout, с Cargo/Rust edition 2024 и заранее заполненным кэшем зависимостей этого workspace:

```sh
cargo check --offline -p extension-row-tally
```

**В этой пробе команда не прошла:** не оказалось `ureq` из зависимостей SDK. Интернет не использовался. Поэтому здесь нет проверенного исполняемого файла или ZIP. `dependencies.core: false` отключает потребность расширения в Core, но не меняет список зависимостей Rust-крейта SDK. Копия одной папки `packages/row-tally` без корневого workspace и `sdk` не самодостаточна.

Для последующей упаковки по [штатной инструкции](https://github.com/Proteus-harness/Proteus-desktop-extensions/blob/ef064381d2194d95faef2b85f6cc3a1c34c6b975/README.md#L107-L131) потребуется также файл лицензии пакета: для унаследованного в этом примере `GPL-3.0-or-later` скопируйте `LICENSE-GPL` из корня checkout в папку пакета. В этой пробе упаковку, установку, включение и открытие Desktop не выполняли. После такой отдельной установки в поддерживаемом Desktop ручная приёмка: открыть «Счётчик рядов», последовательно нажать +1, +1, −1, Сбросить и сверить **0 → 1 → 2 → 1 → 0** вместе с доступностью кнопок. Это инструкция, не результат кликов.

## Чем проверено сейчас

`checks/replay.py` берёт настоящий `sdk/src/ui.rs` и полный неизменённый `example/src/panel.rs`, компилирует их отдельно через rustc. Подмножество реальной serde-схемы Desktop для Card/Stack/Metric/Button проверяет сгенерированные деревья. Тест передаёт обработчику имена действий именно из этих деревьев. Никакой связи с Desktop, окном, Core или SDK host в replay нет. Для полностью локального повторения нужны согласованные **serde** (с derive) и **serde_json** rlib плюс их каталог зависимостей:

```sh
python3 checks/replay.py --sdk-ui "$EXTENSIONS/sdk/src/ui.rs" \
  --widget "$DESKTOP/src/declarative/widget.rs" --control "$DESKTOP/src/declarative/control.rs" \
  --serde "$SERDE_RLIB" --serde-json "$SERDE_JSON_RLIB" --rustc "$RUSTC"
```

Получено **3/3**: все 1 000 достижимых значений и обе границы, все 243 последовательности из пяти действий, отдельно неизвестное действие и сброс, плюс намеренная опечатка `disable` вместо `disabled`, отвергнутая настоящими атрибутами serde. Полный хронологический протокол, ссылки и ограничения в `REPORT.md`.

# Практическая проба: мой первый backend-инструмент на Rust

**Мне удалось собрать собственный модуль и отдельно получить проверенные ответы от его кода. Не удалось собрать его с тем Git pin SDK, который предписывает starter, в имеющемся оффлайн-кэше.** Имя инструмента — count_words; он принимает только строку text и возвращает число фрагментов, разделённых пробелами, в виде текста. Собранный бинарник называется proteus-word-count-example. Я не запускал этот бинарник, не регистрировал модуль и не открывал приложение.

**Что я действительно сделал.** Из [руководства Core](https://github.com/Proteus-harness/Proteus-core/blob/c2cbadee518788f306ffb2b5271036b2658ea8cc/docs/guides/rust-module-sdk.md#L41-L55) перешёл в [самостоятельный starter](https://github.com/Proteus-harness/Proteus-core/blob/c2cbadee518788f306ffb2b5271036b2658ea8cc/examples/modules/rust-tool/README.md#L8-L22). У него собственная Cargo workspace, Rust/Cargo 1.95.0, edition 2024 и [экспериментальный SDK 0.1.0-alpha.2, закреплённый точной ревизией](https://github.com/Proteus-harness/Proteus-core/blob/c2cbadee518788f306ffb2b5271036b2658ea8cc/examples/modules/rust-tool/Cargo.toml#L7-L15). Заменил инструмент echo на count_words, а id экспорта example.echo на example.word_count. Наименование бинарника третье, не одно из этих двух. Свой расчёт и описание входа вынес в src/lib.rs; адаптер src/main.rs передаёт id вызова и аргументы той же функции response, которую можно тестировать без хоста. Из официального Modules для этого не понадобились ни компонент, ни упаковщик, ни сборка всего каталога.

Ещё одна независимая проверка собрала тот же src/lib.rs напрямую с уже имеющимся contracts rlib и проверила только вычисление (компиляция 0,874 с, тестовый бинарник 0,002 с). Это **не** третья сборка SDK; самостоятельный cargo test выше связан с настоящим SDK. В evidence приведены команды, коды возврата и показания монотонного таймера, абсолютные пути машины заменены обозначениями. Использованы Rust/Cargo 1.95.0, serde 1.0.228, serde_json 1.0.151; официальный исходный пример взят из текущего Core c2cbadee518788f306ffb2b5271036b2658ea8cc. Реально скомпилированный SDK — другая официальная ревизия b2c285fcc317379ab47e484945afb7fc2b436331; одинаковая версия alpha.2 не превращает её в прописанный 59da60a. Альтернативный lock входит в offline/ отдельно от предписанного. Версии и исходники upstream не менялись, сеть не использовалась.

**Проверка ответа.** Один тест сверил объявление: обязательный text типа string, иных аргументов нет. В следующем восемь корректных JSON-примеров, включая пустую строку, CR/LF, кириллицу и Unicode-пробелы, дали ожидаемый результат; у каждого полностью сверены сериализованный ToolResult и обратное декодирование, в том числе исходный call_id и текст output. Для синтетического вызова с «Привет, мир!» ответ был:
```json
{"call_id":"synthetic-4","ok":true,"output":"2","content":[],"error":null,"metadata":null}
```
Третий тест отверг семь неверных форм (в т. ч. отсутствующий text, число вместо строки и лишний ключ). Это проверка кода автора, а не тест того, какие ошибки вернёт SDK или приложение. Сам Test Harness был запущен; работающий worker, протокол ввода-вывода, conformance CLI, обнаружение, установка, профиль, вызов моделью и полный путь через Core/GUI не запускались. Универсальной совместимости между двумя ревизиями мы не проверяли.

**Личное впечатление автора: сложность 4/5 в этих оффлайн-условиях (1 — легко, 5 — трудно).** Пример хорошо показывает, как связаны схема, имя инструмента и id вызова. Собственный расчёт короткий. Время ушло на два решения, которые стартовая страница не даёт: как протестировать новый код без запуска внешнего процесса и что считать честным оффлайн-результатом, когда нет exact Git pin. README честно предупреждает, что SDK требует Git-доступа. Я бы добавил в starter один библиотечный тест «JSON аргументы → ToolResult с тем же call_id» и строку «для offline заранее подготовьте и Git-ревизию, и версии Cargo.lock». Такой тест помог бы быстрее понять, что сломалось: вычисление, сборка или подключение. Уверенность высокая в измеренном результате, средняя в переносе оценки сложности на новичка с сетью; успешный запуск в приложении оценивать нельзя.

# Сравнить три предложения в чате Proteus, не разрабатывая расширение

**Да.** Для четырёх колонок и трёх строк я бы просто попросил: «Сравни эти предложения в таблице Markdown, сохрани цены и сроки». Специальный JSON и Rust не нужны. Если требуется таблица в **нативной карточке с заголовком**, у Proteus есть отдельное готовое расширение «Визуализации». [Скопировать запрос с тремя вымышленными предложениями](examples/paste-into-chat.txt). Это запрос агенту, а не инструкция устанавливать пакет.

**Куда вставлять.** Данные и просьбу вставьте в своё сообщение. Таблица или закрытый блок `json-render` должны появиться **в ответе**. Собственное сообщение пользователя по [документации Markdown](https://github.com/Proteus-harness/Proteus-desktop-extensions/blob/ef064381d2194d95faef2b85f6cc3a1c34c6b975/packages/markdown-render/README.md#L3-L11) — буквальный текст. Не ждите, что вставленный туда JSON сразу станет виджетом. Для варианта с карточкой нужны активный обработчик Markdown и зарегистрированный язык `json-render`. Наличие «Визуализаций» проверяется в **Settings → Extensions**; [специальный skill не обязателен для уже правильного блока](https://github.com/Proteus-harness/Proteus-desktop-extensions/blob/ef064381d2194d95faef2b85f6cc3a1c34c6b975/packages/json-render/README.md#L62-L71).

## Опыт пробы

Начал с [корневого списка штатных пакетов](https://github.com/Proteus-harness/Proteus-desktop-extensions/blob/ef064381d2194d95faef2b85f6cc3a1c34c6b975/README.md#L30-L36), в нём нашёл Markdown и «Визуализации». В [описании формата](https://github.com/Proteus-harness/Proteus-desktop-extensions/blob/ef064381d2194d95faef2b85f6cc3a1c34c6b975/packages/json-render/README.md#L22-L43) есть нужная для проверки деталь: заголовок принадлежит карточке, таблица содержит только колонки и строки, все ячейки — строки. Написал свои примеры: [обычная таблица](examples/simple-table.md) и [ожидаемый ответ с карточкой](examples/expected-answer.md). У «Листа» самый короткий срок — день; у «Точки» самая низкая цена — 2 200 ₽. Это учебные предложения, не рыночные цены.

- **Сначала проверил рабочий пример.** Реальный разборщик Markdown счёл блок завершённым и подходящим для зарегистрированного `json-render`. Реальный JSON-рендерер вернул одну карточку с таблицей: проверены 4 названия колонок и все 12 значений по координатам. Отдельно обычный GFM дал одну HTML-таблицу с теми же колонками и ячейками.
- **Ошибка 1: цена как число.** Заменил строку «2 200 ₽» на JSON-число `2200`. Локальный результат: `table rows must contain one string per column`. Длина строки таблицы оставалась правильной; проблема была в типе цены. Вернул строку в кавычках, таблица прошла целиком.
- **Ошибка 2: заголовок не на том уровне.** Перенёс `title` на саму таблицу. Локальный результат: `unsupported field "title"`. Сообщение называет поле, но не указывает, куда его поставить. Сверился с таблицей допустимых полей, перенёс `title` на `card`. Снова прошли все данные. Ошибки видны в локальном выводе парсера; как именно их показывает интерфейс, я не наблюдал.
- **Если вместо карточки остаётся код.** В двух контролях настоящий разборщик не передал блок визуализации, когда из списка языков убран `json-render` или закрывающая строка блока отсутствует. [Документация](https://github.com/Proteus-harness/Proteus-desktop-extensions/blob/ef064381d2194d95faef2b85f6cc3a1c34c6b975/packages/markdown-render/README.md#L22-L32) описывает исходный код как запасной вид. Обычная Markdown-таблица в ответе — более простой выход без JSON-формата.

Активная проба от чтения до проверенного результата — **2 мин 28 с**, включая написание проверки, без установки или ожидания сервиса. Внутри этого времени воспроизводящая команда заняла **0,355 с** (с компиляцией изолированного Rust-стенда и с готовыми зависимостями). Отчёт подготовлен после. Это не оценка времени пользователя.

**Оценка агента в роли пользователя без Rust: 2/5** (1 — один очевидный шаг, 5 — нужна помощь команды). Обычную сравнительную таблицу можно просто попросить. Основное затруднение для карточки — понять, что собственное сообщение и визуализированный ответ различаются и что `title` и `rows` принадлежат разным узлам. Уверенность высокая в формате и проверенных исправлениях, средняя в удобстве для человека: это сценарная проба агента, не наблюдение за живым участником.

Для отделения от приложения невызванная ветка SVG заглушена. Обработка обычного текста проверена библиотекой markdown-rs 1.0.0 в режиме GFM, не полным host.

    python3 checks/replay.py EXTENSIONS_CHECKOUT_OR_BARE RUSTC SERDE_JSON_AND_ANYHOW_DEPS LIBMARKDOWN_RLIB

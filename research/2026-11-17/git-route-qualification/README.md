# Проверка маршрутов истории Git: родители, порядок и предел 64 полос

**Исправление не предлагается.** В [#188](https://github.com/Qweasd123tg/proteus-modules-dot/pull/188) был зафиксирован ложный родитель на семи коммитах. Здесь новый результат: семь вариантов раскладки устраняют тот пример, но каждый портит хотя бы один случай, который правильно показывает исходная версия. В [стенде из восьми независимых проверок](route-gates.rs) нет кода ни одного отклонённого варианта. Его можно прогнать над следующей реализацией без приложения и без настоящего репозитория Git.

## Коротко о выводах

- **Множество родителей важнее номера цвета.** Тест из #188 точно воспроизводит конкретное наложение на старой раскладке, но он привязан к цвету ветки. Нельзя использовать его как единственный критерий для исправления, которое меняет палитру. Новый тест прослеживает публичные отрезки до следующих точек коммитов и сравнивает полученный набор с исходными родителями, не требуя заранее выбранного цвета или номера полосы.
- **Сохранить множество недостаточно: первый родитель виден в форме развилки.** В графе A→C, B→[C,D] исходная раскладка ведёт прямой выход от B к C; перестановка списка меняет прямой выход на D. Вариант с одной полосой на ожидаемый хеш иногда оставлял прямым путь к D в обоих случаях. Оба родителя оставались правильными, но терялось различие между основным и боковым путями. Проверяем этот пример, а не навязываем идентичность каждой линии на любой истории.
- **Лимит 64 нельзя проверять только по числу столбцов после обрезки.** В первом контрольном случае уже занята 61 независимая полоса. Ещё шесть коммитов задают A→[B,C,F], B→[C,E], C→[D,E], а D, E, F — листья. Исходник сохраняет все связи; вариант с присоединением вторичных рёбер к существующей полосе показывает A→E вместо A→F и делает F родителем листа E. После обрезки обе версии сообщают ширину 64. Во втором случае 62 фоновые линии плюс A→C, B→[D,F], C→D, D→[E,F] ломают вариант с сохранением выхода первого родителя: E получает несуществующего родителя F. Исходник именно на этих двух примерах проверен и с учётом перекрывающихся штрихов. У первого примера требуется максимум 64 одновременно учитываемых целей/точек. Во втором частично открыты 65 разных целей, но именно этот рисунок исходник всё же кодирует правильно в 64 физических полосах. Условия не смешиваем: это сравнение с конкретным рабочим отображением, не обещание универсально различать 65 независимых линий.
- **Для ширины смотрите на текущий фрагмент, а не только на максимум страницы.** После 64 уже закончившихся независимых веток идёт узкий хвост из 57 строк с поздними общими родителями. Исходник рисует его в 4 полосы (но с неверными связями), глобальная перенумерация в одном из вариантов — в 29, а компактный вариант — в 4 с верными родителями на этом хвосте. Максимум всей страницы у всех 64. Бюджет ≤6 в стенде выбран только для этой фиксированной истории, не для произвольного графа.
- **Уплотнение каждой строки тоже не бесплатно.** Если одна длинная ветка стоит рядом с восемью короткими, исходник держит её прямой. Перенумерация полос отдельно у каждой границы заставила длинную ветку наклоняться 17 раз без изменения её родителя. Это измерение геометрии, не времени рендера.

## Что реально проверено

[Закреплённый graph.rs](https://github.com/Proteus-harness/Proteus-desktop-extensions/blob/ef064381d2194d95faef2b85f6cc3a1c34c6b975/packages/git/src/graph.rs): commit `ef064381d2194d95faef2b85f6cc3a1c34c6b975`, Git blob `a443d3dc918a89684b1076e784c8f2324b8e995b`. [Обработчик истории](https://github.com/Proteus-harness/Proteus-desktop-extensions/blob/ef064381d2194d95faef2b85f6cc3a1c34c6b975/packages/git/src/history.rs#L64-L87) передаёт координаты и цвета в Desktop. Четыре существующих теста точного исходного файла прошли. Новый независимый стенд на исходнике: **7 из 8**, один ожидаемый красный — строка B ведёт к E и G вместо одного E. Все семь кандидатов дают правильных родителей в этом примере; ни один не проходит весь набор. [Результат каждого прогона и точные SHA-256 исследованных исходников](results.tsv).

| Прототип (не поставляется) | Что помешало принять |
|---|---|
| Online: повторные вторичные рёбра присоединяются к существующей полосе | Новые ложные/пропавшие связи около предела |
| Transfer: первый родитель перехватывает существующую полосу | Исправляет предыдущий пример, но не другие проверенные у предела |
| Frontier: одна занятая полоса на ожидаемый хеш | Смена визуального первого родителя; потеря связей около предела |
| First-pinned: закрепить прямой выход к первому родителю | Порядок восстановлен; на отдельной близкой к пределу истории лист всё ещё получает родителя |
| Global / regions: перенумерация целого графа или его отдельных частей | Глобальная ширина скрывает чрезмерно широкий хвост; оба варианта нарушают рабочие примеры около предела |
| Dense: отдельная перенумерация на границах полурядов | Необязательные изгибы долгой ветки и потеря родителя в контроле у предела |

[Тест](route-gates.rs) использует только `layout`, `Row` и `Segment` и разрешает менять палитру. В каждой половине строки при точном совпадении пары координат остаётся верхний (последний нарисованный) штрих. Переход через обычную точку учитывает непрерывность цвета; поперечное пересечение внутри кривой не считается новым родством. Это проверка координат, а **не** растеризация, скриншот или оценка человеком. Проверки прямого выхода и отсутствия ненужных изгибов — требования к читаемости конкретных иллюстраций, не универсальное определение правильности графа. Восьмёрка проверяет полные валидные истории; неполные страницы исследовались отдельно. Контрпримеры у предела в наборе подобраны так, чтобы исходник проходил эту более строгую проверку. Одинаковые начальная и конечная координаты при разных цветах сами по себе не гарантируют, что зрителю видны обе линии.

При поиске вариантов также проверялись все 2 097 152 семивершинных DAG с фиксированным порядком родителей и независимые префиксы загруженных страниц, включая цели за их пределами. Такой перебор обнаруживает потерю связей, но не гарантирует удачную форму развилки, стабильность при догрузке или корректность после предельного сжатия. Большие переборы не включены в штатные тесты.

## Как повторить

В отдельной чистой копии **Extensions**, задав абсолютный `GATE` до этого файла. Проверено с `rustc 1.95.0`. Команды только компилируют изолированную чистую геометрию; Cargo workspace и приложение не нужны.

```sh
GATE=/absolute/path/to/route-gates.rs
OUT=$(mktemp -d)
rustc --edition=2024 --test -D warnings packages/git/src/graph.rs -o "$OUT/upstream-tests"
"$OUT/upstream-tests"
rustc --edition=2024 --crate-name placement --crate-type rlib -D warnings -O \
  packages/git/src/graph.rs -o "$OUT/libplacement.rlib"
rustc --edition=2024 --test -D warnings -O --extern placement="$OUT/libplacement.rlib" \
  "$GATE" -o "$OUT/route-gates"
"$OUT/route-gates" --test-threads=1
```

У неизменённой версии последняя команда должна вернуть ошибку только для `seven_commits_do_not_gain_parents`; остальные семь проверок должны пройти. Не включайте этот стенд как заведомо зелёный в обязательный CI. Данные Git, код приложения и upstream не меняются. Полный workspace, окно Desktop, реальный репозиторий пользователя, производительность GUI и CI не проверялись.

Срез исходников: **7 ноября 2026 года**. Здесь опубликован полный технический отчёт по Core, Modules, Desktop и Extensions: находки, причинные цепочки, точные source links, условия применимости, отвергнутые гипотезы и план проверок.

## Границы выводов

По зафиксированному в отчёте покрытию прочитан **2921 tracked текстовый файл, 805803 строки** в четырёх деревьях. Это покрытие чтения, не test coverage и не гарантия отсутствия других ошибок.

**Код, тесты, сборки, fixtures, benchmarks и предложенные сценарии не запускались.** Новые дефекты не воспроизводились динамически; производительность, RSS, CPU и реальная эксплуатация не измерены. Публикация отчёта не исправляет исходники и не завершает security audit или runtime-верификацию.

- Core: 914 текстовых файлов, 188630 строк. PNG просмотрен; 11 текстовых members исторического tar.gz прочитаны отдельно, их 10429 строк не прибавлены к общему tracked итогу.
- Modules: 399 текстовых файлов, 69894 строки.
- Desktop: 1159 текстовых файлов, 407995 строк; шесть бинарных файлов сверены только по Git blob, не исследованы содержательно.
- Extensions: 449 текстовых файлов, 139284 LF-строки, включая tracked vendor. Production Node/Pele и opt-in native Rust renderers рассматриваются отдельно.

Tracked vendor входит в отчёт. Внешние зависимости и native Ghostty Zig implementation, загружаемая при сборке, не становятся проверенными от чтения lockfile или build.rs. Детальные исключения и точечные проверки указаны в самом отчёте.

## Приоритеты из отчёта

Сначала: владение работающим child и idle pool, изоляция protocol stdin и безопасные read-only Git helpers. Затем: отмена и deadlines, сохранение durable plan, единая policy, credential history и корректная цель записи, бюджеты очередей и кэшей, согласованность истории и UI.

Ghostty safe API имеет отдельный срочный library track; текущий Desktop exploit path не доказан. Ресурсный дефект Native Mermaid относится к experiment, а не автоматически к production Pele. P1/P2/P3 в отчёте не являются CVSS и не означают доказанную эксплуатацию.

Для конструктора агентов предлагается укреплять существующие contracts, lifecycle, admission и storage boundaries. Новые Core behavior slots для найденных ошибок не требуются. Bundle manifest для составной capability остаётся проектным предложением.

## Проверка публикации и связь с историей

Проверены целостность DOCX ZIP, число PDF-страниц двумя PDF-парсерами и контрольные суммы обоих исходных файлов. У DOCX нет tracked changes, комментариев, макросов или embedded objects; все 529 внешних ссылок ведут на GitHub. Это проверка доставляемого пакета, не повторный аудит исходников и не проверка доступности каждой ссылки.

Изменения этой поставки ограничены документацией и файлами отчёта. Upstream-репозитории, исходники и CI не изменяются.

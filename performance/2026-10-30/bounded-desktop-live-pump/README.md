# Ограниченная порция live-событий и возврат управления executor

Source-only кандидат для `Proteus-harness/Proteus-desktop` на
`a28cc7f507424a570e86dc44230ee323156fdf6c`; main проверен через GitHub
30 октября 2026 года повторно около 16:15 UTC. Отдельный пакет: предыдущий кандидат
action-routes отозван из очереди исправлений и сюда **не входит**.

## Поддерживаемый сценарий и найденная граница

`src/connection.rs::spawn_pump` получает обычный публичный SSE поток на
отдельном thread и отправляет события в unbounded async_channel. Начальная
подготовка `take_initial_events` уже ограничивает порцию 256 событиями, чтобы
не блокировать первый paint непрерывно поступающим потоком.

Но live `src/ui/chat/pump.rs::start` собирает `while try_recv()` до пустой
очереди, без предела. При большом backlog получается неограниченная порция;
при продолжающемся поступлении извлечение не обязано закончиться быстро.
Затем `recv().await` следующей итерации может сразу вернуть Ready. Поэтому
в live-пути нет конечного предела числа событий, обрабатываемых одним poll
foreground-задачи. Синтаксическое `.await` само по себе не гарантирует yield.

Это вывод по control flow и владению каналом, не воспроизведённый freeze и
не измерение задержки. Сценарий не требует нарушения протокола расширений:
это обычные события сессии, которые нельзя выбрасывать ради промежуточного кадра.

## Патч

- `ready_batch` берёт уже полученное первое событие и не более 255 следующих
  готовых событий. Общий предел — 256, как в существующей startup-подготовке.
  Непрочитанный хвост остаётся в том же FIFO канале.
- Существующий `batches` продолжает объединять только соседние совместимые
  text events и не пересекает barriers. Ни snapshot, ни reconnect, ни terminal
  события, ни отдельные исходные deltas не заменяются latest-only значением.
- После применения порции `yield_after_batch` один раз возвращает Pending и
  будит текущую задачу; при следующем poll завершается. Используются только
  std::future::poll_fn и штатный waker — без таймера, задержки в миллисекундах,
  нового thread, detached-задачи или зависимости.
- Ошибка обновления уничтоженного Chat по-прежнему прерывает pump до yield.

Таким образом один poll этой задачи больше не выполняет произвольное число
порций подряд. Реальное распределение времени между задачами/вводом/paint
остаётся обязанностью executor/platform dispatcher. Ни frame fairness, ни
latency SLA этим патчем не обещаются.

## Цена и пределы

Это предел **количества событий**, не байтов и не длительности. Одно событие
может быть большим; сам reducer и подписчики тоже могут быть дорогими.
Общий unbounded channel не меняется: backpressure и общий предел памяти
очереди не реализованы. Деление большого text run на порции уменьшает размер
одного ready Vec, но может увеличить число reducer/layout проходов.
Каждая порция получает дополнительный wake/poll; возможная цена scheduling
явно не измерена. Утверждений об ускорении, RSS или задержке в числах нет.

## Регрессионные исходники

Четыре добавленных теста **не компилировались и не запускались**:

1. Порции 256/256/3 оставляют overflow в FIFO; после существующего partition
   сохраняется точная wire-последовательность, включая границы Disconnected,
   Connected, snapshot и Shutdown.
2. Неполная готовая порция возвращается сразу, не ждёт заполнения бюджета;
   позднейшее событие остаётся доступно отдельно.
3. Реальный Session text reducer на нескольких порциях совпадает с исходным
   поэлементным oracle; покрыта UTF-8 коррекция возле границы порции.
4. Ручной poll будущего yield: сначала Pending и один wake, затем Ready без
   дополнительного wake; новый yield повторяет поведение.

Четвёртый тест проверяет Future, а не native executor fairness. Первые три
не заменяют проверку настоящего окна и полного live-pump. Существующие тесты
barriers/root-thread routing остаются без изменения.

## Выполнено и осталось

Закреплённые preimages совпали с Git blob SHA. Direct installed rustfmt
(edition 2024, skip_children=true) прошёл финальный check; это только разбор
и форматирование. Строгое forward/reverse git apply и побайтное сравнение с
candidate/восстановленным baseline успешны. Whitespace без замечаний.

Не выполнялись Cargo/rustc, тесты, проектные скрипты, сборка, CI или benchmark.
Для будущего разрешённого выполнения: Desktop-only focused stream_batch tests
и существующий native-stream стенд, сохраняя screenshot и настоящий Copy
oracle. Дополнительно проверить длительный backlog нескольких порций,
ввод/прокрутку/закрытие Chat между порциями, reconnect/terminal события у
границ, отсутствие потерь и задержки paint. Сравнить throughput/latency до и
после на одинаковых revisions и нагрузке; меньшее число событий за poll не
считать автоматически выигрышем приложения. Core/modules/extensions ради
этого патча пересобирать не требуется.

# Копировать только видимый префикс результата инструмента

Source-патч для Core `781a47aad8fea9bd48cb30ef0dff043477c355bc`.
Затронутые исходники не изменились относительно `80e828ca`.

`update_tool` копировал весь текст результата, затем обрезал `String` до
10 000 байт. `String::truncate` сокращает длину, но оставляет выделенный
буфер. Поэтому короткий результат в живой проекции мог удерживать память
полной копии большого ответа.

Теперь существующий helper сначала выбирает заимствованный UTF-8-префикс,
и только нужная часть копируется в результат. Лимит и округление вниз до
границы символа сохранены. Новых кэшей, настроек, типов или проверочных
слоёв нет. `compact_json` использует тот же helper, но для его итогового
JSON не заявляется отдельная экономия удерживаемой памяти: `json!` уже
создавал строку по длине обрезанного значения.

Это не устранение всех больших временных строк: более ранний
`ToolResult::text_or_status()` всё ещё может материализовать полный текст.
Измеренного выигрыша времени или RSS нет.

## Проверка

Дополнен существующий тест `snapshots_subagent_card_and_nested_child_tools`:
после прежнего короткого результата проверяется длинный UTF-8 результат,
обрезка между байтами символа и отсутствие удержания полного буфера.
Проверяется строка внутри `TurnProgress`, не её копия из `snapshot()`.
Новой тестовой функции или отдельного стенда нет.

- Точные исходные Git blob SHA сверены с актуальной закреплённой ревизией.
- Строгое применение и обратное применение патча с `--whitespace=error`,
  побайтное совпадение исходных и конечных файлов проверены.
- Прямая проверка установленным rustfmt 1.95.0 пройдена.
- Тесты, Cargo, сборка, CI и приложение **не запускались**. После переноса
  требуется выполнить затронутый существующий test target по upstream runner.

Применять `tool-result-prefix.patch` из корня соответствующего Core checkout.
Исходный репозиторий этим пакетом автоматически не изменяется.

# Reuse the selected final review message when projecting text

In Modules’ plan–execute–review workflow the final review response already owns the selected canonical message. Borrow it through checkpoint rather than allocating an extra deep clone. It still appends both history owners exactly as before, calls checkpoint before output projection and uses the current post-checkpoint history for the empty-output fallback. Neither default Codex turns nor whole transport/app behavior is changed.

Exact scoped native default-layout proof with actual pinned contracts and formatter, with a stub for the checkpoint boundary. Twelve fixtures across replayed ABBA arms gave 48 matching outputs, history entries and checkpoint-order controls. Retained requested bytes were equal. Stress peaks in this scope: 2 MiB selected text 8,389,088→6,291,776 B, 2 MiB selected hidden reasoning 6,292,436→4,194,959 B, and selected large metadata 6,293,867→4,195,913 B. The 2 MiB unselected control does not save that payload. No actual worker, deployment, timing or PSS was measured.

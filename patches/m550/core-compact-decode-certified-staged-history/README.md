# Core: narrow first staged Text parse, with one causal writer walk

Exact M422 Core. This is one candidate, replacing the held W23 two-walk proposal rather than adding a second counted change. The actual first bounded LF-terminated slice is parsed into compact owned text rows on the existing certified single-record startup path. Each message has one inline text part, preserving exact typed IDs, role, phase, and fields needed by display and the prefix. If the narrow reader declines, the stock JournalRecord parser sees the same raw bytes after every temporary narrow owner is gone; only its error is returned.

The causal writer proves whether trying the private decoder is worthwhile using its existing message/part traversal rather than a whole second sweep. The exact first greater-than-4 through 64 MiB writer hint, 4,096–65,536 rows, Append, no compaction/tool bindings and ordinary metadata/name/tool fields gates are unchanged from W23. Optional field checks occur while the candidate remains possible and stop on the first known non-text part, without skipping any original causal/hosted/pending/root checks. Smaller and multi-record inputs do not specialize. Nothing changes the file actually written. This is not a claim of no added checks: an input with late disqualification can still pay inline inspections before that row.

The second actual physical rewind/read, LF check, SHA-256, typed mismatch and EOF/count remain. Prefix/source/canonical/cache/HEAD ordering and complete fallback remain. A first line that decodes but is followed by a fault cannot publish a partial result.

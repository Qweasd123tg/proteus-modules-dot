# Modules: estimate the uncovered message tail once

When the latest usage is valid and the request contains no opaque checkpoint, the old estimator walks every message and then walks the uncovered suffix again. This patch takes one raw byte subtotal per partition and uses the suffix subtotal in both calculations. It still rounds and clamps the whole-request and suffix estimates independently. The prior-usage floor, empty-tail rule, stale-usage fallback and opaque-checkpoint branch are unchanged. No changes to the API, policy, provider or compactor code.

In one isolated native Rust default-layout suite, the exact accounting leaves ran across 17 typed scenarios in stock/proposal/proposal/stock order with all 68 outputs and allocation ledgers verified. A separate visit witness matched the exact sequence of part visits; all 17 ordinary usage report outputs matched byte-for-byte and all 12 tests passed. Four uncovered 8,000-byte tool results took 9→5 part visits, 27→15 allocation requests and 64,220→32,124 cumulative requested bytes. One uncovered 2 MiB result took 4,194,352→2,097,176 cumulative bytes; a covered 2 MiB result was unchanged. Requested peak and retained bytes were unchanged in every case. These are scoped allocator results, not runtime or process-memory measurements. Preserve-order, the whole workflow and provider operation were not run.

The indexed patch is based on the composed M456 Modules snapshot. The identical source hunk also applies and reverses independently on Modules main `e8e77e306092344c00833f3456acba950c851fe3` and the packaged pin `a271aaefcbcdd25f9b68918406f34490c6169bd7`. On either owner revision use `git apply --check source.patch` and `git apply source.patch` without `--index`, because other hunks in that file differ between owner and composed sources. #688 and #696 commute with this hunk and are needed only to reproduce the complete measured leaf, not for standalone application.

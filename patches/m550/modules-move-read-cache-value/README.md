# Modules M387: transfer the already hydrated ReadCache response

The old pinned module SDK uses `serde_json::to_value(response)` to produce a JSON-RPC result. The normal warm Core transcript path asks the module for a content-addressed packed page through `ReadCache`. The storage layer has already parsed the cache into an owned `Value`, checked its source/locator, and computed its ETag. Converting that entire tree to another `Value` needlessly copies both text and container allocations.

This patch selects the existing worker-owned reply converter only for `ReadCache`. The converter moves the complete owned value through the original serialized document's `value` slot. It emits the same metadata/result shells using pinned serde, never reinserts or reorders keys, and leaves legitimate stored null distinct from a cache miss. The standard SDK still handles other metadata, all writes, unknown operations/methods, and unnegotiated display calls. The parser and request validation are identical and still run before execution. Source checks, cache misses, independent host pack/content verification, ETag, quota, publication/rename, the 64 MiB value cap, and SDK transport limits are untouched. No new format or dependency.

## Proof

- Exact full Modules M387 (610 files; pre-tree `860395dd1e95e2401e3e5817ae7d5164b3e7eea4`), two-file candidate tree `4f97edfb6299859d75bd8d1eb3abde154b67d672` with exact inverse. Pinned old SDK Core `0c1b7572313230e5d123e95c722e1258a2e9ecd6`, official Modules lock unchanged; serde default and `preserve_order`.
- Actual warm packed fixture generated by exact M387 Core `write_transcript`/`PendingPack` and retrieved with the native Core v3 broker from a fresh actual old worker. It contains 8 independently compressed `deflate_v1` leaves; **8,296 B** default and **8,496 B** ordered compact, bodies copied separately as `actual-pack-value*.json`. The independent broker also checks the latest named page, stale head and corrupted-pack/named-page fallback. A values-only fixture carries no locators or handles.
- Direct actual worker stdio in both layouts and both JSONL/SQLite storage backends, with and without display negotiation. Entire reply frames are byte identical between stock and candidate, without normalization. Scope includes valid source, an alternate equivalent snapshot handle, wrong source digest, stale source versus append, refused stale writes, unfiltered content-addressed hits, absent/corrupt/restored disposable values, untouched metadata, null/arrays/numeric and Unicode map data, parser/invalid key errors and per-frame cap. The exact first cache replies of **8,454 B** (default) and **8,654 B** (ordered) succeed; at each respective cap minus one the SDK emits no partial reply and reports its original limit error. The same 2 existing durable restart/ambiguous-ACK tests pass in each worker binary.
- Separately on the actual native service in both layouts/backends, the exact **67,108,864 B** cache value is admitted and both converters yield the same streamed response digest; at 67,108,865 B the request validator rejects and the typed consumer’s response validator also rejects. This oversized boundary fixture is not an estimate of a real Core packed-page size.
- On the authentic packed body, all 9 original nonempty string allocations (one key, eight compressed strings: 8,266 B default, 8,466 B ordered) survive into the output unchanged versus 0 in stock. The isolated conversion saves **9,154 B** of requested and scoped net live allocation with default serde, and **9,198 B** with `preserve_order`; on both captured real wire replay and directly hydrated native JSONL/SQLite DTOs. It avoids 11/12 scoped allocation events respectively. This is not end-to-end RSS/PSS/latency, changed disk traffic, or a measurement of the full product.

## Reproduce locally

```sh
python3 proof.py --modules <exact Modules-M387-source.tar.gz> \
  --core <r271/deps/source-archives/Core.tar.gz> --vendor <r274/deps/vendor> \
  --work <new-work-directory> --target <new-cargo-target> \
  --cargo <rust-1.95.0-bin/cargo> --rustc <rust-1.95.0-bin/rustc>
```

This uses the committed values-only authentic packed sample to seed independent durable native fixtures. Add `--prepare-only` for exact source/vendored-registry verification and inverse without building. The recorded run compiled both exact worker arms directly against independently authenticated read-only native SDK libraries, and reused the exact accepted #625 storage rlib (storage source is unchanged by #629 or M387-to-candidate). Work, fixtures, and built outputs are local; no release, merge, or publication implied.

# Desktop Proteus: reuse the page charge during fractional history navigation

One production patch on exact M376. The fractional seek already walks the freshly loaded page to account for its context budget, including nested tool/child JSON. Desktop immediately walked the same rows again when deciding the retained archive window. Lease neither a new cache nor a new payload owner: return the exact count and sum already computed by `ContextSeek`, and let the trim reuse it if those consecutive rows are on the edge that must remain.

The bound is necessary. If the charged rows all fit in the required edge, their nonnegative aggregate is enough: when it fits the budget every prefix fits; when it exceeds the budget the first cutoff must be inside already-required rows. In that second case the required range alone wins, exactly as before. Equality follows the zero-budget path, still visiting the first remaining charge as before. If there is no context or the charged edge is not wholly required, trim uses the ordinary directional walk. No change to the estimated 8 MiB/row budgets, selection, context progress counters, order, protected viewport/target, charge definition, insertion/eviction splice or dropped rows.

The 25 native tests in each stock/candidate × JSON-map arm lift the exact scoped reducers. Actual product `seek_context` identifies the fractional raw-edge cases and exact `ContextSeek` methods account for them. Native typed snapshots and pages round-trip through the authenticated Core/Desktop wire declarations. The producer's named-page path and 50-row window are source-verified. The test cases include the first older page, both archive directions with costs below, equal to and above the budget, return to the live page, invalid revisions, and existing paging regression tests (two full GPUI ListState tests are outside the lift).

Scoped logical work, not wall time: on the 50-row heavily nested first-edge fixture, default mode goes from **137 to 87 row charges** and **217,070 to 108,720 visits to JSON values**. The retained 86 entries, splice/target digests and allocations are identical. Existing archive edges below the budget go from **216,700 to 108,350 JSON visits** in either map mode; the over-budget and live-merge cases also agree on output and allocation totals. Visit counts instrument the exact recursive estimator, not parse, render, or whole-process work. No latency, RSS or full GUI benchmark.

Run `python3 verify.py [--vendor /path/to/cargo-vendor]` with Rust 1.95.0. The optional vendor makes Cargo offline. Apply after #616 on the shared history implementation; `composition.json` verifies exact forward/inverse composition and matching output if #613 is before or after this candidate. #616's layout/ownership optimization is untouched.

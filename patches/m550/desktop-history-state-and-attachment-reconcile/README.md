# Desktop Proteus boot: two independent display-preparation changes

Exact M362 source leaves. This is the Proteus saved-session startup path, not Codex #602 nor the saved-child GET path. Workspace boot starts the SSE subscription early; `Chat::new` non-blockingly drains ready events and invokes the pump before its first render. The fixture supplies the real M362 snapshot shape: 50 resident rows at indices 49,950–49,999 of 50,000, not 50,000 rows in one renderer.

- **`range.patch`** removes the second range/cache-key reconciliation from accepted snapshots. `apply_history_changes` already synchronizes the range and SHA key before announcing history state. On subsequent duplicate work the exact scrollbar setter does not change a nonempty range, and `bind_height_cache` stops on the same key; on an empty range the same geometry is reset again. The first sync, scroll drag cancellation on shrink, pending archive seek, disclosure rebases, height-key refresh, notices and non-snapshot fallback remain. Source audit checks GPUI's cold-notify queue (no prior window invalidator) and exact prepared-SSE startup chain. On valid cursor snapshots the scoped counts drop from two range/key updates to one, including an archive refresh with no visible splice.
- **`images.patch`** skips building a temporary ID set when the per-chat image slot map is empty (for example, the first snapshot before any row has called image loading). Shared cache pruning **still runs** and an already-demanded image keeps the same behavior. 50 resident rows with 200 distinct attachment IDs: seven allocator requests, 8,748 bytes requested, become zero for the isolated retain pass. Warm membership/prune behavior and allocation counts match. This does not change image decode admission, cache capacity, viewport measurements or security.

The pinned reducer proof lifts exact Rust functions for the stream cursor, snapshot application, transcript/key/splice decisions, row-state pruning, scrollbar range and height-key binding, and image-slot retention. GPUI entity effects and shared bitmap cache are boundary recorders, not a full native GPUI launch; one recorder explicitly catches a wrongly skipped shared prune. The proof checks first/empty/rejected/foreign/archived/shrunk snapshot paths, retained archive anchor, and accepted non-snapshot fallback. A separate range-setter case checks resident and clipped fractional seek handling. Both patches compose in either order and reverse to the exact input bytes. The 5 reducer tests (including two lifted existing key tests) pass for stock, both single-patch arms and composition in both JSON map modes.

Reproduce with Python 3 and Rust 1.95: `python3 verify.py [--vendor /path/to/cargo-vendor]`. `--vendor` is offline. The compressed source capsule is split into numbered chunks and checked against its hashes; it includes the upstream GPUI source used by the notification source audit. `receipt.json` records exact scoped outputs, test modes and source/patch IDs. No PID/RSS or timing measurements, no changes to Core, transport, #597 or #602.

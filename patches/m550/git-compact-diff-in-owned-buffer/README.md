# Git Working Tree: ужать уже собранный diff без второго буфера

При открытии «Все изменения» Git собирает общий текстовый diff. Когда у буфера был резерв, конвертация виджета создавала второй буфер с точной длиной, пока исходный буфер ещё оставался жив. Теперь собранная строка ужимается (`String → Box<str> → String`) и передаётся в то же поле `patch` по владению. Для уже точной строки дополнительного запроса памяти нет. Итоговая длина и capacity совпадают как раньше.

Изменяется только `packages/git/src/document.rs` точной полной базы M404 после #644. Бюджет закодированного diff 4 MiB, предел 40 файлов, очередность GET, обработка отказа и нативный протокол не меняются. Ни SDK, ни Node не затронуты.

## Проверка

- 52 native unit теста на обеих версиях, в том числе существующий контроль точной capacity, проволочной формы и границ кешированных diff.
- Реальный бинарник `git` process extension, loopback read-only fixture: 6 byte-for-byte ответов, 8 345 849 байт. Обычная рабочая копия попала ровно в 4 MiB encoded budget, следующий файл запрошен, но не принят. Второй случай пересекает тот же предел за счёт экранирования Unicode/табуляций/обратных косых и CRLF; проверены пути с кавычками, пустые и отсутствующие patch, текстовки для бинарных/слишком больших/недоступных diff. Отдельно проверены cap 40 и отсутствие запроса 41-го, уже tight строка, пустая копия и ошибка HTTP.
- Временный измеритель в настоящем вызове `aggregate_patch` отличает `alloc` от `realloc`. Только промежуток преобразования готового join в виджет:

| Случай | Вход, длина / capacity, байт | Дополнительный логический пик до → после, байт |
| --- | ---: | ---: |
| Обычный diff ровно на wire-пределе | 4 193 376 / 7 440 000 | 4 193 762 → 0 |
| Diff с экранированием | 2 849 027 / 3 256 168 | 2 849 413 → 0 |
| Уже tight | 257 / 257 | 386 → 386 |
| Малые строки до предела 40 файлов | 310 / 512 | 696 → 184 |

`0` означает отсутствие нового логического пика сверх уже живого входного буфера, а не отсутствие памяти. Ужимание запрашивает один `realloc` на итоговую длину вместо отдельного полного `alloc`; системный аллокатор при этом может переместить содержимое внутри realloc. Учёт запрошенных layout bytes (Rust 1.95.0, dev без отладочных символов) не включает внутренний overlap realloc, сборку join до этой функции, другие потоки, физический RSS/PSS или задержку приложения.

## Воспроизведение

```sh
python3 proof.py --baseline /path/to/Extensions-M404-source.tar.gz --vendor /path/to/vendor --work /path/to/scratch
```

Для Linux, Rust 1.95.0 и Python 3.12+. Проверяет хеши и `Cargo.lock`, локально строит обе версии, прогоняет один fixture с измерителем и без него, сравнивает raw bytes и проверяет строгий обратный патч до всех 468 входных записей. Измеритель и fixture не входят в production diff.

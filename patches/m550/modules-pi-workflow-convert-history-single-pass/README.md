# Pi workflow: convert ordinary history in one pass

For the four message roles that Pi 1.5.2 passes through unchanged, collect the same message objects in a new ordered array. Unusual or legacy input goes through the original Pi converter in full. The patch does not change the separately used compaction converter, transcript normalization, provider or tool handling, or the Core request.

Four local arms based on exact owner and scoped sources matched for ten workflow and eleven direct converter controls. In the 6,144-canonical-row history, the normalized SDK-facing transcript stayed at 6,146 rows with the same identities and order, while one 6,146-slot intermediate map array and its follow-up filter pass were removed. The final array is still freshly allocated. The untouched fallback preserves pinned Pi conversions and diagnostics for nonstandard input.

The local check used literal pure pinned Pi source fragments and inert host boundaries, not the full SDK/provider. These are structural array and reference observations, not time or application RAM.

# Core: one prefix part-membership table

## Change
Exact baseline M401 includes #640 and #643. In its display-prefix certificate each known part was a UUID in a hash set. History commits also inserted the same UUID into a second set. The new private map keeps each part once and records whether history ever explicitly committed it. A model observation cannot clear that bit. Suffix inspection still checks the presence of **any** known part without inserting it. Checkpoint retained rows still need both exact ordered canonical SHA and explicit membership for every part; the first explicit commit of a captured result still triggers a full render when that can reveal an older response.

The replacement plus cache codec retain the existing v1 schema, 17-byte UUID/strict 0-or-1 part record, all ID identities, cap, unknown-field and duplicate rejection, and both directions of compatibility. No raw journal scan, validation, source gate, renderer shape, named-page fallback, publication order, hashing rule, storage request, or public transcript page format changes. Raw packed UUID collections were already iterated in randomized hash-table order, so the prefix-document bytes and its dependent ETag/header field are not guaranteed identical across independent projections. Each complete document is verified by its own exact ETag as before. Its digest is paired with that revision's published header; stale digest still means miss. Other page bytes and cursor/fallback outcomes were compared exactly. The old untagged derived JSON is not a persisted supported format and still misses.

## Observed
Native selected exact M401 PreparedSession, strict/projected validation and staging, render, prefix, page save and named-page lookup run with a typed in-process Storage boundary. Two map layouts: serde_json default and preserve_order. In both native 50,000-part cold-start fixtures (one 32.69 MB projected display record and one strict fallback with a 37.39 MB record), requested **live table layouts** held through conversation and display page packing changed from 2,228,256 bytes in two tables to 1,179,664 bytes in one (1,048,592 bytes fewer, 47.06% for those tables). Both are already released at named-page read. Other tracked owners, including #643 compact layout, match. A workload of exclusively uncommitted model parts trades a bool per bucket for removing no populated set, so it can request one additional bucket byte per part table slot; no universal RAM improvement claimed.

These are selected-source native tests and requested allocator sizes, not RSS/PSS or startup time. The source lift's in-process adapter is not a real module worker or installed GUI. Separate native prefix-visit and pack-only timing excludes source reading, full Value hashing/certificate storage, fixture generation and any service/GUI launch; Median process median for 50,000 explicit parts: 13.65→9.16 ms default (−32.90%), 13.61→9.14 ms preserve_order (−32.84%); 12 interleaved processes per fixture and layout, discarding the first of nine iterations within each process. Pinning CPU7 does not remove all shared-host interference; auxiliary mixed and model-only timings are diagnostic, not product claims. See verified.json and the raw ABBA receipt.

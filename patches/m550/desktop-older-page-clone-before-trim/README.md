# Desktop Proteus: do not clone live rows the first older page will immediately evict

Single production patch over the exact M372 Desktop leaves. In the Proteus older-page flow, `Api::history_page` asks for a named revision and deserializes the response. When its first older page is accepted, Desktop used to clone the **entire** live transcript into a display window, prepend that page, then evict the excess. The candidate computes the same trim boundaries over the new page and borrowed resident rows before cloning, then completes the window by cloning only the live prefix that survives.

The candidate preserves the live transcript's separate ownership, allocation/key space, routing and other metadata. It preserves the ordered insertion/eviction splice sequence, row identities, shared text Arc addresses, revision/position checks, and required visible or fractional-seek context. The existing 50-row page, 200-row cache, 8 MiB estimate, and indivisible visible/page rules are unchanged. The same trim decision also continues to serve existing archive pages in both directions. No changes to Core, transport, model/security policy, image decode, or Codex.

**Scoped measurement.** The history reducer takes exactly typed decoded Core wire snapshots/pages. One byte-bound fixture has 50 resident tool/child rows and the first 50-row older page of a 50,000-row archive, 128 KiB per rich row/text. Both arms retain exactly 63 entries, issue the same two splices and make 64 identical charge visits; 37 owned live-row clones are avoided. Default JSON: 13,376,054→8,329,298 requested bytes and 1,115→329 allocator calls. Ordered JSON: 13,356,166→8,324,186 bytes and 1,315→381 allocator calls. A full viewport that must keep all rows and an ordinary small page also do not regress in charged work or allocation volume. The proof covers an indivisible over-budget page, an extra fractional-seek target, subsequent newer/older pages, and stale/mismatched replies.

24 native scoped tests per stock/candidate/JSON configuration (the two original tests requiring full GPUI ListState are not included). The proof lifts the exact relevant reducer methods and uses the pinned wire declarations, including full `AppTranscriptPage`/snapshot shapes. Page and snapshot declarations match native M372 Core; the Core HTTP/cache/rebuild code in the capsule verifies the producer's 50-row window and data projection, but the proof does not run a full HTTP/GUI process. Values are allocator-request totals during page acceptance, not retained heap, RSS, cold latency, or measured AppServer wire. Visible ordering and viewport bounds are checked in the reducer model, not pixels.

Run `python3 verify.py [--vendor /path/to/cargo-vendor]` with Rust 1.95.0. `composition.json` records actual forward/inverse composition with the exact selectors in #597, #602, #609 and #613, applying this candidate both before and after them. The candidate shares a source file with #597 but not its hunks.

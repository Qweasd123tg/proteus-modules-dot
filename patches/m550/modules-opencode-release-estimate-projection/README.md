# OpenCode workflow: release the estimate-only projection sooner

Use the native history representation as the direct input to the existing synchronous token estimator. Only its numeric result is needed across the following host preparation wait. The canonical request still carries the same history and the provider-reported usage floor is unchanged. This does not change the Rust OpenCode Go provider.

In separate Node processes, the actual local workflow and projection code were exercised with an inert SDK estimator and synthetic host. Across 11 paired functional cases, callback outcomes matched. With 8,192 messages and host preparation deliberately held, the original kept the projected context and one fresh projected part reachable through all three forced-GC observation rounds. With this change both were collectible while preparation was still pending; the canonical history stayed live. This is a reachability check, not a measured reduction in application RAM or startup time.

The patch targets the pinned Modules revision. Before/after fingerprints and the scoped index/offset variant after #739 are recorded in the receipt.

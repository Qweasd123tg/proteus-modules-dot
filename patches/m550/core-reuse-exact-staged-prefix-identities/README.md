# Core: re-use a proved identical staged prefix without a second typed decode

## Change
On the existing startup-only single causal all-text Append route, remember exact prefix identities from the intact first decoded staged record and a SHA-256 of that complete raw LF-terminated line. Capture is allowed only for exact single-stage bytes already bounded by the successful writer (>4 MiB through 64 MiB), 4,096–65,536 singleton text rows and no compaction/result bindings. Keep the candidate private until the render callback and physical EOF/count check succeed.

The prefix pass still seeks and rereads the actual tempfile using the same LF/typed-or-match/callback/EOF/count order. It reuses captured identities only on the same byte length and raw line digest; a mismatch is decoded by the original typed path at the same point, as are any extra records. Failure never publishes an identity or cache value. Canonical-history hashes, raw I/O and bounds, source validation, copied roles/page metadata, full fallback, page and cache integrity remain unchanged. No launch-time speed claim: two SHA-256 passes and a bounded singleton metadata check replace the repeated typed parse on a hit.

# Core: reuse the decoded tool state after rebuilding its cache entry

This changes only the repair path for a missing cached latest-tool body. The repair previously deep-cloned the matching decoded tool state and then built a second copy as the cache's serialized Value. It now drops any previous match before writing its replacement and returns the current decoded state after the same write succeeds. Other names, accepted statuses, last-match selection, cache hashes/budgets, write order, late source check and publication rules are unchanged.

The isolated default-layout test uses the exact repair function, real compact DTO decoding, pinned Contracts/serde_json, existing bounded encoding and the real content ETag. The transcript store, cache write, source read and publication are synthetic test boundaries. Each of 16 cases ran stock/proposal/proposal/stock and matched the independent wire and effect oracle; the original inclusive byte limit/escaped UTF-8 test also passed. Controls include an unrelated large payload, repeated matches, a malformed row, both early and late write refusals, stale/missing late source, publish refusal and revision failure.

With one matching tool's args and effective args totaling 4,194,341 bytes, scoped requested-live peak fell from 12,583,023 to 8,388,682 bytes. Scoped gross fell from 8,388,682 to 4,194,341 bytes and request count from four to two; 4,194,341 live bytes remained either way. The meter counts only requests of at least 2 MiB, with the preseeded raw strings live at entry but not in gross. This is not process memory, latency, shipping-binary feature qualification, or a measurement of the store/fast path. Preserve-order was not run.

Single exact indexed hunk on the composed Core source. Against owner main and the packaged Core pin, the same uniquely matching hunk re-anchors from blob 581cb0ba to 471d5915 and reverses exactly. The owner whole leaf is different: it has older transcript traversal, pages and header code. Only the matching hunk and lifted repair body were compared, not those store components, and no native test ran on the owner build.

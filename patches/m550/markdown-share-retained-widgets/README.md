# Markdown: кэш сегментов и последнее показанное дерево делят виджеты

База: полный снимок Extensions на M398, после #638 (467 записей, Git tree `4ac69d505974e52635d68cfb74f1f0c94763352a`). `source.patch` меняет только native Markdown и общий Rust SDK, без JS, формата протокола или новых версий зависимостей.

Проблема: кэш Markdown хранил отрисованные сегменты, а каждый показ создавал глубокий клон каждого видимого сегмента. SDK удерживал этот клон, чтобы при неудаче другой поверхности с тем же ID вернуть последний вид. Поэтому крупный код/HTML дублировался и после отправки, а повторный показ ещё раз копировал всё дерево.

Теперь видимый корень и кэш держат ссылки на одни и те же неизменяемые `Value` сегменты. Свойство сохраняется и при повторной отправке: сериализатор читает виджеты напрямую. Прежние корни произвольного типа SDK также отправляет по ссылке, сохраняя владение для fallback. Ошибка Content по-прежнему отправляется без корня; при смене того же ID на обычную поверхность та же последняя успешная колонка доступна под предупреждением. Закрытие вида, смена сессии и замена колонки освобождают соответствующие владельцы. Невидимый Markdown не добавляет отступов. Сохраняются поля, порядок, `null`/отсутствие полей и compact JSON штатного `preserve_order`. Подключается прямая возможность сериализации уже зафиксированного `serde`; версии и исходники crate остаются прежними.

## Проверка границы

- Настоящий stdin/stdout `markdown-render`: 17 ответов (9 590 782 байта), полный byte-for-byte replay. Крупный блок кода, повтор того же ввода, добавление в хвост после fence, правка fence, позднее объявление ссылки, изменение списка провайдеров, другой контекст/сессия, две ошибки после смены Content → Page, замена успешным plain text и проверка отсутствия прежнего дерева после close.
- Настоящий `analysis`: 8 ответов (23 527 645 байт), локальный синтетический HTTP API. Проверены последовательность и повторный fallback обычных владеющих корней, ошибка Content и адресный revision.
- Проверка bundle `cargo test --locked --offline --workspace` со штатным `preserve_order`. Без одного известного уже на baseline Linux теста дочерних PID Mermaid (сразу после корректного SVG окружение вернуло пустой `/proc/.../children`, ожидается один PID); остальные тесты, в том числе реально адресованная ошибка Mermaid, прошли (339 на исходнике и 340 с патчем). Node-исходники и runtime не менялись. Графическое окно и полный PSS не измерялись.

## Память реального обработчика

Сборка Rust 1.95.0 debug без debug symbols; учёт на потоке рендера, включая отправку через SDK: запрошенные Rust layout bytes (`alloc/realloc/dealloc`), не RSS/PSS и не память инбокса до входа в обработчик.

| Синтетический вид | До | После |
| --- | ---: | ---: |
| Логически удерживаемый прирост после открытия большого prose, байт | 2 308 602 | 1 538 910 |
| Логически удерживаемый прирост большого блока кода (от открытия нового окна и первого малого вида), байт | 3 273 652 | 1 636 860 |
| Дополнительный логический пик повторного показа того же prose, байт | 770 615 | 142 |
| Дополнительный логический пик повторного показа того же кода, байт | 1 637 749 | 256 |

Пик первого парсинга текста в опыте не снизился; первый кодовый сценарий показал +672 байта дополнительного логического пика. У некоторых правок локальный пик *от входа в обработчик* выше: старый успешный корень остаётся доступен для ошибки, а новая версия начинает с меньшего объёма удерживаемых данных. Патч убирает двойное владение виджетами между рендерами, не хранение исходника, не сам разбор Markdown и не общесистемный расход памяти. Для малых узлов есть цена заголовка `Arc` и операции счётчика на сегмент.

## Воспроизведение

Запустить `python3 proof.py --baseline …/Extensions-M398-source.tar.gz --vendor …/verified-vendor --work …/scratch` с Rust 1.95.0 и Python 3.12+. Скрипт проверяет хеши архива и патча, запускает locked native сборки в изолированных каталогах, сравнивает исходные байты wire, временно вставляет измеритель в реальный обработчик, затем строго откатывает патч до всех 467 исходных байтовых записей, включая режимы файлов и ссылки. Измеритель не входит в production diff.

# Desktop Proteus: reuse exactly-sized resident storage when prepending history

One production patch on exact M380, in `src/transcript/mod.rs`. A backward page inserts up to 50 records at the head of a live archive window and may evict old rows at the tail. Once the window has 200 retained rows, its allocated array may still hold 250 slots from the previous insertion. Stock builds a second Entry array and appends the retained rows onto it anyway. The candidate splices the native owned page iterator into the existing array **only if the free slot count is an exact fit**. This moves entries safely, rather than cloning them. It retains the old collect/append path for an unallocated, growing or oversized window, so it does not pin disproportionate capacity left by a previously larger window.

The same wire-item constructor is used in both branches. The prepended page is consumed in ascending order with the same live-shared key allocator. Text and tool payloads, retained Arc identities, visible/seek bounds, splices and eviction budget stay unchanged. The content/iterator source is the real M380 Desktop reducer and Core wire declarations. The packet uses a scoped Rust lift rather than a full GUI/GPUI build (the two ListState-specific product tests are out of scope).

**Scoped result:** Four successive ordinary 50-row Older-page transitions in a 50,000-row archive, after the first 200 entries are resident and capacity is 250. Both arms publish the same 200 rows and insertion/eviction splices. The candidate keeps the same resident allocation rather than replacing it. Default map: **164,992 to 7,760 requested bytes per page**, ordered map: **202,416 to 7,760**. Both: 54 to 52 allocation/reallocation calls. Capacities are identical in these transitions; work and bytes are unchanged on the initial and growing requests. A short 3-row exact fit also reuses capacity, while the oversized and growth controls follow stock. These are allocation-request totals during page acceptance, not RSS or latency.

Run `python3 verify.py [--vendor /path/to/cargo-vendor]` with Rust 1.95.0. The optional vendor makes tests offline. This checks exact source hashes and forward/inverse application, then runs 27 scoped model tests per arm in both JSON layouts. Includes all admitted #616/#621 reducer controls, and `composition.json` verifies byte-exact composition with #597, #602, #609, #613, #616 and #621 in both candidate-first and candidate-last orders. Only the constructor and exact-fit insertion path changed; no transport, Core, Codex, cache-policy or security changes.

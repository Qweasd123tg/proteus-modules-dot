# Core: reserve space once for a large transcript continuation

When an existing reasoning display row is full and a much larger nonblank continuation arrives, the old code could reallocate once for the newline and again for the continuation. The patch reserves for both together in that narrow case. It preserves the final capacity; other append patterns stay on the old path. If reservation fails, it falls back to the original pushes. It does not change selected content, order, text, timestamps or stored transcript data.

The isolated Linux Rust default-layout proof passed 9 tests, including four original tests in each arm and a 13-case ABBA check. All 52 comparisons matched exact wire bytes, final capacity, requested-live peak and retained bytes. Appending a 2 MiB continuation to a full 512 KiB row eliminated one request of 1 MiB; the equivalent UTF-8 fixture also saved one request of 1 MiB. This measures requested allocation sizes, not physical memory, copy cost or elapsed time. No whole application, full history replay, store, lock or preserve-order result.

# Modules M384: transfer strict worker history text to the old SDK response

The canonical fallback can produce one 37 MB `ReadRecords` page even when the display projection declines at its 32 MiB state cap. The old `SessionStorageExport` serialized this fixed, already read page using `serde_json::to_value(response)`, which copied every owned `HistoryMutated.messages[*].parts[*].Text` string. The worker now selects the already verified ownership converter for this one existing operation. There is no new encoding, dispatch method, dependency, negotiation requirement, or worker frame output code. Display operations still require negotiated display projection and are unchanged. Unknown method/op/field and invalid DTO errors go through the same old SDK or pinned parser/validation as before.

The helper (`display_reply.rs`) stays *byte-identical* to #622. It builds ordinary serde object shells, then replaces existing empty Text value slots without inserting/reordering keys. All other journal entries/part types/metadata are serialized normally. No page size/revision/cursor/durable code changes. On strict reads, every outgoing record finished compact JSON serialization before reaching this converter, including an accepted immutable budget-deferred record whose count #625 remembers. Consequently the normal page-internal serialization failure has already surfaced at its original place before the worker's reply conversion; UTF-8 paths are sourced from valid archived JSON, and map fields use string keys/ordinary owned JSON values. The converter never changes order, filtering, admissions, input limits, output limit, or pending ownership.

## Reproduce locally

```sh
python3 proof.py --modules <exact Modules-M384-source.tar.gz> \
  --core <r271/deps/source-archives/Core.tar.gz> --vendor <r274/deps/vendor> \
  --work <new-work-directory> --target <new-cargo-target> \
  --cargo <rust-1.95.0-bin/cargo> --rustc <rust-1.95.0-bin/rustc>
```

Add `--prepare-only` to verify exact archive pins, registry checksums, and inverse without building. With no corpus arguments, the script builds `seed.rs`, which uses real typed native commits to make both durable fixtures. Existing shared durable fixtures can be reused by passing both `--manifest` (array of backend/locator pairs) and `--small-manifest` (object by backend, then `multi`). No network, repo changes, or user's data required. The recorded run directly linked rebuilt exact M384 main.rs arms against independently authenticated read-only native SDK libraries and the byte-identical accepted #625 storage library, skipping a redundant dependency compilation. Track only these local artifacts; no publish/switch/release implied.

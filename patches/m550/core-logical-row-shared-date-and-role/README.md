# Core: dense owning slots for certified startup transcript rows

## Change
The existing single-staged all-text Append certificate already establishes one exact signed message date. The compact representation used to repeat that date and a fat pointer to a static role string in every owning row. Keep the date once for the set and store the canonical role enum per row, using the same sole role mapping for full and compact output. Keep option/field declaration order, including phase, and serialize each compact row through a two-word dated view. The page planner still uses the same cardinality, serialized-byte budgets, packing, hashes and request order; its ordinary paths pass references as before. Only a short page buffer (up to 50 views, 16 bytes each here) transiently repeats the date. No extra whole-history scan or copy.

Eligibility and late spool record validity haven't changed: existing 4,096–65,536 admitted singleton text route, same hidden, duplicate, blank handling, physical EOF/count, cache source and publish fences. Noncompact, warm, borrowed and unpaged paths are unaffected semantically. A named miss still returns every rendered row and transfers original text allocations. This does not optimize the final public vector or claim admission for a >65,536/rich fixture.

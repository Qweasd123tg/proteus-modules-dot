# Count listed tool schemas without allocating a JSON string for each one

The usage report still serializes each listed tool using the same compact JSON encoder and still counts the resulting UTF-8 bytes. Instead of building a temporary String and reading its length, it sends those bytes to a nonallocating counter. One successful model call triggers one report; for K schemas in that request this removes K temporary JSON buffers. It does not remove the serializer traversal, change the tool list, change the model request, or alter usage arithmetic. If an individual serialization fails its contribution remains zero; all valid per-item bytes are summed before dividing by four.

Application: one Modules source leaf on canonical tree b610aa8f8df41195e654f170bd2a052e0f7ee951 (preimage 9e730256b1d00a2653805c0f722445e592652cc4). The checked byte sink follows an existing private implementation in a separate Modules crate, without introducing a dependency on the hook. The allocation sum panics on unrepresentable capacity rather than silently wrapping/saturating. The source-only strict forward/inverse check recovers the exact original leaf. Independent source checks confirm the patch also applies directly and reverses cleanly on owner Modules main e8e77e306092344c00833f3456acba950c851fe3 and on the revision pinned by both Core and Desktop (a271aaefcbcdd25f9b68918406f34490c6169bd7). No dependency on earlier delivery patches.

**Scoped native checks, default and preserve_order serde_json map layouts.** The actual accounting source was linked against the real Modules-pinned Contracts release library, not a fake ToolSpec. Twelve tests passed per layout (24 passes in total): five unmodified tests on each side, a 9-fixture ABBA matrix, and a partial-error/overflow control. Across 72 report rows (36 per layout), complete usage-report byte strings and per-schema unrounded counts agreed across matched arms. Retained requested bytes were unchanged, and the reported allocation figures below were the same in both builds. The empty list was identical on every measure.

- For a synthetic list of 128 small schemas totaling 39,826 encoded bytes, **gross requested bytes per report fell from 114,868 to 180** (391→7 allocation/reallocation calls). Since the original buffers were sequential, peak was only 512→172 B; the 114,688 B gross saving is not a peak saving.
- With one large synthetic input-schema description (~2 MiB), peak was 4,194,468→172 B; with the escape-heavy input it was 4,194,304→172 B. These stress cases do not establish typical schema sizes.

The estimates above are scoped allocator requests above an already constructed fixture, not resident memory, wall time, saved tokens, or whole-worker behavior. A full worker/provider/application was not run. No upstream installation or behavioral change to compaction, execution, or transport is claimed.

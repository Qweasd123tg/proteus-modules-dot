# R161 — OpenCode: не пересоздавать part без сохранённых полей

Один `source.patch` для stock Modules `9469e3b12529d08b1f4a76882693e2065e842c51`
и точной основы после #452 → #462 → #465 → #466 → #467 → #468 → #469 →
#470 → #471. Меняется только `model/opencode-provider/messages.mjs`.
Во второй основе нижний hunk смещён на 17 строк из-за #471, контекст
совпадает полностью, fuzz 0. Обе основы проверены forward/reverse dry-run и
полным byte readback (опция `--no-backup-if-mismatch` исключает файл `.orig`).

Уже созданный native part добавляется в запрос без нового spread-объекта,
если нет принятых полей из сохранённой metadata. Промежуточный extras
объект появляется только после первого поддержанного значения. Тип
part проверяется до выбора быстрого пути даже при type-only/unknown-only
metadata. Белый список, порядок ключей, две прежние операции чтения для
принятого значения, `undefined` как отсутствие, допустимые falsy
значения, порядок `extras → canonical native` и декодированные args
сохранены. Порядок изображения, file/signal и индекс имён #471 не меняются.
Речь о двух конкретных временных объектах, не обо всех аллокациях DTO.

Проверены Node syntax и **14/14** тестов: 6 новых и 8 повторных #471.
На точном неизменённом коде до/после совпали сериализованные native DTO
и ошибки на stock/composed; покрыты ключи, falsy, конфликт encrypted,
getter access, file/cancel и неверный тип. Отдельный тестовый VM-пробник
добавил наблюдение на единственном push, подтвердив идентичность
переиспользованного wrapper и отсутствие extras результата для
absent/type-only/unknown-only/undefined. В production-коде пробника нет.
SDK/Media/file reader были инертными; реальные SDK, file read, запросы,
inference, PSS и задержка не запускались и не измерялись.

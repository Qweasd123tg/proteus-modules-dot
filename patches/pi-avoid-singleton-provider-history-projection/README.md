# R175: Pi model/v14 без массивов-обёрток на каждое сообщение

Раньше адаптер для каждой записи истории вызывал `piMessages([m], model)[0]`.
Теперь он вызывает ту же проекцию для одного сообщения: не нужны одноэлементный
вход и результат `map`. Одна локальная таблица имён на запрос переиспользуется
и очищается до возможного чтения изображения. Она отделена от таблицы адаптера:
как прежде, все части текущей записи сначала участвуют в общем поиске имён,
затем проекция возвращает первый ToolResult. Более поздний вызов в текущей
записи по-прежнему может переопределить имя; пустая строка и отсутствие имени
не смешиваются. Пакетный `piMessages` сохраняет прежнюю общую таблицу на весь
массив. Чтение изображений, ошибки, параметры SDK и отмена не изменены.

Один патч для Modules `331cfc20bbaf821ab07de49868426da29ebdeb64` и для той же
основы с #481. Наложение, снятие и оба порядка с #481 проверены побайтово.
При сравнении без отступов видно, что тело проекции перенесено без изменений.

**13/13** тестов Node 24.22.3: реальный код адаптера, проекции и Pi workflow с
подставными SDK, хостом и чтением одного тестового изображения. Проверены
побайтовая проекция и результат модели, режим Go, конфликты имён, порядок
ошибок и отмены, пакетная проекция и путь #481 с checkpoint. На 50 000
текстовых сообщений число вызовов `map` на одноэлементном входе снизилось
с 50 000 до нуля; до нормализации число конструкторов `Map` снизилось
с 50 001 до 2 (включая общую таблицу). Это счёт операций, не измерение
памяти или скорости. Настоящий SDK, модель и сеть не запускались.

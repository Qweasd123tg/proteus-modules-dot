# R284 deterministic source-recheck acceptance gate

Both default and preserve_order feature graphs must pass the same independently checked cold repair matrix. Measure only requested Layouts for original allocation generations of a fully validated, rendered, best-effort saved SessionReadModel at the real final OpenSnapshot and real conditional ReleaseSnapshot. Record after exact save and before returning the model to either source arm; tag only this final snapshot, not the preliminary named validation or strict replay snapshot. Allocations later reusing a captured address must not count. Projection entry starts a fresh recording generation; test fixture construction and separate diagnostics are excluded. No stock/candidate CRC on Rust object addresses; it is the owner generation and capacity that matter.

* 5,000 and 50,000 public-seeder-shaped rows in both layouts, including a named repair and an unnamed repair, must have zero candidate original owners in all tagged dropped categories across final OpenSnapshot/ReleaseSnapshot. Stock must retain these owners exactly. At least 3.5 MiB at 5,000 and 35 MiB at 50,000 of requested bytes must be freed early in each feature graph. Set allocation bytes must be found from actual element addresses and layout ranges, never inferred from set capacity. Observe separately the canonical header/data, part buffers, text and metadata, context, digest vector, three UUID identity sets, summary owners and rendered row vector/string owners. Counts should reflect original generations, not totals of allocation during the operation. Shares or unclassified owners must be distinguished; incomplete attribution cannot be called complete.
* All original tagged transcript owners present at model capture must remain present through OpenSnapshot and, on successful checked open, ReleaseSnapshot. Require matching transcript capacity and ordered owning rows, public 50-row window capacity, full named response, error text and typed source errors, immutable source/hash/revision validation and genuine cache and release order. Normalize nondeterministic prefix identity ordering only after per-store digest/key checks. Failures before model completion and cache-hit bypasses must not be counted as measured repair. If final OpenSnapshot fails, no release of that nonexistent handle; best-effort release failure on an actual handle must not change semantics.
* Require projected and strict fallback; named prelim mismatch/race, no preliminary unnamed open, validation/renderer/prefix fault, data/prefix/named/head cache faults, valid last recheck and same revision with changed content hash, changed revision/session, unexpected response and typed missing session at final OpenSnapshot, plus invalid before precedence. Do not silently count any missing min-gate checks: explicit HOLD if any required route/case or both layouts cannot be substantiated.
* No CPU, RSS/PSS, allocator usable size, end-to-end latency, worker/native Desktop, peak across full repair, cache-hit, or installed runtime claim. If a checked result concerns an instrumented worker seam, label it. Production code must not include marker or meter behavior. Never move validation, I/O, release, cache publication, final sizing or output; one local ownership change only.

# R284 cold cache repair proof scope

This route uses the exact stock and patched Unix application read_model.rs callers for named full transcript and bounded named or unnamed pages. A cache miss runs the genuine project_sourced_read_model (not project_validated_view), real Core RemoteValidatedRead projected or strict canonical path, real one-file temporary stage and physical record scans, renderer, canonical digest/identity computation, compressed page cache/prefix write, named/HEAD publication, then the genuine final snapshot-backed fingerprint through the real journal_snapshot/read/release sequence. All CanonicalMessage, SessionStorage, AppTranscriptPage, journal validation and fallback types come from the complete pinned Contracts and Session Semantics crates. The stub is a typed SessionStorage test implementation, not the production process or filesystem cache provider; it serves validated journal records and retains actual typed cache key/value/ETag behavior. The initial 5k/50k stress history is exactly the public seeder's four-repeat Cyrillic text shape, with deterministic IDs in one append journal record. There are no owner records.

Only observation calls and visibility required for the harness are added to the common lifted Core. The renderer and prefix-stage observer deliberately alter stage count only on explicit injected renderer/prefix failure cases. Public-shaped happy paths use the actual temp file; metadata verifies byte length and exactly one staged record. The meter records the exact owned model before returning it from project_sourced_read_model, after snapshot release and cache writes; a phase token distinguishes the subsequent authoritative OpenSnapshot from any preliminary named probe, any stage open, and normal warm HEAD reads. The full actual final descriptor is matched on its ReleaseSnapshot: the matched handle can differ from the projected handle yet pass if session/revision/content match. No successful open release is required for an open error, malformed response or wrong session, and a release failure is intentionally ignored as upstream. The malformed test replies reach the actual Core guard by bypassing the typed adapter's good-case response validation; this does not claim external process wire acceptance. Other injection cases are stage renderer failure, later prefix scan failure, invalid journal, initial unavailable named revision and stage race, hash/revision changes, worker disconnect and typed MissingSession, bounded-page precedence after revalidation, rejected page, optional prefix, named and HEAD writes, and warm bypass. Separate compacted-history controls drive a real nonempty canonical model-context observation.

Both arms use the same fixture and run with isolated cache state. Assertions compare entire output representations (or exact formatted failures), bounded response size/capacity and independently verified row identities, role/text/timestamp/order; request sequence and actual publish order; content-page key/value/ETag hashes; and headers. Prefix membership order produced by hash tables is not semantic: each persisted raw ETag is checked by the true decoder, the ordered canonical digests are checked individually, and only the membership sets are sorted for result comparison. Raw output preserves one part digest per arm-equal result, operation sequence hash, physical stage footprint and original-allocation ownership counters. The result only covers this rebuild path. The #571/R263 cache-page substitution proof applies to another entry point and alone cannot reproduce this ownership release. No throughput, overall peak, aggregate allocations, heap pages, process RSS, I/O duration, or full cold application launch claim follows. At the measured point the complete rendered transcript remains live in both arms, while only the candidate releases the specified nontranscript model owners.

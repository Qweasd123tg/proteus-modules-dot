# Resolve the stored revision before cloning resident conversation history

One Core source change, local proof. At the current Core commit `b2d2e6dedf0ea423b5f149c12ef98b8a0de01b14`, the resident `ConversationReader::read` takes the history and context locks, clones all messages, and **then** asks the store for the history revision. When another handle holds the session writer lock, this second owned history sits inside the waiting reader. An unsuccessful revision lookup returns no conversation, so that clone is also wasted on this error path.

The patch asks for the stored revision first. It keeps both guards, their order, the same writer/snapshot/error/release path and the required owning response. The no-store path preserves the original order literally: messages clone, lazy SeqCst revision load, then context snapshot. Nonresident delegation remains byte-for-byte unchanged. Neither eviction nor sharing is introduced.

| Synthetic public history | Stock live clone at writer wait, default | Stock live clone, preserve_order | Candidate clone in either layout |
|---|---:|---:|---:|
| 0 messages | 0 B | 0 B | 0 B |
| 1 message | 678 B | 758 B | 0 B |
| 5,000 messages | 3,403,890 B | 3,803,890 B | 0 B |
| 50,000 messages | 34,088,890 B | 38,088,890 B | 0 B |

The 50,000-message difference is 100,001 requested allocations: the outer vector, one part vector and one owned string per message. On typed worker failure, unexpected response and wrong-session response, stock allocated and discarded that whole clone before returning the error; the candidate returned the same error without allocating it. At cancellation, stock discarded the pending clone; the candidate never made it. Both arms released the guards and allowed a subsequent read. The separate 63-message mixed fixture (tool calls/results, metadata, ordered context and escaped strings) showed 99,495 B/757 allocations in default and 94,455 B/841 in preserve_order, likewise reduced to zero at the wait.

**Successful completion catches up.** Each arm returns an equal, independently owning snapshot with matching exercised capacities and the same gross allocation count/bytes during the poll(s) to success. The refactor does not shrink previously resident input or the returned history, and does not claim lower successful-read peak, idle memory, allocator pages, RSS/PSS, CPU or latency. The boxed read future itself requested 208 B in stock and 184 B in the candidate on these specific x86-64 release builds; those bytes are excluded from the table. Writer contention and faults were injected to expose the phase, not sampled in live user sessions. The large histories use the actual public seeder's constructor in an active resident fixture, not a cold-start measurement. The nonresident path was checked separately, with no savings claimed.

## Evidence

* `source.patch` is the only production edit; preimage `b9e28251c1bc18a003d0b5f62d5db1dbb77d4490`, postimage `237e7f68fca0261e9764f4a600443b54e4f374ee`. Native release with Rust 1.95.0, full pinned contracts/session-semantics, Tokio 1.52.2, async-trait 0.1.89 and anyhow 1.0.102. The focus harness lifts the genuine read, writer registry, revision, open/read/release, and nonresident spawn_blocking path. Only the storage service boundary supplies test replies. See `route-scope.md` for precise limits.
* `GATES.md`, `{default,preserve_order}.jsonl` and matching `*-check.json`: 55 paired actions per layout, 110 stock/candidate pairs total. Input construction, futures' box allocation, and independent message clone are outside poll samples. The thread-local global allocator counts requested Layout, with realloc treated as old-layout free plus new-layout allocation. The independent checker reconciles bytes with exact UTF-8 text lengths and clone counts; admission and cancellation verify genuine lock ownership and wake behavior.
* `*-route.jsonl` and `*-route-check.json`: 25 behavioral cases per arm per layout; lease, immutable snapshot, wrong response/session, typed error, ignored release error, nonresident worker-thread read, four cancellation points, queued sibling, and no-store. Reopened same-service/session handles share the real weak-registry writer. Successful snapshot revisions, contents and request/release order match.
* `proof.py` first verifies local immutable inputs, builds a focused crate and regenerates the exact route lift. Stage verified 147 pinned Core files, 152 locked archives, 8,573 archive members, both feature graphs and the generated lift. The four actual focused executables were built and run on the verified shared offline lane; the portable recipe was independently staged, not advertised as a second whole-workspace build. To replay with the pinned local Core checkout, official crate archives and Rust binaries, use `python3 proof.py --core CORE --archives ARCHIVES --rust-bin RUST_BIN --work NEW_EMPTY_DIR --action run`. It does not need network access. Raw receipts can also be checked with `python3 check_layout.py default.jsonl` and `python3 check_route.py default-route.jsonl`; repeat for preserve_order.

No remote writes, full desktop run, worker-process benchmark or deployment.

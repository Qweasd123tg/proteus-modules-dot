# R283 focused resident-conversation route

This is not a full Core, Desktop, worker-process, or native cold-open benchmark. The pinned upstream bodies under test include both TurnConversation::read implementations (stock and the single source patch), actual RemoteSessionStore::history_revision, the real shared Tokio writer registry and lock, and the open/descriptor/conversation/Drop methods of RemoteJournalSnapshot. The nonresident branch uses the original Tokio spawn_blocking call. The complete real contracts and session-semantics crates supply the message, storage protocol, snapshot, context and model types. The projection-only inactive fields of the remote writer and snapshot retain their exact source-declared storage layout. Test setup constructs the writer's valid lease/revision state directly; no lease-acquisition operation is being benchmarked. Async storage calls are rejected at the boundary because the exercised methods use blocking requests.

The program lift_route.py STOCK_CORE_TREE CANDIDATE_CONVERSATION_FILE OUT/route checks Git blob IDs and emits OUT/route/core.rs; copy route.rs to OUT/main.rs and use the locked manifest. One test-only widening makes the two TurnConversation types visible to drivers; no behavior inside a lifted method is replaced. The only response seam is a typed SessionStorage implementation. Good requests and responses are contract-validated, including exact immutable prefix/session on read/release. Selected malformed responses deliberately pass directly from the fixture to the real open / conversation discriminant and owner checks, simulating a bad in-process storage provider; they are not an allegation that a process transport accepts invalid wire replies. Typed MissingSession is injected as an actual error; ReleaseSnapshot errors are ignored by the original destructor. Actual vs expected request order and writer availability are asserted separately from the memory measurements. Recorder storage and lock probes belong to the fixture, not the application. No OS RSS, latency, throughput, cold-history or storage-worker memory conclusion follows from this route.

The route binary emits 25 cases per arm: shared writer lease and no-lease success at 0, 1, 5k, and 50k synthetic messages for both source arms; open/owner/typed-worker faults, best-effort release, actual nonresident blocking route with external writer + context deliberately still locked, distinct persisted conversation, four cancellation points, a queued sibling and no-store controls. Reopening through the real weak registry proves that a separately opened same-service/same-session handle occupies the very same writer lock. Cancellation includes the point after the real waiter has received a permit but before repoll: errors and cancellation before a snapshot exists send no release request; once a real snapshot exists, normal Drop makes the expected release. The public seeder's actual message constructor creates the histories once per scale; both arms share the same resident Arc, including its IDs. In route controls, these are synthetic in-memory payloads, with no operating-system or production-traffic measurement. The independent measured binary supplies separate mixed fixtures and scoped requested/live byte assertions.

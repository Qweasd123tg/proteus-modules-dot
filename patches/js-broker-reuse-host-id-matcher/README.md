# R162 — JS broker v3: один matcher host invocation ID на процесс

Один `source.patch` для точного Modules `9469e3b12529d08b1f4a76882693e2065e842c51`
и той же основы с выбранными патчами до #472 из `SOURCE-PROVENANCE.json`.
Оба preimage файла `components/module-runtime-js/component.mjs` совпадают
побайтово: ни один из выбранных предыдущих патчей его не меняет. Для обеих
основ повторное применение и снятие патча дали точные байты, без fuzz.

Брокер задаёт строку generation из валидного initialize и не меняет её после
ready. При первой проверке строкового ID брокер создаёт и затем переиспользует
один RegExp на время своего запуска. Выражение и отсутствие флагов
сохранены; нестроковый ID по-прежнему отклоняется до RegExp. Не меняются
порядок проверок, границы dispatch, lineage, отмена, callback IDs, права
и wire schema. На успешном initialize без вызовов RegExp не создаётся.

**7/7** проверок на реальном исходнике stdio брокера и Node 24.22.3 с
инертным export. Сравнили точные stdout-байты для initialize, root/nested
вызовов и callback, отмены, ошибочных ID и длинных десятичных строк.
Отдельный тестовый наблюдатель засёк 10 вызовов конструктора до патча и
один после при тех же 10 проверках; для init-only, только нестрокового
ID и неуспешного initialize во всех вариантах ноль. Наблюдателя в
патче нет. Это подсчёт вызовов конструктора, не замер компиляции движка,
задержки или памяти. Установленный Node 24.12.0, SDK и реальные профили
не запускались; запросов, credentials и сетевого доступа не было.

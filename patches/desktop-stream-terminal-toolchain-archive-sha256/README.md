# Desktop: SHA-256 архивов Ghostty без загрузки всего файла в память

В `scripts/terminal_toolchain.py` контрольная сумма рассчитывается блоками в одном буфере на 256 КиБ. Свежая загрузка по-прежнему проверяется до и после атомарного переноса, кэш проверяется без новой загрузки. Не меняются закреплённые хеши, проверка пакетных хешей самим Zig, блокировка, очистка временного файла и сообщения об ошибках. Для отдельного вызова скрипта нет новой зависимости от версии Python.

На точном Desktop stock и stock + collector #477 прошли **5/5** исходных и **8/8** тестов с патчем (CPython 3.12.14). Проверены валидный кэш и загрузка с локального файла, повреждённый кэш и несовпадение уже после переименования.

Для локального архива **16 777 329 байт** сохраняются digest и объём входа: две проверки на свежей загрузке, одна на кэше. Наблюдаемый пик отслеживаемых аллокаций Python в `download()` упал с **16 783 212 до 268 466 байт** на свежей загрузке и с **16 781 867 до 267 377 байт** на кэше (stock). Запросы к потоку не превышали **262 144 байт**; последний блок меньше максимума и проверяется тем же SHA-256.

Это проверка памяти этапа подготовки сборки, не Desktop RSS, время, физический I/O или запуск приложения. Для малого файла тоже выделяется фиксированный буфер. Настоящие загрузки, установка Zig, Cargo и релиз не запускались.

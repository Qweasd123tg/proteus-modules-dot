# Desktop developer launcher: use the selected Core for module preflight

The development launcher used to resolve `PROTEUS_BIN` and then check the modules in the Desktop portable, even when that portable was unrelated to the selected backend. For the default backend, and for explicit aliases of that backend, the bundled module check is unchanged. For an independent backend, check existing adjacent module metadata using the same validator and root layout convention as Desktop's inventory. An explicit executable without adjacent metadata is responsible for its runtime; this supports independently installed Core wrappers without requiring a duplicate portable bundle.

Only the developer launcher's preflight changes. Extension compatibility checks, executable resolution, PATH and attached/Codex argument forwarding are unchanged. The preflight does not certify the modules eventually selected by a wrapper or by runtime PATH lookup. No Core process, Cargo build, real attach, or extension is launched by the proof. The real launcher runs against inert artifact fixtures and a fake Cargo that only records arguments and environment. See `receipt.json` for exact sources and tested scopes.

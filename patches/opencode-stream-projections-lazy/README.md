# R153 — OpenCode: загружать request/response только для stream

Один изменённый файл: `model/opencode-provider/adapter.mjs`. Патчи —
альтернативы, не накладывать оба:

- `source.patch` для исходного Modules `9469e3b12529d08b1f4a76882693e2065e842c51`;
- `composed.patch` для точной сборки после #452 (collector), #462 (выбранные
  роли Worker) и #465 (локальный describe для Go/Zen).

При создании model export не загружаются два локальных файла проекции запроса
и ответа (`messages.mjs`, `response.mjs`). После проверки первой подходящей
операции `stream` они загружаются вместе. Одновременные первые запросы ждут
одну пару import; успешно загруженная пара используется без нового import
или await на следующих вызовах. После ошибки pending очищается. Отсутствующий
export проверяется до credential/resolve; детали дефекта пакета не уходят в
ответ. Методы, manifest, credentials, resolve, transport, catalog/seed,
config schema и runner не меняются.

До и после ожидания проверяется отмена. К моменту завершения import отменённый
вызов не запускает auth/resolve/transport. Сам ESM import не прерывается и
может завершиться для другого одновременного запроса; латентность отмены не
измерялась. Первый корректный stream оплачивает отложенную загрузку. Если
пакет отсутствует или сломан, ошибка теперь приходит как прежний
санитизированный `request_error` первого stream, а не как прежний сбой
статической загрузки adapter при initialize.

Проверено: обе точные основы, применение/обратный dry-run с 0 fuzz, readback
изменённого leaf и Node syntax. Изолированный Node VM: 8/8, реальные исходники
adapter, messages, response и локального context helper, инертные SDK,
metadata runtime, auth, quota и transport. Сравнены manifest и metadata методы,
отклонённые операции, события и номера ACK/terminal для первого и повторного
запросов, injected/default transport, ошибки до/после видимого события и
неисправные exports. Отдельно проверена одна пара загрузок для конкурентного
первого stream и отмена до и во время него. Metadata-ветка не конструирует два
локальных leaf и context helper в проверенной проекции. Это не число всех
загруженных npm modules: возможные транзитивные импорты native SDK не менялись
и не измерялись. Реальный поставочный SDK, Core/Desktop startup/first turn,
фактическая сеть, latency и память не запускались и не измерялись.

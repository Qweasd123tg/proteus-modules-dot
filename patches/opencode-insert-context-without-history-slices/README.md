# R166: OpenCode workflow, один массив для вставки контекста

Меняется только `withContext` в `workflow/opencode-runtime/workflow.mjs`.
Вместо двух временных срезов истории новый массив строится одним вызовом
`toSpliced(anchor, 0, msg)`. Без чанков возвращается тот же объект; при
наличии чанков сообщение контекста вставляется перед первым User.
Сохраняются порядок и ссылки на сообщения, сами чанки, стабильные ID,
состав и метаданные контекстного сообщения. Пустой слот после User
по-прежнему становится собственным `undefined` в результате. Поиск и
ошибки отсутствующего User не меняются. История не мутируется.

Установленный OpenCode launcher и тестовый скрипт закрепляют Node
24.12.0, в котором есть `toSpliced`. Один `source.patch` для точного
Modules `9469e3b12529d08b1f4a76882693e2065e842c51` и выбранной основы
через #475: ни один из этих патчей не меняет данный файл. #474 меняет
отдельный файл компакции, а #475 относится к Extensions. Для обеих
основ patch/reverse с fuzz 0 дали побайтовое совпадение.

**6/6** тестов Node 24.22.3 на точной функции (добавлен только тестовый
export; прочие импорты инертны). Сравнены байты JSON, IDs, ошибки, позиции
первого User, sparse-слоты, повторный вызов и неизменность источника.
На 32 768 элементах истории наблюдались два среза на 32 768 ссылок до
патча и ни одного после; результат получен единым нативным вызовом
`toSpliced`. Это подсчёт срезов и копируемых ссылок, без замера
памяти или задержки. Штатный Node 24.12.0, SDK, модель, полный workflow,
чтение файлов клиента и сеть не запускались.

# Pi: переиспользование массива частей ответа

В необязательном Pi workflow ответ модели сначала проецируется в формат Pi.
Если в результате ровно одна запись и её части уже лежат в новом массиве,
`assistant()` возвращает этот массив без повторного копирования ссылок.
Для нескольких записей, пустого результата, пропуска или строки
System/Developer остаётся прежний `flatMap`. Проекция не меняется, входные
записи не мутируют и сам массив результата не связан с их массивами.

Прямой импорт фактических JS-модулей, пять парных проверок в четырёх вариантах:
331cfc20, с этим патчем, с #484 и с обоими. На одной синтетической записи с
20 000 частями ушли один вызов `flatMap` и одно копирование 20 000 ссылок;
порядок, ссылки на сами части и сериализованный ответ совпали. Проверены
tool/opaque/native-части, исходные вложенные ссылки, ошибки и все ветви
без переиспользования. SDK, модель и сеть не запускали; время и память
не измеряли.

Одна правка в `components/pi-runtime-js/messages.mjs`, совместима с #484.
Прямое и обратное применение сходится побайтово, без fuzz; после #484
единственный блок смещён на две строки из-за его более ранней правки.

# OpenCode: использовать уже созданную первую часть запроса сжатия

При преобразовании сообщения для вспомогательной модели сжатия
`canonical()` уже создаёт первую часть с UUID. Сохраняем её вместо
создания такой же части с новым UUID. Остальные части, пустые сообщения,
пропуски в массиве и связь с результатом инструмента остаются прежними.

В пяти парных проверках фактического JS-моста и функции `canonical()`
совпал весь запрос к заглушке Core после нормализации проверенных
UUIDv4. Ниже только структурный результат: на 50 000 непустых
синтетических сообщениях число вызовов UUID снизилось со 150 000 до
100 000. Проверены мультимедиа, ошибки, порядок частей и отмена.
Нативный SDK, модель, инструменты и сеть не запускали; время и память
не измеряли. Это путь отправки вспомогательного запроса при сжатии,
не запуск процесса и не чтение истории.

Единственный патч подходит для 331cfc20 и для базы с #474 и #486.
Оба порядка относительно этой пары и откат сходятся побайтово без fuzz.

# R190: сгенерированный launcher OpenCode не импортирует pathlib

Меняется только Python-строка, из которой установщик пишет launcher.
После разрешения символьных ссылок `os.path` строит прежние пути к
комплектному Node и `worker.mjs`. Вызов `execv`, параметры `["node", worker]`,
наследование окружения, рабочей директории и статуса выхода не меняются.
Аргументы launcher по-прежнему не передаются. Установка npm, состав
пакета, права файла и генерация манифеста остались прежними.

Разрешение пути строгое: если файл исчез или имя стало циклической
ссылкой после открытия скрипта, запуск прекращается до `execv`.
В таком случае сообщение и момент ошибки могут отличаться от прежнего
нестрогого `Path.resolve`. Это не гарантия против всех замен файла.

Патч для Modules `331cfc20bbaf821ab07de49868426da29ebdeb64`.
**8/8** тестов Python 3.12.14: точный извлечённый launcher с инертным
исполняемым файлом в отдельном префиксе, абсолютный и относительный путь,
PATH, ссылки, перенос, ошибки запуска и проверка argv. Из импортов
извлечённого launcher исчез `pathlib`. Настоящий установщик, npm, Node
из пакета и сеть не запускались; время и память не замерялись.

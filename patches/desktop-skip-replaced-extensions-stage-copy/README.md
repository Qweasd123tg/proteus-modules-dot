# Desktop: не копировать заменяемые расширения при выборочной сборке

При `--components extensions` готовая база больше не копирует старый `share/extensions` в staging перед заменой всего каталога. Исключается только этот путь в обычной реальной базе. Символьные ссылки в корнях, алиасы базы, необычные режимы каталогов, смешанное обновление, `--full` и `--reuse-binaries` не получают новый путь.

Предварительная проверка готовой базы и новых расширений, проверка собранных файлов, хеши/лицензии, блокировка, атомарная публикация и сохранение рабочего пакета при ошибке не меняются. Исключение относится к уже заменяемому содержимому: ошибки чтения отдельных старых файлов больше не возникают на пропущенном копировании. Это не изменение общей поддержки ссылок и не защита от внешних конкурентных писателей.

На точном Desktop и Desktop + #477/#479: **20/20** исходных и **25/25** тестов с патчем на каждой основе. Отдельная проверка реального Python orchestration с инертным упаковщиком подтвердила одинаковые 33 конечных пути, SHA-256 файлов, режимы и цели ссылок; исходная база не менялась. В каждой паре исчезли **3** вызова копирования старого каталога, всего **4 194 387 байт** входных файлов синтетической базы.

Запуск Cargo, установка, сеть, реальная публикация и замеры времени или физического I/O не выполнялись.

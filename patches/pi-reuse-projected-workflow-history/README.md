# R172: Pi workflow, одна проекция истории для состояния цикла

После прежнего `piMessages(history, model)` хвост для `runAgentLoop`
берётся тем же `slice(-1)`. Затем в уже созданном приватном массиве
ссылки на префикс сдвигаются в обратном порядке и на место первого
элемента записывается прежнее system-сообщение. Нет временного среза
префикса и отдельного большого массива состояния. Исходная canonical
history, содержимое сообщений, хвост, порядок и параметры SDK не
изменяются. Пустая история даёт только system в состоянии и пустой
хвост; обычные дыры в массиве после проекции сохраняют старый результат.

Один `source.patch` для Modules `331cfc20bbaf821ab07de49868426da29ebdeb64`
и выбранной основы через #480; этот файл и зависимости проекции в обеих
основах побайтово совпадают. Наложение и снятие проверены с fuzz 0.
Имеющийся installer включает этот Pi workflow. В исходниках Pi v1.5.2
`runAgentLoop` сам копирует входные сообщения в рабочий массив; этот
патч убирает только промежуточные копии Proteus, не копию SDK.

**7/7** тестов Node 24.22.3 на точных workflow и `piMessages`,
с инертным SDK и хостом: пустая история, один User/System, ToolResult,
очерёдность, неизменность источника, sparse-слоты, ошибки и один полный
локальный путь до мок-ответа модели, включая checkpoint и terminal.
В отдельной ветке проверки на 32 768 сообщениях пропал срез префикса
на 32 767 ссылок; хвост из одного элемента остался, а переданный массив
состояния совпал с приватной проекцией по идентичности. Это наблюдение
структуры, не измерение latency, RSS или PSS. Штатный npm SDK, модель,
настоящие инструменты и сеть не запускались.

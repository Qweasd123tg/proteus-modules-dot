# R164: OpenCode compaction, прямой индекс результатов инструментов

В `nativeContext` хук по-прежнему индексирует весь контекст до перевода
сообщений и до обращения к native prompt. Два вызова `flatMap` больше
не собирают промежуточные списки и пары: запись идёт прямо в прежний Map.
Сохраняются порядок обхода, результат из будущего сообщения, учёт всех
ролей (включая предыдущие checkpoints) и правило «последний result
одного call_id побеждает». Индекс остаётся в пределах одного вызова.
Ограничения inline media, формат запроса, оценки, права и отмена не меняются.

Один `source.patch` подходит для точного Modules `9469e3b12529d08b1f4a76882693e2065e842c51`
и выбранных последующих патчей через #473: они не меняют этот файл.
Ранее предложенное переиспользование prompt estimate уже целиком находится
в stock, включая прежний тест. Это проверено снятием и обратным наложением
точного патча с fuzz 0 и побайтовым сравнением обоих файлов. R164 также
проверен применением, снятием и побайтовым сравнением для обеих основ.

**7/7** изолированных тестов Node 24.22.3 с точным JS и инертным SDK:
одинаковый сериализованный контекст, результаты из будущих / повторных
вызовов, ошибки, checkpoints, inline images и отмена до чтения истории.
Отдельный тестовый наблюдатель на 2 048 сообщениях зафиксировал в старом
индексе 8 193 промежуточных массива этих четырёх видов: внешний результат,
внутренние результаты, результаты callback и пары. В новом их нет,
и в обеих версиях те же 2 048 записей в Map. Это подсчёт операций данного
индекса, не замер heap, RAM или времени. Реальные SDK, модель, сеть,
файлы клиента и полный нативный сценарий компакции не запускались.

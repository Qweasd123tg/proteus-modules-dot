# Установка пакетов Desktop: общий patch от 5 ноября 2026

Пакет для переноса в `Proteus-harness/Proteus-desktop`. Публикация и слияние
этого каталога в `proteus-modules-dot` доставляют артефакт; исходный Desktop
от этого не меняется. Готовый бинарник и portable-сборка сюда не входят.

## Состав

`desktop-installation.patch` объединяет три совместимых изменения:

1. Обновление Agent Plugin из каталога сохраняет `enabled` прежней привязки
   профиля, включая переход на другой путь версии. Новая установка без
   прежней привязки включена по умолчанию; соседние плагины не меняются.
2. ZIP и каталог проверяют полностью подготовленные файлы расширения обычным
   on-disk валидатором до замены установленной папки. Неполные ссылки на
   `SKILL.md` отклоняются; прежний пакет сохраняется, временная папка убирается.
   Проверка не запускает команду расширения.
3. README поясняет подготовку Ghostty/Zig перед прямым Cargo, а пример
   каталога использует правильное имя `mcp.json` для Agent Plugins 1.0.

Перестановка обновляемого плагина в конец списка остаётся прежним поведением
`remove/add`. Сохранение состояния не означает сохранение позиции в списке.
Изменения процессного протокола, SDK и Core в этот patch не входят.

## Применение

В чистой рабочей копии Desktop, сохранив свои незакоммиченные изменения:

```sh
git switch -c fix/desktop-installation-20261105 6e66189b50c112cf13448fc1feaa1eee5a3c85d6
git apply --check /absolute/path/to/desktop-installation.patch
git am /absolute/path/to/desktop-installation.patch
git diff HEAD^ HEAD --check
```

Применяйте общий patch один раз. Он уже включает все три исходных изменения.
Для другой базы сначала проверьте совместимость; применимость к будущему
`main` не подтверждена. SHA созданного `git am` commit может отличаться из-за
метаданных коммитера; итоговое tree на указанной базе должно совпасть.

## Выполненные проверки

- Последовательное применение трёх исходных patches к базе даёт ровно то же
  Git tree, что общий интеграционный commit.
- Общий patch применяется к указанной базе; `git diff --check` проходит.
- `rustfmt` Rust 1.95.0 проходит для пяти изменённых Rust-файлов.
- `python3 scripts/check_licenses.py`: PASS.
- `python3 -m unittest discover -s scripts -p 'test_release*.py'`: 118 PASS.
- Изолированная Rust-проверка объединённых исходников: 31 PASS, 0 FAIL.
  Включены настоящие `packages`, `manifest`, `package`, `session`, все модули
  каталога и их тесты, а также настоящие `settings/draft`, `addons` и `mcp`.
  Проверены оба новых теста `enabled`, ZIP/catalog preflight и соседние
  сценарии установки, discovery, MCP, локального Git и packaged skills.
- Зависимости Rust-проверки закреплены по Desktop `Cargo.lock`; сверены все
  пары `(name, version)`. Используется настоящий закреплённый
  `proteus-contracts` из Core `08e0ee67ff8115fd545b08e4a937e38388fc8f53`.
- Отдельная проверка preflight на исходном baseline воспроизвела три
  ожидаемые ошибки новых регрессий: первая ZIP-установка, ZIP-обновление и
  установка из каталога. На исправленном preflight все 22 теста прошли.

Изолированная проверка не собирает GPUI: `BadgePlace` и константы протокола
скопированы дословно, `config_dir` возвращает `None`, а обращение к UI resolver
иконок вызывает panic. Эти заменённые пути в 31 успешном тесте не вызывались.
Проверка подтверждает файловую установку и модель профиля, а не всё приложение.

## Что ещё нужно перед production-поставкой

Полный Desktop gate, нативное окно и portable не проверены. Первоначальный
native Cargo-прогон остановился до тестового бинарника из-за заполненного
диска. В окружении также отсутствуют `clang`, `ld.lld` и dev-пакеты
`xcb`, `xkbcommon`, `xkbcommon-x11`, `fontconfig`, `freetype2`.

В подходящем окружении после переноса выполните `python3 scripts/test.py`,
проверьте установку и обновление через нативное окно, затем обновите Desktop
portable командой `python3 scripts/portable.py --no-archive` по `BUILDING.md`.
Сборка Core, backend-модулей или расширений для этого patch не требуется.

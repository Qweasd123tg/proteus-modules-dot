# Pi: не пересканировать обычные части ответа

При преобразовании истории Pi уже видит каждый принятый вызов инструмента.
Запоминаем его сразу, вместо повторного обхода готовых частей сообщения
Assistant. Если запись содержит склонированный Opaque-блок, оставляем
исходный обход: он учитывает фактический итоговый тип после наложения
нативных полей. Нативный заголовок по-прежнему может переопределить
`stopReason`; ранний возврат ToolResult не меняется.

Восемь парных проверок фактического JS-кода на четырёх базах: 331cfc20,
+#484, +#503 и +#484+#503. В синтетической записи с 50 000 частями без
вызовов и без принятого Opaque повторный обход посетил 50 000 → 0 частей,
с тем же выходом. Проверены нативные поля, принятый Opaque с отличающимся
типом после клонирования и наложения, ToolResult, ошибки и переиспользование
массива из #503. Без SDK, сети, реальных инструментов и замеров времени
или памяти.

Патчи взаимоисключающие: `source.patch` для базы без #484,
`composed.patch` после #484. #503 можно применить до или после выбранного
варианта. Прямое и обратное применение сверены побайтово без fuzz.

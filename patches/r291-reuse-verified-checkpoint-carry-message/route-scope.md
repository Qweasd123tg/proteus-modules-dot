# R291 strict/live checkpoint carry

The full pinned Contracts and Session Semantics crates are built as genuine native Rust path crates with actual im and both Serde layouts. The strict route first writes real TurnOpened, HistoryMutated Checkpoint, tool requested/resolved, and genuine accepted ToolResultRecorded values to a temporary physical JSONL fixture. Each is read back as a real JournalRecord and passed to the exact JournalValidationState::apply_sequenced. The later checkpoint (including rejected typed cases) is also physically written and read back, then applied to clones of the same validated state; original committed state stays unmodified. This is a physical test fixture and strict validation boundary, not a deployed process transport or persistence-worker claim.

The no-store route executes the exact native Core WorkflowHistoryRecorder::checkpoint implementation, real Tokio locks, and known Core role/compaction preparation and delivered-message weave. A typed test sink accepts actual ToolExecutionRecorder calls in order: requested/resolved per declared execution call, then the accepted finals. The checkpoint has no new sink events. A small actual held-history case verifies checkpoint obtains the capture and compaction guards while waiting for history, then resumes; all guards release. Store and steering branches are unexercised, with fail-fast compile-only placeholders, and neither can silently simulate actual inputs. The ACK's own clone and proposal assembly are unchanged and outside the measured carry scope.

Observed route controls distinguish ordinary carried output/error/structured content, partial acknowledgement with pending bindings reordered and old results completed out of order, final receipt into the returned binding state, a later checkpoint, none/already acknowledged/equal prefix and valid compaction bypass, removed/changed bindings, changed ACK/typed identity rejection, stale revision target, and a strict late active-ID rejection after actual carry work. The direct public rebase/record_at controls intentionally manufacture unsupported internal history fixtures to test exact error precedence, first matching ID, inconsistent raw result call IDs or lost prefix; they are not claimed as accepted durable journal histories.

The source-bound proof observer tags the actual first prepared canonical message's owned allocated generations before the original typed equality, then its actual owning row after the original insertion. The stock proof stores the same old equality temporary only long enough to tag it, then drops it prior to the unchanged comparison-result guard and second construction. The candidate pointer/generation must remain alive for qualified carry and must not do so for the malformed mismatched raw-ID fallback. Metadata, payload bytes, enclosing parts/content buffer capacity, raw/nested ownership and typed output stay exact. Requested allocator Layout sampled per carry begins before the first construction and ends after insertion or error. Only the second unnecessary construction is attributed. Other whole-history clones, ordinary result recording, ACK/output, physical I/O, CPU/timing, RSS/PSS and overall runtime/cold-open memory are not claimed.

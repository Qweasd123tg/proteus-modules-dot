# Desktop: один SHA-256 для подготовленного архива релиза

`release.assets()` проверяет содержимое копии, которая попадёт в поставку, против digest из успешного smoke. Та же проверенная пара путь/digest используется в отсортированном `SHA256SUMS`; остальные файлы хешируются как прежде. Копирование, требования к provenance/status и [проверка после переноса](https://github.com/Proteus-harness/Proteus-desktop/blob/b6a7ec2d8d7e486c8aba01291aa8c89774c4cded/.github/workflows/release.yml#L147-L149) не меняются.

Точные срезы Desktop stock и stock + collector #262: **12/12** исходных и **13/13** тестов с патчем на каждой основе (CPython 3.12.14). Регрессия в `scripts/test_release.py` подменяет только байты скопированного архива: исходник соответствует smoke, но подготовленная копия отклоняется до записи smoke в поставку и `SHA256SUMS`.

Ещё **24** синтетических прогона точной `assets()` в изолированном временном каталоге. Для архива 8 МиБ: **2 → 1** полных прохода SHA-256 (**16 777 216 → 8 388 608** прочитанных для digest байт). Все шесть выходных файлов нормализованного fixture, включая пять отсортированных строк `SHA256SUMS`, побайтно совпали. Устаревший до копирования архив по-прежнему отклоняется; изменение исходника после копирования не отменяет успешный smoke для неизменной копии. Отдельная повторная проверка отклонила изменение копии после расчёта контрольной суммы.

Это объём чтения именно для SHA-256, не замер времени или дискового I/O: `copy2`, smoke и проверка переноса остаются. Полный релиз, CI, подпись, загрузка и публикация не запускались. Изменение не делает цепочку атомарной при внешнем конкурентном писателе.

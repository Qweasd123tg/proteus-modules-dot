# R155 — OpenCode Go: каталог для quota нужен только при fallback к env

Применить **один** из патчей с `-p1 --fuzz=0`: `source.patch` к Modules
`9469e3b12529d08b1f4a76882693e2065e842c51`, `composed.patch` к выбранной основе
после #452 → #462 → #465 → #466. Меняются только model adapter и чтение credential.

При штатном Go quota без явного ключа/источника и без подменённых runtime/credential
сначала выполняется то же read-only чтение OpenCode SQLite. Если найден сохранённый
ключ, вызов не запрашивает имена env у ModelsDev. Если DB отсутствует или в ней нет
строки нужного provider, прежняя последовательность env names используется как
прежде. Проверка отмены стоит до и после ожидания names; отсутствие names означает
пустой список, а malformed names не становятся допустимыми. Ключи или данные
каталога не кешируются; новые пути/разрешения не нужны.

SQL, static decoder, order active/latest и чтение committed WAL остались прежними.
Inactive строка может быть выбрана после отсутствующих active строк, как раньше.
Удалённая строка ведёт к обычному fallback; повреждённая/неподдержанная выбранная
строка, пустой ключ, OAuth и ошибка DB не ведут к fallback. Для явных
`models_file`/`models_url` (включая пустую строку), явного ключа, injected runtime
и injected credential сохраняется прежняя ветка. Явный ключ по-прежнему валидирует
`database_path`, но не открывает DB. `stream`, `catalog`, `describe`, manifest,
сам запрос квоты и граница ошибок quota не меняются.

Обе основы прошли forward / reverse dry-run с нулевым fuzz, byte readback и
проверки синтаксиса. Изолированная проверка Node VM: **7/7**. Выполнялись
точные model adapter и reader, настоящий Node SQLite с синтетическими локальными
строками, проверено сохранение DB/WAL байтов при чтении. Vendor schema,
runtime/ModelsDev, quota sink и inference были инертными. Покрыты saved key,
нет DB/строки, ошибки выбранной строки/DB, explicit/injected ветки, обычный
сценарий model stream и отмена. Не было доступа к пользовательским ключам,
web catalog или quota; настоящая SDK/сеть/старт/PSS не запускались и не измерялись.
Это устраняет лишний запрос имён при сохранённом ключе в одной quota-ветке,
но не отложит eager picker и не гарантирует изменение idle памяти.

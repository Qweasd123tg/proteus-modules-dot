# R169: OpenCode, быстрая адресация текущего stream block

В приватном для одного запроса collector теперь хранится ссылка на
последний использованный блок. После прежней проверки непустого string
ID совпадение типа и ID позволяет использовать уже существующий блок,
не собирая составной ключ и не обращаясь к Map. При смене блока поиск
возвращается в тот же Map; чередование блоков, их порядок и локальные
UUID, позднее обновление метаданных, проверка ошибок и финальные события
не меняются. При чередовании cache hit не обещан.

Меняется только `model/opencode-provider/response.mjs`. Одна версия
`source.patch` для точной основы Modules `331cfc20bbaf821ab07de49868426da29ebdeb64`
и выбранных последующих изменений через #477: #452 уже присутствует в
основе и не меняется, остальные выбранные изменения этого файла не касаются.
Повторное применение/снятие патча прошло с fuzz 0 и побайтовой сверкой.

**5/5** проверок Node 24.22.3: точный collector, воспроизводимые UUID,
побайтовые события и terminal DTO, чередование text/reasoning/tool с одним
ID, повторный вход в старый блок, авторитетное end, поздняя metadata, ошибки
и конец потока. На 50 000 соседних delta одного блока обращений к Map и
формирований составного ключа 50 000 -> 1; вставка в Map одна в обеих
версиях, хеш всех emitted/terminal bytes совпал. Это подсчёт операций
на синтетическом входе, не замер latency, heap, RSS или PSS. Нативный
SDK, установленный Node 24.12.0, сеть, настоящий провайдер и credentials
не запускались и не использовались.

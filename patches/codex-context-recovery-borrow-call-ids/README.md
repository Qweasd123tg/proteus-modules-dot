# Codex: не копировать идентификаторы при повторе после переполнения контекста

При локальном сжатии Codex после ошибки переполнения убирает самое старое
сообщение и связанные с ним вызовы и результаты. Теперь этот проход
заимствует идентификаторы, а не клонирует их. Если идентификатор один или
все его повторы одинаковы, таблица не создаётся. При втором отличном
идентификаторе остальные сохраняются во временном HashSet.

Порядок и содержимое оставшихся сообщений и частей, сравнение точных
идентификаторов, удаление целого сообщения с совпадающим верхнеуровневым
идентификатором и правила повтора не меняются. Если в первом сообщении
вообще нет идентификатора, остальные сообщения сохраняются, даже если
они уже пустые. Удалённое сжатие и обычный запуск не затронуты.

Rust 1.95.0: 7/7 парных проверок в отладочной и 7/7 в оптимизированной
сборке. Выполнены точные извлечённые функции до и после изменения с
минимальными моделями типов. Сверены значения, порядок и принадлежность
строк, 768 сгенерированных историй, повторное удаление и случай с 1 024
разными идентификаторами и 32 768 последующими сообщениями. В большом
примере число временных копий ID снизилось с 33 791 до нуля. Это следует
из структуры вызовов; измерений аллокатора не было. Время, память
процесса и полная сборка не проверялись. Провайдер и сеть не запускались.

Один файл `hook/codex-context-preparation/src/recovery.rs`. Точный откат
возвращает исходные байты, без fuzz и смещений. В #514, #517 и #521
изменяются другие файлы этого модуля.

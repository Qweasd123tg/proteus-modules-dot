# R191: Pi возвращает сжатую историю без отдельного массива хвоста

`toSpliced(0, cut, compacted)` сразу создаёт итоговый массив: сначала сводка,
затем те же сообщения начиная с `cut`. Исходная история не мутируется.
Прежними остаются порядок вычисления полей ответа, выбор границы,
замена последнего User, идентификаторы, метаданные, запрос сводки и ошибки.

Один патч для Modules `331cfc20bbaf821ab07de49868426da29ebdeb64` и той же
основы с #484. Оба порядка наложения и снятие проверены побайтово.
Метод доступен требуемому Pi Node ≥22.19. Обычные разреженные массивы
на выходе по-прежнему уплотняются; нестандартные подклассы не проверялись.

**6/6** тестов Node 24.22.3 с точным JS компактации и проекции,
инертным SDK и хостом. На 125 000 синтетических сообщениях при границе
32 000 исчез временный срез на 93 000 ссылок; итоговые байты
и идентичность сохранённых сообщений совпали. Это наблюдение структуры,
не замер времени или памяти. Настоящие SDK, модель, инструменты
и сеть не запускались.

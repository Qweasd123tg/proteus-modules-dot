# OpenCode: загружать только модули выбранной роли

Пакет для `Proteus-harness/Proteus-modules` (`9469e3b12529d08b1f4a76882693e2065e842c51`). Один [патч](source.patch) для `workflow/opencode-runtime/worker.mjs`.

Отдельный OpenCode Worker для роли `model` больше не импортирует обработчики промпта, файловых инструментов, контекста и сжатия истории напрямую на старте. Каждый из этих обработчиков импортируется в уже существующей ветке выбранной роли прежде, чем Worker завершит `initialize`. Сами условия выбора, фабрики и манифесты не меняются. Worker с несколькими объявленными экспортами всё так же инициализирует все объявленные обработчики. Сбой загрузки выбранного обработчика по-прежнему не даёт Worker стать готовым: теперь брокер может вернуть ошибку `initialize` вместо падения процесса до ответа. Сбой неиспользуемого обработчика больше не блокирует независимую роль.

Не меняются упаковка, конфигурация, сетевой каталог моделей и сроки его обновления. Исправление применяется к JavaScript в пакете Modules; подмена одного бинарника Core его не включает. Это устранение лишней работы по коду, а не подтверждение причины паузы с ярлыка. Замеров скорости и памяти не было.

```sh
git apply --check /path/to/source.patch
git apply /path/to/source.patch
```

## Проверка

Патч применился без пробельных ошибок на точном main и на наборе Modules через #457. Node 24 проверил синтаксис. Изолированный тест исполнил точный Worker и реальный брокер v3 с подставными обработчиками, без сети: шесть ролей по отдельности, все шесть вместе, шесть отклонённых привязок и ошибки загрузки выбранного и невыбранного обработчика. В изолированном сценарии model-only число загруженных точек входа ролей — 5 → 1. Весь пакет, реальный OpenCode SDK и Desktop не запускались.

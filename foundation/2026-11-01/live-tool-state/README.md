# Актуальное состояние инструмента во время выполнения

Source-патч для Core `80e828ca4e7e8a7550c4d3c49d865b599414d9e8`.

## Что исправляется

Plan в режиме «Всегда» читает `/history/tool-state`. Раньше этот endpoint
проверял только сохранённый индекс: запись нового события в журнал делала
его устаревшим, хотя авторитетная живая проекция уже содержала новый план.
В результате нормальный активный ход мог показывать «План недоступен».

Для уже открытой сессии endpoint теперь читает ту же серверную проекцию,
которая обновляется до публикации SSE, под её существующим lock. Сначала
берётся последний подходящий tool текущего хода, затем завершённых ходов
в ещё выполняющейся очереди, затем подтверждённого завершённого прошлого.
Отказанные и неуспешные вызовы не заменяют предыдущий принятый; пустые
аргументы остаются авторитетным результатом, а не поводом вернуть старый план.
Определение принятого статуса сохранено: исключаются только failed/denied.

Для закрытой сессии прежний компактный SQLite-путь и 409 не меняются.
Запрос не запускает runtime, не перечитывает весь журнал и не создаёт новый
постоянный кэш, поток или API. Формат JSON прежний. `revision` активной сессии
теперь обозначает непрозрачную ревизию серверного представления (stream/seq),
а не fingerprint файлов; SDK уже использует её как непрозрачное значение.

## Владение и границы

- Завершённый индекс принадлежит `CompletedTranscript`; промежуточный индекс
  хранит завершённые queued-turns до общей фиксации. Это разные сроки жизни:
  запоздалое фоновое чтение прошлого не должно стирать новые queued-turns.
- Общая фиксация заменяет завершённое состояние и очищает промежуточное.
  История и индекс фонового обновления связаны с закреплённым чтением, а не
  со случайной более новой страницей SQLite.
- При загрузке повреждённого или старого вспомогательного индекса используется
  однократное чтение компактных полей проверенных строк той же display-ревизии.
  Это не повторный запуск канонического projector и не работа на каждый render.
- Непроверенная устаревшая история при запуске не становится авторитетной:
  пока её фоновые проверки не закончены, отсутствие подходящего живого tool
  по-прежнему может дать 409. Ошибка не подменяется пустым или старым планом.
- Активный ответ отражает согласованное серверное представление, как SSE;
  он не обещает немедленно замечать внешнюю ручную правку файлов журнала.

Цена исправления: в памяти удерживается последний `AppToolState` на имя
инструмента для завершённого прошлого и, при queued-turns, для промежуточных
ходов. Тела результатов и rendering metadata исключены, но args/effective_args
остаются. Это O(числа имён инструментов и их сохранённых аргументов), не общий
лимит памяти и не заявление об экономии RAM. Текущий хвост не копируется
целиком: lookup читает существующий `TurnProgress`.

## Проверено

14 исходных файлов, +422 / −29 строк. Два новых целевых теста описывают
переходы живого состояния/queued-turns/отказа/сброса и HTTP-чтение при stale
SQLite; существующие тесты индекса дополнены проверками загрузки полного
компактного состояния и восстановления старого auxiliary index.

Точные Git blobs и SHA256, strict forward/reverse с побайтным восстановлением,
whitespace и прямой установленный rustfmt проверены. По 615 Rust-файлам текущей
базы проверены constructors и callers изменённых типов/сигнатур; пропусков нет.

# Independent source-form bootstrap architecture review

Verdict: the proposed persistence-local projection is a coherent minimal direction for the known missing-standalone-profile recovery defect, not a reason for an architecture HOLD. Read the pinned Core producer, initial TOML/JSON serialization branches, InstructionSourceConfig, instruction loader and Instructions documentation. No code/tests were executed and no patch is approved yet.

The source contract requires exactly one of file/text. Loading rejects both or neither, then resolves a valid file entry by filling text while retaining its file reference, kind, priority and order. Consequently a legitimate loaded runtime AppConfig has file+text even though that shape is invalid as input source. On a missing profile path the builder intentionally falls back to its in-memory config; blindly serializing that runtime representation recreates invalid source.

A private helper cloning AppConfig and clearing text only on entries with file.is_some() restores source representation for bootstrap. Inline-only text remains unchanged. Use it only for missing ordinary standalone TOML full initialization and JSON NotFound initialization. Existing documents and minimal directory overlays are not source-recreated and need no instruction rewrite. Runtime state and generic Serialize must remain unchanged. Keep the original initial-default/full-provider seeding, including the provider-preservation proposal's distinction between existing and missing targets.

Limits: there is no provenance bit distinguishing loader-resolved file+text from an arbitrary manually constructed conflicting AppConfig. This helper is a source projection under the producer's loaded-config contract, not validation of arbitrary source. The actual loader must still reject input files containing file+text. Preserve the reference spelling; relative references retain semantics when recreating the same profile location, but moving to another location would require a separate rebasing contract. Absolute references remain absolute. The helper does not restore missing instruction assets: subsequent loading should still fail if referenced files are unavailable, and it must not silently replace references with cached text to conceal that failure.

Recommended exact controls for later review: TOML/JSON actual load → remove only profile → persist → reload with surviving assets; mixed inline/file entries retaining order/kind/priority; relative and absolute file references; unchanged original in-memory resolved text; malformed source both/neither rejection; missing referenced asset failure; initial default without instructions; existing-profile and directory behavior unchanged. They are proposed scope, not run results. Published semantic-validation and provider-preservation patches need mechanical composition checks, without treating those checks as runtime qualification.

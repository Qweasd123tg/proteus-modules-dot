# Independent pre-patch contract review

Source-only verdict: the narrow removal of absent-provider injection is contract-backed and merits an exact candidate. No broad managed-field redesign or HOLD is required for this boundary. No project code, persistence tests, Rust/toolchain or behavioral substitute was run.

The production builder reloads an existing config path via AppConfig::load before applying a builder request. Provider definitions are not edited by that request; active-provider selection is separate. Includes merge first and local files override them, while directory overlays apply last. Injecting the already merged providers map into a previously absent local providers section therefore freezes inherited values on an unrelated Save. Keeping an existing explicit providers section unchanged, and keeping an absent section absent, preserves source ownership without changing selection semantics.

Missing standalone profiles are already initialized through complete AppConfig TOML serialization or the JSON next.clone path. Those paths should remain intact. The specially named directory overlay is intentionally not full-seeded. Remove only ProvidersToml and the two missing-providers insertion paths; do not delete explicit sections, including those materialized by older versions, because their provenance cannot now be inferred.

The two existing fixtures identified by the coordinator construct AppConfig::default over an existing file/directory with no provider definitions. Rust Default supplies fake/Some(fake), whereas deserializing an existing provider-less source supplies empty providers/None, as documented for model-free profiles. Production uses the latter loaded value. Replacing those fixture configs with AppConfig::load(actual source path) is therefore a legitimate alignment with producer semantics, not concealment of a supported provider-edit operation. In the directory-precedence test, explicitly clear workflow and module_config after load so the original complete managed-removal assertions remain meaningful. Do not alter the independent file-operation assertions or mechanics.

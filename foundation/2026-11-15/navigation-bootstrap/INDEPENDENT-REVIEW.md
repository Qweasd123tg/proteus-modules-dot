# Independent navigation bootstrap design review

Verdict: a bounded source candidate is justified; no blocking HOLD is needed for the described design. This addresses known files-initialization #1, not a new finding. No project code, native UI, tests or toolchain was executed.

announce_scope currently sends Context and optionally a deduplicated session snapshot, but neither carries per-context active_document. SDK event handling installs document metadata before calling extension.event and rendering; Files specifically consumes navigation_changed to reveal/select the active document. Context alone updates scope/session metadata. Existing workspace_update already uses NavigationChanged for a metadata refresh, so the event is not currently restricted to an exact physical navigation gesture.

Capture initialize_navigation from the prior announced flag, preserve Context→optional snapshot ordering, then send one session-lifetime NavigationChanged with captured session and host.active_document(cx). This supplies document metadata before subsequent view render and does not need a new protocol. Send this per context even when shared-session snapshot dedup suppresses a second snapshot: document metadata belongs to the context, not just the session. Host::active_document filters to the displayed space and matching extension's focused document; this is not an instruction to mark all retained views active.

Marking announced only when self.process.is_some() repairs the demonstrated source path where SessionOpened schedules deferred start and calls announcement while send is a no-op. The later initial announcement must not be suppressed by those unsent messages. Treat this flag as attempted announcement with an available transport, not a delivery acknowledgement: send still ignores its immediate result under the existing transport behavior. Existing restart/reset sets announced false and permits reseeding. Preserve the existing scope/session/workspace bookkeeping even if no process is present unless a separate reason requires changing it.

Already-announced ordinary SessionOpened should not add this synthetic navigation event; the real event remains unchanged. A genuinely unannounced scope followed immediately by a real SessionOpened may still produce bootstrap plus real-event renders. That is bounded added work, not an exactly-once render guarantee. Likewise a newly attached/rehosted context can trigger session-local renders of existing same-session views before its own view is registered. SDK per-context document restoration must be checked in proposed consumer controls, not inferred from snapshot dedup alone.

Source review should verify deferred first announcement, restart, second context sharing session/snapshot, different context documents including None, already-announced SessionOpened, and non-session lifetimes. Proposed extracted-method/std-only controls can check message ordering and guards, but cannot qualify GPUI timing, actual transport delivery, native focus or Files UI recovery. Actual SDK consumer tests and native qualification remain NOT RUN until available. No security, file-action or broader retained-view scheduling policy change is needed for this narrow candidate.

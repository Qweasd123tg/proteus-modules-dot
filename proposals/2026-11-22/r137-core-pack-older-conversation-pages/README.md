# Proteus Core: упаковка старых страниц кеша беседы

Патч меняет один вызов в `save_model`: каноническая история беседы использует уже существующую упаковку старых страниц. Последние 50 сообщений, порядок, хеши логических страниц, формат чтения, Worker и его лимиты не меняются. Новый кеш не требует миграции. На несжимаемых данных упаковка может не уменьшить число объектов.

**Статус:** проверено на точной ревизии Core `32e56ecb4cc6da324c60dd6ae2da78f3b7e46e7f` с тестовым хранилищем. Это не замер диска, Worker, времени запуска или памяти Desktop. Ранее опубликованный замер на 5 000 сообщений был на коде **без этого патча**.

## Применить и собрать локально

Подходящие исходники: stock Core `32e56ecb4cc6da324c60dd6ae2da78f3b7e46e7f` или точное составное дерево Core M150/M200 с SHA-256 `1286bbee614ba3ed2e12cf3af92639d83b79b9425b9dc982dded5f83aa482215` (это хеш дерева исходников, не Git-коммит). Не применяйте поверх произвольной ветки, если проверка не проходит.

Проверьте скачанные файлы командой `sha256sum -c SHA256SUMS` в папке пакета. В отдельной чистой рабочей копии Core, из корня репозитория:

```sh
PATCH=/абсолютный/путь/canonical-conversation-pack.patch
git apply --check -- "$PATCH"
git apply -- "$PATCH"

CARGO_INCREMENTAL=0 cargo test --locked --offline -j1 -p proteus-core --lib \
  core::session_store::remote::view::tests:: -- --test-threads=1
CARGO_INCREMENTAL=0 CARGO_PROFILE_RELEASE_DEBUG=0 \
  cargo build --locked --offline --release -j1 -p proteus-core --bin proteus
```

Для офлайн-сборки зависимости из `Cargo.lock` должны уже быть в локальном кеше. На Linux с готовым кешем лучше иметь от 3,2 ГиБ свободно на диске исходников, Cargo target и временных файлов; для чистой сборки может понадобиться больше. Если `git apply --check` не проходит, не применяйте патч принудительно: сначала уточните ревизию исходников.

## Что прошло

- Собраны два отдельных `proteus-core --lib`: исходная ревизия и та же ревизия с патчем. Штатный набор `remote::view` прошёл **16/16 на обеих сборках**.
- В отдельном сценарии реальная реализация Core на тестовом хранилище сохранила 953 сообщения. Число объектов, на которые ссылаются канонические страницы, снизилось с **20 до 5**. Логические страницы и данные совпали. Последние 50 сообщений по-прежнему читаются из отдельных страниц без чтения архивных пакетов.
- Дописывание до 1 001 сообщения не пересоздало старые объекты. Проверены чтение прежней именованной версии и восстановление после потери или повреждения старого пакета. Исходный бинарник Core прочитал новый кэш без чтения журнала и перезаписи кэша.
- SHA-256 подтверждения прогона с патчем: `e0e7f1b45f6ad75680ee9d166ab443725d3c22da3da7ce841f511e3e3f67524a`.

## Быстрая проверка результата

Сравните две сборки Core с одним и тем же Worker и одинаковым профилем на отдельных тестовых копиях одного синтетического диалога. Для каждой сборки сделайте первый запуск без производного кеша и повторный запуск с сохранённым кешем на том же пути. Не удаляйте кеш рабочих диалогов и не сбрасывайте системный кеш. Сравните время до готовности, полную каноническую историю и страницы в начале, середине и конце. Отдельно проверьте дописывание после неполной последней страницы. Для 50 000 укажите, сколько сообщений реально активно, сколько только отображается, и не смешивайте headless с Desktop.

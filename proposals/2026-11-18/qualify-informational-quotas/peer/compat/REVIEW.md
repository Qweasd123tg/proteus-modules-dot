# Independent review: informational quota scope

**GO** `57fadeac6a94f314d1fa4bdb1272026a57222f146baf63b9b7f1ff160bd1c0a6`, on the two pure public quota text renderers. The [Core data declaration](https://github.com/Proteus-harness/Proteus-core/blob/c2cbadee518788f306ffb2b5271036b2658ea8cc/crates/proteus-contracts/src/contracts/model_quota.rs#L17-L28) says an informational bucket's applicability to the active model is *unknown*. It must not determine remaining allowance. Saying the resource definitely does not apply or is not exhausted would be inaccurate. The proposed annotation correctly states the uncertainty, once per flagged bucket in its existing card title and in a separate summary line, without contradicting the resource’s own status.

A local Rust harness serializes/deserializes the Core declarations and calls [describe](https://github.com/Proteus-harness/Proteus-desktop-extensions/blob/ef064381d2194d95faef2b85f6cc3a1c34c6b975/packages/quota/src/describe.rs#L63-L96) and [render](https://github.com/Proteus-harness/Proteus-desktop-extensions/blob/ef064381d2194d95faef2b85f6cc3a1c34c6b975/packages/quota/src/view.rs#L8-L48) from the real extension. JSON output is recorded via a minimal API-compatible visual node fixture. The clock display is fixed: no timestamp formatting, UI pixels, service, refresh, provider or permissions are exercised.

810 synthetic snapshots in each of five builds: base, marker alone, #191 alone, and both application orders. Exact expected minimum across non-informational windows (including no applicable windows), marker count, bucket-specific placement, and byte-for-byte remaining visual/text traces after removing only new scope markers all passed. Missing informational defaults to false on Core and reserializes omitted; covered alongside explicitly false and true. Three additional deserialized snapshots each contained 2,499 buckets (1,250 informational). With zero, one, or two supplemental notices the recursive counts of all widget nodes returned by render were respectively **4,999, 5,000 and 5,001**, unchanged in all five builds. The marker changes only an existing title; it consumes text bytes but not extra nodes. This does not prove acceptance by a host or establish an outer wrapper count or byte limit. Equal bucket names in distinct buckets were not separately tested. Initial SHA 292532b… could not apply with #191 due to view.rs imports. The final patch and #191 `1a5ac591b780c8018d50242f15a3b0bda7ac692066283eead76b959abf90f4d0` apply in either order with no manual editing and identical source bytes.

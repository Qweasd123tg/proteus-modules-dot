# Why these literal strings can be checked without running Mermaid

Target: official Mermaid tag `mermaid@11.12.0`, commit `0116b272b4b558f60ec292fb994148956287eaa1`. The test does **not** load or run the Mermaid package. There is no previously available local Mermaid, generated parser, or Jison package in the audited dependency environments. This is an explicit reconstruction of a small determinable grammar domain, not a full renderer test.

1. [Diagram.fromText](https://github.com/mermaid-js/mermaid/blob/0116b272b4b558f60ec292fb994148956287eaa1/packages/mermaid/src/Diagram.ts#L19-L44) preprocesses Mermaid entity codes before parser invocation. In [utils.ts](https://github.com/mermaid-js/mermaid/blob/0116b272b4b558f60ec292fb994148956287eaa1/packages/mermaid/src/utils.ts#L896-L928) two unanchored, line-local style/classDef substitutions run first and can remove a semicolon. Then `#name;` / decimal codes are protected, while normal text remains. This matters for the innocuous name `Status style:C#`: the rejected first attempt produced `Status style:C#35;` which lost its final semicolon. The final patch emits `Status style#58;C#35;` which recovers the original. This is about a *literal name*, not a Mermaid directive.
2. The [stadium and square node token rules](https://github.com/mermaid-js/mermaid/blob/0116b272b4b558f60ec292fb994148956287eaa1/packages/mermaid/src/diagrams/flowchart/parser/flow.jison#L171-L195) and [regular square delimiter and text rules](https://github.com/mermaid-js/mermaid/blob/0116b272b4b558f60ec292fb994148956287eaa1/packages/mermaid/src/diagrams/flowchart/parser/flow.jison#L272-L282) enter the text state before a quoted caption. A double quote enters the [string-specific lexer](https://github.com/mermaid-js/mermaid/blob/0116b272b4b558f60ec292fb994148956287eaa1/packages/mermaid/src/diagrams/flowchart/parser/flow.jison#L82-L87); each nonempty run of non-quote characters emits one STR, and a quote terminates that mode. Backslash is an ordinary character in it. The only tokens present in our regular-caption interior are STR and (after a prematurely closed quote) TEXT. The special backtick-Markdown opener, shape switches, nested structural tokens and raw tags in user names are outside the fixture alphabet. The static Core line-break marker, when present, is inside a quoted string; examples retain that marker as authored rather than attempting to lay it out.
3. The [shape production](https://github.com/mermaid-js/mermaid/blob/0116b272b4b558f60ec292fb994148956287eaa1/packages/mermaid/src/diagrams/flowchart/parser/flow.jison#L430-L443) expects a single text derivation. On STR/TEXT alone the [complete restricted text grammar](https://github.com/mermaid-js/mermaid/blob/0116b272b4b558f60ec292fb994148956287eaa1/packages/mermaid/src/diagrams/flowchart/parser/flow.jison#L504-L512) accepts an initial STR or TEXT and then only TEXTs, since [textToken](https://github.com/mermaid-js/mermaid/blob/0116b272b4b558f60ec292fb994148956287eaa1/packages/mermaid/src/diagrams/flowchart/parser/flow.jison#L594-L600) does **not** include STR. Therefore ordinary `Site "Alpha" notes` gives STR, TEXT, STR on the old Core bytes and cannot satisfy this production; the candidate yields a single STR. A Windows-style path gives a single STR on both and consequently preserves the count of emitted backslashes verbatim: two old, one correct.
4. For ordinary text, the check escapes literal XML text, restores Mermaid's protected entities once according to [decodeEntities](https://github.com/mermaid-js/mermaid/blob/0116b272b4b558f60ec292fb994148956287eaa1/packages/mermaid/src/utils.ts#L925-L928) and decodes one XML text node with Python's standard library. This checks the textual value defined by the [official escape convention](https://github.com/mermaid-js/mermaid/blob/0116b272b4b558f60ec292fb994148956287eaa1/packages/mermaid/src/docs/syntax/flowchart.md#L874-L886); it cannot determine what every renderer/theme does with htmlLabels, arbitrary markup, or unusual whitespace layout.

The probes use real Core Rust graph strings; the formal small grammar projection and XML text decoding are clearly distinguished from a genuine end-to-end Mermaid JS parser or browser. It would be incorrect to relabel these counts as browser/UI coverage.

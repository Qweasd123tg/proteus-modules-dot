# Plain quoted node names in Core's full Mermaid diagram

**Result:** The explicit full-diagram CLI path used JavaScript-style backslash escaping for data in a Mermaid flowchart string. Mermaid does not treat backslash as a quote escape inside that string. An ordinary profile named `Site "Alpha" notes` therefore produces an invalid node-label token sequence. `C:\Notes` is still a string but contains *two* backslashes rather than the one in the profile. A literal `#quot;` can silently become a quote instead of the five characters the author supplied.

The [public TopologySnapshot](https://github.com/Proteus-harness/Proteus-core/blob/c2cbadee518788f306ffb2b5271036b2658ea8cc/crates/proteus-contracts/src/app_protocol/topology.rs#L3-L17) stores the name as a string; [Core uses that same type](https://github.com/Proteus-harness/Proteus-core/blob/c2cbadee518788f306ffb2b5271036b2658ea8cc/crates/proteus-core/src/core/topology/types.rs#L1). The [documented Mermaid mode](https://github.com/Proteus-harness/Proteus-core/blob/c2cbadee518788f306ffb2b5271036b2658ea8cc/docs/guides/inspect.md#L36-L44) is [dispatched to the actual Rust renderer](https://github.com/Proteus-harness/Proteus-core/blob/c2cbadee518788f306ffb2b5271036b2658ea8cc/crates/proteus-core/src/main.rs#L388-L399). Its [five node-caption emission sites](https://github.com/Proteus-harness/Proteus-core/blob/c2cbadee518788f306ffb2b5271036b2658ea8cc/crates/proteus-core/src/core/topology_render/mermaid.rs#L27-L131) enclose text in double quotes. The test inputs are synthetic public snapshots, not examples of names observed in any real project.

### What changes

Patch SHA-256 `6f3c5c6329d0d2b37155d340ec9bceec92b53be4cac9e064f763e773e2198c82`. For the ordinary quoted nodes only, preserve literal backslashes, encode quotes using Mermaid's documented `#quot;`, and protect literal entity-looking text. `#quot;` in a name becomes `#35;quot;` in the serialized string; the recovered label is literally `#quot;`. A regular name with no character needing encoding is borrowed as-is. A colon is encoded as `#58;` in an already-encoded label; the fast path with no quote/hash/ampersand keeps names such as `C:\Notes` literal. This avoids collisions with a Mermaid pre-parser rule without hard-coding its keywords in Core. The earlier SHA `43e70d5a…` failed on `style:C#` and **is not the recommendation**. Existing intentional line breaks between label parts remain unchanged. Raw edge labels (`|…|`), other output formats, IDs/order/classes, the input snapshot and all other renderers are untouched. This is not a general Mermaid sanitizer or a promise about arbitrary markup.

### Evidence and boundary

Compile the complete pinned pure Rust renderer against a synthetic projection of only the data fields it reads (not the application) and compare the literal emitted bytes. Apply the *same* in-patch Rust tests to the original and final files: red on assertion, green on the final. A separate small offline oracle projects the [official 11.12.0 flowchart lexer](https://github.com/mermaid-js/mermaid/blob/0116b272b4b558f60ec292fb994148956287eaa1/packages/mermaid/src/diagrams/flowchart/parser/flow.jison#L82-L87), relevant [node-text productions](https://github.com/mermaid-js/mermaid/blob/0116b272b4b558f60ec292fb994148956287eaa1/packages/mermaid/src/diagrams/flowchart/parser/flow.jison#L500-L512) and [documented entity rule](https://github.com/mermaid-js/mermaid/blob/0116b272b4b558f60ec292fb994148956287eaa1/packages/mermaid/src/docs/syntax/flowchart.md#L874-L886). Source inspection pinned the exact upstream grammar; its JS code was neither downloaded nor executed. See GRAMMAR.md for the proof, context and exclusions.

The figures cover ordinary captions with literal quotes, spaces, Unicode, filenames containing ampersands/hash, entity-looking strings and backslashes, drawn from all five sites. Across 388 synthetic graphs, the oracle recovered 309/1,939 texts on the original and 1,939/1,939 on the patch; 536 baseline cases were outside the label grammar or undecodable in the documented model. This is **not** a population rate. All 309 initially correct tested texts remained correct; graph structure, edges and classes were unchanged. These cases concern a published spec for data and a real shipped output function, not a drag, live CLI, browser render or CLI performance measurement. The tests do not assert complete Mermaid-engine compatibility, DOM/SVG layout or pixel-identical rendering.

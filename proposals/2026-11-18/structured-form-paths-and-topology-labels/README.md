# Настройки разных полей не должны открываться вместе; имя узла должно оставаться именем

**Два предложения к исходникам.** В Desktop изменён способ адресовать строку формы, но не её значение или подпись. В Core имя для `inspect topology --format mermaid` теперь записывается по правилам **подписанного узла Mermaid**, а не по правилам строковых литералов Rust или JavaScript. Отдельно уточнён контракт для авторов расширений из #201/#204; нового исправления ввода нет.

### 1. Один результат поиска мог подсветить две строки формы

В модуле есть объект с буквальным ключом `panel.theme` и отдельный объект `panel`, внутри которого находится `theme`. Оба имеют поле `value`. Для данных это разные массивы ключей: `["panel.theme","value"]` и `["panel","theme","value"]`. Для поиска, подсветки и раскрытия Desktop прежде собирал из них одинаковую строку `panel.theme.value`. Сами редакторы и значения не сливались. Это видно в [поиске по дереву полей](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/ui/settings/search.rs#L425-L478) и [сопоставлении адреса с отрисованной строкой](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/ui/settings/spot.rs#L158-L176). Поиск по уникальному заголовку вложенного поля мог вернуть **один** результат, а при переходе подсветить **два**; раскрытие одной группы могло раскрыть и вторую. Отдельный конфликт существовал между буквальным двоеточием и служебной меткой секции дополнительных параметров.

[Предложение для чистого Desktop](patches/structured-form-identity.patch) отделяет внутреннюю идентичность от подписи: экранирует разделители в каждом сегменте до сборки адреса и использует одну функцию и в поиске, и в отрисовке. Точки между уровнями, подписи поля и данные модулей не меняются. Если сам ключ содержит точку, человек по-прежнему может увидеть одинаковый текст пути в двух подписях; исправляется **куда ведёт действие**, не язык отображаемой подписи.

| Проверка | До | С предложением |
|---|---:|---:|
| 384 поиска по уникальным заголовкам, неверная или двойная видимая цель | 288 | 0 |
| 192 пары независимых раскрытий, общий флаг вместо двух | 192 | 0 |
| 192 пары разных дополнительных секций, общий ключ | 192 | 0 |
| Независимые 216 переходов из Finder до отбора видимых строк: подсвечена лишняя строка | 216 | 0 |

[Журнал независимого до](checks/scopes/peer/before.log) и [после](checks/scopes/peer/after.log). Ещё один независимый тест декодировал 1 155 200 адресов; 5 040 прежних строк без разделителей остались побайтно теми же. [Результат](checks/scopes/encoding/result.txt). Реальные публичные DTO Core прошли serde с двумя разными путями. Мы не подтвердили такое сочетание в штатном модуле: записи [публичного каталога Modules](https://github.com/Proteus-harness/Proteus-modules/blob/0fe8e3b4dfb64ca2e07df8af016d7ccc3a7de45f/proteus-catalog.json) и файлы exports для file-tools, git-tools, plan-tool и rust-lsp называют экспорты, но сами не описывают поля. Использована схема стороннего автора в памяти; запуск host, его семантическая проверка, GUI и сохранение профиля не проверялись.

**Если уже применён сырой поиск из [#206](https://github.com/Qweasd123tg/proteus-modules-dot/pull/206), выберите [этот альтернативный дифф](compat/identity-after-raw-search.patch) вместо основного.** Обычный `git apply` двух исходных диффов конфликтует рядом с функцией адреса. На совмещённом источнике повторён прежний [независимый тест #206](checks/scopes/encoding/raw206-peer.log): все 1 608 целей режима JSON ведут к редактору и все 1 608 целей режима формы сохраняются. Ранги, лимит 60 и невалидный редактируемый текст не изменились.

### 2. Core: кавычка могла оборвать имя узла диагностической диаграммы

Профиль с именем `Research "Alpha"` превращался в текст наподобие `["Research \"Alpha\""]`: в обычной строке узла Mermaid обратная косая **не экранирует кавычку**. Имя `C:\Notes`, напротив, получало лишнюю обратную косую. [Предложение для Core](patches/quoted-mermaid-nodes.patch) исправляет пять мест подготовки подписанных узлов. Рёбра, идентификаторы, классы и другие форматы вывода не меняются. Ранний вариант отозван: он улучшал простые кавычки, но искажал ранее корректное буквальное имя `style:C#`.

[Проверка на исходном Rust-форматтере](notes/core-labels.md) и [границы грамматического стенда](notes/GRAMMAR.md). На 388 синтетических диаграммах текст для 309 из 1 939 обыкновенных подписей восстанавливался точно до изменения, для 1 939 из 1 939 после. Независимый проверяющий использовал другой набор из 1 410 имён: 206 случаев разрыва строки и 774 случая неверного текста → 0; все 430 ранее совпадавших имён сохранились. [Подробный журнал](checks/mermaid/peer/results.log). Это результат **реального Rust-вывода и двух ограниченных проверок** по закреплённой [грамматике Mermaid 11.12.0](https://github.com/mermaid-js/mermaid/blob/0116b272b4b558f60ec292fb994148956287eaa1/packages/mermaid/src/diagrams/flowchart/parser/flow.jison), не запуск полного движка Mermaid, браузера или проверка пикселей. Гарантии для произвольной разметки в имени и любых версий Mermaid не даются.

### Уточнение для авторов расширений: смена типа поля с тем же ID

[Протокол](https://github.com/Proteus-harness/Proteus-desktop-extensions/blob/ef064381d2194d95faef2b85f6cc3a1c34c6b975/PROTOCOL.md#L462-L465) просит сохранять ID, действие, тип и назначение интерактивного контрола между отрисовками. Поэтому наблюдение о пустом блоке при смене `multiline → compact search` с прежним ID в [#201](https://github.com/Qweasd123tg/proteus-modules-dot/pull/201) воспроизводимо, но это **не обещанная миграция**. Аналогично, повторная привязка изменённого действия в [#204](https://github.com/Qweasd123tg/proteus-modules-dot/pull/204) повышает устойчивость; документация не обещает произвольную смену `action`. Это уточняет трактовку прошлых отчётов, а не отменяет их стендовые результаты.

Чтобы добавить поиск к заметке и **не потерять черновик**, оставьте прежний редактор с его ID и прежним объявленным значением и добавьте отдельное поле поиска с новым ID. В 168/168 синтетических случаях текст и запись редактора сохранились. Только заменить ID недостаточно: после исчезновения прежнего контрола его запись была убрана в 168/168 случаях. При сохранении ID, но смене объявленного значения на пустую строку 167 из 167 непустых черновиков были перезаписаны **до отрисовки**, поэтому запасная отрисовка не вернула бы их. Физический фокус и выделение не тестировались. [Проверки и безопасный вариант для автора](notes/stable-input.md). Патч автоматического переноса не предлагается.

### Как повторить

Требуются Python 3, Git, rustc (проверено 1.95.0) и локальные `serde`/`serde_json` rlib с транзитивными зависимостями. Запуск из корня пакета:

```sh
python3 checks/verify.py --desktop "$DESKTOP_REPO" --core "$CORE_REPO" --extensions "$EXTENSIONS_REPO" --dot "$DOT_REPO" --deps "$RUST_DEPS" --rustc "$RUSTC"
```

[Записанный полный результат](checks/recorded.log), [контрольные суммы](SHA256SUMS). Для неглубокого клона dot можно передать проверенные недостающие Git blobs из `checks/prior.tsv` через `--proposal-cache`; сам тест ничего не скачивает. Применение и откат происходят в изолированных временных файлах. Вдобавок к #206 проверены выбранные пересекающиеся исходники #186, #202, #203 и #205; остальные старые предложения не переквалифицировались.

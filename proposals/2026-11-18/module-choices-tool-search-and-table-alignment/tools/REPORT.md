# Поиск инструментов: «git status» находит штатную строку и на самой странице Tools

В [реальном объявлении git_status](https://github.com/Proteus-harness/Proteus-modules/blob/0fe8e3b4dfb64ca2e07df8af016d7ccc3a7de45f/tool/git-tools/src/lib.rs#L31-L54) разработчик написал «git status» как одно из поисковых названий. Глобальный поиск настроек Desktop уже находит соответствующую строку по этим двум словам. Но если ввести те же слова в поле «Поиск по имени или описанию» на самой странице Tools, строка пропадает: название содержит подчёркивание, а в описании между git и status стоят другие слова. Никакого запуска Git для воспроизведения не требуется.

Это два независимых способа поиска, **не сбой перехода**: при нажатии глобального результата [Desktop очищает локальный фильтр](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/ui/settings/spot.rs#L136-L142). Глобальный Finder ищет каждое слово в заголовке или сопутствующем тексте. [Локальная форма](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/ui/settings/tools.rs#L39-L61) до правки требовала, чтобы [весь запрос был одной подстрокой](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/settings/catalog.rs#L449-L454) названия или описания. То же условие определяет видимость строки внутри пакета и среди инструментов вне пакетов.

**Предложение:** tools-word-filter.patch, SHA-256 `1160d6a4a0b991adfeac0b46175204ecc29fb2711cf60467b93e0ebdd681756d`, против Desktop 2307e9c67125bbe66f15ced51317a2dfcc437aa4. Для строки зарегистрированного инструмента все слова локального запроса должны встретиться в названии или описании; можно в другом порядке или в разных полях. Отдельный список недоступных имён имеет только название и проверяется по нему. Вложенные недоступные имена внутри пакета по-прежнему выводятся только при пустом запросе; состав пакетов, владельцы, ранжирование глобального Finder и источники данных не меняются. Небольшой ToolQuery принимает исходный текст, нормализуется один раз за вызов tools_page и заимствуется обоими обходами. Названия и, лишь когда нужны, описания всё ещё обрабатываются при проверке каждой строки; это **не** утверждение об измеренном ускорении.

**Встречаемость и предел обещания.** В точечной выборке трёх инструментов из двух штатных компонентов («Git tools», «Rust LSP») раньше находился 1 из 3 запросов с пробелами вместо подчёркиваний: «git diff» уже присутствует в [его описании](https://github.com/Proteus-harness/Proteus-modules/blob/0fe8e3b4dfb64ca2e07df8af016d7ccc3a7de45f/tool/git-tools/src/lib.rs#L74-L76). «git status» и «lsp diagnostics» находились только глобально; после правки локально 3/3. Также находит «rust diagnostics» и «show changes» по видимым словам. Из десяти штатных aliases этих трёх инструментов до правки локально совпадали два, после шесть (глобально шесть), **не потому что Desktop читал список aliases**. «changed files», «review diff», «type errors» и «check rust file» так и не обязаны совпадать; поля, которых нет в локальной строке, не добавляли. [Публичное описание и поисковые подсказки Rust LSP](https://github.com/Proteus-harness/Proteus-modules/blob/0fe8e3b4dfb64ca2e07df8af016d7ccc3a7de45f/tool/rust-lsp/src/lib.rs#L99-L121). Это не статистика по всему каталогу. Глобальный поиск также учитывает source, другие страницы, ранжирование и предел 60 результатов: тождество двух выдач не заявляется.

**Проверка.** Нативный тест берёт из трёх неизменяемых публичных объявлений только name, description и aliases; имена и описания проходят round trip через настоящий Core ConfigBuilderTool с синтетическим source и нейтральными остальными полями. Затем компилируются настоящий локальный matcher и глобальный Finder. 58 696 ранее совпадавших положительных проверок подстрок, регистра и краевых пробелов на этих описаниях сохранились. Корректно разделяются слова кириллицы и греческие буквы, Tab и Unicode-пробел; добавление отсутствующего слова отклоняет результат. Независимая проверка: 19 558 комбинаций «запрос/строка», все 850 прежних попаданий сохранились, ещё 788 выполнили новый критерий; отдельно 19 558 проверок только названия и 120 проверок выбора пакета/строки. Это source/data replay с реальными объявлениями, а не запуск регистрации, git, rust-analyzer, GUI или чтение настоящих настроек.

**Совместимость.** #186 (desktop-exact-title.patch) менял ранжирование глобального Finder. #206 (raw-settings-search-target.patch) менял адрес результата глобального поиска в режиме JSON. Они, в отличие от этого кандидата, меняют src/ui/settings/search.rs. Последовательности #186→#206→R20 и R20→#186→#206 дали байт-в-байт одинаковые пять файлов. В объединённом replay вновь 3/3 имён, 6/10 aliases и ни одной потери прежнего положительного результата. На закреплённом Desktop прежний tool_matches использован только в трёх местах одного UI-файла, и обе функции с обновившимся списком аргументов вызываются только в нём. Полный Desktop не собирался.

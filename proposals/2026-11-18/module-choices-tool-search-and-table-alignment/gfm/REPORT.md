# Штатный Markdown: сохранить выравнивание столбцов таблицы

**Что замечает человек.** В отчёте «Товар | Цена | Получено» числа в столбце цены должны быть справа, а пометки о получении по центру. Desktop располагал их слева, даже если это было явно задано в Markdown. При обратном преобразовании таблицы в Markdown вместо правого и центрального разделителей также получались левые. Это ошибка представления содержимого, не ошибка расчёта цен/сумм Core или Modules.

**Где теряется информация.** Штатное [расширение Markdown](https://github.com/Proteus-harness/Proteus-desktop-extensions/blob/ef064381d2194d95faef2b85f6cc3a1c34c6b975/packages/markdown-render/extension.json#L12-L23) обрабатывает `text/markdown`: [преобразует GFM в HTML через markdown-rs 1.0 и возвращает rich_text](https://github.com/Proteus-harness/Proteus-desktop-extensions/blob/ef064381d2194d95faef2b85f6cc3a1c34c6b975/packages/markdown-render/src/inlines.rs#L217-L222). Например:

    | Товар | Цена | Получено |
    | --- | ---: | :---: |
    | Груша | 12 | да |
    | Слива | 1234 | нет |

В настоящем результате производителя `align="right"` стоит у заголовка и обеих ячеек цены, `align="center"` у всех трёх ячеек последнего столбца. [Desktop монтирует этот rich_text как HTML](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/ui/extensions/declarative/rich_text.rs#L20-L51); [парсер ячеек извлекал только содержимое и ширину](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/vendor/gpui-base/src/text/format/html.rs#L275-L312). О нативной геометрии известно не только из названия свойства: движок [распределяет свободную ширину до/после ячейки и применяет text_center/text_right](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/vendor/gpui-base/src/text/node.rs#L4180-L4214). [Генератор Markdown](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/vendor/gpui-base/src/text/node.rs#L2147-L2186) читает те же столбцы. В примере прежде возвращалось `| :-- | :-- | :-- |`; кандидат возвращает `| :-- | --: | :-: |`. Существующее правило оформляет как `:--` и неявное, и явное левое выравнивание: побайтового восстановления исходника нет и не требуется.

**Предложение.** `gfm-table-column-alignment.patch`, SHA-256 `2b06870760b71e11d24c5c7722eec6b9f94725307c882f545689093daa185c3e`. Меняется только `vendor/gpui-base/src/text/format/html.rs`. При уже существующем обходе ячеек извлекаем согласованные колоночные подсказки из прямоугольной таблицы с первой строкой заголовков th и остальными td. Для ячейки допускаются отсутствие атрибутов либо единственный обычный GFM align (left/center/right). У всех строк должна совпасть схема колонок; при конфликте, ином размере строки, ином виде ячейки или постороннем атрибуте ячейки оставляем прежнее поведение таблицы. Не выводим выравнивание из чисел, языка, CSS или одной ячейки среди конфликтующих. В таблице без явного выравнивания массив подсказок не выделяется. Совпадающая по структуре рукописная HTML-таблица получит тот же результат; происхождение не закодировано в rich_text. Направление письма строки не превращает физическое right в left.

**Проверки, без реальных данных.** На 1 024 синтетических GFM-таблицах (1–4 колонки со всеми сочетаниями 4 вариантов выравнивания; 0, 1 или 3 строки данных; русский, иврит, арабский, числа; пустая ячейка и недостающие/лишние поля исходной строки) слой геометрии давал неверный вариант в 934 случаях → 0. Разделитель целой таблицы: 934 → 0; для выборки из нескольких ячеек: 932 → 0. Девять контролей с несовместимыми атрибутами/ячейками или стандартной таблицей без выравнивания не изменились. Эти показатели пересекаются и не складываются. Отдельный тест в патче обращается к штатному parse; полная сборка этого теста в GPUI не запускалась. Rustfmt проверен.

**Воспроизведение.** `python3 checks/replay.py DESKTOP_TREE BEFORE_HTML AFTER_HTML RUSTC LIBMARKDOWN DEPENDENCY_DIR`; Desktop pin 2307e9c6, Extensions ef064381. Первый аргумент может быть checkout или bare GIT_DIR. Нужен совместимый предсобранный markdown-rs 1.0.0; шаг не скачивает зависимости. Стенд компилирует настоящие markdown-rs, Rust-функции parse_table_row, column_align, to_markdown, table_selected_source и ветвь размещения ячеек. Для простых тегов/абзацев применён локальный адаптер дерева стандартной библиотеки. Это не исполнение полной цепочки minifier/html5ever/GPUI, не визуальное тестирование и не чтение/запись буфера обмена. Доказано содержимое собственной Markdown-сериализации таблицы/выборки, не результат каждого режима копирования приложения. Исходный minifier [переписывает атрибуты, а не удаляет align](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/vendor/gpui-base/src/text/format/html5minify/mod.rs#L516-L548).

[Предыдущее предложение #197](https://github.com/Qweasd123tg/proteus-modules-dot/pull/197) восстанавливает границы при копировании части таблицы и меняет node.rs. Эта работа заполняет потерянное значение выравнивания в HTML parser, в другом файле. Это не полная реализация выравнивания HTML, не изменение внешних репозиториев и не выпуск приложения.

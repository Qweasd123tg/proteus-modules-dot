# Поиск параметров в режиме JSON ведёт к видимому редактору

**Сценарий.** Настройки выбранного модуля открыты в режиме JSON. По глобальному поиску пользователь находит «Размер листа», известный по схеме, и нажимает результат. На [Desktop `2307e9c`](https://github.com/Proteus-harness/Proteus-desktop/tree/2307e9c67125bbe66f15ced51317a2dfcc437aa4) поиск отдаёт адрес строки поля из формы. Но здесь [вместо строк отображается один редактор JSON](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/ui/settings/params.rs#L121-L160). У [перехода и подсветки](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/ui/settings/spot.rs#L127-L165) нет элемента с этим адресом. Для вложенного поля поиск ещё и запоминает открытие групп, которых в режиме JSON нет. Это не потеря введённого текста; #205 относится к другому действию, явному переключению режима.

Патч сохраняет результаты по схеме. Когда модуль отображается как JSON, местоположение совпадения заканчивается на «· JSON», и найденный параметр ведёт к **редактору этого модуля целиком**. Нужные внешние разделы раскрываются, внутренние группы формы не открываются. Поиск не переключает режим, не проверяет и не переписывает текст; он не перемещает курсор к ключу внутри JSON. Искомый параметр может отсутствовать в самом объекте. Имена и адреса в обычной форме, ранжирование и предел числа результатов не меняются.

[Поиск выбранного модуля](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/ui/settings/search.rs#L237-L256) вызывает [поиск полей схемы](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/ui/settings/search.rs#L341-L357). [Cписок результатов](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/ui/settings/nav.rs#L347-L380) показывает место и передаёт курсору навигации адрес выбранной записи. Предложение не зависит от подключения службы, открытия профиля или от формата его хранения.

**Проверка.** В Rust компилировались настоящие `search_params`, `Finder`, рекурсивный обход `Scope::fields`, `is_json`, `params_body` и ключи для подсветки. Структуры данных вымышленные; вместо GPUI используется дерево, записывающее адреса и текст. Обычные контролы формы представлены метками, с проверкой исходных мест их привязки, без рисования. Два модуля с совпадающими названиями полей, четыре сочетания режимов, три пути внешнего раскрытия, корректный и незавершённый raw JSON, вложенные и advanced-поля, несколько совпадений и отсутствие результатов. Из 432 найденных целей 216 не имели видимого адресата до патча, 0 после. Для 144 до патча добавлялись лишние невидимые группы; после патча 0. Упорядоченные пары «модуль и поле», число совпадений, полная цепочка раскрытий для тестовой обычной формы, текст/ошибка raw-редактора и изоляция соседей проверены. Не тестировались пиксели подсветки, физическая прокрутка или положение каретки.

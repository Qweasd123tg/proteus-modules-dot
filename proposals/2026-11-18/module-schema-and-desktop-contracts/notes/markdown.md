# Markdown: visible inline backticks must not select a delimiter

**Verified public native TextView contract; not an observed OS gesture or clipboard effect.** In ```A `` `x` `` B``` the inline-code run displays three characters, a backtick, x, and a backtick. Select its first character: the public [selected_source_range](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/vendor/gpui-base/src/text/state.rs#L419-L439) promises the original source occurrence. Previously the map gave bytes 2..3 (opening delimiter) instead of 5..6 (the literal character). Conversely the opening delimiter 2..4 unexpectedly mapped to some rendered text. The [range-highlight conversion](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/vendor/gpui-base/src/text/range_highlight.rs#L376-L399) shares this map. Selecting visible spaces adjacent to a trimmed padding space can similarly address the wrong source bytes.

The [parser’s display arm](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/vendor/gpui-base/src/text/format/markdown.rs#L820-L831) already knows the node type, the source and the literal value. Previously the greedy aligner searched from the opening delimiter. The patch assigns one exact linear source segment **only when** the body without its delimiters, or that body without one pair of ASCII padding spaces, equals the parser's value. This is positive slice equality, not a reimplementation of CommonMark. If there is no contiguous literal match, the existing code-only (no entities/escape decoding) alignment is retained. No changes to text, Markdown serialization, clipboard, block code/fences, math, other marks or UI events. No unverified stock app interaction is claimed.

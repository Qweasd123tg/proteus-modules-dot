Это подтверждают назначения PR, их merge-коммиты и пути изменённых файлов: у 17 PR корень `proposals/`, у трёх `research/`, у одного `foundation/` и у одного `polish/`. [Метаданные GitHub для каждого PR](prs.tsv). Таким образом, действительно опубликованы материалы, стенды, диффы и исправления самих отчётов. Ни один из этих PR не был направлен в upstream Core, Modules, Desktop или Extensions. Это не вывод о наличии ошибки в любой выпущенной версии.

Отдельно проверены **9 точных диффов, 13 файлов, все четыре upstream**: для Modules #184, Core #185 и #191, Extensions #199 и #204, Desktop #201, #202, #203 и #205. Оригинал каждого диффа сверялся по [неизменяемому Git blob](samples.tsv). На текущих закреплённых ветках девять применились вперёд; ни один из девяти не применился «назад» к исходному дереву. После применения откат точно восстановил исходные байты. [Результаты](result.txt). Это свидетельство отсутствия именно проверенного изменения **в такой форме и в таких строках**, не поиск всех альтернативных реализаций. Не исследовались форки, выпуски, все ветки или все диффы из 22 PR.

### Что остаётся существенным

1. **Смена вида поля с сохранением ID.** В [#201](https://github.com/Qweasd123tg/proteus-modules-dot/pull/201) актуализируются обработчики при сохранении типа. Смена multiline → compact search может оставить пустой блок: старый редактор не соответствует новому визуальному типу. Для автора пока безопаснее разные ID; исправление с тем же ID должно определить судьбу локального черновика, фокуса и выделения. Стенд, не пользовательское наблюдение. Новый пакет не решает это.
2. **Целостная установка сторонней возможности.** В [#198](https://github.com/Qweasd123tg/proteus-modules-dot/pull/198) проверены границы Core/Modules и Desktop Extensions: отдельно работающие части не доказывают, что сторонний автор может одним действием установить, включить и совместно обновлять логику, инструмент и панель. Штатная комплектация может уже включать обе части, как у «Плана». Новой установки и повторной проверки всех жизненных циклов здесь не было.
3. **Две неопределённости в данных Git-интерфейса, не косметические.** Для [маршрута родителя в Git-графе (#189)](https://github.com/Qweasd123tg/proteus-modules-dot/pull/189) пока нет варианта, одновременно прошедшего проверку связности и ширины на всех контрпримерах. Для [файлов с именами `notes` и `file:notes` в Git Changes (#205)](https://github.com/Qweasd123tg/proteus-modules-dot/pull/205) одинаковая строка может означать путь или ID; изменение приоритета не восстанавливает происхождение. Это два разных дефекта. Здесь граф и выбор файлов заново не тестировались.

**Что проверять при внедрении:** в первую очередь пользовательские примеры с потерей или изменением данных (например, незавершённый JSON из #205 и многострочные значения из текущего пакета), затем маршрутизацию действий и выбора. Эти материалы позволяют отобрать готовые сценарии для нативных интеграционных тестов, но сами таким тестом полнофункционального Desktop не являются.

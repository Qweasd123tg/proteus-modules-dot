# Как настройки Desktop трактуют схему автора модуля

Модуль может объявить параметр «массив многострочных строк». Core сохраняет именно такую схему. Desktop, однако, раньше принимал её за список однострочных тегов: вставка двух строк `Header` и `Body` в новое значение могла дать `HeaderBody`. Уже существующее значение от одной отрисовки не портилось; весь модуль можно было редактировать как JSON.

**Предложение:** только для явно многострочного массива обычных, несекретных строк открыть редактор JSON-массива. Запись `["Header\nBody"]` сохраняет одно значение с переводом строки. Обычные теги не меняются. Первый вариант отброшен на независимом ревью: он принял бы также `42` и `[1]`. Финальный действительно требует строки, различает пустой список и сброс параметра. Цена: у этого одного вида поля больше нет чипов, их перетаскивания и подсказок; пользователь редактирует JSON, а не вставляет произвольный текст как валидный JSON. [Патч](patches/desktop/multiline-array-editor.patch) · [Что проверено и почему](notes/multiline.md).

Это сквозное расхождение, а не предположение о несовместимых версиях: публичная схема в закреплённом Desktop [Core b6f48cd](https://github.com/Proteus-harness/Proteus-core/blob/b6f48cdaaec0e97a083ac81c6292c711a10fe65d/crates/proteus-contracts/src/domain/config_schema.rs) и [текущем Core c2cbade](https://github.com/Proteus-harness/Proteus-core/blob/c2cbadee518788f306ffb2b5271036b2658ea8cc/crates/proteus-contracts/src/domain/config_schema.rs) — один и тот же Git blob `5c1cb74d5d7afc957c05165c1b916019529a5129`. Оба дерева проверены: `276ab0513c64235aaebe6250f0f3269ff8c6351c` и `cd8dae1f22259ac02540b99e277d02a6b78be82d`. На реальных serde и функциях выбора/форматирования/разбора ранее расходились 9 из 9 примеров, с предложением — 0. [Независимый тест](checks/multiline/peer/REVIEW.md): 90 вариантов маршрутизации, 576 сохранённых массивов, отклонены 12 неверных форм. Настоящий модуль, который обязательно использует такое поле, не предъявляется; это путь, предусмотренный интерфейсом для авторов.

### Ещё три проверенных предложения к Desktop

| Область | Что меняется | Результат и граница |
|---|---|---|

Сохраняются режим, текст и ошибка, даже если ключ не написан в документе. Это не обещание найти строку или поставить каретку на ключ. | [Патч](patches/desktop/raw-settings-search-target.patch), [обоснование](notes/raw.md). | Выделение встроенного кода Markdown | Если текст содержит буквальный обратный апостроф, выделение могло указывать на одноимённый **разделитель** вместо литерала; обратная подсветка также адресовала чужие байты. Для однозначного непрерывного тела определяем точное начало; не меняем поведение неоднозначных многострочных контейнеров. | [Патч](patches/desktop/inline-code-source-origin.patch), [пример: байты 2..3 вместо 5..6](notes/markdown.md). Остались затраты поиска и копия ID самой кнопки. Не замер FPS; реальные вкладки не закрывались. |

### Поправка только к документации SDK

[`list` и `lane_row`](patches/extensions/sdk-list-and-lanes-contract.patch): один клик посылает `preview`, двойной клик и Enter — `open`. Для строки `lanes` нужны `cells` по числу колонок, включая пустую строку под граф. Без `cells` даже строка с одной графической колонкой не проходила десериализацию. [Точный пример](notes/sdk.md) проверен на действующем валидаторе Desktop; независимый `rustdoc --test` прошёл 1/1. Поведение SDK не меняется.

### Что внедрено

[Сверка #184–205 и незакрытые вопросы](adoption/README.md): все **22 PR** слиты в репозиторий предложений. Для девяти конкретных диффов на четырёх текущих upstream проверено, что они по-прежнему применяются вперёд. Не называть это интеграцией в продукт. ### Воспроизведение

Python 3, git, POSIX `patch`, совместимые rustc/rustdoc (проверено 1.95.0), готовые serde/serde_json/anyhow rlib и markdown-rs 1.0.0 с соответствующей зависимостью. Из корня пакета:

```sh
python3 checks/verify.py --desktop "$DESKTOP_REPO" --core "$CORE_REPO" --modules "$MODULES_REPO" --extensions "$EXTENSIONS_REPO" --dot "$DOT_REPO" --deps "$RUST_DEPS" --markdown "$MARKDOWN_RLIB" --rustc "$RUSTC" --rustdoc "$RUSTDOC"
```

Нужны соответствующие локальные Git-объекты: [Desktop 2307e9c](https://github.com/Proteus-harness/Proteus-desktop/tree/2307e9c67125bbe66f15ced51317a2dfcc437aa4), [Core c2cbade](https://github.com/Proteus-harness/Proteus-core/tree/c2cbadee518788f306ffb2b5271036b2658ea8cc), [Modules 0fe8e3b](https://github.com/Proteus-harness/Proteus-modules/tree/0fe8e3b4dfb64ca2e07df8af016d7ccc3a7de45f), [Extensions ef06438](https://github.com/Proteus-harness/Proteus-desktop-extensions/tree/ef064381d2194d95faef2b85f6cc3a1c34c6b975) и [dot 3647395](https://github.com/Qweasd123tg/proteus-modules-dot/tree/36473954b15f518654909ea8d78a298cdb4a29be). Для неглубокого клона dot необязателен путь `--proposal-cache` к недостающим опубликованным diff-файлам, названным по проверяемому Git blob SHA. Автоматического скачивания нет.

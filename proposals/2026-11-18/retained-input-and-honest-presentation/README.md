# Когда на экране уже новое поле, а срабатывает старое действие

Шесть проверенных предложений для Desktop и расширения Files. **Ни одно не интегрировано в upstream.** Первым стоит исправить привязки ввода: сменив назначение поля, автор расширения сейчас не может полагаться на то, что Enter отправит текст в новое действие. Для пользователей штатных настроек наиболее заметны неверный выбор по Enter в палитре шрифтов и подмена значения тега.

## 1. Расширения: действие поля должно соответствовать тому, что сейчас показано

[Публичный SDK](https://github.com/Proteus-harness/Proteus-desktop-extensions/blob/ef064381d2194d95faef2b85f6cc3a1c34c6b975/sdk/src/ui.rs#L199-L209) задаёт ID, действие редактирования, а также опциональную отправку и число строк. Когда следующий виджет использует тот же ID, [Desktop обновляет текст и подсказку, но подписки продолжают использовать первоначальные имена действий](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/ui/extensions/declarative/fields.rs#L335-L443). Например, переход с `save.previous` на `save.next` оставляет первую команду активной; даже удалённая автором отправка по Enter может продолжить срабатывать. У сохранённого многострочного редактора после следующего ввода также возвращается прежнее минимальное число строк.

[Предложение](patches/retained-input-bindings.patch) читает актуальные действия и минимальную высоту из описания сохранённого поля. В 360 обновлениях **без смены типа** 330 из 1440 событий не соответствовали новому описанию до патча, 0 после; неверная высота после редактирования — 216 из 324 → 0. При независимом тесте двух полей с непереданными черновиками оба текста, ID редакторов и подписки сохранились; 44 неверных события из 96 → 0. Использована точная ветка подготовки и её callbacks, а не запущенный плагин; не утверждаем, что конкретный штатный модуль обязательно меняет эти имена.

**Открытый дефект, не входит в правку:** если расширение сохраняет ID, но меняет многострочный редактор на однострочный компактный поиск, старая сущность остаётся многострочной, а [ветка поиска вместо неё рисует пустой блок](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/ui/extensions/declarative/render.rs#L282-L305). Обе схемы по отдельности допустимы; переход подтверждён стендом. Простая замена сущности могла бы потерять локальный черновик, фокус или выделение, поэтому её здесь не предлагаем. Автор может дать контролам разных типов разные ID.

## 2. Настройки: сохранить именно то, что человек видит

| Сценарий | Предложение и проверка |
|---|---|
| У строки с ключом `dense` заголовок «Compact», а у другого варианта **ключ** `Compact`. Удалить тег с видимой надписью «Compact» и ввести её обратно: раньше Enter или «Добавить» мог вернуть `dense` в зависимости от порядка объявления. | [Приоритет точного значения тега](patches/tag-literal-value.patch). 264 замены из 1152 → 0; независимая матрица: 846/1296 → 1296/1296 точных возвратов, ещё 1299 контрольных проверок сохранены. |
| В общем числовом поле `Number` набрать обратно показанное целое `9007199254740993`. После редактирования черновик содержал `9007199254740992.0`: менялось не написание, а значение. | [Не терять представимое целое](patches/number-exact-whole.patch). Из 2288 целочисленных написаний раньше искажались 350, после — 0. Независимая сверка двоичных разрядов: 4297/12 565 → 12 565/12 565 точных результатов. |

Для тегов [чип показывает значение](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/ui/settings/tags/editor.rs#L153-L175); [ручной ввод](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/ui/settings/tags.rs#L160-L175) ранее одинаково трактовал чужой заголовок и точный ключ. Неоднозначный заголовок по-прежнему можно выбрать кнопкой конкретной подсказки. Для заголовков без точного совпадения остаётся прежний порядок. Это редактор тегов строкового enum, **не** группа числовых/смешанных галочек из [исправленного доказательства #200](https://github.com/Qweasd123tg/proteus-modules-dot/pull/200).

Для [общего числового поля](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/settings/schema.rs#L137-L178) ровно представимые числа, например 42, сохраняют прежнюю форму. Меняется только ввод целого, которое можно точно хранить в JSON `i64/u64`, но исказило бы чтение через binary64. Запись `9007199254740993.0` или с экспонентой **всё ещё** следует прежней политике округления. Это не произвольная точность, не изменение поля `Integer` и не утверждение о записи на диск без сохранения.

## 3. Палитра: Enter на лупе должен открыть поиск, а не выбрать шрифт

В штатном выборе шрифта переместите курсор списка, затем Tab на кнопку-лупу. Нажатие Enter должно открыть поиск, как Space. Но [родительский обработчик](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/ui/picker.rs#L199-L241) перехватывал Enter раньше кнопки и выбирал строку; [палитра шрифтов при выборе закрывается](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/ui/settings/fonts.rs#L208-L242). Это вывод из действующего кода, а не наблюдение за настоящим окном.

[Патч](patches/picker-header-enter.patch) выбирает строку по Enter только при фокусе списка или поля поиска. Нажатие на кнопках поиска и «Назад» проходит к их обычной клавиатурной обработке. На точных обработчиках Picker и GPUI со стендом диспетчеризации: 104 расхождения из 14 976 → 0. Независимо проверены отменённое клавиатурное нажатие, смена фокуса, пустой список и поле поиска: 82 из 192 → 0. Остальные клавиши не изменены.

## 4. Diff: отсутствие текста не доказывает, что файл пуст или не менялся

Публичный [виджет Diff](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/declarative/widget.rs#L216-L225) принимает текст и отдельный список файлов. На `{"patch":"","files":[{"path":"notes.txt","status":"modified"}]}` карточка сообщает «Содержимое не изменилось»; для добавленного файла — «Пустой файл». Статус этого не доказывает. Даже когда в том же diff есть патч другого файла, ошибка сохраняется.

[Патч](patches/metadata-only-diff.patch) показывает «Текст изменений не предоставлен», только если для данной карточки нет строк, нет собственного текста патча и нет явного сообщения. Удаление известно по статусу, а реальная пустая Git-добавка, обычное переименование, строки и исходные байты остаются прежними. Действительная библиотека `proteus-diff`: 8/8 исходных тестов, новая проверка падает без правки, 9/9 после. Изолированный независимый тест: ложные подписи 77/77 → 0/77; ещё 283 неизменных случая. Штатный Git-производитель и экран не запускались, частота такого входа не измерялась.

## 5. Files: не набирать очередь папок, которые «Развернуть всё» всё равно пропустит

[Обход](https://github.com/Proteus-harness/Proteus-desktop-extensions/blob/ef064381d2194d95faef2b85f6cc3a1c34c6b975/packages/files/src/tree.rs#L291-L324) ограничен 256 посещёнными каталогами, но копировал пути всех обнаруженных дочерних папок в очередь. [Предложение](patches/bounded-expand-frontier.patch) оставляет в очереди только то, что укладывается в остаток лимита, с сохранением порядка.

На дереве 64×32 копий дочернего пути при постановке в очередь стало 255 вместо 2112, её пик — 249 записей вместо 2048. Посещены те же 256 каталогов в том же порядке. Независимая проверка: 797 форм, одинаковые 110 596 обращений к синтетическому источнику в каждой версии; проверены пустые/недоступные списки, ранее открытые папки, порядок и граничные размеры. Это не обещание ускорения диска, изменения числа системных запросов или решения ранее описанной проблемы длинных свёрнутых цепочек.

## Как повторить и что не проверено

[Скрипт](checks/verify.py) проверяет [SHA-256](SHA256SUMS), извлекает файлы закреплённых Git-версий, применяет и побайтно откатывает все шесть патчей во временном каталоге. Для тестов собирает чистые библиотеки и обработчики, заменяя окна, отправку событий и список папок контролируемыми стендами. Нужны Python 3, Git, Node и rustc с edition 2024; в `DEPS` должна быть ровно одна совместимая rlib каждого из serde с derive, serde_json и anyhow, вместе с их транзитивными зависимостями. Использованы Rust 1.95.0 и Node 24.22.1. Установка и сеть не нужны.

```sh
python3 checks/verify.py --desktop "$DESKTOP_REPO" \
  --extensions "$DESKTOP_EXTENSIONS_REPO" --deps "$DEPS" --rustc "$RUSTC"
```

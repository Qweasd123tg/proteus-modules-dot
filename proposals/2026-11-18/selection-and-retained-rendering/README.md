# Desktop и Core: что пользователь видит, что сохраняет редактор и что копирует рендер

Четыре независимо проверенных **предложения** и два подтверждённых дефекта **без патча**. Они не установлены в Proteus. Приоритет для интеграции: сначала убрать ложное изменение настроек и различить одноимённые проекты. Самый важный открытый дефект — потеря цели Markdown-ссылки при частичном копировании.

**Настройки.** [Обработчик](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/ui/settings/fields.rs#L239-L271) проверяет возвращение того же набора уникальных JSON-значений именно для нескольких галочек. Только в этом случае он передаёт [черновику](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/settings/draft.rs#L144-L173) исходный порядок. Новые составы и остальные массивы сохраняют прежнюю семантику. Это не нормализация повторов или удалённых из схемы значений и не утверждение о записи без подтверждения. Реальный профиль не открывался.

**Проекты.** Меняется только [список внутри меню](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/ui/chrome/projects.rs#L46-L80). Не меняются область действия, порядок, лимит восьми пунктов, недоступность и реальный путь по клику. [Основной список выбора папки](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/ui/launcher.rs#L251-L296) уже показывал пути. Ревью забраковало ранний вариант: третья папка возвращала длинный общий префикс первых двух. Два таких ярлыка теперь занимают по 16, а не по 445 символов в контрольном примере. Проверка строк и синтетических кликов, не гарантия видимости произвольного имени в любом шрифте или окне. Windows и графическое меню не запускались.

**Строки.** [Место обновления](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/ui/extensions/declarative/fields.rs#L566-L594), [хранилище строк](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/ui/extensions/declarative/rows.rs#L77-L103) и [захват для рисования](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/ui/extensions/declarative/lanes.rs#L70-L78). Предложение передаёт срез, удерживает неизменённые снимки по позиции и использует тот же Rc в отрисовке. На сильно сократившемся наборе внутренний буфер освобождает излишек. Сверены содержимое старых снимков, курсор, выбор, повторяющиеся ID, уведомления, пересчёт и цель прокрутки. Сравнение по-прежнему линейное; массовая перестановка не бесплатна. Это не маршрутизация Git-графа, не замер FPS, памяти процесса или живого GUI.

**SVG.** [Чистая функция адаптера](https://github.com/Proteus-harness/Proteus-desktop-extensions/blob/ef064381d2194d95faef2b85f6cc3a1c34c6b975/packages/mermaid-render/svg-theme.mjs#L86-L105) копирует карту только перед первой локальной записью. На шести тегах, каждый из которых переопределяет переменную, остаются все шесть копий. Доказана экономия операций с картой; не заявляем исправления цветов, ускорения Mermaid в миллисекундах, снижения RSS или отличия в пикселях. Код Pele и встроенный worker не запускались.

## Две диагностики, не решения

**Частичное копирование Markdown-ссылки.** Выделить только «Guide» внутри `[the Guide][Manual]` в режиме копирования исходника, где `[Manual]: /guide "Handbook"`. Вместо ссылки на `/guide` получается `[Guide]( "Manual")`. [Чтение ссылки](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/vendor/gpui-base/src/text/format/markdown.rs#L924-L939) хранит ключ отдельно от определения. [Визуализация](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/vendor/gpui-base/src/text/node.rs#L2964-L2976) разрешает его, а [частичная реконструкция](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/vendor/gpui-base/src/text/node.rs#L1047-L1085) записывает пустой URL и метку вместо заголовка.

Простой совет «записать нормализованный ключ» не работает: у `A B C` ключ становится `ab c`, который при повторном разборе отличается от исходного; ломается и `A &amp; B`. В [эксперименте на настоящем markdown-rs 1.0.0](checks/references/source-label.txt) текущая стратегия восстановила цель и заголовок в 0 из 336 случаев, наивная — в 200, сохранение исходного написания метки — в 336. Последний вариант **не встроен в модель Desktop**. Даже ему нужно соответствующее определение в документе назначения; одноимённое чужое определение сменит цель. Изолированный повтор исходного форматтера и эксперимент с парсером — не тест буфера обмена. Plain text и копирование всего исходника сюда не входят.

**Ширина текста в CLI.** Для тестовых рабочих путей с `AB`, `Пр` и `é` правая граница [рамки REPL](https://github.com/Proteus-harness/Proteus-core/blob/c2cbadee518788f306ffb2b5271036b2658ea8cc/crates/proteus-core/src/main/repl_render.rs#L35-L72) стоит в колонке 75 (с нуля), с `東京` — 77, с `e` + U+0301 — 74. В [таблице](https://github.com/Proteus-harness/Proteus-core/blob/c2cbadee518788f306ffb2b5271036b2658ea8cc/crates/proteus-core/src/main.rs#L472-L506) следующая колонка начинается с 6, 8 и 5 соответственно. Данные не теряются. На Linux в C.UTF-8 результат `wcswidth` совпал с независимой проверкой для этих символов. Нужна общая политика ширины терминальных ячеек для измерения и дополнения; случайная прибавка пробелов испортит другой случай. Не тестировались живой REPL, эмуляторы терминала, эмодзи или все шрифты.

## Как повторить

[Единый локальный проверочный скрипт](checks/verify.py) сверяет [контрольные суммы](SHA256SUMS), извлекает только необходимые файлы из уже имеющихся Git-репозиториев, применяет все четыре патча во временном каталоге, проверяет побайтный откат и запускает проверки. Нужны Git, Python 3, Node, Linux с C.UTF-8, rustc с edition 2024 и две уже собранные тем же компилятором библиотеки: serde_json 1.0.152 и markdown 1.0.0, с их транзитивными библиотеками рядом. Использованы rustc 1.95.0 и Node 24.22.1. Скрипт ничего не загружает и не меняет checkout.

```sh
python3 checks/verify.py --desktop "$DESKTOP_REPO" --core "$CORE_REPO" \
  --extensions "$DESKTOP_EXTENSIONS_REPO" --serde-json "$SERDE_JSON_RLIB" \
  --markdown-rlib "$MARKDOWN_RLIB" --rustc "$RUSTC"
```

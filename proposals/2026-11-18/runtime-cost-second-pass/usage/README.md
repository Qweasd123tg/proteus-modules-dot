## Usage: считать разбивку по моделям без повторного обхода истории

[Исходный расчёт](https://github.com/Proteus-harness/Proteus-desktop-extensions/blob/a35cea08be83ee8e5ecbfce9ef5050a1c00eb247/packages/usage/src/report.rs#L232-L302) сначала собирает список моделей, а затем **для каждой** снова обходит запросы и заново форматирует их названия. Для N запросов и M моделей одна `by_model` создаёт N × (M + 1) ключей, хотя достаточно N. [Панель Usage](https://github.com/Proteus-harness/Proteus-desktop-extensions/blob/a35cea08be83ee8e5ecbfce9ef5050a1c00eb247/packages/usage/src/view.rs#L182-L263) использует этот результат для таблицы и отдельно вычисляет общий итог периода.

**[Предложение](usage-by-model.patch).** Один накопитель считает расход и статусы как для всего выбранного периода, так и для каждой модели. Таблица `IndexMap` хранит по одному итогу на модель, а не ссылки на все запросы. Отдельные списки расхода токенов и цен больше не нужны. Ключ `provider/model`, порядок сложения стоимости, повторные запросы и отсутствие необязательных счётчиков сохраняются. При равном числе токенов первой остаётся модель, которая прежде появилась в журнале. Сам алгоритм тарифов не меняется. `indexmap` становится прямой зависимостью пакета, но новых версий и новых сторонних пакетов в Cargo.lock нет: та же сборка уже использует `indexmap` через `serde_json`. В основном файле 41 добавленная строка вместо 60 удалённых.

**Что измерено.** Это синтетические сеансы, до 20 видимых карточек на странице. В одном release-бинарнике находятся две настоящие `view::render` и обе версии расчёта; в каждой серии измерены медианы 11 парных прогонов с чередованием порядка. Приведены две серии; время указано **для полной проекции содержимого Usage в `view::render`**, без внешней шапки выбора сессии, передачи и отображения в Desktop:

| Запросов / отображаемых моделей | Серия 1, мс | Серия 2, мс |
|---|---:|---:|
| 2 / 1 | 0,081 → 0,081 | 0,050 → 0,051 |
| 32 / 1 | 0,521 → 0,503 | 0,347 → 0,357 |
| 80 / 2 | 0,682 → 0,631 | 0,434 → 0,414 |
| 800 / 2 | 2,794 → 2,132 | 2,777 → 1,998 |
| 1200 / 7 | 5,681 → 2,965 | 5,736 → 3,123 |
| 2048 / 64 | 33,837 → 4,328 | 28,571 → 3,840 |

На коротких сессиях устойчивого выигрыша не видно. На длинных с двумя моделями он есть; крайний многомодельный пример демонстрирует рост, а не типичное число моделей пользователя. [Первая серия](native.log), [повтор](native-repeat.log).

**Память отдельно от времени.** На странице для 2048 запросов и 64 моделей число запросов выделения/перевыделения памяти сократилось с 277 587 до 20 865. При 800 запросах и двух моделях пик добавочно запрошенных живых байтов только у `by_model` снизился с 12 704 до 556; при 2048/64 он, наоборот, вырос с 20 880 до 28 656 из-за таблицы моделей. **Пик полной проекции `view::render` не изменился ни в одном из семи примеров.** Например, 335 499 байт в обоих вариантах на 2048/64. Это отслеживание запросов Rust-аллокатора вокруг вызова; не RSS и не вся память приложения. [Изоляция аллокатора](alloc.log).

**Проверка.** Пин из [Desktop 210cc9f](https://github.com/Proteus-harness/Proteus-desktop/blob/210cc9f274ffe40533b390a0d9e940f251a9fa22/repositories.json): Extensions `a35cea08be83ee8e5ecbfce9ef5050a1c00eb247`. Сверены [54 Git-объекта](source-blobs.tsv), исходный `report.rs` — `f5aa5ec1e8e65eb6729f1ad013b74f5b8f6dbb25`. Прямое и обратное индексное наложение без остатка. Rust 1.95.0: в отдельных каталогах сборки [10/10 штатных тестов до](baseline-cargo.log), [12/12 после](candidate-cargo.log). Независимая нумерация и группировка плюс прежняя формула итога: 882 сравнения групп, порядка и всех полей, включая биты суммы в долларах; 1470 сравнений байтов полного JSON виджетов до/после и состояния после корректировки фильтров. Покрыты пустые периоды, смешанные модели, повторы и одинаковые суммы, строки с `/`, неизвестные тарифы и пропуски токенов. Это не бенчмарк живого интерфейса или процесса по сети; другие обходы для фильтров и списка моделей не меняются.

**Повторить.** Нужны Rust/Cargo, Python 3, Git, чистая копия закреплённого Extensions и доступные offline зависимости его Cargo.lock. Выполнить `python3 reproduce.py /path/to/Proteus-desktop-extensions`. Стенд проверит Git blobs и соберёт временные копии, не меняя указанный checkout. [Чистый прогон именно этой команды](clean-replay.log) прошёл, в том числе 10/10 и 12/12 в раздельных каталогах сборки и обе release-пробы. Сама проверка времени не включает инструментирование аллокатора.

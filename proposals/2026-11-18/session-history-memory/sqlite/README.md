# SQLite: повторно использовать запрос чтения и хешировать строку без временной копии

[Исходник](https://github.com/Proteus-harness/Proteus-modules/blob/37b3d9c4db0b8cb5c4ca6cec690ebf7ce64c1979/storage/session-storage/src/backend/sqlite.rs) · [патч](sqlite-journal-reads.patch) · [исходные измерения](native-results.json).

* При последовательном чтении снимка выполняется один и тот же индексированный запрос с двумя новыми границами. Вместо повторной подготовки для каждой записи применяется штатный кеш rusqlite, уже включённый в зависимости. SQL, порядок записей, проверка fingerprint, декодирование и проверка идентификаторов не меняются. Обратная сторона: подготовленный запрос остаётся в уже существующем кеше соединения до вытеснения или закрытия.
* При вычислении fingerprint данные нужны лишь до перехода к следующей строке SQLite. Теперь байты BLOB читаются по ссылке, без отдельного `Vec<u8>` для всей записи. Новый тест сравнивает и значения пустого/непустого BLOB, и точный тип ошибки старого/нового извлечения на TEXT, INTEGER, REAL, NULL.

**Замер настоящего backend:** Rust 1.95, SQLite 3.54.1 (версия из закреплённой сборки), release-профиль, Linux x86_64. Для каждой нагрузки обе реализации читали один и тот же подготовленный файл; проверены последовательности и независимый SHA-256. На каждый замер отдельный процесс; один прогрев пары, затем восемь пар в чередующемся порядке. Продолжительность относится к измеряемому вызову, а пик RSS (Linux VmHWM) — ко всему этому тестовому процессу.

| Нагрузка | Время, медиана до → после | Пик RSS процесса, медиана до → после |
|---|---:|---:|
| Проход по 12 000 записям (текст по 256 байт) | 136,00 → 69,67 мс | 8,09 → 7,79 МиБ |
| Создание холодного снимка, запись с текстом 16 МиБ | 28,09 → 21,95 мс | 37,21 → 21,23 МиБ |
| Fingerprint префикса той же записи | 31,21 → 21,57 мс | 37,21 → 21,23 МиБ |

До/после здесь относится к одному патчу SQLite. Это не RSS Desktop/сервера, не ускорение всех запросов, не сокращение размера журнала. Пики двух операций не складываются.

**Воспроизведение.** С Rust/Cargo в PATH: `python native_benchmark.py /path/to/Proteus-modules > results.json`. Скрипт берёт указанный commit, собирает обе версии с неизменённым Cargo.lock и подключает [драйвер](native_probe.rs) только в тестовые копии. Чтобы проверить рабочий пакет после патча: `python scripts/test.py -p session-storage --lib` из checkout Modules. [Результаты](checks.txt): 30 passed, 0 failed, 1 штатный ручной замер отдельно; ещё 2/2 теста настоящего процесса storage (JSONL и SQLite) прошли. Совместимость с #213 проверена [отдельно](../snapshot-213.md).

## Анализ хода: не хранить все строки для расчёта высоты

[Исходник Analysis](https://github.com/Proteus-harness/Proteus-desktop-extensions/blob/a35cea08be83ee8e5ecbfce9ef5050a1c00eb247/packages/analysis/src/nodes.rs#L55-L108) собирает ссылки **на все строки** текста или форматированного JSON, хотя 19 экранных строк дают 358 пикселей, а начиная с 20-й высота всегда 360. [Патч](analysis-height.patch) считает строки по мере чтения и останавливается, как только достигнут предел. Он не обрезает текст и не меняет то, что можно прочесть или скопировать. Дополнительная память расчёта высоты меняется с O(число строк) на O(1). Чтобы найти конец одной длинной строки, алгоритм всё ещё просматривает её целиком.

**Результат на реальной функции, которая строит карточку.** В одном release-процессе вызваны исходная и изменённая версии `disclosure`; полные возвращённые JSON-деревья виджетов совпали на всех пяти входах. Медианы 11 чередующихся пар (синтетические входы, не время отображения в окне):

| Что получает карточка | До → после |
|---|---:|
| Текст: 100 000 строк `x\n` | 0,815 → 0,014 мс |
| JSON: массив из 100 000 элементов `null` | 1,868 → 0,727 мс |
| Короткая текстовая подпись | 2,109 → 1,910 мкс |
| 1 000 000 эмодзи в **одной** строке с переносом | 2,942 → 3,001 мс |
| Поле JSON с **одной** строкой из 1 000 000 ASCII-символов | 1,741 → 1,871 мс |

На многострочных записях ускорилось даже построение целой карточки, включая подготовку её текста. На длинных однострочных записях ускорения нет: последний случай стал медленнее примерно на 0,130 мс. [Повторный запуск](projection-repeat.txt) подтвердил направление: 0,798 → 0,013 мс для многострочного текста и 1,746 → 1,973 мс (+0,227 мс) для строки в JSON. Это предложение **для многострочных деталей**, не универсальное ускорение Proteus. На 100 000 строк у изолированного `height` зафиксировано 16 запросов выделения/изменения размера и 2 097 152 байта пикового живого запрошенного объёма; после правки оба значения равны нулю. Это не RSS и не размер всего виджета.

**Проверка.** [Пин Desktop `210cc9f`](https://github.com/Proteus-harness/Proteus-desktop/blob/210cc9f274ffe40533b390a0d9e940f251a9fa22/repositories.json): Extensions `a35cea08be83ee8e5ecbfce9ef5050a1c00eb247`. Исходный Git blob `9860c5ada746f55ac1bc717d9e2410d3b66856f4`, итоговый `762942e98a21d22e7112b98a9c4456309395e6f5`. Проверены индексное наложение и обратное наложение без остаточного diff. В отдельной копии сверены 55 исходных Git-объектов, включая все исходники analysis/SDK и Cargo.lock. На Rust 1.95.0 пакет `extension-analysis`: [11/11 до](package-before.txt), [12/12 после](package-after.txt). У настоящих старой и новой функций [49 242 результата](native-results.txt) совпали с независимым эталоном на Python `str.splitlines()`: разные сочетания разделителей, CRLF, Unicode и границы 110 символов. [Полный протокол карточек](projection-results.txt). Отдельный скалярный прототип отклонён после замеров; он не входит в предложение. Потребность в больших блоках в реальных сессиях, GPUI, FPS, RSS всего процесса и полная сборка Desktop не проверялись.

**Повторить** из этой папки, передав чистую копию закреплённого Extensions. Нужны Python 3, Git, rustc/cargo 1.95 и зависимости Cargo.lock (проба карточек работает offline; если кеш пуст, сначала запустите обычный пакетный тест).

```sh
python3 native_check.py /path/to/Extensions
python3 projection_check.py /path/to/Extensions
```

Для штатной проверки из чистой копии Extensions: `cargo test --locked -p extension-analysis`, затем наложить патч и повторить команду. Общий вывод не зависит от измерения времени: в расчёте высоты нет вектора ссылок, а внутри одной многострочной карточки после насыщения лишние строки для высоты не просматриваются.

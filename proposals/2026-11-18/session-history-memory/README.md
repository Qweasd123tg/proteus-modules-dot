# Меньше памяти при открытии истории Proteus

**Я бы начал с двух патчей хранилища.** Первый убирает глубокую копию уже проверенной истории в Core. Второй не копирует крупную запись SQLite только ради хеширования и не готовит заново один SQL-запрос на каждую строку. Третий патч, для панели Analysis, полезен прежде всего на многострочных карточках.

| Где | Сравнение на одном входе (до → после) | Что именно измерялось |
|---|---|---|
| [SQLite: чтение журнала](sqlite/README.md) | **136,0 → 69,7 мс** на 12 000 записей | Создание тёплого снимка и чтение до конца через настоящий Rust backend в release. |
| [SQLite: холодная проверка](sqlite/README.md) | **37,21 → 21,23 МиБ** пикового RSS; **28,09 → 21,95 мс** | Отдельный тестовый процесс; в журнале одно сообщение с текстом 16 МиБ. На том же префиксе RSS также снизился, значения не складываются. |
| [Core: открытие истории](core/README.md) | **32,37 → 16,47 МиБ** дополнительной живой памяти | 256 сообщений по 64 КиБ, каждое в отдельной записи. Если все сообщения лежат в одной записи, пик **не меняется**. Это измерение аллокатора, не RSS; ускорение Core не установлено. |
| [Analysis: построение карточки](analysis/README.md) | **0,815 → 0,014 мс** для 100 000 коротких строк; **1,868 → 0,727 мс** для JSON-массива из 100 000 элементов | Полная сборка значения карточки, не отрисовка окна. Для JSON с одной строкой в 1 МБ результат обратный: **1,741 → 1,871 мс**, в повторной серии +0,227 мс. |

**Патчи:** [Core](core/move-validated-history.patch), [Modules/SQLite](sqlite/sqlite-journal-reads.patch), [Extensions/Analysis](analysis/analysis-height.patch). Каждый рассчитан на свою ревизию. Формат журнала, результаты чтения и отображаемый текст не меняются. Для upstream это предложения, не изменения его исходников, бинарников или установленных приложений.

**Проверки:** библиотека session-storage и два межпроцессных теста, целевые проверки Core с отрицательным контролем ревизии, пакет extension-analysis и сравнение Rust-версий с независимым эталоном. Методики, тестовые драйверы и результаты по каждому пути приведены по ссылкам. В одной сборке весь Desktop с тремя патчами не запускался. Общий RSS приложения, скорость ответа модели и время от открытия окна до готовности не измерялись.

**Закрыт отдельный пробел в проверке [#213](snapshot-213.md):** прежний Rust-тест воспроизвёл преждевременное закрытие снимка на текущих Modules, исправление из #213 прошло тест на обеих реализациях хранения. [Два небольших выигрыша](other-paths.md) в рантайме OpenCode и проверке лицензий не включены в приоритетные патчи.

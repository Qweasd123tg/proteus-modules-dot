# Почему не добавлены ещё два патча

**[Сборщик ответов OpenCode](https://github.com/Proteus-harness/Proteus-modules/blob/37b3d9c4db0b8cb5c4ca6cec690ebf7ce64c1979/model/opencode-provider/response.mjs).** Хранение ID отдельно для каждого типа блока вместо составного строкового ключа проверили на настоящем JS-классе. На 240 синтетических ответах по 1 024 события с короткими ID `text` и `reason` медиана семи пар запусков Node 24.22.3 составила 39,24 → 21,81 мс. Это всего около **0,073 мс на один такой ответ**, без сети или модели. Отдельные таблицы по типу требуют дополнительной постоянной памяти на ответ. 138 сравнений исходной/изменённой реализации совпали. С исходным SDK на закреплённом Node 24.12.0 штатные тесты преобразования сообщений прошли 16/16, с двумя регрессиями 18/18. Полный SDK не проверялся. В приоритетную поставку не включено.

**Проверка лицензий Desktop.** Если исключить каталоги зависимостей/сборки до обхода и разбирать подходящий Cargo-манифест один раз, ускоряется проверка разработки, а не работающее приложение. На чистом исходном архиве Desktop `210cc9f2` медиана десяти прогретых запусков на Python 3.12 составила 79,73 → 43,37 мс; обе версии дали 0 диагностик. На дереве с 1 200 каталогами fingerprints, 200 vendored-пакетами и 200 вложенными каталогами сборки: 49,01 → 6,49 мс. Это не измерение установленного Desktop. Отдельный PR под этот инструмент не открывался.

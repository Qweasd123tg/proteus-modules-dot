# Три места, где Proteus делал работу, результат которой не использовал

Это три независимых патча для действующих исходников, а не правка запущенного приложения. Каждый применяется к **своему** репозиторию. Ревизии Modules и Extensions совпадают с [закреплёнными в Desktop](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/repositories.json).

**[Modules: выбор слов для поиска](patches/query-terms.patch).** [Исходник](https://github.com/Proteus-harness/Proteus-modules/blob/0fe8e3b4dfb64ca2e07df8af016d7ccc3a7de45f/context/context-pack/src/search_queries.rs). Из функции убран список из 22 разных слов: каждое и так проходит общее правило. Четыре проверки расширений файлов тоже ничего не решали: строка уже разделена по точкам. Остались два понятных условия отбора, а ключ для удаления повторов создаётся только у подходящего слова. Порядок, исходное написание, предел в четыре результата и резервный ответ сохранены. Например, одинокое `lib.rs` по-прежнему возвращается целиком как резервный ответ, хотя в смешанном запросе точка разделяет слова.

**[Extensions: видимые ходы в панели анализа](patches/visible-turns.patch).** [Исходник](https://github.com/Proteus-harness/Proteus-desktop-extensions/blob/ef064381d2194d95faef2b85f6cc3a1c34c6b975/packages/analysis/src/summary.rs). Вместо промежуточного вектора ссылок на всю историю берём последние 8 ходов (200 в раскрытом списке) непосредственно из обратного итератора. Если выбранный ход ещё не виден, поиск продолжается по остатку. Порядок сохранён, в том числе когда за пределами видимой части несколько записей с выбранным ID. В таком случае остаток по-прежнему просматривается до конца.

**[Desktop: имена файлов на карточке diff](patches/diff-paths.patch).** [Исходник](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/crates/diff/src/parse.rs). При чтении заголовка Git по-прежнему находится граница первого пути с учётом кавычек и экранирования, но сам этот путь больше не декодируется: нужен второй. В обычной паре `---` и `+++` старое имя сохраняется один раз, а отображаемое имя определяется второй строкой. Добавление, удаление и переименование продолжают различаться. Патч не применяет diff и не обращается к файловой системе.

### Проверка на Rust 1.95

| Область | Что прошло |
| --- | --- |
| Modules | В полном закреплённом checkout: `cargo test --locked --offline -p context-pack --lib extract_search_queries`. 3 до правки, 4 после, 21 тест вне фильтра. У двух версий настоящей функции совпали результаты для 137 257 сгенерированных строк с контрольным словом, прежнего словаря и 4 096 комбинаций порядка. |
| Extensions | `cargo test --locked -p extension-analysis`: 10 из 10 до и после. На 880 сочетаниях обе версии совпали с независимым ожидаемым порядком. Собран и проверен ZIP пакета analysis; в Desktop не устанавливали. |
| Desktop | Библиотека `proteus-diff` проверена отдельно, с исходным манифестом и версиями зависимостей из Cargo.lock Desktop. Все 8 существующих и 2 новых теста прошли и на старом, и на новом парсере. Для 7 168 синтетических diff совпало полное отладочное представление публичного результата, включая пути, статусы и строки. |

У всех трёх патчей проверены исходные Git blob, строгое наложение и побайтный возврат. Это не проверка полной сборки Desktop, живого GUI или производительности. Изменения не затрагивают предложения на HOLD. Штатные тесты не удалены. Отдельную реорганизацию тестовых фикстур и формата внутреннего отчёта в пакет не включали.

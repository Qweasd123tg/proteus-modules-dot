# Independent GO: retain only focus handles still belonging to the rendered rows

Exact patch SHA-256: `ed51bc679d73e0da6715a0e1b66a99fe8326436aee8bac656b203e743e9c1848`. Applied with no fuzz to official Desktop blob `7193ede57c29ca7e9ecd2e2795476e3c8fda18f0` on [pinned main](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/ui/reorder.rs#L517-L559). The patch changes only the membership test at prepaint; the same height map was already necessary and built for layout.

- A [single Vec of rows](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/ui/reorder.rs#L226) provides ids, and exactly one element per row in the [same order](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/ui/reorder.rs#L263-L283). Closure callbacks do not filter or remove elements. Before prepaint, the component inserts a new handle only when absent. Arrange receives both vectors and [requests one layout per element](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/ui/reorder.rs#L497-L533). Therefore zip contains every id. Hash key membership is independent of zero/nonzero height and row position. Equal duplicate ids have the same membership result both ways (not a claim that duplicate ids are a generally valid interface design).
- Retention mutates neither map values nor focus objects. Same ids preserve their handle identities; once removed, the map no longer retains their values. More references outside the map can of course keep a handle alive.
- 12,288 replacement-frame inputs per version validated with actual extracted request-layout, zip, height and retain expressions, independent expected key sets and pointer identity/liveness checks. Includes all 6-key previous/replacement subsets, reorderings, duplicate-content rows, complete replacements and empty states. False counterexample excluded: independently malformed ids/children/layouts vectors could drop an id, but there is no such route in this private constructor.
- For 1,024 touched live ids reversed: 524,800 old key equality comparisons vs. 1,024 new hash operations. For replacing 1,024 by 1,024 disjoint keys, state holds both groups before pruning: 1,573,376 old comparisons vs. 2,048 new hash operations. Post-patch hash collisions can incur equality checks; the hash operations and equality counts are *not timings or comparable unit costs*. This replaces one quadratic membership scan with expected linear hashing at ordinary map behavior, not a claim that all arrange/layout or frame time is linear.
- No full GPUI build, drag/gesture, screen-reader, GUI or frame-rate claim. Synthetic identity handles are Rc; GUI focus restoration was not run.

Use `python3 replay.py PATH/TO/pinned/reorder.rs PATH/TO/reorder-focus-index.patch [RUSTC]` in this directory. Also see `gate.rs.in` and `results.txt`. The launcher picker negative finding is separate.

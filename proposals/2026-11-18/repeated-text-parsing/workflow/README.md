# Не нормализовать один и тот же deferred tool call дважды

**Что меняется:** только dispatch `proteus_tool_call` в `coding-workflow`. На месте одного и того же вызова больше не строятся повторно мета-схемы и не дублируются декодирование, валидация и копирование аргументов. Это измеримый выигрыш обработчика, но не доказанное ускорение долгих ходов целиком. Без общего кеша, изменения формата или пропуска обязательных проверок.

[Исходники dispatch + prepare](https://github.com/Proteus-harness/Proteus-modules/blob/37b3d9c4db0b8cb5c4ca6cec690ebf7ce64c1979/workflow/coding-workflow/src/dynamic_tools.rs#L148-L191) на Modules `37b3d9c`: `handle_meta_tool_call` сначала вызывает `normalized_meta_call`, затем [`handle_deferred_call → prepare_deferred_call`](https://github.com/Proteus-harness/Proteus-modules/blob/37b3d9c4db0b8cb5c4ca6cec690ebf7ce64c1979/workflow/coding-workflow/src/dynamic_tools.rs#L314-L338) снова вызывает `normalized_meta_call`. Успешное первое преобразование переписывает только `args` клона; `raw_arguments`, имя, фаза и идентификатор остаются прежними. Между двумя преобразованиями нет ни обращения к хосту, ни нового ввода. Вызов без raw также проходил лишнюю валидацию.

На закреплённом [Core `4c032ee`](https://github.com/Proteus-harness/Proteus-core/blob/4c032eeb7c51b2467064d7cd10fc6f8008ae51e4/crates/proteus-contracts/src/domain/tool_validation.rs#L15-L41) одна успешная нормализация для valid raw сначала разбирает JSON для валидации схемы, а затем workflow повторно разбирает его, чтобы сохранить эффективные `args`. [Патч](deferred-parse.patch) убирает один полный такой проход: **4 → 2** разбора raw и **2 → 1** компиляции/проверки схемы в dispatch. Это подсчёт по исходникам, не инструментирование. Малформированный ввод как раньше возвращается после первой ошибки. Отдельный [чекпоинт до исполнения](https://github.com/Proteus-harness/Proteus-modules/blob/37b3d9c4db0b8cb5c4ca6cec690ebf7ce64c1979/workflow/coding-workflow/src/scaffold.rs#L63-L82) не меняется. Оставшиеся два разбора внутри одной нормализации не скрыты: их устранение требует отдельного решения о том, где принадлежат результат разбора и диагностика общего валидатора.

### Измерение

Нативные baseline/after, Rust 1.95.0 `--release --locked`, Linux x86_64, AMD EPYC 9V74; дочерние процессы закреплены на одном разрешённом CPU. Одинаковый input: аргументы скрытого инструмента записи с переводами строк, кавычками и UTF-8; типизированные `args` и исходная строка совпадают, как их [выставляет адаптер OpenAI Responses](https://github.com/Proteus-harness/Proteus-modules/blob/37b3d9c4db0b8cb5c4ca6cec690ebf7ce64c1979/model/model-pack/src/adapters/openai/response/item.rs#L80-L86). Работа с реальной ФС и вызов модели заменены штатным тестовым хостом. В dispatch измеряется вызов production handler, включая контрактный JSON-вызов видимого каталога/внутреннего инструмента; в полном workflow измеряется `CodingSingleLoopWorkflow::run_json` от входа до сериализованного выхода, включая контекст, 2 синтетических ответа модели, чекпоинты и события. Подготовка fixture и проверки вне таймера. Это не замер сети, HTTP/UI, настоящей модели/ФС или расхода памяти.

12 пар для каждой строки, порядок AB/BA меняется (по 6 каждого); один полный разогрев процесса плюс дополнительная первая пара не учитываются. Время до/после — медианы среднего времени на один вызов в пакете. Δ — медиана **парных отношений**, поэтому знак не обязан совпадать с отношением двух независимых медиан.

| Сценарий | До | После | Парная Δ | Быстрее |
|---|---:|---:|---:|---:|
| Dispatch, 139 байт raw | 25,34 мкс | 14,94 мкс | −39,5% | 12/12 |
| Dispatch, 151 617 байт raw | 784,60 мкс | 556,35 мкс | −29,0% | 12/12 |
| Полный workflow, 139 байт | 329,36 мкс | 318,52 мкс | −4,1% | 9/12 |
| Полный workflow, 151 617 байт | 9,94 мс | 9,84 мс | +1,0% | 4/12 |
| `proteus_tool_describe`, неизменённый путь | 12,55 мкс | 12,67 мкс | +0,9% | 4/12 |

На большом входе **нет подтверждённой сквозной выгоды**. Ускорение в обработчике относится ко всему удалённому проходу, не только к JSON-парсеру; не экстраполировать проценты на каждый инструмент или полный ход агента. [Сырые пары](results/paired.csv).

### Паритет и повтор

В обеих сборках прошли все 111 штатных library tests этого crate; один отдельный ignored probe запускается явно. Патч усиливает существующий тест полного workflow: сохранённые raw ссылаются на другой инструмент, чем `args`; исполняется строго вызов из raw и ровно его аргументы попадают в чекпоинт. [Отдельный probe](probe.rs) проверяет 12 сценариев, в том числе fallback без raw, конкурирующие raw/typed, ошибки парсера и схемы, запрет фазы, рекурсию, недоступный инструмент, поиск описания и ответы обоих размеров. Ошибочные вызовы не исполнились. Полные ToolResult совпали в двух сборках после замены случайного call ID на константу в сравнительном выводе (оригинальный ID независимо проверен на каждом вызове). [Результаты паритета](results/parity.json). Полный репозиторий и UI не тестировались.

Из любого существующего клона Modules с данным коммитом и его зависимостями: `bash reproduce.sh /path/to/Proteus-modules /new/output` (на Linux опционально `--cpu N`). Скрипт собирает две временные локальные копии, применяет патч только к одной и проверяет обе. В папке результатов — CSV, протоколы и JSON паритета.

### Почему не добавлен кеш в других местах

* [OpenCode stream collector](https://github.com/Proteus-harness/Proteus-modules/blob/37b3d9c4db0b8cb5c4ca6cec690ebf7ce64c1979/model/opencode-provider/response.mjs#L72-L127) передаёт фрагменты аргументов как строки без JSON.parse. При завершении готовый объект проверяет `isJson` и использует `block.call`; завершающее текстовое событие вправе скорректировать собранный текст. При этом [OpenCode repair](https://github.com/Proteus-harness/Proteus-modules/blob/37b3d9c4db0b8cb5c4ca6cec690ebf7ce64c1979/workflow/opencode-runtime/repair.mjs#L4-L19) запускает hook и может вернуть изменённый JSON; независимо вызываемый файловый адаптер не обязан получить тот же исходный текст. Это не тот дубль.
* [JSONL/SQLite codec](https://github.com/Proteus-harness/Proteus-modules/blob/37b3d9c4db0b8cb5c4ca6cec690ebf7ce64c1979/storage/session-storage/src/codec.rs#L102-L136): inline-запись из байтов разбирается один раз; типизированный JournalEntry строится через [from_value](https://github.com/Proteus-harness/Proteus-core/blob/4c032eeb7c51b2467064d7cd10fc6f8008ae51e4/crates/proteus-contracts/src/storage/journal.rs#L240-L249), не вторичным парсингом строки. `to_vec` проверяет размер канонического представления, SHA-256 сверяет байтовую целостность; это не повторный разбор JSON. Для внешнего blob исходные байты другие.
* [Публичный analysis route](https://github.com/Proteus-harness/Proteus-core/blob/4c032eeb7c51b2467064d7cd10fc6f8008ae51e4/crates/proteus-core/src/app_server/http/analysis.rs#L16-L58) считывает проекцию для данного запроса. Два прохода по короткой HTTP query выбирают разные поля (`session_dir` и `turn_id`); projection и подробности выбранного хода работают уже со структурами. Это не повторный JSON/Markdown parse неизменяемого тела и не доказательство необходимости кешировать состояние между запросами.

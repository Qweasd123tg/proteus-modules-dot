# Независимый корпус: какие ответы и какие разборы сохранились

Два release-процесса `markdown-render` сравнивались полными JSONL-ответами, не снимками отдельных HTML-фрагментов. Источники: все **652 примера** [CommonMark Specification 0.31.2](https://spec.commonmark.org/0.31.2/) и три файла документации из публичного [Proteus-core 8ea2cdaf](https://github.com/Proteus-harness/Proteus-core/tree/8ea2cdaf4195ae24e941354f68d4e97335d139d7/docs): правила памяти, тестирования и описание архитектуры. Личные чаты и внешние модели не использовались. Корпус спецификации не вложен: повтор использует оригинальный `spec.json` с проверкой SHA-256.

**Совпали 5 237 ответов из 5 237**: 5 213 для примеров спецификации, 24 для документов Proteus. Каждый текст передавался одному и тому же view последовательностью: префиксы до полного текста, неизменившийся повтор, откат на половину текста, завершение, смена списка языковых обработчиков; между документами view закрывался. Сверены все байты ответов, включая тип, дерево, имена виджетов и ревизии. Это проверка **отсутствия изменений поведения между версиями**, а не проверка соответствия Proteus эталонному HTML CommonMark. [Хеши](results.json) · [драйвер](equivalence.py).

Отдельные инструментированные процессы считали вызовы parser в четырёх местах (не использовались для измерения времени). Здесь каждый пример отправлен сначала целиком в новый view, затем без изменения текста и набора языков с новой source_revision:

| Входы | Построения routing AST до → после | Вызовы компилятора GFM HTML до → после |
|---|---:|---:|
| 652 полных примера CommonMark, свежий view | **652 → 212** | 666 → 666 |
| Те же источники повторно, те же view | 62 → 37 | 0 → 0 |
| 3 документа Proteus, свежий view | 3 → 2 (103 242 → 90 245 байт на этом этапе) | 18 → 18 |
| Те же документы в тех же view повторно | 2 → 0 | 0 → 0 |

В таблице считаются вызовы, а не тексты: один документ может дать несколько сегментов для компилятора. В действительном Desktop одинаковая строка может отсеяться ещё до этих процессов, поэтому искусственная повторная доставка не означает стоимость каждого кадра. Набор CommonMark специально покрывает синтаксис и **не** описывает частоту конструкций в чатах пользователя. На больших реальных документах с блоками ограждений или определениями routing обычно по-прежнему нужен. [Сырые счётчики](route-counts.json) · [драйвер](route_counts.py).

Воспроизведение после сборки обычных и инструментированных процессов, из каталога этого отчёта:

```sh
curl -fsSL https://spec.commonmark.org/0.31.2/spec.json -o spec.json
python3 equivalence.py "$BASE" "$PATCHED" spec.json "$CORE_CHECKOUT"
python3 route_counts.py "$INSTRUMENTED_BASE" "$INSTRUMENTED_PATCHED" spec.json "$CORE_CHECKOUT"
```

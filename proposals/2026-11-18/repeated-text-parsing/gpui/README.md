# GPUI: не внедрять общий кеш или обход нормализации HTML

**Реальный повтор есть, но не на двух главных сценариях #215.** Путь HTML сначала [разбирает исходник и сериализует нормализованную разметку](https://github.com/Proteus-harness/Proteus-desktop/blob/210cc9f274ffe40533b390a0d9e940f251a9fa22/vendor/gpui-base/src/text/format/html5minify/mod.rs#L180-L190), затем [разбирает результат в DOM](https://github.com/Proteus-harness/Proteus-desktop/blob/210cc9f274ffe40533b390a0d9e940f251a9fa22/vendor/gpui-base/src/text/format/html.rs#L95-L132). Если байты изменились, это два разных входа. Проверенный контрфактический вариант оставляет исходное DOM только при полном совпадении байтов; иначе уничтожает его до второго разбора. Ни истории, ни глобального кеша. Продуктового патча нет.

| Выход настоящего расширения → вход нативного HTML5ever | Фактические вызовы на одно построение DOM | Прочитано байтов до → после |
|---|---:|---:|
| #215, исходный текст с операторами сравнения и амперсандами, без URL, 60 971 Б HTML | 2 → 2 | 121 942 → 121 942 |
| То же, URL, 61 029 Б HTML | 2 → 2 | 122 056 → 122 056 |
| Обычные предложения, кириллица и переносы, 53 051 Б HTML | 2 → 1 | 106 102 → 53 051 |
| Те же предложения + URL, 53 109 Б HTML | 2 → 2 | 106 216 → 106 216 |

Последовательность узлов, данные и атрибуты, дочерние узлы, ошибки и quirks совпали во всех **187** синтетических случаях. Среди 35 малых plain-примеров повтор на идентичных байтах обнаружен в 15, среди 36 HTML-ответов Markdown-расширения в 0, среди 110 независимых HTML-контролей в 18. Это специально сформированный корпус, **не оценка частоты у пользователей**. Ветка совпадения ускорила изолированную стадию для обычных предложений 0,256 → 0,144 мс; изменение единиц процентов на двух miss-наборах #215 не считаем выигрышем.

**Память.** На miss-контроле 380 007 Б один этап до и после: 40 385 выделений/перевыделений, пик живых запрошенных данных 1 087 487 Б, на возврате DOM 263 200 Б. На обеих фикстурах #215 показатели также в точности равны. На hit с предложениями пик 177 426 → 172 773 Б, возвращаемое дерево по-прежнему занимает 66 680 Б. У всех восьми замеров после уничтожения DOM прирост живой измеренной памяти нулевой. VmHWM пяти отдельных Linux-процессов с 380 007 Б miss: медианы 3 608 → 3 612 КиБ, диапазоны 3 556–3 652 и 3 524–3 640 КиБ пересекаются. Экономию RSS не заявляем.

**Отдельный повтор в состоянии виджета (по исходникам, не GUI-трасса).** При [первичном создании HTML-состояния или замене до 4 096 Б включительно](https://github.com/Proteus-harness/Proteus-desktop/blob/210cc9f274ffe40533b390a0d9e940f251a9fa22/vendor/gpui-base/src/text/state.rs#L532-L603) синхронный разбор даёт правильную высоту на первом layout. В отсутствие последующих обновлений фоновый [BaselineAck повторяет тот же исходник](https://github.com/Proteus-harness/Proteus-desktop/blob/210cc9f274ffe40533b390a0d9e940f251a9fa22/vendor/gpui-base/src/text/state.rs#L1266-L1317) для своей базы на случай append; UI этот результат не коммитит. Очередь умеет заменить старый запрос или объединить его с append: нельзя считать по два разбора на каждую ревизию. Свыше 4 096 Б замена разбирается только в фоне. [Те же HTML-байты в уже подготовленном RichText](https://github.com/Proteus-harness/Proteus-desktop/blob/210cc9f274ffe40533b390a0d9e940f251a9fa22/src/ui/extensions/declarative/rich_text.rs#L21-L36) сами по себе не инициируют повтор. [Непустое расширение Markdown может обрабатываться как append; изменённый HTML через set_text заменяется целиком](https://github.com/Proteus-harness/Proteus-desktop/blob/210cc9f274ffe40533b390a0d9e940f251a9fa22/vendor/gpui-base/src/text/state.rs#L339-L383). Изменение конфигурации парсера и пересборка Markdown с глобальными ссылочными определениями имеют другие причины. Наивный перенос видимого AST в worker не проверен: узлы содержат разделяемое изменяемое состояние выделения/геометрии.

**Воспроизведение.** Rust/Cargo 1.95.0, CPU Linux, режим release. `python3 reproduce.py /путь/к/Proteus-desktop [--offline]` в этой папке. Скрипт работает во временной копии и проверяет Git-идентичность обоих исходников. Зависимости с зафиксированными версиями/контрольными суммами из Cargo.lock Desktop. Корпус в архиве, `make_corpus.py` опционально воссоздаёт его из ELF #215; SHA в [results.json](results.json). Счётчик оборачивает Read, таймер запускается в отдельной сборке без счётчика, аллокатор в третьей. В пределах каждой сборки обе версии находятся в одном ELF. Область измерения заканчивается на возврате RcDom, до GPUI BlockNode, layout и paint. Окно, реальное число вызовов через TextViewState, PSS и FPS не измеряли.

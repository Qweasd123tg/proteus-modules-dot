# Когда ускорение обычного текста доходит до клиента

Для двух синтетических сообщений из #215 проверили **путь до получения и проверки дерева виджетов нативным транспортом Desktop**, а не только обмен из Python с расширением. На многострочном тексте 53 762 Б без ссылки выигрыш сохранился. На 53 784 Б с URL его нет. Это не время до пикселя и не память всего приложения.

| Вход | До → после, мс (серия 1; повтор) | Пик одновременной выборки PSS тестового хоста + расширения, МиБ (серия 1; повтор) |
| --- | --- | --- |
| 114 Б без URL | 0,033 → 0,026; 0,033 → 0,023 | 3,88 → 3,68; 3,90 → 3,61 |
| 144 Б с URL | 0,038 → 0,038; 0,037 → 0,038 | 3,93 → 3,88; 3,95 → 3,98 |
| 53 762 Б без URL | **10,29 → 0,74; 8,05 → 0,48** | **8,08 → 4,36; 8,13 → 4,35** |
| 53 784 Б с URL | 9,86 → 9,87; 7,85 → 8,17 | 8,12 → 8,17; 7,98 → 8,03 |
| 860 162 Б без URL, стресс | 545,20 → 12,06; 470,36 → 9,33 | 66,91 → 14,64; 66,96 → 14,37 |

**Что включено.** Оба release-расширения работали с одним бинарником хоста. Исходящий типизированный запрос готов заранее. Таймер начинается перед штатным `Process::send` (кодирование, лимиты, очередь, запись в pipe), проходит обработку расширением, [чтение кадра и разбор входящего сообщения](https://github.com/Proteus-harness/Proteus-desktop/blob/210cc9f274ffe40533b390a0d9e940f251a9fa22/src/declarative/process.rs#L255-L288), [проверку дерева](https://github.com/Proteus-harness/Proteus-desktop/blob/210cc9f274ffe40533b390a0d9e940f251a9fa22/src/declarative/protocol.rs#L275-L305) и заканчивается после получения `Signals::recv` и сверки view/revision/session в потребителе. Хеш полученного rich-text HTML и отсутствие inline-слотов проверялись уже вне таймера и совпали для обеих версий. Не включены создание Chat/DTO, GPUI, подготовка HTML на стороне UI, compositor, реальный Core/сессия или модель.

В каждой серии восемь чередующихся пар свежих процессов, внутри каждой один прогрев и 12 измеряемых запросов для 53 КБ (96 коротких, 2 стрессовых). Сначала медиана запросов, затем медиана процессов. Оба процесса закреплены за CPU 8 на общем Linux-хосте; это не полностью изолированное ядро. Две независимые серии показывают разброс, а не доверительный интервал. [Сырые итоги](results.json), [повтор](repeat.json).

**Память измерялась отдельно** четырьмя парами, также после прогрева. Один проход считывал `Pss` из `/proc/<pid>/smaps_rollup` сначала тестового хоста, затем его единственного прямого дочернего процесса; сверяли путь образа дочернего процесса. Для каждого запуска брали максимум **сумм в одном проходе**, а потом медиану максимумов. Это не сумма пиков за разные моменты и не точный непрерывный максимум: чтения последовательны, между ними процесс продолжает работать. Частота около 1 мс плюс время чтения, поэтому короткий всплеск, особенно в быстрой версии, мог не попасть в выборку. В JSON сохранены число выборок, состав пары в её пике, стартовое и конечное состояния. Память ядра, GPU, Core, интерфейса и наблюдателя не складывали. Для реального Desktop те же резидентные страницы и библиотеки делятся с другими процессами: переносить полученные абсолютные величины нельзя.

### Маршрут и границы

1. [Строка пользователя](https://github.com/Proteus-harness/Proteus-desktop/blob/210cc9f274ffe40533b390a0d9e940f251a9fa22/src/ui/chat/thread.rs#L189-L222) идёт в `text/plain`; ответ ассистента идёт в `text/markdown` и этой оптимизации не получает. [Выбор](https://github.com/Proteus-harness/Proteus-desktop/blob/210cc9f274ffe40533b390a0d9e940f251a9fa22/src/ui/extensions/declarative/content.rs#L46-L62) делает первый включённый установленный обработчик формата. Штатный [markdown-render](https://github.com/Proteus-harness/Proteus-desktop-extensions/blob/a35cea08be83ee8e5ecbfce9ef5050a1c00eb247/packages/markdown-render/extension.json) зарегистрирован для обоих, а [по умолчанию](https://github.com/Proteus-harness/Proteus-desktop/blob/210cc9f274ffe40533b390a0d9e940f251a9fa22/src/preferences.rs#L457-L490) отключён только analysis. При отсутствии обработчика Desktop оставляет SelectableText; при другом первом обработчике #215 неприменим.
2. [Replies](https://github.com/Proteus-harness/Proteus-desktop/blob/210cc9f274ffe40533b390a0d9e940f251a9fa22/src/ui/chat/replies.rs#L46-L97) для нового body передаёт весь `entry.text`. Неизменённый retained row переиспользует entity, не запускает парсер заново на каждом кадре. Даже при новом Arc с равным содержимым [updated_content](https://github.com/Proteus-harness/Proteus-desktop/blob/210cc9f274ffe40533b390a0d9e940f251a9fa22/src/ui/extensions/declarative/content.rs#L86-L103) может подавить повторную отправку. [Окно истории](https://github.com/Proteus-harness/Proteus-desktop/blob/210cc9f274ffe40533b390a0d9e940f251a9fa22/src/ui/chat/history.rs#L16-L18) номинально 200 строк/8 МиБ, [не режет отдельную большую строку](https://github.com/Proteus-harness/Proteus-desktop/blob/210cc9f274ffe40533b390a0d9e940f251a9fa22/src/ui/chat/history.rs#L66-L81). После замены набора [исчезнувшие ключи удаляются](https://github.com/Proteus-harness/Proteus-desktop/blob/210cc9f274ffe40533b390a0d9e940f251a9fa22/src/ui/chat/pump.rs#L265-L279); повторное открытие может потребовать рендер. [Runtime](https://github.com/Proteus-harness/Proteus-desktop/blob/210cc9f274ffe40533b390a0d9e940f251a9fa22/src/ui/extensions/declarative/mod.rs#L240-L272) локализован по владельцу и расширению, а [bound chat](https://github.com/Proteus-harness/Proteus-desktop/blob/210cc9f274ffe40533b390a0d9e940f251a9fa22/src/ui/extensions/host.rs#L141-L167) не закрепляет процесс бессрочно за workspace. При нехватке обязательных server/workspace [процесс может ещё не стартовать](https://github.com/Proteus-harness/Proteus-desktop/blob/210cc9f274ffe40533b390a0d9e940f251a9fa22/src/ui/extensions/declarative/runtime.rs#L222-L252). Быстрые замены допускают [одну выполняющуюся и одну последнюю ревизию](https://github.com/Proteus-harness/Proteus-desktop/blob/210cc9f274ffe40533b390a0d9e940f251a9fa22/src/ui/extensions/declarative/runtime/content_queue.rs#L10-L42); это не очередь всех отрисовок.
3. [32 КиБ](https://github.com/Proteus-harness/Proteus-desktop/blob/210cc9f274ffe40533b390a0d9e940f251a9fa22/src/declarative/widget.rs#L605-L621) относится к каждому вложенному inline-source (максимум 256), не к HTML всего rich_text. Здесь inline-слотов ноль. Предел [одного кадра транспорта](https://github.com/Proteus-harness/Proteus-desktop/blob/210cc9f274ffe40533b390a0d9e940f251a9fa22/src/declarative/process/io.rs#L11-L42) 16 МиБ, плюс совокупные лимиты; для больших данных важен размер **закодированного JSON**, не одна длина исходника. Все пять входов действительно прошли. В присутствии даже одного `://` (необязательно настоящей ссылки) #215 оставляет прежний парсер и границы выделения URL.
4. [Пока новое представление не готово](https://github.com/Proteus-harness/Proteus-desktop/blob/210cc9f274ffe40533b390a0d9e940f251a9fa22/src/ui/extensions/declarative/content.rs#L303-L354), body может показывать исходный SelectableText. Только после [сверки session](https://github.com/Proteus-harness/Proteus-desktop/blob/210cc9f274ffe40533b390a0d9e940f251a9fa22/src/ui/extensions/declarative/runtime.rs#L511-L551), [ревизии и последовательности](https://github.com/Proteus-harness/Proteus-desktop/blob/210cc9f274ffe40533b390a0d9e940f251a9fa22/src/ui/extensions/declarative/view.rs#L169-L180), [prepare](https://github.com/Proteus-harness/Proteus-desktop/blob/210cc9f274ffe40533b390a0d9e940f251a9fa22/src/ui/extensions/declarative/view.rs#L264-L315) начинается/переиспользуется [TextViewState::html](https://github.com/Proteus-harness/Proteus-desktop/blob/210cc9f274ffe40533b390a0d9e940f251a9fa22/src/ui/extensions/declarative/rich_text.rs#L16-L44). Предел синхронной полной замены **4 096 байт HTML**; более длинный HTML [разбирается фоновым заданием](https://github.com/Proteus-harness/Proteus-desktop/blob/210cc9f274ffe40533b390a0d9e940f251a9fa22/vendor/gpui-base/src/text/state.rs#L531-L564). У `is_ready` [остаётся true для предыдущей разметки](https://github.com/Proteus-harness/Proteus-desktop/blob/210cc9f274ffe40533b390a0d9e940f251a9fa22/vendor/gpui-base/src/text/state.rs#L272-L283), пока готовится замена, и true возможно при ошибке. ACK, готовность или первый доступный исходник не являются подтверждением показа текущей rich-ревизии.
5. Для настоящего визуального сравнения отдельно отмечать: поступление конкретной пользовательской строки, первый представленный кадр с читаемым исходником, подтверждённый коммит нативного HTML соответствующей ревизии без ошибки, первый представленный кадр с этой rich-ревизией. На уже открытом view привязывать все метки к ID/revision; на свежем view — не смешивать времена старта процесса/хоста с warm-циклом. Считывание пикселей вести отдельной серией от PSS-трассировки; одинаковая картинка plain и rich без URL не различает эти стадии, нужен счётчик кадра/маркер режима. Встроенный [scrollbar visual fixture](https://github.com/Proteus-harness/Proteus-desktop/blob/210cc9f274ffe40533b390a0d9e940f251a9fa22/src/ui/chat/scroller/scrollbar/context_tests.rs#L86-L105) намеренно **выключает** text/plain: сам по себе он не проверяет расширение. В этом отчёте GUI не запускали.

### Как повторить

Нужны Linux, Rust 1.95, исходники Desktop на `210cc9f`, каталог закреплённого crates.io `gpui-kit-assets-0.8.1`, локальный кеш Cargo и обе подготовленные полные рабочие копии Extensions с release-бинарниками в `packages/<id>/bin`. В одной на `a35cea0` нет функциональных изменений, во второй применены [четыре строки #215](https://github.com/Qweasd123tg/proteus-modules-dot/blob/f0fed4b9f62f668cdf54646edc1061d41f2f6fb2/proposals/2026-11-18/runtime-cost-second-pass/plain-text/plain-links.patch). Выполнять в каталоге этого отчёта; `B` — несуществующий локальный каталог сборки.

```sh
python3 prepare.py "$DESKTOP" "$GPUI_KIT_ASSETS" "$B"
python3 prepare_gate.py "$DESKTOP" "$B"
cargo build --manifest-path "$B/Cargo.toml" --target-dir "$B/target" --release --locked --offline
for ext in "$EXT_BASE" "$EXT_AFTER"; do
  PROTEUS_TEST_EXTENSIONS_SOURCE="$ext" "$B/target/release/stock_gate"
done
python3 run.py "$B/target/release/desktop-transport-probe" "$EXT_BASE/packages" "$EXT_AFTER/packages"
```

[Сверены 14 оригинальных blob модулей транспорта, протокола, манифеста и валидатора](blobs.json); Cargo использует клиентский contracts pin `105f825`, не shipping-ревизию сервера. В headless-обвязке нет UI: проверка имён иконок использует тот же набор имён файлов из `gpui-kit-assets` вместо графического enum; тип места badge вырезан из исходников, а ненужный поиск пользовательского каталога не выполняется. В измеренном пути plain rich_text запросов иконок не было. Запущено [неизменённое тело штатного теста](https://github.com/Proteus-harness/Proteus-desktop/blob/210cc9f274ffe40533b390a0d9e940f251a9fa22/src/declarative/protocol.rs#L475-L519) для обеих поставок: обнаружение 14 пакетов без ошибок, настоящий `tests/wire.py --wire`, разбор и проверка неизвестных узлов. Отдельно разобраны обе сохранённые идентичные трассы по 173 сообщения, SHA-256 `0b4f227a307137a6fe43e0ecc85b8a17a9c454bf84c337c6ca3a953155a0848b`. Это не запуск штатного test target полной сборки Desktop.

После приведения обвязки к читаемому виду повторена вся серия: [метрики и хеши использованных ELF](formatted.json). На 53 762 Б: 8,37→0,46 мс, однопроходный суммарный PSS 8,12→4,42 МиБ. С URL: 8,17→8,48 мс. Исходная версия хоста для первых двух серий сохранена в [main.measured.rs](main.measured.rs); в третьей серии использован [main.rs](main.rs). Обе версии прошли разбор сохранённых штатных трасс.

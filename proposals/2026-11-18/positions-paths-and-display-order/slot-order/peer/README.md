# Независимая проверка публичных рендереров слотов

Core c2cbadee518788f306ffb2b5271036b2658ea8cc. Сравниваются обычные синтетические сериализованные снимки в памяти. Поле `SlotTopology.order` документировано как порядок отображения; `TopologySnapshot.slots` есть публичный `Vec`, а оба рендера публично экспортированы в `core/mod.rs`. Сборщик Core уже сортирует слоты по (order,id). Не воспроизведено изменение в штатном CLI при обычном сборе данных: это расхождение двух разделов отчёта и двух представлений одного корректного, но не отсортированного входного DTO.

Перебираются все перестановки до четырёх заведомо разных id (включая японский текст), все подмножества активных значений, четыре назначения весов, включая равные, ноль и u32::MAX. Независимый эталон строит возрастающие корзины в BTreeMap и сохраняет порядок входа внутри корзины, не использует helper рендера. Нативно исполняются существующие serde DTO (внешний отсутствующий owner объявлен заглушкой: tools пуст), весь Map, plain Table, Markdown и helpers. Вызов секции runtime подменён фиксированным текстом. Никакой сборщик конфигурации/CLI/файловые профили не вызываются.

На **1772 снимках** до правки 1160 Markdown-таблиц и 501 plain-таблица расходятся с ожидаемым порядком; после 0 и 0. Порядок в отдельной и встроенной карте сохранён, как и фильтр active только для plain Table; fixture включает 1264 входа с совпадающими весами. На 612 уже упорядоченных снимках **оба полных вывода относительно заглушки побайтно прежние**. Вход при форматировании не изменяется.

Исходный patch `bc6f2306ab783d01227a87c0cf971c3182f9d7622731de9fe1e580763ce2746d` для чистого Core. Если применён #192 streamed table, вместо него выбрать **только** `slot-display-order-after-streamed-table.patch` (`eb24fc29677839c85e73b4fe34ea004335efaaf4ac40d3bed098b9a628f58d76`), поскольку в оригинальных патчах расходится контекст импорта. Наш дополнительный вариант сохраняет оптимизацию #192. Проверены прямое и обратное применение на соответствующих исходниках и повторён тот же нативный перебор: результаты в result-after192.txt. Предыдущие #188 Markdown code spans и #203 line endings по отдельности совместимы с исходным вариантом в обоих порядках. #185 меняет обработку висячих узлов/обрезки карты, не порядок слотов. Оба новых вызова имеющегося ordered_slots строят временный вектор ссылок и стабильно сортируют; это изменение корректности, не оптимизация.

`python3 run.py BEFORE_CHECKOUT AFTER_CHECKOUT RUSTC SERDE_DEPS_DIR`. Нужны доступные компилятору rlib serde с derive и serde_json. Никакая полная сборка проекта не запускается. Минимальные базы должны содержать в BEFORE закреплённые файлы публичного DTO, table, markdown, map и helpers, а в AFTER — table и markdown.

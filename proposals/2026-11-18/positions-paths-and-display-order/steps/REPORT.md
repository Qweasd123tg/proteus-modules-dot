# Do not commit a pending step from an earlier option list

**Candidate** (Desktop only): `steps-current-options.patch`, SHA-256 `2177673fb53fa3032a4ecc7aca63c4650233a85e1e7a3c6d27c49e209dfa38ab`. Fixes the specific ordering **pointer already down → same Steps control receives a changed list of labels → release**. It leaves an ordinary change of externally selected index alone. No change to the public protocol.

**Why it matters.** The shipped Model popup renders `steps` with stable ID `reasoning` and action `effort`; two or more available effort choices keep that control present. [It derives its option names anew on every popup render](https://github.com/Proteus-harness/Proteus-desktop-extensions/blob/ef064381d2194d95faef2b85f6cc3a1c34c6b975/packages/model/src/popup.rs#L21-L49), [in incoming order, deduplicated by value](https://github.com/Proteus-harness/Proteus-desktop-extensions/blob/ef064381d2194d95faef2b85f6cc3a1c34c6b975/packages/model/src/settings.rs#L37-L54). [The receiver interprets the index against the then-current list](https://github.com/Proteus-harness/Proteus-desktop-extensions/blob/ef064381d2194d95faef2b85f6cc3a1c34c6b975/packages/model/src/main.rs#L99-L109), ignores an out-of-range index and skips resubmitting the current effort. This is not a model change. [The public contract](https://github.com/Proteus-harness/Proteus-desktop-extensions/blob/ef064381d2194d95faef2b85f6cc3a1c34c6b975/PROTOCOL.md#L478-L484) specifies a numeric index, unlike Picker’s JSON value. [The Desktop schema](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/declarative/widget.rs#L701-L708) allows both roots.

The actual [refresh branch](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/ui/extensions/declarative/view.rs#L595-L620) retained `scrub`. The control [clamps it for the caption but sends it verbatim on release](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/ui/extensions/declarative/steps.rs#L46-L74). Source links for [pointer move/press and both releases](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/ui/extensions/declarative/steps.rs#L130-L170) and the [stock surface](https://github.com/Proteus-harness/Proteus-desktop-extensions/blob/ef064381d2194d95faef2b85f6cc3a1c34c6b975/packages/model/src/main.rs#L32-L35).

| Already pressed | List on release | Old action (inert recorded result) | New result |
|---|---|---|---|
| Maximum in Low, Medium, High, Maximum | Low, High; externally selected Low | Caption High, sends 3; stock lookup returns none | Caption Low; no action |
| Medium in same initial list | Maximum, High, Medium, Low; externally selected Low | Caption High, sends 1; stock lookup resolves High rather than the original Medium | Caption Low; no action |

736 synthetic native sequences. In the 608 changed-list cases, the old release always emitted an action derived from the old gesture; after the candidate, zero. This count measures the explicit *do not commit the interrupted gesture* rule, not 608 incorrectly persisted settings. All 128 identical-list/selected-only cases and all 736 subsequent fresh click + keyboard controls remained correct. Exact in-patch unit test passed in the isolated harness. rustfmt check passed on both changed source files. See `checks/native.log`. Run `python3 checks/replay.py BEFORE AFTER EXTENSIONS_TREE RUSTC DEPS`; it compiles the real option producer, index lookup, gesture methods, cursor projection, track geometry and retained update, with inert local adapters for render/request/callback state. No actual provider, filesystem data, settings write or application launch; not full cargo or UI automation.

**Boundaries.** We established a supported producer of both layouts and the exact consumer ordering, not observed timing or frequency of an external option refresh between mouse-down and release in a live window. A late *new mouse-down* from an obsolete painted frame after synchronization was not established; the fix does not tag frames and does not claim to block it. Desktop receives labels, not semantic values: a change in underlying values that leaves the complete displayed list identical is unobservable, especially with duplicated labels explicitly supported by [the producer tests](https://github.com/Proteus-harness/Proteus-desktop-extensions/blob/ef064381d2194d95faef2b85f6cc3a1c34c6b975/packages/model/src/tests.rs#L174-L183). We do not remap by name or claim end-to-end freshness across later receiver changes. When the control disappears, [the state map prunes the ID](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/ui/extensions/declarative/fields.rs#L175-L181); reappearance creates a new Stepper. The candidate specifically covers a surviving ID. Checked PR #1–207 titles/bodies for stepper/scrub/effort; no matching proposal.

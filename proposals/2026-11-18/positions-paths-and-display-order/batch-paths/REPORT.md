# В раскрытой карточке штатного read_many_files показать запрошенные файлы

При аргументах `{"paths":["README.md","src/lib.rs","docs/guide.md"]}` заголовок карточки в Desktop показывает «README.md +2». Но даже после раскрытия пользователь не видит имён двух остальных файлов в **разделе аргументов**: целый ключ считается уже показанным, а полный текст карточка строит только для скалярной строки. Если других аргументов нет, этот раздел пуст. Мы не утверждаем, что пути исчезают из самих аргументов или что их никогда нельзя найти в выводе инструмента.

Это не предположение о стороннем авторе. В [официальной декларации из Modules](https://github.com/Proteus-harness/Proteus-modules/blob/0fe8e3b4dfb64ca2e07df8af016d7ccc3a7de45f/tool/file-tools/src/read_many.rs#L24-L64) read_many_files требует массив строк paths; в описании указан максимум 20 файлов, но JSON Schema не выставляет maxItems. Мы взяли именно этот статический дескриптор. Он десериализован **реальным публичным Core ToolSpec** и обратно без потери ни одного значения JSON (не запуск и не регистрация модуля). Затем проверены чистые [классификация и заголовок](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/tool_display/mod.rs#L35-L49), [фильтр остальных аргументов](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/tool_display/mod.rs#L106-L125) и [ветвь раскрытой формы](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/ui/chat/tool_row.rs#L401-L445) на синтетических значениях. Статическое имя экспорта file_tools не подменяет имя пользовательского инструмента read_many_files.

**Кандидат: path-list-preview.patch**, SHA-256 `0b6274f2bf8b6dc65b3a1993327f70519b20f3a0e0276ec881bde1b596e58548`, к Desktop `2307e9c67125bbe66f15ced51317a2dfcc437aa4`. Источником классификации остаётся существующая таблица Desktop, в UI не добавляется вторая проверка имени инструмента. Только уже выбранная известная роль paths и массив из 2–20 строк получают отдельное, выделяемое текстовое представление при раскрытии. Одна строка на каждый путь: стандартная Rust Debug-запись сохраняет границы, кавычки и переводы строк внутри имени. Порядок, включая дубликаты, сохраняется. Названия любых других инструментов с общим fallback paths, произвольные аргументы/массивы и служебные ключи остаются без изменений. Это не новый блок «Копировать», не правка источника данных и не общее отображение JSON.

**Границы.** Для одного имени и для массивов длиннее 20 поведение здесь не меняется. До 20 строк при раскрытии, а не обычное 12-строчное начальное превью Fold; зато общий новый блок не превышает 2000 байт UTF-8. Эта ёмкость делится между путями поровну, и на каждом пути сохранено до 160 исходных Unicode-скаляров. Очень длинное имя получает закрытую кавычку и отдельное многоточие; используются только целые символы и их полные escape-последовательности. Короткое имя с неиспользованным бюджетом не передаёт остаток соседнему: даже если суммарно список мог бы вместиться, длинные соседи могут оказаться усечены. Если общий префикс длинен, видимые записи могут остаться неразличимыми. Заголовок и вывод инструмента не изменены. Ранняя версия без общей границы не рекомендуется.

**Проверка.** 114 нормальных списков (2–20 имён, 6 обычных вариантов), включая кириллицу, CJK, повтор, кавычки, пробел и встроенный LF: в текущей раскрытой карточке 0/114 содержат отдельные имена, после 114/114. Заголовки и посторонний параметр line_numbers остались прежними. Контрпримеры: пустой, одиночный, 21/1024 элемента, смешанные значения, чужое имя инструмента; обычная полная строка read_file сохранена. Реальная функция argument_details собрана с маленькими инертными построителями элементов: они фиксируют текстовые строки и переданный текст code_block, а не изображают запущенный GPUI. Независимый тест: 12 616 списков без перестановок, утраты строк и превышения лимита (6547 с явным усечением); 655 неприменимых форм без изменений. Для всех 1 112 064 Unicode-скаляров в начальной и средней позиции оценка экранирования нигде не занизила размер; максимальный измеренный блок 1999 байт, 20 строк. Не читал реальные сообщения и tool events, не вызывал tool, не открывал упомянутые в примере файлы и не использовал OS clipboard.

**Воспроизведение.** Обычные checkout или bare repositories чистых версий Modules/Core, а для изменения Desktop — рабочая копия после применения патча. `python3 checks/replay.py MODULES CORE DESKTOP SERDE_JSON_RLIB CORE_CONTRACTS_RLIB RUSTC --expect before` (или after). Совместимые библиотеки должны иметь каталог со своими transitive rlibs; не смешивать независимо скомпилированные serde_json. Нативный прогон: rustc 1.95.0, serde 1.0.228, serde_json 1.0.151. Применение вперёд, обратная проверка и rustfmt на новых чистых функциях прошли. Это не полная сборка Desktop и не проверка официального Cargo.lock.

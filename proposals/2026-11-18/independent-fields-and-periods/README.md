# Чужие состояния в формах и строки не того периода

**Четыре проверенных предложения, не изменения установленного Proteus.** Главные два: многострочная настройка и самостоятельный раздел расширения не должны открывать друг друга; фильтр «Последний ход» не должен учитывать запросы, про которые сама панель пишет «Вне хода».

## 1. Черновик заметки открывает посторонний раздел

Автор поместил в одну форму многострочное поле с ID `note` и отдельную секцию с ID `input-preview:note`. Это **разные публичные ID**; форма проходит исходную [валидацию схемы](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/declarative/widget.rs#L574-L605). Когда текст достаточно длинный для сворачиваемого предпросмотра, установить секции начальное состояние «открыта» было достаточно для раскрытия редактора. Нажатие заголовка редактора раскрывало или сворачивало и секцию. Удалённый, затем заново добавленный виджет мог получить чужое прежнее состояние.

Причина не в авторской разметке: [рендерер собирал внутренний строковый ключ](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/ui/extensions/declarative/fields/textarea.rs#L55-L105) в том же словаре, что и [публичные Disclosure](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/ui/extensions/declarative/fields.rs#L290-L301). [Предлагаемый патч](patches/textarea-preview-ownership.patch) хранит один флаг у самого поля. Не нужно резервировать префикс ID или отдельно добавлять технический ключ при очистке. Сохраняются ключ анимации и прежние условия мыши, клавиатуры и роста поля.

В [нативной проверке](checks/preview/probe.py) реальная схема разбирала JSON; фактические операции чтения, клика, изменения, обхода и удаления выполнялись над записывающим состоянием без окна. Из 3 072 трёхшаговых последовательностей с пересечением пространств имён **2 880** давали хотя бы одно неверное состояние до правки и **0** после. Ещё 3 072 последовательности с обычными ID остались правильными. Независимая [повторная проверка](checks/preview/peer.log): 148 неверных наблюдений из 224 → 0, включая возвращение сначала одного, затем другого виджета. Фокус, экранную геометрию и анимацию в настоящем окне не измеряли.

**Если уже применено [предложение о привязках ввода из #201](../retained-input-and-honest-presentation/patches/retained-input-bindings.patch):** эти самостоятельные diff затрагивают одни строки. Вместо обычного патча примените [версию поверх #201](compat/preview-after-bindings.patch), не оба файла. На этой комбинации повторены проверки и изоляции, и прежних обработчиков/минимума строк, включая сохранение двух независимых черновиков. [Результат перекрёстной проверки](checks/preview/peer-combined.log).

## 2. «Последний ход» включал запросы «Вне хода»

Даны две синтетические строки: у одной `turn_id: null`, у другой такого поля нет. У снимка нет ID последнего хода. В стандартной панели **«Последний ход»** получалось «Запросы: 2 из 2», обе карточки помечались **«Вне хода»**. Такой же результат выдавал «Весь чат». [Выборка](https://github.com/Proteus-harness/Proteus-desktop-extensions/blob/ef064381d2194d95faef2b85f6cc3a1c34c6b975/packages/usage/src/report.rs#L138-L164) считала отсутствие одного JSON-значения равным отсутствию другого.

[Предложение](patches/usage-latest-turn-scope.patch) при отсутствии непустого ID последнего хода оставляет этот период пустым. В том же примере «Последний ход» показывает «Запросы: 0 из 0» и «По этим фильтрам запросов нет»; «Весь чат» по-прежнему показывает обе строки. Ничего не удаляется, и последняя строка массива не объявляется последним ходом. [Проверка точных подписей](checks/usage/ux.log).

В 1 080 сочетаниях снимка, периода и модели исправлены 30 расхождений. Независимая сверка по идентичности и порядку строк: 604/864 → 864/864 при отсутствующем, null или пустом ID; без изменений 864/864 с непустым последним ID, 1 728/1 728 для «Весь чат» и 6 912/6 912 для явно выбранного хода. [Результаты](checks/usage/peer/result.txt). Это контролируемая проекция: наличие и частота таких комбинаций в реальных сессиях не измерялись.

## 3. Две строки «Ширина» без единиц измерения

В схеме модуля у «Экрана» одно дополнительное поле «Ширина», измеряемое в пикселях; у «Печати» тоже одно, но в миллиметрах. В форме видны две строки «Ширина» без обоих авторских заголовков и пояснений. Значения и технические ключи различны. Это допустимый **пример схемы**, не утверждение о составе поставляемого модуля.

[Построитель групп](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/ui/settings/group.rs#L25-L61) скрывал секционную подпись, если все поля дополнительные, а одиночное поле [сразу выводил обычной строкой](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/ui/settings/group.rs#L90-L112). [Патч](patches/advanced-section-header.patch) сохраняет отличительную подпись и пояснение, не вводя ещё одного раскрытия. Он не меняет поиск, действия полей и их адреса. Независимое ревью отклонило первый вариант: заголовок, отличающийся только краевыми пробелами, дублировался. В финальном варианте пробелы игнорируются **при сравнении**, исходный выводимый текст не переписывается. 4/868 → 0/868 неверных представлений; [независимо](checks/settings/peer/final.log) 22/1 008 → 0/1 008, прежние адреса всех полей и число кнопок сохранены. Сверялись структуры и надписи, не пиксели.

## 4. Перенос Windows добавлял фиктивную строку отчёта

В [Markdown-отчёте Core](https://github.com/Proteus-harness/Proteus-core/blob/c2cbadee518788f306ffb2b5271036b2658ea8cc/crates/proteus-core/src/core/topology_render/markdown.rs#L69-L106) между двумя строками описания заменялся только LF. С CRLF оставался отдельный CR. В проверенном GFM-парсере таблица с двумя инструментами превращалась в три строки: окончание описания становилось именем лишней строки.

[Патч](patches/markdown-cell-line-endings.patch) превращает каждый логический перевод строки (LF, CRLF или CR) в один пробел. На реальном парсере markdown-rs 1.0.0 исправлены 6/9 неверных таблиц; 6 561 контрольная строка без CR дала прежние байты. Добавленный Rust-тест падает до и проходит после. [Независимая проверка](checks/markdown/peer/result.txt): 24/28 → 0/28 неверных структур, включая данные в соседних столбцах и следующей строке. Результат относится к экспорту Core, а не к уже рассмотренным копированию или рисованию Markdown в Desktop. Не каждый парсер показывает дефект: Pandoc на простом примере его скрывает. Экранирование произвольного Markdown **не исправлено**: например, исходный обратный слеш перед вертикальной чертой всё ещё может породить лишний столбец.

## Что сознательно не опубликовано как исправление

- Переключение многострочного редактора в однострочный поиск с тем же ID ([открытый случай #201](../retained-input-and-honest-presentation/README.md)) не решается простой заменой компонента. Нативный однострочный ввод превращает `A\r\nБ` в `AБ`; прежнее байтовое выделение буквы Б больше не подходит. До выбора продуктовой политики автору безопаснее использовать разные ID, сохранить черновик в модели расширения **до** смены вида и явно задать текст нового поиска. Разные ID сами по себе черновик не переносят.
- В vendored DatePicker подтверждено несовпадение кнопки года и открываемого двадцатилетия. Найден потребитель в самом календарном наборе, но ни штатного экрана приложения, ни декларативного элемента расширения, который его использует. Не включаем это изменение как пользовательское исправление Proteus.

## Воспроизведение

[Общая проверка](checks/verify.py) ([протокол прогона](checks/result.txt)) читает закреплённые Git-объекты; всё изменение исходников происходит во временном каталоге. Четыре основных патча применены в прямом и обратном порядке, все шесть затронутых файлов после обратного применения побайтно совпали. Отдельно проверен стык с #201. Для повторения нужны Git, Python 3, Rust 1.95.0, локальные совместимые rlib для serde (с derive), serde_json и anyhow, markdown-rs 1.0.0 с зависимостями и локальный Cargo-кеш serde_json 1.0.151 для независимого теста.

```sh
python3 checks/verify.py \
  --desktop "$DESKTOP_GIT" --core "$CORE_GIT" --extensions "$EXTENSIONS_GIT" \
  --dot "$DOT_GIT" --deps "$RUST_DEPS" --markdown "$MD_RLIB"
```

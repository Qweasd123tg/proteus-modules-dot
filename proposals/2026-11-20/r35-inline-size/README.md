# Modules: проверить размер inline JSON без временного буфера

База: Proteus-harness/Proteus-modules `cf999371f6e564376565738bebc3416aad12f908`. Перед применением: `git apply --check <inline-size.patch>`. Независимый патч, в том числе от #246.

Декодер раньше строил компактный JSON в `Vec<u8>` только чтобы сравнить длину с лимитом. Теперь он отдаёт тому же сериализатору существующий счётчик байтов; условие, лимит, канонический результат и путь внешних payload не меняются. Добавлена проверка точного размера для Unicode, экранирования, чисел, повторного ключа и вложенных структур.

`cargo test` выбранного пакета: 60 unit + 2 process прошли, один ранее игнорируемый тест сохранён. На 909 записях синтетической истории с настоящим проходом кодека, по три раза в Debug и Release: 470 412 146 → 423 036 853 суммарно запрошенных Rust-аллокатором байт за проход, с одинаковым хешем канонического вывода. Это сокращение запрошенных аллокаций на 47 375 293 байта, не пиковый RSS и не ускорение открытия приложения.

SHA-256: `25976084beeaeeb084f6f2732245f16bcc149f86ee6e4dc047565fc737ae6178`.

Сырые счётчики: `allocations.csv`. Для повтора на двух чистых копиях базы (к одной применить патч) поместить `allocation_probe.rs` в `storage/session-storage/src/codec/` и добавить в `codec.rs` строки `#[cfg(test)]` и `mod allocation_probe;`. Передать путь к одному закрытому all-inline журналу schema 21 в `PROTEUS_CODEC_PROBE_JOURNAL` и запустить `cargo test --release --locked -p session-storage --lib measure_inline_decode_allocations -- --nocapture --test-threads=1`. Путь к пользовательским данным не требуется; подойдёт такой же синтетический журнал. Измеритель не меняет журнал.

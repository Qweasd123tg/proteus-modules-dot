# Can the cold route return a bounded page without building every row?

**Decision for this patch:** don't replace the general renderer. Its output is intrinsically mutable for supported inputs; the actual fix in this directory changes only the lifetime of the already finished window. A prospective forward-only path below is a separate, unbuilt experiment, not a claim about the current implementation or performance.

1. Limit the experiment to the cold Unix `/history/page` API with absent usable HEAD; `/history` intentionally returns every row. Factor the body of `project_sourced_read_model` so the streaming attempt and existing fallback share **one** `RemoteValidatedRead::open_for_display`, cursor and `RemoteJournalSnapshot`; don't invoke the old function anew and thereby capture a newer revision.
2. Strictly verify the immutable journal as today. From `RemoteJournalSnapshot::scan_display` certify every projected record: only `HistoryMutated`, no visible non-compaction Replace and every payload is ordinary Text. Initially reject every model/turn/tool/image/reasoning/hosted/citation record, non-text hidden parts included. Compaction Replace is not a regular reset: deduplicated retained parts stay in display, and fresh compactor-sourced parts are hidden exactly as today.
3. Two **local** staged passes are possible. First, certify shape and calculate exact count; using current `TranscriptReplay::render_record` plus `timestamps.collect_record::<false>` avoids a duplicate counting algorithm. Drain rows after each record and clear *all* row-position indexes (keep first-occurrence dates and seen-part identities); collect prefix identities and canonical history fingerprints during this pass. If a scan sees an unsupported kind, finish no publication, dispose of partial working state and invoke the general renderer on this same snapshot. Cost tradeoff: two full projection passes vs today's classify/render/prefix passes; avoid blowing replay traffic when staging is unavailable. Alternatively, use preflight/count that reuses the exact inclusion predicate; don't hand-maintain it twice.
4. Count gives exact `[start..end)` and `pack_before = total.saturating_sub(50)` **before** page writes. Split out the state machine behind `view/cache/pages::write_pages`: one owned leaf at the existing logical-row/encoded-byte cap; reuse `encoded_len`, `PageRef` hash, and `PendingPack::push/flush` unchanged. As second pass emits rows, feed page writer and retain only requested response. Clone only requested rows as necessary; never decode the entire cache to get the response. Verify final count matches the certified count. Unpreserved partial cache writes are disposable. Avoid a third tempfile if local staged input is available. If handling in blocks, bound by rows before moving into the producer; a large display record can still use large heap and even a single permitted row can be large.
5. Preserve cache publication ordering: write existing conversation, transcript/context/identity data, then named revision and HEAD only after the complete validated output. Keep tool index empty only because tools were certified absent. A stale but valid HEAD can require byte-level common-prefix comparison: fall back to the current code rather than manufacturing `base: None` for the next header. No writer lease or storage protocol change. Quota/full disk/failed WriteCache must still return the requested validated page; if a writer fails, discard that cache-builder state and keep reading until the same snapshot's window is complete.
6. Preflight and postflight must preserve existing wanted-revision checks. Always perform the final `SourceFingerprint::try_read(store)? == source` (session locator/incarnation, full revision and content digest) immediately before returning, including cache failure. Do not use computed rows or `ReadCache.source` as a freshness witness. Preserve bounds error precedence with a changed source. Do not return any response before validation passes complete.

**Gate, not promise:** stable page/leaf/pack layout vs legacy (ordinary packed display leaves exact, prefix encoding contains randomized HashSet order so compare decoded IDs, not nondeterministic certificate/document digests); latest, interior, first, empty, invalid position, pinned old post-append; cache failure halfway and final-witness race; repeated IDs across records, retained hidden/compactor occurrences, non-monotone timestamps, 49/50/51 and byte-split leaves; text followed late by reasoning/citation/tool/normal Replace must select the existing renderer, emit no speculative HEAD. Fixed-corpus A/B at the measured cold concurrency: tree and per-process PSS **plus live owned bytes**, active durable ACK, first token, page checks. O(history) exact identity sets and canonical model history remain. This is not a universal fixed-heap design.

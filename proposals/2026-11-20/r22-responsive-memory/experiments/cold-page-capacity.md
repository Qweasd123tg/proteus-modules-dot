# Холодная страница не должна владеть буфером всего архива

Core `048378da7cbe890d8bf8a0152e55eb28ecb5013d`, архив без индекса. После полного, строго сверенного replay выбирают 0–50 строк для HTTP. У `Vec::into_iter().skip(start).take(count).collect::<Vec<_>>()` один из вариантов оптимизации Rust сохраняет исходную аллокацию. Поля отброшенных строк (например, строки текста) к этому моменту уже уничтожены. Сохраняется именно непрерывный массив слотов `AppTranscriptMessage`, а не их содержание. Этот массив остаётся у page при передаче с blocking pool в async HTTP handler и до завершения сериализации JSON; не до окончания передачи по сети.

Узкая правка: `Vec::with_capacity(count)` и `extend` в отдельно выделенный буфер окна. Ничего не клонируется; источник, повторная сверка перед возвратом, cache hit, правила pinned revision, запись кеша, точный текст/роль/ID и целостность не меняются. База исходного кода R20 имеет ту же строку. В `crates/**/*.rs` Core, `src` и `crates` Desktop и Modules поиск аналогичной последовательности `into_iter/skip/[take]/collect` нашёл один этот путь; это не аудит всех адаптеров Vec.

## Изолированная проверка владения

Rust 1.95.0, x86_64 Linux, реальный тип из **workspace Core**, не тип из независимо собранного Modules worker. `vec_capacity_probe.rs` собирает 125 000 синтетических разных строк, чередует роли и проверяет порядковые ID/роль/текст каждого результата; обе ветки используют общий один итератор. Текущий размер слота 640 байт, входная capacity 131 072; результат `vec_capacity_probe.log`:

| Окно | Возврат stock: len / cap / байты массива | Отдельный буфер: len / cap / байты массива |
|---|---:|---:|
| последние 50 | 50 / 131072 / 83886080 | 50 / 50 / 32000 |
| 50 в середине | 50 / 131072 / 83886080 | 50 / 50 / 32000 |
| в позиции 0 | 0 / 131072 / 83886080 | 0 / 0 / 0 |

Это не 80 МиБ экономии максимального PSS. Полный вектор существует во время рендера, построения prefix, записи cache и заключительной сверки источника в обеих ветках. Освобождение аллокации не гарантирует возврат страниц ядру. Это исключение лишнего владения после сверки; обычный cache hit не затронут.

Пересобрать probe в workspace с уже построенными workspace Contracts и `rustc` подходящей версии:

```sh
D=/path/to/core/target/release/deps
rustc --edition=2024 -C opt-level=2 -C link-arg=-fuse-ld=lld \
  -Ldependency="$D" --extern proteus_contracts="$D/libproteus_contracts-<exact_core_fingerprint>.rlib" \
  vec_capacity_probe.rs -o vec_capacity_probe
./vec_capacity_probe
```

`cold-page-capacity.patch` включает три случая на реальном Core API, с недоступным кешем чтения и записи. Четыре существующих теста в том же модуле проверяют недоступную именованную ревизию при изменившемся источнике, ошибку источника при последней сверке, corrupt canonical и границы страниц. Для штатного запуска:

```sh
python3 scripts/test.py -p proteus-core --lib app_server::read_model::tests::
```

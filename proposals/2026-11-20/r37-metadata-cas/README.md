# ETag метаданных без второй сериализации значения

База: [Proteus-modules@9469e3b](https://github.com/Proteus-harness/Proteus-modules/commit/9469e3b12529d08b1f4a76882693e2065e842c51), Core SDK «0c1b757». Изменён только storage/session-storage/src/metadata.rs, включая тест совместимости. SHA-256 source.patch: ebb23f1b3628c2fab4037556cb1688487057929e5364424bcc88f5bfe4450f8d.

При новой записи CompareExchangeMetadata со значением хранилище строило два одинаковых JSON-буфера самого значения и дополнительно соединяло UUID и JSON во временном векторе. Теперь буфер, который нужен для файла, служит входом и для вычисления ETag: SHA-256 получает 16 исходных байт UUID и затем точные JSON-байты. Хеш имени файла по-прежнему считается только от JSON. Хеш запроса с ключом и ожидаемым ETag остался отдельным, как и проверка ранее сохранённых receipts. Tombstone, импорт старых файлов, проверка размера, коллизий, повторов и atomic replace не менялись. Чтение журнала, его валидация и проверка префикса здесь не затрагиваются.

## Проверенные затраты

Весь вызов внутреннего metadata::compare_exchange с настоящими файлами и синхронной записью, без создания входного JSON, проверки ответа и последующего чтения тестом. Локальный счётчик Rust-аллокаций суммирует запрошенные размеры alloc/alloc_zeroed/realloc. После одного прогрева выполнено по три итерации на размер и сценарий; внутри каждой пары одни и те же значения, UUID и ключи. Размер в таблице относится к сериализованной JSON-строке, включая кавычки.

| Размер JSON | Новая запись, запрошено байт: до → после | Новая операция с уже существующим объектом: до → после | Повтор ранее выполненной операции: до = после |
|---:|---:|---:|---:|
| 64 байта | 5 900 → 5 676 | 9 468 → 9 244 | 4 967 |
| 64 КиБ | 661 238 → 398 937 | 1 253 984 → 991 683 | 528 983 |
| 1 МиБ (предел документа) | 10 491 638 → 6 297 177 | 19 931 744 → 15 737 283 | 8 393 303 |

При 1 МиБ новый объект потребовал 147 вместо 152 вызовов аллокатора, суммарно на 4 194 461 запрошенный байт меньше. Это не снижение peak RSS на 4 МиБ и не измерение времени запуска Desktop. Хеш запроса, холодное чтение и разбор метаданных, синхронизация диска и транспорт по-прежнему стоят своих ресурсов. Частота крупных CAS в рабочих сессиях не измерялась.

## Проверки

* Все 27 пар в results.csv: совпали байты объекта и SHA-256 файла с метаданными/receipt после операции; проверен ETag независимо через конкатенацию исходных байт. Результат повторного запроса совпадает с первым. Конфликт содержимого для того же operation ID, неверный ожидаемый ETag, изменённый существующий объект, изменённый объект при повторе и размер на один байт выше предела дают ошибки.
* Постоянный тест фиксирует два известных ETag для двух UUID и одного JSON с Unicode и escape-последовательностями; оба ссылаются на один файл с известным SHA-256. Существующие тесты также покрывают tombstone, восстановление, потерю ACK, внешние blobs и изменения обеих сторон journal prefix.
* Независимый rustc 1.95.0 собрал исходный и изменённый crate с теми же rlib зависимостей (Core pin проверен), не используя готовый бинарник библиотеки. Ветвь базы: 64 теста прошли с учётом измерительного, 1 ручной тест пропущен; кандидат: 65 прошли с учётом измерительного, 1 пропущен. Для процессного прогона библиотека, worker и штатный integration test связаны заново **без** измерительного модуля: оба теста прошли на этом worker. cargo fmt --all --check и git diff --check прошли. Тот же worker установлен через штатную функцию package.install в изолированный временный runtime: SHA файла совпал с manifest, --version вернул 0.1.0-alpha.3. Весь workspace и release-производительность не проверялись.
* Патчи SQLite borrowed BLOB, проверки размера inline JSONL, форматирования SHA и borrowed JSONL framing затрагивают другие места. Отдельно проверено наложение полного стека в таком порядке: SQLite, inline JSONL, hex-вариант поверх SQLite, JSONL framing, затем этот патч. Полный библиотечный прогон стека без измерителя приведён в stack-suite.log. Предыдущие предложения не нужны для применения этого патча.

Команда **bash verify.sh /path/to/Proteus-modules** воспроизводит A/B через обычный Cargo; нужен локальный checkout с исходным commit. Временный измеритель не входит в исходный патч. Полные пары счётчиков и обе контрольные суммы: results.csv.

# Релиз Desktop: освободить TAR каждого репозитория сразу после распаковки

В `scripts/release.py:source_archive` четыре временных несжатых TAR оставались на диске до конца упаковки общего `sources.tar.gz`. Одна строка освобождает каждый TAR после закрытия и успешной распаковки. Порядок репозиториев, `git archive … HEAD`, фильтр извлечения `data`, структура и способ сжатия итогового архива не меняются. При сбое очисткой по-прежнему занимается внешний `TemporaryDirectory`.

**На точных исходниках релиза:** максимум выделенных файловых блоков на границах этапов **131,9 → 77,8 МиБ (−41%)**. Посчитаны временные TAR, распакованные обычные файлы и конечный gzip. До начала сжатия оставалось **56 709 120 → 0 байт** несжатых копий. Метрика не включает исходные checkout, каталоги, inode и прочие накладные расходы ФС; это не замер RSS или скорости сборки.

Проверки:

- База Desktop `b6a7ec2d8d7e486c8aba01291aa8c89774c4cded`; Core `32e56ec`, Modules `9469e3b`, Extensions `892f627` взяты из её `repositories.json`. Два реальных экспорта: 4 453 записи в неизменном порядке, совпали имена, типы, размеры, режимы, владельцы, цели ссылок и SHA-256 содержимого каждого обычного файла. Временные метки и байтовое равенство gzip не проверялись.
- Синтетика: четыре локальных Git-репозитория по 4 МиБ. Экспортированы именно committed-байты; сохранены executable-бит и относительная ссылка; незакоммиченные, игнорируемые файлы и незакоммиченные правки не попали. При принудительной ошибке Git на четвёртом репозитории в обоих вариантах staging исчез, существующий выходной файл не изменился.
- Все **12** тестов `scripts/test_release.py` прошли на кандидате. `git apply --check` и `git diff --check` прошли. В самом проекте меняется только одна строка; все дополнительные файлы в этом каталоге относятся к измерению.
- Полные gates, сборки приложений/модулей, публикация релиза и CI не запускались. Для измерения читались Git-объекты: код из экспортируемых проектов не запускался.

**Повторить:** потребуются Python с поддержкой `tarfile.extractall(filter="data")` и Git. Здесь использованы Python 3.12.14 и Git 2.52.0. Из каталога с этим пакетом, с checkout нужных ревизий:

```sh
git -C "$DESKTOP" show b6a7ec2:scripts/release.py > baseline.py
git -C "$DESKTOP" apply --check "$PWD/source.patch"
git -C "$DESKTOP" apply "$PWD/source.patch"  # в отдельной рабочей копии
python3 -B probe.py baseline.py "$DESKTOP/scripts/release.py"
python3 -B probe.py baseline.py "$DESKTOP/scripts/release.py" --pinned "$DESKTOP" "$CORE" "$MODULES" "$EXTENSIONS"
(cd "$DESKTOP/scripts" && python3 -B -m unittest -v test_release)
```

`probe.py` использует только функцию `source_archive` из двух проверяемых файлов. Протоколы замеров: `measurements.json` (синтетика) и `pinned.json` (исходники релиза). Последовательность числа временных TAR после каждой распаковки, перед сжатием и после него: `1,2,3,4,4,4 → 1,1,1,1,0,0`.

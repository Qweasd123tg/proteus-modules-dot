# Оценка непрозрачного входа модели: передача без копии

Независимый Core-кандидат на `048378da7cbe890d8bf8a0152e55eb28ecb5013d`. Вызов `ModelService::estimate_input` держал весь запрос до ответа и отдавал адаптеру глубокую копию непрозрачных частей. Для проверки, какие оценки провайдер вправе вернуть, нужны только уникальные идентификаторы запрошенных opaque parts.

[Патч](estimate-ids.patch) проверяет запрос и сохраняет отдельное одноразовое множество ID перед передачей владения. Для одного результата ID удаляется из множества: повторный или неизвестный ID поэтому отклоняется; допустимы неполный, пустой результат и оценка в ноль токенов. Обе границы проверки (сервис и внешний процесс) остаются независимыми. Внешний адаптер по-прежнему сериализует весь запрос в wire `Value`, но не обязан держать исходный typed request, пока внешний процесс отвечает. Это **не** устранение копий протокола транспорта. Добавлен только Rust helper, не поле DTO, не новое разрешение, не кэш и не изменение протокола. Проверка запроса перед выбором отмены в BoundModel оставлена на прежнем месте.

| Один opaque payload | Успешная оценка, выделено байт до → после |
|---:|---:|
| 1 КиБ | 1 759 → 264 |
| 1 МиБ | 1 049 311 → 264 |
| 8 МиБ | 8 389 343 → 264 |

Для 8 МиБ, если адаптер вернул `Pending`, **первый poll** потребовал 8 389 071 → 244 байт. Процесс не обязан освобождать ту же память ОС. Счётчик суммирует размер запросов Rust-аллокатору, не учитывая исходный подготовленный буфер и создание внешнего future до poll; это не live heap/RSS, задержка или замер сериализации. Применимо только если выбранная конфигурация запрашивает input sizing, а не ко всем вызовам модели. Объём данных растёт в ширину одной части, не в количество частей.

Проба компилирует настоящий файл ModelService, использует соответствующий arm исходного crates/proteus-contracts и его существующий thread-local счётчик. Она проверяет исходный адрес **и содержимое** строки, выбранное состояние future и ошибки. При одинаковом содержимом в stock адрес у адаптера отличался от адреса входа, у кандидата совпал во всех семи вариантах. Проверены `Some` с нулём токенов, `Pending`, `None`, неизвестный и повторный ID; текстовая часть отклоняется до вызова адаптера. Это локальная синтетическая проверка без внешнего провайдера. [До](stock.txt), [после](candidate.txt), [сводка](results.json).

Воспроизведение с Rust/Cargo 1.95.0, Linux x86_64, lld и Python 3: `bash reproduce.sh /abs/Proteus-core /new/output`. Скрипт создаёт временный Cargo example только в новой копии, отдельно проверяет contracts и process fixture. Есть также средство независимого запуска к уже собранным точным Cargo dependencies: `python3 run-probe.py SRC DEBUG_DEPS OUT [REFERENCE_DEPS]`; последний аргумент — каталог с однозначными именами артефактов исходного arm, если в целевом каталоге есть результаты нескольких Cargo feature sets.

**Результат проверок кандидата:** [4 tests contracts](contract-gates.txt), [2 tests с независимым Python worker](process-gates.txt). Внешний адаптер передал точный запрос, обработал unsupported/None/нулевую оценку, отклонил неизвестные/повторные ID и невалидное число; отмена дошла до ожидающего процесса. Числа кандидата также дословно совпали при отдельной сборке пробы через Cargo example. Полный workspace suite и реальный провайдер не запускались. `cargo fmt --all -- --check`, `git diff --check` и `git apply --check` на точной базе прошли. Обе независимые production-правки этого раунда накладываются в любом порядке. Дополнительно собрана общая конфигурация с патчем из [#238](https://github.com/Qweasd123tg/proteus-modules-dot/pull/238). Все 26 целевых тестов прошли ([детали](combined-gates.txt)); полный workspace suite не запускался.

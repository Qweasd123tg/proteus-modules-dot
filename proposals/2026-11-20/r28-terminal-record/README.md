# R28: один семантический проход для последней записи JSONL

Компонент: `Proteus-harness/Proteus-modules`, база `cf999371f6e564376565738bebc3416aad12f908`. Кандидат `terminal-read.patch`, SHA-256 `a17f104f65cf2cf0fd5b72cb409943fe2126d3a7561d5f931b3de042131356de`. Локальное дерево Git после применения: `2dd8a69047dfedf8e046da394feee021dd43e400`. Нет изменений wire-контракта, флагов или формата хранения.

**Путь.** R24 при проверке settlement запрашивает `ReadRecords(after_seq=N−1,limit=1)`. Если descriptor ещё не был строго проверен, штатный worker подтверждает полный фиксированный префикс через семантический fold, перематывает fd и декодирует все N записей снова ради одной последней. На прогретом *уже строго проверенном* snapshot этого первого fold может не быть, поэтому не каждый запрос делает 2N.

Кандидат сохраняет в переменной текущего вызова только саму последнюю запись из незавершённого fold, без клона. После полного чтения, проверок EOF, SHA-256, семантики и ревизии вызывается существующая `confirm_verified_data`. Для JSONL она заново хеширует **весь закреплённый диапазон fd** и отказывает в быстром пути, если хотя бы одна запись ссылается на внешний payload. Только на стабильной известной версии источника подтверждённая запись попадает в штатные проверки размера и построение страницы. Внутри handle не появляется кеш последней записи. В случае дрейфа версии кандидат перепроверяет префикс и перечитывает обычным способом; source без версии (включая SQLite) сохраняет прежний маршрут.

**Операционный счётчик.** На неизменном inline-JSONL из 8 записей: штатный 16 декодирований, кандидат 8; ответ совпадает с отдельным handle, включая сами записи. Проверены limit=1/32, пустая следующая страница, повтор, перемотка; на SQLite остаётся 16. Счётчик fingerprint I/O совпадает с размером фиксированного журнала. Это не уменьшение физических чтений вдвое: полный второй hash-проход сделан намеренно, возможны чтения из page cache. Нет утверждения о latency без отдельного A/B.

**Инварианты.** Старый handle после append возвращает свою запись, а не новую; подмена ревизии handle, перезапись префикса/последней строки без изменения длины и truncation завершаются ошибкой. Отдельный тест дописывает байты через второй fd ровно на EOF валидации и проверяет правильную старую запись *и* обычный повторный проход. Пропавший внешний blob до терминала отвергается, в том числе при повторном запросе после восстановления и успешной проверки.

**Повтор.**
```sh
git apply --check terminal-read.patch && git apply terminal-read.patch
python3 scripts/test.py -p session-storage -p proteus-session-storage-module
cargo build --release --locked -p proteus-session-storage-module
```
В местном offline-кеше общий `cargo metadata` официального runner не разрешил нерелевантный для Linux пакет `android_system_properties v0.1.5`; точный альтернативный запуск Linux: `cargo test --offline --locked --jobs 1 -p session-storage -p proteus-session-storage-module -- --test-threads=2`. `red.log` — ожидаемое падение теста счётчика на базе (16 вместо 8); `tests-final.log` — прогон кандидата.

Проверено на финальном дереве: 63 unit-теста и 2 SDK process-теста прошли, 0 упали; 1 отдельный ручной perf-тест пропущен. Форматирование, git diff --check и git apply --check на исходной базе прошли.

Дополнительно: реальный R24 Core со штатным и финальным release worker прошёл одинаковые девять проверок холодного подключения: ошибки несовпадения конфигурации, содержимого и эффективных настроек, запрет второго writer, потеря текущего writer, изменение метаданных/настроек, следующий ход и отказ на устаревшей квитанции. Отдельно проверено изменение байтов журнала между двумя проверками Core при той же ревизии. Обе сборки обнаружили новый digest и отказали в повторном подключении со старой квитанцией. Эти результаты приводятся в `debug-*.json` и `gate-*.json`.

Скрипты внешних проверок используют `probe.py` и `fixture_workflow.py` из [R27](https://github.com/Qweasd123tg/proteus-modules-dot/pull/236). В `PROTEUS_R27_PROBE` укажите каталог с этими файлами, а в `R27_PROBE` полный путь к его `probe.py`. Нужно задать четыре бинарно-независимых переменных окружения из README R27: `PROTEUS_PEER_CLI`, `PROTEUS_TEST_SESSION_STORAGE_MODULE`, `PROTEUS_TEST_REFERENCE_MODULE`, `PROTEUS_EXAMPLE_MODULES`. Выполнить `python3 -B check_proof.py` и `python3 -B current_head_gate.py` (Linux).

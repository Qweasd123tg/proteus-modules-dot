# Выбор корней rg-search без попарного перебора

**База:** `Proteus-harness/Proteus-modules@9469e3b12529d08b1f4a76882693e2065e842c51`. Изменён только выбор корней перед запуском ripgrep; контракт, выражение поиска, постфильтрация и порядок выдачи сохранены.

После разрешения префиксов `starts_with` каталог мог оказаться корнем сам по себе и одновременно находиться внутри другого выбранного каталога. Прежде сравнивали каждую пару кандидатов, чтобы не передавать оба в rg. Уникальные пути уже упорядочены по компонентам: предок идёт перед своими потомками, а потомки образуют непрерывную группу. Поэтому достаточно сверить очередной путь с последним **оставленным** корнем. Для n ≥ 1 непересекающихся путей проверок `starts_with` теперь n−1 вместо n(n−1). Сортировка и проверки файловой системы по-прежнему выполняются; общая подготовка не стала линейной. Выбранные PathBuf перемещаются вместо клонирования. Общий корень `.` имеет прежний приоритет.

**Что именно замерено:** release-оптимизированная функция `search_roots` (с реальными проверками существующих каталогов на Linux, но без запуска rg и сканирования файлов). В каждом раунде оба варианта получают один и тот же набор существующих соседних директорий, с чередованием порядка; ниже медианы 7 раундов в общей среде, а не SLA.

| Число корней | До | После |
|---:|---:|---:|
| 0 | 82 нс | 53 нс |
| 1 | 1,86 мкс | 1,66 мкс |
| 16 | 75,9 мкс | 36,7 мкс |
| 128 | 2,80 мс | 0,203 мс |
| 512 | 43,3 мс | 0,871 мс |
| 2048 | 460 мс | 4,01 мс |

Доли миллисекунды на узких запросах зависят от окружения; больших end-to-end ускорений для обычного запроса с одним корнем не ожидаем. Сырые результаты: `roots.log`. Стенд берёт код обеих функций напрямую из исходников; маленький DTO предоставляет ровно два используемых поля. Для 14 336 комбинаций точные OS-строки аргументов и их порядок совпали (вложенность, похожие имена, пропавшие директории, нормализация, Unicode, повторы и общий корень). Случайные идентификаторы чанков не сравнивались: алгоритм предшествует их созданию.

Для повтора: взять checkout указанной базы, применить приложенный `source.patch`, запустить рядом лежащие `probe.py` и `probe.rs`:
```sh
python3 probe.py /path/to/patched/Proteus-modules 9469e3b12529d08b1f4a76882693e2065e842c51
```
При доступной общей Cargo metadata штатная команда проверок: `python3 scripts/test.py -p rg-search --lib --release`. Полный workspace, другие ОС и прикладная задержка поиска не проверялись.

Фактические целевые тесты Linux: 12 прошли, один ранее отмеченный ручной тест остался игнорируемым. Полный runner остановился до тестов из-за отсутствующей Android-зависимости в офлайн-кэше; crate проверен напрямую. SHA-256 патча: `ad41535a74a875e95a72c7f3727af69db0aa9c2dfc69fd11ceaad7a61f955b7e`.

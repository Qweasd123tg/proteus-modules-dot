# Proteus-core: не копировать всё сообщение ради превью сессии

**База:** `Proteus-harness/Proteus-core`, `048378da7cbe890d8bf8a0152e55eb28ecb5013d`. Применить `core-preview.patch`. Это код Core, который вычисляет сводку при полном построении удалённого представления и при публикации суффикса/подтверждённого хода. Правка каталога в модуле хранения [#241](https://github.com/Qweasd123tg/proteus-modules-dot/pull/241) этот путь не меняет. Патч применяется отдельно, без #241.

Раньше `remote::view::cache::summary` копировала весь выбранный текст, пересчитывала в нём все символы и затем возвращала короткую строку. Теперь она сначала делает прежний `trim` на заимствованном тексте, находит границу 160 Unicode scalar values, если она есть, и выделяет место только под результат. Те же первые 160 символов и те же три ASCII-точки, включая внутренний пробел на границе. Приоритет пользовательского сообщения, порядок частей, fallback на другую роль, значения статуса tool, проверка дескриптора и поля сводки не меняются. Никаких изменений DTO, cache/hash, storage или прав доступа.

**Измерено:** один процесс, точные тела старой и новой функций `summary`, реальные типы Core contracts, фиксированный in-memory ответ на `Describe`. Сравнение всего DTO между вариантами для каждой строки, вход создаётся до замера; аллокатор считает все запросы alloc/realloc, включая одинаковые накладные расходы дескриптора. Порядок ABBA; повторы и значения всех проходов в `allocations.csv`.

| Вход | Было: запросы / байты | Стало: запросы / байты |
|---|---:|---:|
| 64 байта ASCII | 6 / 104 | 6 / 104 |
| 1 МиБ ASCII | 9 / 1 049 256 | 6 / 203 |
| 16 МиБ ASCII | 9 / 16 777 896 | 6 / 203 |
| 1 МиБ Unicode (🦀) | 11 / 1 051 656 | 6 / 683 |
| 1 МиБ текстового вывода tool | 10 / 2 097 832 | 7 / 1 048 779 |
| 1 МиБ пробелов | 5 / 40 | 5 / 40 |

Эти числа не измеряют RSS, cold-open latency или длительность хода. `trim` может просмотреть длинные серии краевых пробелов. Канонический `ToolResult::text_or_status` по-прежнему может построить полную временную строку; не дублируем его правила рендера. Для обычного длинного текста только строка результата при ASCII-префиксе занимает 163 байта.

**Проверки:** 18/18 тестов Core `core::session_store::remote::view` на патче, включая два новых теста с 160/161 scalar, пробельными и приоритетными частями, tool fallback и полями дескриптора. Проверки `cargo fmt --all --check` и `git diff --check` прошли. Использован прямой запуск Cargo: штатный `scripts/test.py` остановился при подготовке несвязанных модульных fixtures, потому что в offline-кэше нет crate `cfg_aliases v0.1.1`; тесты remote view используют собственный backend. Workspace/desktop не собирались, upstream не изменён.

**Воспроизведение** из исходной копии Core на указанной базе (указать каталог файлов предложения; Rust 1.95.0):
```sh
git apply "$PROPOSAL/core-preview.patch"
cargo fmt --all --check && git diff --check
cargo test --locked -p proteus-core --lib core::session_store::remote::view
python3 "$PROPOSAL/probe.py" . "${CARGO_TARGET_DIR:-target}/debug/deps" "${TMPDIR:-/tmp}/preview-build"
```
Для probe нужны `rustc` из того же toolchain и ровно одна пара `proteus_contracts`/`anyhow` rlib в каталоге зависимостей. Для обычного запуска в подготовленной среде передать те же package/target штатному `scripts/test.py`.

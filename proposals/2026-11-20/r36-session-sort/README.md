# Desktop: не обходить дерево проекта при каждом сравнении в списке чатов

База: `Proteus-harness/Proteus-desktop` `b6a7ec2d8d7e486c8aba01291aa8c89774c4cded`. Для применения: `git apply --check source.patch`, затем `git apply source.patch`. Только `src/sessions.rs`; патч не меняет другие части Desktop.

Раньше стабильная сортировка заново пересчитывала время последнего изменения по всем видимым потомкам проекта при каждом сравнении. Теперь при трёх и более проектах ключ вычисляется один раз за сортировку. Для двух проектов остаётся одно прямое сравнение, для пустого списка и одного проекта времени сортировки и обхода потомков нет. Верхняя строка не требует стека; один временный стек потомков используется для всех корней проекта. Новых полей, постоянного кэша и загрузки истории нет.

Сортировка стабильна: при одинаковом максимальном времени проекты остаются в прежнем порядке первого появления. Поиск по-прежнему исключает несовпадающих потомков из расчёта времени, но учитывает включённых потомков любой глубины и папки. Отображение закреплённых и архивных строк, привязки родителей, порядок строк, обработка циклов, поиск и сохранённые отметки не изменены.

Счётчики одного запуска реального `SessionMarks::arrange` с уже созданными входными DTO, Linux x86_64, Rust 1.95.0. Запросы Rust-аллокатору включают `alloc`, `alloc_zeroed` и `realloc`:

| Каталог | Запросов до → после | Суммарно запрошено байт до → после |
|---|---:|---:|
| Один проект, 4 корня по 160 потомков | 3 234 → 3 234 | 348 084 → 348 084 |
| Два проекта, 3 корня по 2 потомка | 104 → 100 | 9 106 → 9 122 |
| 8 проектов, по одной строке, уже отсортированы | 61 → 48 | 3 256 → 3 272 |
| 48 проектов, по 8 корней без потомков | 5 374 → 1 327 | 182 576 → 150 960 |
| 32 проекта, по 4 корня и 16 потомков каждого | 11 599 → 8 704 | 943 728 → 886 704 |

В некоторых маленьких вариантах меньше запросов, но на 16–48 больше суммарно запрошенных байт; таблица не скрывает этот компромисс. Это не RSS, не время кадра, не время открытия каталога и не сквозной замер. Все 12 вариантов в `proof.log`.

Проверены 16 headless-тестов точных модулей на базе и 17 после правки. Новая проверка покрывает стабильность равных ключей, потомка из другой папки и пересортировку при поиске. 10 256 точных дифференциальных сравнений полных списков (все видимые данные, порядок, дерево, закреплённые, архив, его счётчик), разные поиски, тайтлы, Unicode, смешанные ключи, циклы и отсутствующие родители. См. `tests.log`. GPUI/GUI не собирался.

Воспроизведение: `bash verify.sh /путь/к/Proteus-desktop`. Скрипт использует временный checkout указанной базы, фактические исходники и отдельный Cargo-пакет без GPUI. Проект берёт сетевые зависимости Cargo при отсутствии кэша. Для замера сравниваются обе реализации в одном процессе (`probe.rs`).

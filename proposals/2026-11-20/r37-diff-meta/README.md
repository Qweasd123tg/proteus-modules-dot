# Desktop: линейное сопоставление метаданных большого diff

База: `Proteus-harness/Proteus-desktop` `b6a7ec2d8d7e486c8aba01291aa8c89774c4cded`. Патч меняет только headless-крейт `proteus-diff`. Применение в целевом checkout: `git apply --check source.patch`, затем `git apply source.patch`.

При открытии или обновлении diff клиент дополняет разобранные карточки данными `FileInfo`, в том числе если текст патча недоступен. Раньше каждая запись заново просматривала растущий список. Для 4 096 новых путей это 8 386 560 сравнений уже созданных карточек. Теперь при **более чем 128 записях** используется временный индекс путей: ожидаемое время сопоставления O(число блоков патча + число записей) при обычной стоимости сравнения и хеширования пути. Ключи заимствуются у входных метаданных, дополнительное место пропорционально числу различных путей в них. Индекс освобождается перед подготовкой строк, не включается в результат и не живёт между обновлениями. До порога остаётся прежний линейный поиск без таблицы.

Порядок блоков патча и порядок появления дополнительных карточек сохранён. Если несколько блоков носят одно имя, меняется только первый. Повторная метаинформация не создаёт новую карточку: побеждает последний непустой статус, а сообщение добавляется только в карточку без строк. Существующий контент и строки diff не переписываются.

**Изолированный замер:** настоящий публичный `proteus_diff::parse` и освобождение результата, Linux x86_64, Rust 1.95.0, `-O`, одна нить. Входы подготовлены заранее, обе версии в одном процессе, чередование порядка, медиана 11 серий после прогрева. Ниже время в миллисекундах в одном прогоне. В первом сценарии текстового патча нет, во втором каждому пути соответствует блок заголовка, метаданные даны в обратном порядке.

| Число записей | Только метаданные: до → после | Блоки и метаданные: до → после |
|---:|---:|---:|
| 1 | 0,000171 → 0,000176 | 0,000207 → 0,000220 |
| 128 | 0,0487 → 0,0466 | 0,0619 → 0,0612 |
| 129 | 0,0500 → 0,0377 | 0,0621 → 0,0573 |
| 256 | 0,1349 → 0,0804 | 0,1671 → 0,1101 |
| 1 024 | 1,482 → 0,280 | 1,572 → 0,416 |
| 4 096 | 22,303 → 1,287 | 22,052 → 1,949 |

Цена ускорения для 4 096 различных путей: дополнительно 12 запросов и 540 732 суммарно запрошенных байта у Rust-аллокатора; это не пик памяти и не RSS. До 128 записей включительно число и объём запросов совпали на измеренных сценариях. Ускорение малых списков не заявляется. Результаты не измеряют отрисовку окна, задержку GPUI или произвольный пользовательский репозиторий. Полные измерения в `timing.log` и `alloc.log`; замеры времени и аллокатора разнесены по разным сборкам.

**Проверка:** 13 тестов крейта на базе, 14 после патча, 15 при наложении поверх предложения №245 (пары строк). Проверка наложения выполнена в порядке «№245, затем этот патч» на указанной базе. 512 детерминированных смешанных сценариев сверяют все поля результата, включая полные патчи, статус, строки, координаты и пары; включены пустые, повторные и Unicode-пути, конфликтующие статусы и три размера возле порога. Дополнительно сверялся полный результат всех 20 сценариев измерений. Окно GPUI не запускалось.

**Воспроизведение:** `bash verify.sh /путь/к/Proteus-desktop [путь/к/diff-pairs.patch]`. Скрипт создаёт временную копию исходного коммита, выполняет `cargo test --locked -p proteus-diff --lib` и компилирует обе версии фактического крейта для сравнений. Передайте отдельный патч №245 вторым аргументом для совместной проверки. При заполненном Cargo-кэше можно задать `CARGO_NET_OFFLINE=true`.

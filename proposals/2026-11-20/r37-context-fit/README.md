# Context-pack: не ранжировать чанки, если все поместились

База: `Proteus-harness/Proteus-modules@9469e3b12529d08b1f4a76882693e2065e842c51`. Исходный commit исправления: `ead1762e0ae9927203fc3f4b0ade97e3e8ce1a2b`. Патч меняет только бюджет контекста для repo_aware/codex_context и добавляет тест со смешанными источниками, пустым чанком и многобайтным символом.

Когда все чанки помещаются в байтовый бюджет, изначальный порядок провайдеров уже является конечным порядком. Возвращаем тот же вектор; вместо распределения по двум коллекциям и двух сортировок нужен проход по длинам строк. Используется `checked_sub`: при первой нехватке места немедленно включается прежняя логика. Приоритет обязательных инструкций, ошибки переполнения, выбор целых чанков, приоритет оценки, порядок и DTO не меняются. Обработка JSON из провайдеров предшествует бюджетированию и не обходится. Все локально вычисленные оценки конечны; баллы стороннего поставщика проходят через `serde_json::from_str<Vec<ContextChunk>>` (`retrieval.rs::provider_chunks`); проверенный декодер отклонил NaN/«NaN», ±Infinity и ±1e100. Поэтому расхождение компаратора для Rust-only NaN не относится к допустимому входу. Перенос одного и того же входного вектора может сохранить ранее зарезервированную свободную ёмкость до сериализации результата; экономию RSS не заявляем.

**Результат.** 26/26 тестов реального crate, включая точную границу. 5650 дифференциальных сравнений полного DTO либо точного текста ошибки с неизменённой базовой функцией (разные наборы и оценки, нулевая длина, лимит от нуля до чуть выше суммы и usize::MAX). Дополнительно отдельный тест сравнивает допустимые крайние оценки для 21 бюджета. Форматирование workspace и `git diff --check` прошли. Из-за дискового лимита не запускались полная сборка, установка, интеграция клиента и полный turn: локально использован rustc с зависимостями из кеша от закреплённого Core `0c1b757`.

**Что измерено**: только функция отбора, на одном Linux-хосте; не весь сбор контекста. Реальный ContextChunk с 256 байтами текста, смешанными источниками, путями, метаданными и разными оценками. Создание/клонирование входа до таймера, сброс результата после таймера. Счётчик учитывает запросы alloc/alloc_zeroed/realloc и полный новый размер при realloc; это **не** пиковая или удерживаемая память. Медиана 101 пары после 4 разогревочных, порядок вариантов чередуется; время показано с включённым одинаковым счётчиком. Повтор в чистом архиве базы: `reproduced.log`.

**Повтор:** `python3 reproduce.py /path/to/Proteus-modules` при наличии указанной базы в истории, Rust 1.95, зависимостей Cargo и lld. Скрипт распакует чистый git archive во временную директорию, применит патч, скомпилирует обе реальные версии budget.rs как части одного теста и запустит проверки; исходный checkout не меняется. Стандартный вариант использует Cargo; также доступен режим `--cached-rustc FILE` с аргументами поиска и выбора уже собранных зависимостей, по одному аргументу в строке. Именно этим режимом проверен полный повтор на данном хосте. Для штатного CI модуля: `python3 scripts/test.py -p context-pack --lib`.

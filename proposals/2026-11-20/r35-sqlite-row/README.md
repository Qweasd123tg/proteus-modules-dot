# Modules: декодирование журнала из SQLite-строки без промежуточной копии

Исходная база: Proteus-harness/Proteus-modules `cf999371f6e564376565738bebc3416aad12f908`. Перед применением: `git apply --check <sqlite-row.patch>`. Независимый патч; здесь исходный репозиторий не меняется.

Десериализует запись из BLOB внутри времени жизни текущей строки SQLite, не копируя весь BLOB в отдельный Vec. Итоговая каноническая запись остаётся владеющей. Сканирование, содержимое записи и обработка ошибок проверены отдельно. JSONL не меняется.

В изолированном замере фактического `Snapshot::next` для записи с текстом 8 МиБ: 5 → 4 вызова аллокатора, 16 779 111 → 8 389 880 суммарно запрошенных байт. На остальных трёх размерах также исчезла одна копия закодированной записи, выход и SHA-256 совпали. Это не RSS и не скорость запуска. Целевые Cargo-тесты: 59 unit + 2 process прошли, один ручной тест остался игнорируемым. Общий runner был заблокирован отсутствующей офлайн-зависимостью.

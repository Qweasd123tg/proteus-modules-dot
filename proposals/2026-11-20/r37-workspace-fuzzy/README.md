# Core: не собирать строку запроса заново для каждого пути

База: `Proteus-harness/Proteus-core@32e56ecb4cc6da324c60dd6ae2da78f3b7e46e7f`. Изменена только реализация поиска путей для панели файлов (`/workspace/search`), не агентский инструмент поиска.

Раньше каждое слово запроса переводилось в нижний регистр, затем разбивалось на `Vec<char>`. При оценке очередного пути слово снова собиралось в UTF-8-строку. Теперь остаётся исходная нормализованная строка: точное совпадение, префикс и подстрока проверяются по ссылке, а для нечёткого совпадения используется её итератор Unicode-символов. Нового кэша нет. Выбор кандидатов Git/обходом, игнорируемые и удалённые пути, лимиты, правила начисления баллов и сортировка остались прежними.

**Замер на Linux, Rust 1.95.0:** реальный вызов `search()` по одной директории с 4096 сгенерированными файлами и небольшими служебными записями; сначала без Git, затем с Git. В каждом режиме восемь запросов, порядок сравнений ABBA. Счётчик охватывает запросы alloc/alloc_zeroed/realloc процесса поиска от входа в функцию до возврата, включая сбор кандидатов и сортировку; исключает подготовку входа, сериализацию результата и отдельный процесс Git.

| Сценарий | Запросы к аллокатору, до → после | Запрошенные байты, до → после |
|---|---:|---:|
| Git, три слова `source needle TXT` | 22 340 → 10 042 | 2 093 096 → 1 994 640 |
| Обход без Git, тот же запрос | 42 447 → 30 149 | 1 986 033 → 1 887 577 |
| Git, два слова `文件 ЖЯ` | 18 238 → 10 041 | 2 060 227 → 1 994 635 |
| Git, контроль без слов (прямой вызов helper) | 10 040 → 10 040 | 2 125 540 → 2 125 540 |

Это суммарно запрошенные байты, не RSS и не пиковая память. Снижение задержки интерфейса не измерялось. На каждый путь по-прежнему нужна строка в нижнем регистре.

**Проверка:** оптимизированная изолированная сборка двух версий реального модуля, реального Git-адаптера и зависимостей. Все 8 тестов прошли, включая тест Core для игнорируемых, удалённых, неотслеживаемых файлов и корня внутри репозитория. На 255 744 парах «запрос–путь» значение `Option<i64>` совпало; полные JSON-ответы двух версий совпали в 16 сценариях файловой системы. Граница 200 результатов, отсутствие совпадений, Unicode с расширением при смене регистра и смешанные запросы проверены. `cargo fmt --all --check` и `git diff --check` прошли. Полный Cargo workspace, маршрут HTTP целиком и сборка готовой поставки в этом проходе не запускались.

Воспроизведение из checkout базы (стенд: Linux, Git, rustc 1.95.0, lld, совместимые собранные Rust-зависимости в одном каталоге):

```sh
git apply "$PROPOSAL/source.patch"
cargo fmt --all --check && git diff --check
python3 "$PROPOSAL/probe.py" . "$DEPS" "$(mktemp -d)"
```

`DEPS` содержит по одному совместимому rlib для anyhow, serde, serde_json, libc, tempfile и их зависимости. Для штатной проверки в полном checkout: `python3 scripts/test.py -p proteus-core --lib workspace_search` и `python3 scripts/test.py -p proteus-core --lib workspace::search::tests`. Сырые счётчики и вывод изолированных тестов — `gates.log`.

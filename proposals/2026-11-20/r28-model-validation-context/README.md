# Проверка ответа без копии истории запроса

Core: `048378da7cbe890d8bf8a0152e55eb28ecb5013d`. В двух местах история копировалась только ради проверки будущего ответа: прямой `ModelService::stream` после shaping и `invoke_model` для сырого `replay prompt`. [Патч](validation-context.patch) передаёт полный запрос адаптеру без изменений, а для проверки оставляет уже существующий `ModelResponseValidationContext`: имена и поверхности tools в порядке объявления. Проверка структуры ответа, обработка неизвестных имён, совпадения первой декларации и ошибок остаются за прежним валидатором. В обычном привязанном ходе этот подход уже применялся, поэтому это не новое ускорение всех чатов.

| Объём одного user-сообщения | Прямой ModelService, выделено байт до → после | invoke_model в replay, выделено байт до → после |
|---:|---:|---:|
| 1 КиБ | 5 441 → 3 176 | 4 258 → 2 848 |
| 1 МиБ | 1 052 993 → 3 176 | 1 051 810 → 2 848 |
| 8 МиБ | 8 393 025 → 3 176 | 8 391 842 → 2 848 |

Это сумма запрошенных у Rust-аллокатора байт на текущем потоке, не RSS, peak или время ответа. Микротесты вызывают реальные функции в полном libtest Core. Один локальный адаптер отдаёт фиксированный успешный ответ; в replay другой сохраняет вход без копирования и возвращает фиксированный ответ. Модель, строка и runtime приготовлены до измерения, набор tools пустой. Начальный запрос, чтение/проекция журнала, копии при выборе сохранённого обмена и формирование итогового отчёта не измерены и не исправляются. Для непустого списка сохраняются имена и типы tools, т.е. это не обещание нулевых аллокаций.

17 штатных тестов затронутых модулей и 2 измерительных теста прошли. [Прямой сервис](service-gates.txt) отклоняет неверную поверхность, сохраняет ошибки и terminal-семантику. [Prompt replay](replay-gates.txt) передаёт ровно сохранённый запрос, не пишет в старый журнал, не выполняет локальные tools и требует подтверждённого включения hosted-tools. Остальные тесты workspace и живой provider не запускались.

**Проверка:** Linux x86_64, Rust/Cargo 1.95.0, stock JSONL process worker SHA-256 `d9929cc7592c7c5f537b8a9c63b8cb5d09ae5a6ffc7c7306e48940bcb4c7c44e`. В обе сборки внесён одинаковый временный [измерительный патч](alloc-probe.patch), который использует тестовый thread-local аллокатор из contracts; он не входит в production-патч. Cargo test был повторён с одним job, привязав компилятор к одному доступному CPU после SIGKILL при первой сборке. Форматирование, `git diff --check` и применение к точной базе проверены. [Сырые строки до](baseline.txt), [после](candidate.txt), [сводные данные](results.json).

Для нового каталога и установленного Rust с linker lld: `bash reproduce.sh /abs/Proteus-core /abs/proteus-session-storage-module /new/output`. Для ограничения пиков сборки задайте `CARGO_BUILD_JOBS=1` и при необходимости запустите команду через `taskset -c <доступный-CPU>`.

# Desktop: не пересоздавать текстовую копию при обновлении истории

База: Proteus-harness/Proteus-desktop `7ccb6c8634c40f450d83bb6e9eff891dc776ee6b`. Применить `desktop-reset.patch` после `git apply --check`. Независимо от #245. Этот PR содержит патч, а не изменение исходного репозитория.

`Transcript::reset` сверяет входной текст с подходящей строкой и использует существующий Arc, когда текст совпал. При изменении создаётся новый, как раньше. Сохраняются ключи, правила сопоставления по роли и идентификатору, приоритет последнего старого повтора, временные метки и диапазоны для обновления ленты. `append_page` не меняется.

Изолированный вызов фактического кода транскрипта с уже выделенными входными DTO: 256 неизменившихся строк по 16 КиБ, в том числе 64 позиционные, дали 264 → 8 запросов аллокатору и 4 393 292 → 194 892 суммарно запрошенных байта. При 32 изменённых строках из 256: 264 → 40 запросов и 4 393 548 → 719 948 байт. При полностью изменённых строках, холодном заполнении и пустом входе счётчики совпали. Это не RSS, не время открытия окна и не замер GPUI.

Проверка: 43 целевых теста кандидата против 41 у базы, точное сравнение полей, сплайсов, повторного использования Arc и следующего ключа на 12 321 переходе снимков. Воспроизводимый локальный probe связывал те же закреплённые Cargo-зависимости; GUI-приложение целиком не собиралось.

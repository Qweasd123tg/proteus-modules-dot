# R20: результаты локального сравнения

Фиксированный синтетический набор. В каждом случае 4 из 100 пассивных архивов по 125 000 строк отображения и один активный turn A. Первая группа: четыре параллельных последних страницы по 50 строк. Обычный production-код Rust-клиента Desktop с настоящим 30-секундным лимитом, без графического окна. Сам /send и SSE наблюдает отдельный драйвер.

| Запуск | Окно 4 страниц, мс | Самый медленный вызов внутри Rust API, мс | PSS во время страниц, МиБ | TurnStarted ≤, мс | Первый текст, мс |
|:---|---:|---:|---:|---:|---:|
| indexed-A1 | 99.1 | 95.1 | 78.5 | 78.4 | 298.2 |
| indexed-B1 | 65.4 | 63.3 | 78.4 | 56.8 | 129.8 |
| indexed-B2 | 66.7 | 64.3 | 81.2 | 58.2 | 144.5 |
| indexed-A2 | 77.3 | 75.4 | 82.9 | 68.9 | 148.1 |
| absent-B | 23863.0 | 23861.4 | 889.7 | 8510.3 | 11016.2 |
| absent-A | 22567.7 | 22565.9 | 948.4 | 7579.5 | 9533.2 |
| wire-A | 80.3 | 77.3 | 88.0 | 55.5 | 147.0 |
| wire-B | 96.7 | 94.4 | 89.3 | 71.0 | 171.4 |

A = stock, B = candidate. Indexed: полный перезапуск после обычной HTTP-подготовки на тех же inode, оба штатных индекса сохранены. Absent: первый запрос к архивам без любых индексов приложения. Отдельные wire A/B добавляют перехватчик; для заявлений о скорости/памяти использовать uninstrumented строки выше. TurnStarted SSE не является сырым ACK.

* wire-A: первый latest по архивам OpenSnapshot=[2, 2, 2, 2], ReadCache=[2, 2, 2, 2]; pinned OpenSnapshot=[0, 0, 0, 0]. Реальный успешный wire ACK TurnOpened через 43.9 мс от отправки A; на эту границу ещё не вернулось 4/4 запросов.
* wire-B: первый latest по архивам OpenSnapshot=[1, 1, 1, 1], ReadCache=[2, 2, 2, 2]; pinned OpenSnapshot=[0, 0, 0, 0]. Реальный успешный wire ACK TurnOpened через 67.3 мс от отправки A; на эту границу ещё не вернулось 4/4 запросов.

При готовой индексированной истории ускорение наблюдалось в обеих очередностях, но только на этом Linux-стенде; это не production percentile. Снижение памяти на готовом пути не доказано. При отсутствии индекса отдельный B/A не ускорил полный replay; ожидание активной сессии сохраняется. Здесь не тестируются аварийное питание, перенос каталогов или конкурентная порча диска.

Доказательства: три проверенные страницы на архив (последние 50, первые 50 по pinned revision, последние 50 повторно), обе роли, ID и текст всех возвращённых строк, равенство исходного digest архивов, неизменность 96 невыбранных, четыре реальные загрузки HEAD при подготовленной истории, целостность turn A и канонического model prompt. Приложены сводки, таймстемпы, идентификаторы бинарников, драйвер и стенд. Готовая проекция уже работала в stock; результат двух разных приёмов (подготовка vs исправление чтения) не складывать.

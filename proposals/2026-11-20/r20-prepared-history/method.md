# R20 local process-cold history controls

A baseline and a one-axis candidate use the same release JSONL worker, deterministic reference provider, production Core HTTP/SSE and the pinned Desktop Rust history API (its own 30 s global deadline, no retry). This is the actual HTTP client code driven headless, not rendering, tab lifecycle, physical I/O coldness or a Desktop /send. Foreground uses stock synchronous loopback /send, native SSE observed by the separate harness. Server plus its children only are included in PSS, not Desktop or the test process. The user's own sessions are never read.

## Inputs and arms

100 synthetic archives, four selected archives with 125,000 transcript rows each; 96 others have 100 rows each; A (active session) initially has 100. Journal mutations in groups of 100 end with a retained **model** history of 100 canonical messages per large archive, while the **display** still contains 125k rows. Corpus manifest and original journal/blob digest are checked. No claims about a single 125k-token active context, 125k separate turns, or cold OS buffers.

- **Indexed restart**: clone only the originally cache-free fixture into an isolated case *before* preparation; use fixed stock Core and worker going through ordinary /history/page for each of the four. Verify the 50 most recent and first 50 pinned rows against independent IDs/roles/text. Stop Core and all its observed children. On the same absolute session path, with unchanged inode/device/ctime of the journal, metadata, persistent worker catalog, blobs if any and display HEAD, start a new Core + storage worker. No sidecar is copied, synthesized or hand-edited. Record exact persisted index inventory and source identities. Each arm prepares its own independent copy through identical stock binaries.
- **Absent**: first access to the originally app-cache-free archive, no previous projection or worker catalog; same corpus, preparation deliberately omitted. This tests strict full-replay fallback, not the candidate's intended hit path. OS page cache is not purged. Do not conflate the effect of preparing the archive with a speedup caused by the patch.
- **Secondary, counted/instrumented**: otherwise identical indexed A/B with a Python byte-stream relay interposed between Core and the same stock worker. Counts actual RPC requests by operation/session/global monotonic time per first/pinned/warm HTTP window. Successful TurnOpened ACK is timestamped on observing the complete worker response at the relay and matched by request ID, operation and record IDs, canonical kind, session and turn; this ACK is not inferred from SSE. The extra process and logging alter performance; never mix these latency/PSS values with the uninstrumented pair. Only small ACK frames are decoded; scope claimed is TurnOpened/TurnSettled.

In every arm four simultaneous first requests (distinct archive sessions) overlap a request to active A sent **after an observed open of selected session.json**. This is earlier and the same trigger for both index states, not proof that any particular broker lock was acquired. Report number of archive requests still pending at each event, including when zero. For each archive verify latest tail 50, pinned first 50 at exact initial revision, then latest tail again, including content identity and source revision. Archive bytes rehashed including unselected; ordinary inactive endpoints queried only after timing to verify sessions were never activated. Full prompt, single durable committed foreground turn, text/settlement and projection verified from canonical journal. TurnStarted on SSE is explicitly only an upper bound on durable open; first text is the first actual assistant text delta.

## Reproduce

Linux/inotify, /proc PSS, Python 3.12. Reuse a checkout of Core at the pinned baseline for the sampler and fixture profile; R17/R19 inputs as named in run.sh and previous seed tooling. r20-bench/run.sh uses fixed baseline producer hashes, and accepts candidate CORE_BIN, CORE_SHA, CORE_COMMIT, CASE_PATH, OUT, SIZE=tiny. The optional --desktop-bridge path selects the actual compiled desktop API harness; otherwise only Python raw HTTP is tested. All output and case paths must be fresh. Prepare binary receipts and Desktop driver in advance and do not run unrelated compilation or parallel benchmark arms. pair.sh runs both orders of indexed A/B, a single absent B/A and two separate counted arms. To change root layout, adapt local paths in the run wrapper; do not substitute a self-computed binary hash for a verified source build receipt.

    CANDIDATE_SHA=<source-and-build-receipt> bash r20-bench/pair.sh | tee r20-bench/evidence/timing.log
    python3 r20-bench/summarize.py r20-bench/evidence/{indexed-A1,indexed-B1,indexed-B2,indexed-A2,absent-A,absent-B,wire-A,wire-B} > r20-bench/evidence/results.json

cold_window.peak_tree_kib is max measured PSS *during actual archive page requests*, not an extrapolated maximum. cold_and_hot_peak_kib spans the combined send and four-page phase, sometimes longer than the pages. Idle/retained are sampled medians. Nominal 10 ms sampler sleep plus sampling overhead; a very brief phase can escape it. The Python receive/validation wrapper makes observed history times slightly longer than the Rust api_ms stored separately in the full raw run. No percentile claims with two order-reversed indexed observations. Condensed per-arm reports, client outcomes, identity checks and timing markers are included. The stand can regenerate raw summaries and per-process samples.

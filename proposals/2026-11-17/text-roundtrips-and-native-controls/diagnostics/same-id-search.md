# Разные формы одного поля

В [описании узла Input](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/declarative/widget.rs#L135-L157) число строк определяет вид нативного поля; валидатор требует от поиска одну строку. Отдельно допустимы `id=filter, lines=4, search=false` и `id=filter, lines=1, search=true`. На [новой принятой ревизии](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/ui/extensions/declarative/view.rs#L297-L312) запись сохраняется по паре «Input, id». [Существующая запись](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/ui/extensions/declarative/fields.rs#L339-L366) не меняет разновидность. [Ветка поиска](https://github.com/Proteus-harness/Proteus-desktop/blob/2307e9c67125bbe66f15ced51317a2dfcc437aa4/src/ui/extensions/declarative/render.rs#L282-L304) с сохранённой Area явно выбирает пустой Div. На чистой новой записи с однострочным поиском получается Search; ситуация с удалением записи между ревизиями иная.

Стенд извлекает тело подготовки текущей записи; оконные объекты, хранение строк и события упрощены. Выбор Area/Line в ветке поиска берётся из исходника, создание графических объектов заменено названиями вариантов. При 6×6 допустимых описаниях, 2 контекстах, 2 состояниях фокуса и 2 сценариях значения получилось 128 несовпадений разновидности. Это не 128 независимых пользовательских инцидентов. Счётчик rows измерял входные данные для макета, не пиксели.

Из каталога пакета (Desktop закреплён в README): `python3 checks/field/assemble.py /path/to/Desktop > /tmp/proteus-field.rs`, затем `rustc --edition=2024 /tmp/proteus-field.rs -o /tmp/proteus-field` и `/tmp/proteus-field`. Ожидаемый **красный** результат см. [в протоколе](../checks/field/before.log). Нет предлагаемого исправления и зелёного «после».

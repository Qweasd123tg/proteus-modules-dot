# direct-patch: применять текстовые hunks без копирования каждой строки

База: **Proteus-harness/Proteus-modules@9469e3b12529d08b1f4a76882693e2065e842c51**. Локальный commit `4ec256547c945926572e78b3d22e43ccb6ea4028`.

При обновлении файла `direct-patch` раньше копировал все строки оригинала и дополнительные строки из разобранных hunks. Теперь до финальной сборки текста он хранит ссылки на исходное содержимое и разобранные строки патча. Поиск, позиция следующего hunk, LF/CRLF и отсутствие конечного перевода строки работают по-прежнему. Парсер, проверки путей, валидация и запись файлов не меняются.

## Проверки

- Полный scope crate `direct-patch`: **24/24 → 25/25** в обоих графах. Оба исходника скомпилированы rustc 1.95.0 Linux x86-64 с теми же ранее собранными locked Cargo dependencies: Release library graph с sorted keys и Debug workspace test graph с `serde_json/preserve_order`. Общий target не менялся; полный workspace gate не запускался.
- **18 полных побайтных сравнений** (по три пары): результат hunk, итог публичного применения и реальные байты временного файла. Независимые ожидания для короткого и большого обновления, LF/CRLF, смешанных окончаний, отсутствия конечного LF, удаления содержимого и двух обычных ошибок сопоставления. На ошибках файл остался прежним.
- `rustfmt --check`, `git diff --check`, точное применение к базе и к копии M100 с уже применёнными R57–R63 (включая R62/R63). В накопительном варианте оба изменённых файла совпали с standalone побайтно. Накопительный вариант не собирался.

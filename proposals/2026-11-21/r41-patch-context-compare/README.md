# Codex patch: поиск Unicode-контекста без двух временных строк на каждую пару

Репозиторий: `Proteus-harness/Proteus-modules`, база `9469e3b12529d08b1f4a76882693e2065e842c51`, проверенный локальный commit `2070fa7e52a8452760e298ffd95b273b921be334`. Меняется только реализация последнего, самого мягкого прохода поиска контекста в Rust-модуле `codex-patch`. Данные на диске, формат патча и контракт результата не меняются.

Когда точное совпадение и два прохода с удалением пробелов ничего не находят, модуль сравнивает строки с поправкой на типографские кавычки, тире и пробелы. Прежний код строил два `String` целиком на каждую пару. Новый сравнивает два итератора нормализованных Unicode-символов: первое отличие завершает проверку этой пары, а совпадение требует одинакового конца обеих строк. Таблица замен, `trim()`, порядок строгости и ограничение EOF не менялись.

## Измерение в настоящем пути применения патча

Два запуска одних и тех же исходных сценариев: базовый commit и он же с патчем. На каждый сценарий по три повтора с восстановлением файла. Счётчик оборачивает весь вызов `apply_patch`: парсинг, проверку, а для успешного результата и повторное чтение, применение и подготовку ответа. Подготовка файлов, проверка результата и транспорт не измеряются. Сумма байтов учитывает полный новый размер при перераспределении; это не пиковая память и не RSS.

| Сценарий | Выделения до → после | Запрошенные байты до → после |
|---|---:|---:|
| После 4096 строк совпала последняя, только с заменой типографских знаков | 49 234 → 8 266 | 2 403 308 → 1 690 508 |
| Совпадения нет ни в одной из 4096 строк | 24 623 → 4 143 | 1 051 006 → 694 654 |
| Та же позиция, точное совпадение | 8 265 → 8 265 | 1 690 432 → 1 690 432 |
| Та же позиция, достаточно убрать конечные пробелы | 8 265 → 8 265 | 1 690 444 → 1 690 444 |

Побайтово совпали содержимое файла и сериализованный Rust `Result` (включая текст ошибки) во всех **9** сценариях. Кроме таблицы, это оба направления несовпадения длины, EOF с совпадением и без, предпочтение строгого совпадения и многострочные блоки. Счётчики стабильны в трёх повторах каждой ветки. `results.log` содержит все результаты и хэши итоговых файлов. Латентность, память процесса и Desktop не измерялись.

## Проверки и воспроизведение

- Полный тестовый target библиотеки `codex-patch`: **28/28**. Добавлен один тест на многострочный fuzzy-match с обманчивыми префиксами разной длины; он проверяет итоговые байты реального файла. `cargo fmt --all --check` и `git diff --check` прошли.
- Linux x86_64, rustc 1.95.0, оптимизация проверяемого crate `-C opt-level=3`, реальные скомпилированные зависимости (Core `0c1b7572313230e5d123e95c722e1258a2e9ecd6`, thiserror 2.0.18). Проверен исходник библиотеки через rustc с этими зависимостями. Полный workspace, установка пакета и Desktop не проверялись.
- Для обычного checkout: `python3 reproduce.py /path/to/Proteus-modules` (Git, Rust и доступ к закреплённым зависимостям). Скрипт берёт точный commit в двух временных копиях, применяет `candidate.patch` только ко второй, запускает реальные проверки с `probe.rs` и сравнивает результат. Абсолютные байты могут меняться с путём и сборкой. `--local-compiler` позволяет использовать эквивалентную обёртку rustc с уже собранными зависимостями. Для тестов самого патча: `git apply candidate.patch`, затем `python3 scripts/test.py -p codex-patch --lib`.

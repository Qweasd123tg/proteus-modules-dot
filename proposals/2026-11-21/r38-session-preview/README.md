# Core: копировать только видимое превью сессии

База: `Proteus-harness/Proteus-core@32e56ecb4cc6da324c60dd6ae2da78f3b7e46e7f`. SHA-256 `source.patch`: `81422a44840d6761c55cf1f153750960580948242a168db0a403bb8cafd8a7c9`.

При построении или обновлении сохранённого представления сессии Core показывает до 160 символов первого подходящего сообщения. Старый путь копировал весь текст, считал все символы и только затем готовил короткую строку. Теперь текст и reasoning остаются заимствованными до выбора первых 160 Unicode scalar values; копируются видимый срез и прежний суффикс `...`. Пробелы Unicode по краям по-прежнему удаляются **до** усечения, внутренние пробелы сохраняются. На границе ровно 160 символов суффикса нет. Пользовательские сообщения имеют тот же приоритет; когда подходящего нет, сохраняется запасной поиск по всей истории. Метаданные сессии, привязка к источнику и запись кеша не менялись.

**Локальный замер выделений.** Полные функции `cache::summary` из базы и патча в одном оптимизированном бинарнике; реальные типы Proteus, одинаковый синтетический ответ хранилища без I/O, сообщения подготовлены вне измерения. Порядок ABBA, повторы дали одинаковые счётчики. Считаются запросы alloc/alloc_zeroed/realloc, при realloc — полный новый размер. В числах есть накладные расходы mock-дескриптора и получения summary.

| Содержимое первой подходящей части | Запросов, до → после | Запрошено байт, до → после |
|---|---:|---:|
| ASCII, 32 / 160 символов | 6 → 6 | 37 → 37 / 165 → 165 |
| ASCII, 161 символ | 11 → 6 | 933 → 168 |
| ASCII, 1 МиБ | 9 → 6 | 1 049 221 → 168 |
| Reasoning из эмодзи, 1 МиБ | 11 → 6 | 1 051 621 → 648 |
| Результат инструмента, текстовый output в 1 МиБ | 10 → 7 | 2 097 797 → 1 048 744 |
| Только пробелы / непрозрачная часть, 1 МиБ | 5 → 5 | 5 → 5 |

Длинные строки из одних пробелов по-прежнему нужно проверить. В ветке tool result существующий `text_or_status()` по-прежнему материализует полный текст: устранена следующая копия, не исходная. Это не замер RSS, скорости запуска, полного replay, частоты длинных сообщений или операций хранилища.

**Проверка**: 5 741 точное сравнение полного `AppSessionSummary` с базой (5 ролей; text/reasoning/tool/opaque; одно или несколько сообщений/частей, разные длины и Unicode). Дополнительно проверены отрицательная дата и пустой parent, три ошибки дескриптора/чтения, два новых unit-теста и ABBA-замер. `gates.log` содержит результат прогона. Весь тестовый target библиотеки proteus-core прошёл typecheck с кешированными зависимостями (rustc --test --emit=metadata, без линковки; 7 предупреждений вне изменённых строк, см. typecheck.log). Прошли форматирование всего workspace, проверка whitespace и прямое/обратное применение. Полный workspace и приложение не запускались.

**Повторить** из чистого Core с этой базой в git, Rust 1.95 и lld:
```sh
cargo build --locked -p proteus-contracts
python3 "$PROPOSAL/probe.py" . "${CARGO_TARGET_DIR:-target}/debug/deps"
```
`probe.py` восстанавливает исходный файл через `git show`, применяет патч во временной директории, компилирует обе функции и тесты с одним набором Cargo-зависимостей. Нужен один набор rlib (например свежий target); рабочий checkout не меняется. Для обычной проверки после применения `source.patch`: `cargo test --locked -p proteus-core --lib core::session_store::remote::view`.

# Desktop: передавать границы страницы чата без временного вектора

При подготовке списка сообщений Desktop уже знает до трёх диапазонов, для которых ещё не загружено окружение: начало страницы, конец страницы и строку или группу, которой принадлежит нижняя отметка. Раньше перед отрисовкой эти границы копировались во временный `Vec`. Теперь виртуальный список получает готовый `RowContext` и для каждой строки использует его существующую проверку.

Механизм измерения, порядок обхода, загрузка страниц, закрепление высот и прокрутка не переписаны. Пустые диапазоны, перекрытия, интервалы между спрятанными строками, свёрнутые группы и приоритеты выбора направления ведут себя как раньше. Отдельная строка нижнего резерва по-прежнему проходит по существующему пути.

База: [Proteus-desktop b6a7ec2d](https://github.com/Proteus-harness/Proteus-desktop/commit/b6a7ec2d8d7e486c8aba01291aa8c89774c4cded). SHA-256 патча: `bed3aef0d7d4bfcc2a75037420c82bf412dce9a25ab6762dc50d81dab6e96072`.

## Проверка

Стенд использует исходный транскрипт и точную логику `RowContext`, включая проверку скрытых строк и реальные типы диапазона и направления. На синтетических страницах проверены полная и отсутствующая страница, обрезка с одной или с обеих сторон, свёрнутые цепочки, несовпадающие ссылки дочерних сессий и скрытая строка между нижней группой и последней сырой строкой.

Из исходного `Cargo.lock` сверены **125** идентичностей зависимостей (имя, версия, источник и контрольная сумма), включая закреплённый `proteus-contracts`. Прямое и обратное применение, `git diff --check` и rustfmt прошли. Три затронутых файла совпали с базой в M100 и фактических сводных Desktop через R60 и R61; проверка применения прошла на всех трёх снимках.

Прошли все **42** узких теста: 41 штатный тест транскрипта и один новый тест границ. Совпали **560** контекстов и **14 560** решений о возможности измерить строку.

## Запросы к аллокатору на одну подготовку границ

| Синтетическая страница | Запросы, до → после | Запрошенные байты, до → после |
|---|---:|---:|
| Первая неполная страница, средняя страница, конец неполной истории | 1 → 0 | 64 → 0 |
| Средняя страница со скрытыми строками и свёрнутой нижней группой | 13 → 12 | 946 → 882 |
| Полная история или нет диапазона | 0 → 0 | 0 → 0 |

В последней строке выигрыша в запросах нет. На x86-64 переносимый объект сам стал больше: 24 → 48 байт, взамен отдельного буфера в неполной странице. Счётчик суммирует `alloc` и `realloc` только в модели контекста и проверки строк; полная отрисовка, время и RSS не измерялись.

## Как повторить

`git apply --check /путь/source.patch` из checkout базы. Узкая проверка: `bash verify.sh /путь/Proteus-desktop`. Нужны Bash, Git, Python 3.11+, Rust 1.95 с rustfmt и локальный Cargo-кэш для `harness.lock`. Стенд собирается без сети в один Cargo job. См. [evidence.log](evidence.log). Полная нативная сборка, отрисовка и прокрутка в окне GPUI в этот прогон не входили.

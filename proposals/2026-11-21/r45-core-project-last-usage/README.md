# Core: строить разбивку токенов только для последнего события

Самостоятельный патч к [Proteus-core@32e56ecb](https://github.com/Proteus-harness/Proteus-core/commit/32e56ecb4cc6da324c60dd6ae2da78f3b7e46e7f). При холодном чтении карты контекста Core преобразовывал *каждый* подходящий `TokenUsageUpdated` в формат ответа: строил список категорий и выделял строки с источниками оценок. Все такие списки, кроме последнего, тут же устаревали. Теперь на этапе разбора хранится только последняя проверенная типизированная запись о токенах вместе с её `turn_id` и временем; преобразование происходит один раз после чтения журнала.

Полный разбор каждой строки через прежний `EventEnvelope` и выбор сессии сохранены. «Последняя» означает последнюю подходящую запись в **порядке файла**, а не с наибольшим timestamp или номером. Ошибочные записи по-прежнему учитываются в диагностике, даже если принадлежат другой сессии; ошибка чтения не заменяется неполным успешным ответом. В сериализованный кэш помещается та же проекция, а не исходное событие. Для уже прогретого Unix-кэша выигрыша нет. Не меняются API, правила доступа, wire, сортировка или состав данных.

## Измеренная экономия

Полный вызов сборщика карты на отдельном журнале с указанным числом событий выбранной сессии. Обе версии получают один и тот же файл; первое чтение холодное для программного кэша каждой версии (не обязательно для кэша ОС). Использован штатный счётчик аллокаций текущего потока из `proteus-contracts`. В окне измерения: чтение, типизированный разбор, сборка проекции, публикация в кэш и возврат готового ответа; вне окна: создание файла, HTTP и сравнительная сериализация ответа.

| Записей × категорий на запись | Вызовы аллокатора, до → после | Запрошено байт, до → после |
|---|---:|---:|
| Пустой журнал | 13 → 13 | 9 794 → 9 794 |
| 1 × 4 | 38 → 38 | 10 597 → 10 597 |
| 128 × 0 | 463 → 336 | 14 007 → 13 074 |
| 128 × 4 | 1 752 → 990 | 66 226 → 33 118 |
| 1 024 × 4 | 13 849 → 7 711 | 449 271 → 182 609 |
| 1 024 × 12 | 32 296 → 17 974 | 1 798 084 → 1 013 102 |

При 1 024 × 4 устранено 6 138 запросов, суммарно на 266 662 байта меньше (59,4%). Это сумма запросов к аллокатору с учётом нового размера при realloc, **не RSS, пиковая память или ускорение всего запроса**. На всех размерах проверены полное совпадение сериализованного ответа и равенство счётчиков для повторного вызова с прогретым Unix-кэшем. Конкретные небольшие постоянные зависят от длины временного пути и версии библиотек.

## Проверки

- Четыре штатных теста `context_map` на базе и четыре на кандидате, включая расширение существующего сценария: более поздняя в файле запись с меньшим временем заменяет предыдущую целиком, а последняя чужая запись игнорируется.
- Два дополнительных теста сравнивают базу с кандидатом: замеры выше и смешанный журнал с другой сессией, Unicode-пробелами, повреждённым typed-событием чужой сессии, оборванным JSON и невалидным UTF-8. Проверены как поиск по session ID, так и прежний fallback без ID. **Всего 10/10** на Linux x86-64.
- Проверены форматирование workspace, whitespace и применение в обе стороны. Отдельная проверка индекса: совместим с более ранними патчами подсчёта JSON, ограничения превью и освобождения истории (#284, #288, #295); это не проверка запущенного комбинированного стека. Полная библиотечная тестовая цель Core прошла типизацию (`rustc --test --emit=metadata`), без линковки полного бинарника. Полный workspace, HTTP/GUI, macOS и Windows в данном прогоне не запускались.

Воспроизведение из checkout указанной ревизии с собранными зависимостями:
```sh
# PROPOSAL — абсолютный путь к этому каталогу.
git apply --check "$PROPOSAL/source.patch"
python3 "$PROPOSAL/probe.py" . "${CARGO_TARGET_DIR:-target}/debug/deps"
git apply "$PROPOSAL/source.patch"
# Обычный штатный target в окружении с process fixtures:
python3 scripts/test.py -p proteus-core --lib app_server::context_map::
```
Скрипт требует git, Python 3, rustc 1.95, lld и один согласованный набор rlib. Он достаёт исходники из закреплённого git-объекта, собирает оба варианта реальных функций и запускает тестовый бинарник во временной директории, не меняя checkout.

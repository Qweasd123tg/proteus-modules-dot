# Core: переносить имена и описания инструментов в сводку настройки

Самостоятельный патч к [Proteus-core@32e56ecb](https://github.com/Proteus-harness/Proteus-core/commit/32e56ecb4cc6da324c60dd6ae2da78f3b7e46e7f). Реестр уже отдаёт владеющий список описаний инструментов. Сводка сначала читает его для человекочитаемого текста, а затем раньше снова копировала имена и описания в поле `registered_tools`. Теперь после рендера эти строки переходят в структурированный ответ. Избыточная ёмкость освобождается перед переносом: короткое описание не будет удерживать крупный входной буфер.

Порядок, структура JSON, метка источника, значение `safety` и признак параллельных вызовов не изменены. Рендер текста, модель, поиск файлов, содержимое реестра, вычисление прав и порядок обновления конфигурации не затронуты.

## Измерение

Замерена **только проекция уже полученного списка в `registered_tools`** на синтетических данных. Метод реестра, текстовый рендер, сериализация списка и HTTP/stdio не входят в замер. Счётчик отражает запросы аллокатору, включая уменьшение ёмкости через realloc; это не RSS, пик или задержка всей сводки. Размеры тестовых списков и описаний не являются производственной статистикой.

| Список инструментов | Вызовы аллокатора до → после | Запрошено байт до → после |
|---|---:|---:|
| 0 инструментов | 0 → 0 | 0 → 0 |
| 1, строки точной ёмкости | 6 → 4 | 216 → 166 |
| 24, обычные конструкторы строк | 102 → 83 | 4 608 → 3 791 |
| 128, строки точной ёмкости | 539 → 309 | 24 474 → 18 239 |
| 22, длинные многострочные описания, строки точной ёмкости | 95 → 55 | 51 492 → 3 155 |
| 24, намеренно раздутые входные буферы | 102 → 102 | 4 608 → 4 608 |

На всех контрольных входах итоговые ёмкости вектора, имён и описаний остались прежними. [Полные результаты](probe.log).

## Проверка

- На **7** наборах сериализованный JSON поля `registered_tools` побайтно совпал с прежним. Покрыты пустой список, разные источники, оба значения параллелизма, Unicode, NUL, многострочные описания, пустое описание и вход с запасом ёмкости.
- Пройдено 7/7 с измерителем. Выполнены штатные HTTP-тесты изменения и истории конфигурации, тест перезагрузки реестра и процессный тест `remember`. Прямое и обратное применение, `git diff --check` и форматирование прошли. Патч также применяется поверх Core из подготовленной 95-патчевой композиции; это проверка применения, не совместный запуск.
- Весь workspace, настоящий интерфейс, сетевой провайдер, macOS и Windows не запускались.

Из чистого checkout указанной ревизии, Rust 1.95, Linux x86-64:

```sh
# PROPOSAL — абсолютный путь к этому каталогу.
git apply --check "$PROPOSAL/source.patch"
cargo fetch --locked
# С настроенными process fixtures Core, как для scripts/test.py:
python3 "$PROPOSAL/probe.py" . "${CARGO_TARGET_DIR:-target}/r54-config-summary"
```

Измеритель добавляет прежнее выражение проекции и счётчик только в тестовую сборку временной копии. Источник и тесты сравниваются в одном бинарнике с одними зависимостями.

# Диагностика: повторный учёт размера истории

Метрика считает не время и не выделения памяти, а работу внутри штатного `Entry::retained_bytes`: число оценок строк, число различных версий оценённых строк и число входов в рекурсивный `value_bytes`. Узел JSON учитывается один раз на каждый реальный вызов функции, включая листья, объекты и массивы. Суффикс в синтетической строке или результате инструмента различает прежнюю и изменённую версии одного ключа без хеширования JSON.

Принадлежность к фазе помечается в узком временном стенде: `core.trim`, `core.context.loaded`, `codex.live.trim`. Тройки в журнале означают «неизменившиеся ранее загруженные, изменённые ранее загруженные, новые». Отладочная трассировка старта и её отдельный подсчёт не используются. Счётчики компилируются только в стенд и не попадают в production-патч.

| Сценарий | Оценок строк до → после | Посещений JSON до → после |
|---|---:|---:|
| 200 строк + 50, страница старше или новее, вложенные tool-данные | 300 → 200 | 10 200 → 6 800 |
| 200 + 50 с защищённой границей видимой области | 251 → 249 | 8 534 → 8 466 |
| Фаза дополнительного контекста при дробном поиске | 50 → 50 | 1 700 → 1 700 |
| Лимит только по байтам, крупная строка за пределами видимой области | 101 → 101 | 0 → 0 |
| Крупная видимая строка сохраняется целиком | 100 → 100 | 0 → 0 |
| Снимок без изменений или с изменением живого хвоста без подгрузки | 0 → 0 | 0 → 0 |
| Codex: добавление текста в существующую строку с запасом бюджета | 0 → 0 | 0 → 0 |
| Codex: замена или вставка элемента | 200 → 200 | 3 400 → 3 400 |

В обычной подгрузке до правки 200 различных прежних версий оценивались 250 раз, а 50 новых версий по одному разу. После правки оцениваются 150 прежних сохранённых и 50 новых, каждая по разу. В Codex замена пересчитала 199 неизменившихся строк и одну изменённую; вставка пересчитала 199 неизменившихся и одну новую. Это сравнение формы работы, не утверждение об одинаковости двух механизмов.

Как искать такой класс массово: помечать фазу и версию существующего объекта, сравнивать количество визитов с количеством версий и переходить к оптимизации только там, где повторяется один и тот же payload. Сначала проверять обычный сценарий, затем отсутствие работы и реальное изменение. После этого требовать совпадения результата и границ. Здесь устранён двойной обход вытесняемых по числу строк; неизменившиеся сохранённые строки всё ещё пересчитываются между страницами. Перенос долговечного кэша в production не предлагался.

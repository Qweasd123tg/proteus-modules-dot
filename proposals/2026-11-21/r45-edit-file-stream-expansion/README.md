# file-tools: точечное редактирование без копии развёрнутого файла

Независимый патч для **Proteus-harness/Proteus-modules** на базе `9469e3b12529d08b1f4a76882693e2065e842c51`. Локальный проверочный commit `3ea59bd65da2418c18381fbf5f8ecf74e32d957e` имеет именно этого родителя. Меняется только `tool/file-tools`, без изменений Core, протокола и зависимостей. Никакой установки не требуется для проверки патча.

`edit_file` раньше сначала собирал всю новую строку, затем одним вызовом писал её во временный атомарный файл. При массовой замене короткого маркера большим фрагментом результат может во много раз превосходить исходник. Патч направляет однократные и растущие замены через буфер записи прямо в тот же временный файл. При множественных нерастущих заменах сохранён стандартный `str::replace` и один `write_all`: выход не длиннее входа, а на плотных заменах сборка строки оказалась быстрее записи каждого фрагмента через буфер. От полного входного буфера патч не избавляет.

## Поведение

* До создания временного файла остаются проверки аргументов (непустой шаблон и отличие замены), пути, каталога и заявленного метаданными размера исходника (2 MiB), чтение валидного UTF-8, полный подсчёт неперекрывающихся вхождений и отказ при неоднозначности. Если файл изменится между stat и read, прежнее поведение не изменено: это не новый строгий предел фактического чтения.
* Проверка размера результата теперь явная, до открытия стадии: сложение и умножение проверены; верхняя граница `isize::MAX` сохраняет прежнюю представимость Rust-буфера. Для вычитания из длины входа используется число неперекрывающихся оригинальных совпадений: их суммарная длина не больше входа. Новые совпадения внутри вставленного текста не просматриваются. Сохраняются UTF-8, CRLF, удаления, текст ошибок обычных входов и счётчики результата.
* Никакой записи в исходный inode: прежний `workspace_file_for_atomic_write`, после всех записей явный `BufWriter::flush` на потоковой ветке и затем прежний `commit`. Flush основного дескриптора делегируется обычному `File::flush`; гарантии синхронизации остаются в `commit` (sync файла, rename, sync родительской директории). Ошибка чтения/проверки не начинает запись; ошибка частичной записи или финального flush не вызывает commit. После уже состоявшегося rename ошибка sync директории, как и прежде, не обещает откат.

## Измерение

Linux x86-64, rustc 1.95.0. Два отдельных прогона, каждый: одна разогревочная пара и семь измеренных пар с чередованием порядка. Каждый вызов запускается в отдельном процессе. Время содержит формирование контракта фикстурой, настоящий `EditFileTool::invoke_json`, атомарную запись на tmpfs и разбор ответа; создание входного файла и проверка выходного за таймером. RSS — VmHWM вызывающего тестового процесса сразу после возврата, не объём памяти файловой системы и не замер всего приложения. Измеряемый crate собран с opt-level=3, с одними и теми же локальными зависимостями закреплённого Core. Сырые пары включены в logs.

| 65 536 замен маркера на 512 байт, 448 KiB → 32,375 MiB | 36,190 → 22,522 / 36,451 → 19,673 | 36 024 → 2 888 / 35 952 → 2 888 |
| Одно совпадение у конца файла 1 950 009 байт | 3,834 → 2,761 / 4,293 → 3,291 | 6 328 → 4 460 / 6 328 → 4 352 |

Выигрыш на массовом расширении воспроизвёлся. На коротких изменениях ускорение не установлено: в обоих прогонах медиана хуже на 14–42 мкс. Не переносить эти цифры на реальные диски или весь агентский ход.

## Проверки и повторение

* `cargo test --locked -p file-tools --lib`: **31/31** на конечном варианте; журналы cargo-suite.log и второго запуска suite.log. В новых тестах сравниваются фактические байты, счётчики UTF-8 и неперекрывающихся совпадений, сохранение данных при неоднозначности. Стандартная обёртка `python3 scripts/test.py -p file-tools --lib` не прошла подготовку общей metadata без сети (нет `android_system_properties 0.1.5`), а прямой native Cargo-test прошёл. Полный workspace/CI, процессная поставка и установка не запускались.
* В обоих сравнениях версии выдали идентичные байты и полные JSON-ответы во всех четырёх сценариях, включая пути; отдельно сверены независимые ожидаемые байты и счётчики. Три принудительных отказа записи (RLIMIT_FSIZE, стадия частично записана / ошибка при последнем flush / ветка нерастущей замены) дали одинаковые ошибки, неизменный исходник и отсутствие временного файла.
* В Linux с Rust, Cargo и доступом к закреплённым зависимостям из каталога пакета: `python3 reproduce.py /путь/к/Proteus-modules` (по умолчанию оптимизированная Cargo-сборка обеих версий). Нужен указанный git-объект; исходный checkout не меняется. Для применения: `git apply --check /путь/candidate.patch`, затем `git apply /путь/candidate.patch` на указанной базе. Хеши в SHA256SUMS.

# Запись кеша сессии без промежуточной копии всего JSON

`WriteCache` для JSONL и SQLite раньше собирал весь файл `{source,value}` в растущем `Vec<u8>`, а затем копировал его в файл. Теперь тот же сериализатор пишет прямо во временный файл через буфер 1 КиБ. Маленькие фрагменты объединяются, длинные строки проходят через буфер без дополнительной копии. Сам входной `Value` по-прежнему целиком в памяти. Изменение касается записи **одноразового кеша**, не канонического журнала, архива или чтения кеша.

**Лимиты и отказы.** Контракт уже проверяет размер компактного JSON значения (до 64 МиБ). Обычный заголовок с `null` вместо значения меньше дополнительного бюджета 1 МиБ: значит, файл заведомо поместится в прежние 65 МиБ. При необычно длинном заголовке считаем точный размер всего файла до создания временного, не выделяя массив байтов. Буфер явно сбрасывается до прежнего `sync_data`, проверки личности сессии и атомарного переименования. Формат, ETag, порядок удаления старых кешей, ошибки и обработка устаревшего префикса не меняются.

**База:** [Proteus-modules@9469e3b](https://github.com/Proteus-harness/Proteus-modules/commit/9469e3b12529d08b1f4a76882693e2065e842c51). Самостоятельный локальный commit `02b8618d090e024a97771adeba6b12bbed53607d`. SHA-256 `source.patch`: `f8259634c55ffe389dda434dbdff2569fc94ea5b9a51b2ac00ba6ac6f307eda0`. Проверено применение на чистую базу и поверх отдельного предложения R39 о повторном PutBlob; совместная сборка этих двух патчей не запускалась.

## Память при вызове StorageService::execute(WriteCache)

Rust 1.95.0, Linux x86-64, один поток теста, debug-профиль Cargo, готовый запрос. В таблице медианы трёх записей после одного прогрева на каждом варианте и backend. Сумма запросов учитывает полную новую ёмкость при realloc. Пик — наибольший прирост *живых* байтов на потоке относительно начала операции, с вычетом освобождений. Это не RSS, не размер кеша ядра и не весь объём памяти процесса.

| Вход | Backend | Байт запрошено, до → после | Прирост в пике, байт, до → после |
|---|---|---:|---:|
| Короткий объект, файл 438 Б | JSONL | 83 643 → 83 771 | 67 899 → 67 899 |
| То же | SQLite | 18 440 → 18 680 | 2 123 → 2 123 |
| Строка 256 КиБ | JSONL | 871 362 → 83 771 | 526 620 → 67 899 |
| То же | SQLite | 806 159 → 18 680 | 526 620 → 2 123 |
| 4 096 вложенных объектов, файл 253 264 Б | JSONL | 868 987 → 345 851 | 263 618 → 67 899 |
| То же | SQLite | 803 784 → 280 760 | 263 618 → 2 123 |
| Строка 4 МиБ | JSONL | 12 667 842 → 83 771 | 8 390 940 → 67 899 |
| То же | SQLite | 12 602 639 → 18 680 | 8 390 940 → 2 123 |

На маленьком файле выигрыша нет: запрошенных байтов стало на 128–240 больше. Остальные расходы всего вызова, в том числе проверка контракта, источника и вычисление ETag, остаются. Ускорение не заявляется: для 4 МиБ медиана полного вызова с синхронизацией на диск в этом прогоне JSONL 338 → 331 мс, SQLite 339 → 362 мс. Это локальные последовательные debug-прогоны, не оценка пользовательской задержки.

## Что проверено

- На обеих версиях и обоих backend каждый записанный файл сравнивался **байт в байт** с компактным `{"source":<тот же snapshot>,"value":<то же значение>}`, а ответ — с ожидаемым ETag. Новый экземпляр сервиса прочёл исходное значение и ETag для всех восьми сочетаний входа и backend. Случайные ID снимков различны между запусками; сравнивался ожидаемый файл именно текущей сессии, а не хеш между разными сессиями. Размеры файлов и ETag совпали между вариантами в 24 парах измерений.
- Необычно большой экранируемый snapshot ID без превышения лимита сохраняется; подмена целевого файла каталогом сохраняет ответ `CacheWritten { etag: None }` и не оставляет `.tmp`. Превышение 65 МиБ за счёт экранирования ID на обеих версиях возвращает тот же текст `cache value exceeds maximum` и оставляет предыдущий файл без изменений.
- Фокусная проверка `cargo test --locked --offline -p session-storage -p proteus-session-storage-module -- --test-threads=1`: **64 библиотечных и 2 процессных теста прошли**, один существующий ручной perf-тест пропущен. `cargo fmt --all --check` и `git diff --check` прошли. Стандартный Python runner остановился до запуска тестов: в офлайн-кеше отсутствует Android-only зависимость `android_system_properties v0.1.5`. Полный workspace и системные профилировщики не запускались.
- Локальная установка worker через `python3 package.py --profile dev --package session-storage --install /path/to/stage` выполнена. SHA-256 установленного worker совпал с `module.json`. Это проверочная установка, не релиз.

**Воспроизведение:** `bash verify.sh /path/to/Proteus-modules /path/to/empty-results`. Нужны git-объект указанной базы, Rust/Cargo и зависимости workspace. Скрипт создаёт отдельный временный checkout, добавляет только измерительный тест, проверяет обе версии и пишет CSV. Можно передать свой `CARGO_TARGET_DIR` для переиспользования зависимостей. Исходная таблица — `results.csv`; две малые служебные метрики могут зависеть от длины путей и реализации аллокатора.

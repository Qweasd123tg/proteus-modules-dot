# Core: передавать результат дочернего хода в декодер без клонирования JSON

Самостоятельный патч к [Proteus-core@32e56ecb](https://github.com/Proteus-harness/Proteus-core/commit/32e56ecb4cc6da324c60dd6ae2da78f3b7e46e7f). Иногда дочерний процесс успевает завершить первый ход до обработки переданного сообщения. Тогда ответ на передачу сообщения содержит результат нового хода (`AgentOutput`), а не краткое подтверждение `queued`. Раньше обработчик сначала делал глубокую копию уже разбранного JSON, хотя вызывающая сторона после этого исходник не использовала.

Теперь обработчик забирает имеющееся значение после прежней проверки ID ожидаемого ответа и флага успеха, затем передаёт его в тот же `serde_json::from_value::<AgentOutput>`. Незнакомый ID не забирает данные: обычный ответ на первичный `Send` по-прежнему обрабатывает вызывающая сторона. Порядок разрешения ID, ошибки, проверка `queued`/`accepted`, границы хода, права, контракты и strict-read пути не меняются.

## Замер

Замеряется действующий обработчик ответа **после разбора stdio-JSON**. В воспроизводимом тесте две версии исходного модуля скомпилированы вместе с каноническим `AgentOutput` и закреплёнными зависимостями. Подготовка JSON, список ожидаемых ID, сериализация результата, транспорт и дочерний процесс находятся за границей замера. Счётчик отражает вызовы аллокатора и запрошенные байты, включая realloc, а не задержку, RSS или память всего хода. Размеры текста и метаданные в таблице синтетические.

| Ответ дочернего процесса | Вызовы аллокатора до → после | Запрошено байт до → после |
|---|---:|---:|
| Короткий Unicode-текст, без метаданных | 4 → 0 | 679 → 0 |
| Текст 64 КиБ, без метаданных | 4 → 0 | 66 180 → 0 |
| Короткий текст и сводка | 40 → 6 | 6 070 → 2 792 |
| Короткий текст и вложенные метаданные | 137 → 30 | 39 589 → 18 352 |

Ноль означает отсутствие новых выделений на этой стадии, а не бесплатный разбор входного JSON.
Нераспознанный ID, обычный ответ `queued` и ошибки до декодирования не стали дешевле: соответствующие контрольные счётчики остались прежними. [Все результаты](probe.log).

## Проверка

- На 16 фикстурах побайтно совпали сериализованные результаты, цепочки ошибок и состояние ожидаемого ответа. Проверены первичный/неизвестный ID, повтор после подтверждения, отказ дочернего процесса, отсутствующую или неверно типизированную полезную нагрузку, `queued` без принятия, `null` и вложенные метаданные, Unicode и управляющие байты. Для чужого ID отдельно проверено, что исходный JSON остаётся доступен.
- Чистый кандидат прошёл **14/14** `process_agent_control`: дочерний процесс действительно заменил первый результат результатом нового хода; проверены также раздельная доставка, targeted cancel, ошибки запуска и неправильный первичный `Send`. Использованы существующие тестовые process fixtures. Форматирование, прямое/обратное применение и проверка пробелов в diff прошли. Патч применим поверх первой 50-патчевой композиции по проверке применения; совместный исполняемый прогон не выполнялся.
- Полный workspace, настоящий провайдер, macOS и Windows не проверялись.

Из чистого checkout указанной ревизии, Rust 1.95, Linux x86-64:

```sh
# PROPOSAL — абсолютный путь к этому каталогу.
git apply --check "$PROPOSAL/source.patch"
cargo fetch --locked
python3 "$PROPOSAL/probe.py" . "${CARGO_TARGET_DIR:-target}/r52-receipts"
git apply "$PROPOSAL/source.patch"
# С настроенными process fixtures:
python3 scripts/test.py -p proteus-core --test process_agent_control
```

Измеритель создаёт временную копию и не добавляет production-код или зависимости.

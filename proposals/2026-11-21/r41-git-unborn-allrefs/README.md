# Core: история всех Git-веток, когда у текущей ветки ещё нет коммита

Воспроизведение: в репозитории есть история, но после `git switch --orphan docs` у новой текущей ветки нет первого коммита. Запрос `GET /workspace/log?all=true` возвращал пустой список: проверка наличия HEAD срабатывала до выбора веток и тегов. Поэтому граф мог выглядеть пустым, даже когда коммиты оставались доступны по другим ссылкам.

`source.patch` отдельно применяется к `Proteus-harness/Proteus-core@32e56ecb4cc6da324c60dd6ae2da78f3b7e46e7f`. Если HEAD не разрешается и запрошены все ветки, обработчик передаёт Git уже предусмотренный набор `--branches --remotes --tags`, не добавляя несуществующий HEAD. Поле `head` остаётся `null`. При существующем HEAD набор аргументов не изменился, в том числе в detached HEAD. Если `all=false`, история ветки без коммитов по-прежнему пуста. Изменение не трогает запись в репозиторий, формат ответа или клиент.

**Что измерено:** поведение, не быстродействие. Один и тот же набор из шести тестов на настоящих временных Git-репозиториях: до исправления 5/6, после 6/6. Новый сценарий, вошедший в патч, переключается на ветку без коммитов, оставляет только тег и remote-tracking ветку и проверяет обе страницы с `limit=1`. У старого обработчика первая страница была пустой; обращение к `entries[0].summary` давало `null` вместо `latest`. Проверены также совсем пустой репозиторий, обычная история с ветками, родителями и метками, detached-коммит вне именованных веток, изменения, детали и diff. Тесты вызывают производственный обработчик под HTTP-маршрутом и его штатный Git launcher; сам HTTP-сокет и Desktop не запускались. Весь workspace не собирался.

**Воспроизведение** из checkout с доступным указанным Git-объектом (Rust 1.95, lld, Git; при проверке Git 2.52.0). Скрипт берёт файлы из закреплённой ревизии, применяет патч исключительно во временной директории и компилирует два сфокусированных Rust test-бинарника с одним набором уже собранных зависимостей. Передать `debug/deps` с единственным вариантом каждой требуемой `.rlib`:

```sh
python3 "$PROPOSAL/probe.py" . "${CARGO_TARGET_DIR:-target}/debug/deps"
```

Обычная проверка после применения в чистую рабочую копию:

```sh
git apply --check "$PROPOSAL/source.patch"
git apply "$PROPOSAL/source.patch"
cargo test --locked -p proteus-core --lib workspace_git_history
```

В `probe.log` сохранён дифференциальный прогон, в `gates.log` — отдельные проверки патча. `typecheck.log` — диагностика проверки библиотечного test target с кешированными зависимостями; это не запуск всей suite. Целостность: `sha256sum -c SHA256SUMS`.

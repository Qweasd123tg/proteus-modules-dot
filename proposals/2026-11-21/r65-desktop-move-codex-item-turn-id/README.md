# Desktop: не копировать ID хода в обычных событиях Codex

Когда Codex сообщает начало или завершение элемента, Desktop уже получает принадлежащую ему строку `turnId`. Раньше преобразование в `Item` копировало эту строку ещё раз. Теперь строка передаётся без копии. Старые страницы истории по-прежнему передают заимствованный ID, который копируется один раз.

Для длинных значений ограничитель сразу выделяет место под ту же UTF-8 часть и ту же пометку об обрезке. Это не увеличивает ёмкость строки, которую оставляет в памяти новый путь. Обычный короткий текст по-прежнему копируется привычным способом. Методы, входные поля, временные отметки, статусы и видимый текст не меняются.

База: [Proteus-desktop b6a7ec2d](https://github.com/Proteus-harness/Proteus-desktop/commit/b6a7ec2d8d7e486c8aba01291aa8c89774c4cded). SHA-256 патча: `03c393020eefd891e485b1501fb4f4a3a4de4247a23d5a9e2e94f7d5cc31d2e8`.

## Проверка

- **26 112** сравнений возвращаемых значений живых событий, **1 792** сравнения чтения истории и **64** сценария на границе UTF-8 и ёмкости. Сверены пустой, отсутствующий, неверно типизированный и длинный ID, отметки начала и завершения, статусы и типы элементов. У результата обычного события ёмкость строки ID не увеличилась; у заимствованного исторического ID она осталась точной и такой же.
- **7/7** тестов исходного модуля, **8/8** с патчем. Стенд использует исходные файлы проекции и типов, а выражение исторического вызова извлекается без изменений из клиента Codex. Сверены **14** идентичностей зависимостей, в том числе `serde_json 1.0.152` с `preserve_order` и `raw_value`.
- Прямое и обратное применение, `git diff --check` и rustfmt прошли. Затронутый файл совпадает с базой в M100 и фактическом сводном Desktop через R61. Наложения R62–R65 поверх последнего снимка побайтно совпадают в обоих порядках.

## Запросы к аллокатору на преобразование события

| Синтетический случай | Запросы, до → после | Запрошенные байты, до → после |
|---|---:|---:|
| Начало ответа | 5 → 4 | 114 → 84 |
| Завершение команды | 14 → 13 | 513 → 483 |
| ID на границе 128 КиБ | 6 → 4 | 524 380 → 131 170 |
| Нет ID | 3 → 3 | 54 → 54 |
| Обычный текстовый фрагмент | 3 → 3 | 49 → 49 |
| Некорректный элемент | 1 → 1 | 30 → 30 |

Счётчик суммирует `alloc` и `realloc` только внутри проекции уже разобранного JSON на Linux x86-64. Большой ID — проверка предельного случая, а не типичный трафик. Полная сборка, GPUI, время и RSS не измерялись.

## Как повторить

`git apply --check /путь/source.patch` из checkout базы. Узкая проверка: `bash verify.sh /путь/Proteus-desktop`. Нужны Bash, Git, Python 3.11+, Rust 1.95 с rustfmt и локальный Cargo-кэш для `harness.lock`. Стенд собирается без сети в один Cargo job. См. [evidence.log](evidence.log).

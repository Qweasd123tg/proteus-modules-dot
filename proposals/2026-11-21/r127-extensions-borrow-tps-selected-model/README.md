# TPS: не копировать выбранную модель при повторной отрисовке

Badge и Popup раньше копировали строки провайдера и модели при каждом обновлении, прежде чем сравнить их с сохранённой парой. Теперь сравниваются те же строки из состояния, а собственная пара создаётся только при прежнем сбросе по смене сессии или модели. Пустые строки по-прежнему считаются заданными, отсутствующее или нетипизированное поле по-прежнему не задаёт модель. Один короткий регрессионный тест проверяет заимствование фактической строки, пустой провайдер и нетипизированное имя модели.

Выбор последнего запроса, частота опроса, сроки, ошибки, обновление по завершению запуска и все поля сохранённого состояния не меняются. Патч не меняет маршрут, параметры, доступ, аутентификацию, лимиты и протокол.

## Проверка

Один точный патч проверен на upstream `892f627570369ed60d7205eb0d351c753ec4305f` и накопленной базе M150 с изменениями Extensions через #446. Релизные unit-тесты TPS: 4 → 5 и 6 → 7 соответственно. На обеих базах фактические релизные бинарники выдали одни и те же 46 stdout-кадров (40 347 байт), включая обычные обновления Badge и Popup, отдельную смену провайдера и имени, отсутствующую/пустую модель, ошибку 503, обновление после завершения запуска, смену сессии, отсутствие сессии и Preview. Совпали восемь GET по порядку, пути, сессии и статусу. Никаких записей, action-кадров, stderr или запросов к реальным сервисам.

Отдельный пробник измеряет только сравнение модели и сброс состояния до опроса, запроса и построения виджетов. Один обычный повтор: 2 вызова аллокатора / 30 запрошенных байт → 0 / 0. Двенадцать обычных повторов: 24 / 360 → 0 / 0, с более длинными Unicode-строками: 24 / 876 → 0 / 0. Смена действительного провайдера, имени или сессии требует столько же работы и выделений, как раньше. Нетипизированное имя больше не вызывает временную копию провайдера. Состояния во всех 11 проверках совпали, включая сохранённые сроки, флаги, измерение и ошибку. Эти цифры относятся только к этапу сравнения и не означают измеренный выигрыш по времени, RSS или всей отрисовке.

Для воспроизведения: `reproduce.py STOCK_REPO THROUGH_443_REPO --context-446 EXACT_446_PATCH --target EXISTING_TARGET --lock COMMON_LOCK`. Без `--admit-exclusive` это только локальная проверка входов. Для прогона нужен общий lock, тёплый отдельный Cargo target/home с точными зависимостями, Rust/Cargo 1.95.0 и одна задача locked/offline. Ровно две изолированные копии исходников. На обеих файловых системах оставлены прежние пороги 512 MiB на входе и 256 MiB stop, плюс резервы 32 MiB для исходников и 48 MiB для target перед экспортом. Сравнение привязано к свежим Cargo-артефактам, точным исходникам и релизному профилю. Полный workspace, нативный UI и отдельные штатные процессные тесты не запускались.

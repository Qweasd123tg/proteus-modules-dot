# Desktop: строить ключ высот истории без склейки строк

При синхронизации диапазона чата Desktop вычисляет ключ сохранённых высот строк. Раньше он собирал строку целиком: существующий ID вкладки, двоеточие и UUID сессии. Теперь те же байты поступают в SHA-256 по частям, а UUID кодируется в 36-байтный локальный буфер. Строка ID вкладки пока создаётся как раньше; промежуточной объединённой строки нет.

Ключ на диске не меняется. В хеш входят те же байты, включая строчные шестнадцатеричные цифры и дефисы UUID. Защита от подключения сохранённых высот до разрешения сессии, стабильность при переподключении, базовая ревизия, общий префикс и привязка к лейауту не изменены. Повторно использовать файлы высот можно без миграции.

База: [Proteus-desktop b6a7ec2d](https://github.com/Proteus-harness/Proteus-desktop/commit/b6a7ec2d8d7e486c8aba01291aa8c89774c4cded). SHA-256 патча: `469b3abb283e8be2c36dff599628fde019636438ac524d3a1728eea192a31f43`.

## Проверка

- **30 240** полных ключей совпали с исходной версией на каждом из двух исходных деревьев. Дополнительно для каждого случая проверена независимость от идентификатора процесса. Включены обе формы ID вкладки, длинные и Unicode-значения, потеря байта при преобразовании Unix-пути в UTF-8, разные UUID, ревизии, отсутствие сессии, границы префиксов и размеры около блока SHA-256.
- Новый штатный тест сверяет хеш с исходной форматированной строкой. Стенд извлекает точные исходную и изменённую функции ключа, тип ключа, хеширование и получение постоянного ID из сессии, оставляя минимум полей вместо нативной сессии. Использованы реальные `proteus-tabs`, `AppTranscriptCursor`, SHA-256 и UUID. Сверена **131** идентичность зависимостей.
- Проверка прошла на чистой базе и на Desktop, собранном из запечатанного M100 и десяти опубликованных правок вплоть до общего PR #391 (последняя Desktop-правка #388). Совпадение с промежуточным сводным снимком проверено по полному отпечатку файлов и ссылок. Сохранились **11** исходных символических ссылок; `Cargo.lock` не менялся. Прямое и обратное применение, `git diff --check` и rustfmt прошли.

## Запросы к аллокатору на один ключ

| Синтетический случай | Запросы, до → после | Запрошенные байты, до → после |
|---|---:|---:|
| Восстановленная история | 4 → 2 | 228 → 63 |
| История с переписанным окончанием | 4 → 2 | 228 → 63 |
| Unicode в пути вкладки | 5 → 2 | 288 → 43 |
| Контроль с непрозрачным ID | 5 → 2 | 212 → 37 |
| Постоянный ID сессии ещё отсутствует | 0 → 0 | 0 → 0 |

Счётчик суммирует `alloc` и `realloc` одного вычисления в Linux x86-64. Отрисовка, чтение дискового кэша, его попадания, полный запуск, время и RSS не измерялись. Нативная проверка геометрии остаётся отдельным этапом.

## Как повторить

`git apply --check /путь/source.patch` из checkout базы. Узкая проверка: `bash verify.sh /путь/Proteus-desktop [путь-к-сводному-Desktop]`. Нужны Bash, Git, Python 3.11+, Rust 1.95 с rustfmt и локальный Cargo-кэш для `harness.lock`. Стенд собирается без сети в один Cargo job, на временной копии исходников. См. [evidence.log](evidence.log).

# Git: компактные записи History и Graph

Обе панели раньше оставляли в памяти по одной JSON-карте верхнего уровня на запись загруженного журнала. Теперь на входе в кеш страница переносит пять строк, число даты и два исходных массива в закрытую модель расширения. Имена полей и остальные данные верхнего уровня не хранятся. Родители и метки в исходном порядке; глубже JSON не уплотняется. Кеши ветки и всех ссылок не объединяются.

Не меняются размер страницы (100), запросы, повтор страницы после ошибки, фильтрация графа, меню, вывод, сброс по ссылкам или права на действия. Graph по-прежнему игнорирует нестроковых родителей при построении линий; для показа Undo Commit по-прежнему достаточно непустого массива родителей (включая `[null]`). Для резервного запроса остался тот же исходный JSON и лимит 1; операция Undo в wire-проверке не вызывается. Одно место на каждую полученную запись, включая некорректную; поиск и короткий хеш сохраняют порядок совпадений. JSON отдельных коммитов и diff не меняется.

## Применение

- [source.patch](source.patch): отдельно к точному upstream Extensions `892f627570369ed60d7205eb0d351c753ec4305f`.
- [cumulative.patch](cumulative.patch): **вместо** первой версии к проверенному M150 с #394, #395, #397, #399, #402, #404, #406, #409, #412, #414 и #416. На этом дереве сохраняется оптимизация #375: работа с заимствованным журналом, добавление страницы на месте и сохранение указателя уже загруженной строки при ошибке и успехе. Вариант для upstream не заявляет эту прежнюю оптимизацию как новую.

## Узкая проверка

[reproduce.py](reproduce.py) проверяет подлинные исходники и порядок накладок, применимость и обратимость патча, форматирование, тесты пакета, проверку штатного release-бинарника через loopback и отдельный замер. См. `python3 reproduce.py --help`; аргументы: локальный Git с upstream-коммитом, корень исходников M150, 11 точных накладок по порядку, существующие `--target` и общий `--lock`. Для сборки нужен прогретый офлайн-кеш Cargo, Rust 1.95.0, заданный `CARGO_HOME` и явный флаг `--admit-exclusive`. Один job, не менее 512 МиБ свободными на каждом из двух томов при входе, порог остановки 256 МиБ. Без этого флага только предварительная проверка.

Сравнение сырых строк stdout до и после, протокол 4, UTC, только разрешённые GET на синтетический loopback. Отдельно от wire-запуска тестовый счётчик System считает живые запрошенные байты и блоки в одном потоке после разбора и помещения страницы в хранение, без корней UI. Перемещение строк и двух массивов, освобождение обоих кешей и тёплое чтение проверяются отдельно. Штатный ответ в измерении содержит полные хеши и короткие имена, тему, автора/email, дату, линейных и двух родителей, редкие метки; это синтетическая форма ответа, не статистика по репозиториям.

| Точный upstream | 200 268 Б | 66 980 Б | 133 288 Б |
| M150 + накладки до #416 | 223 596 Б | 66 980 Б | 156 616 Б (70,0%) |

На составном дереве одна страница удерживает 1 730 → 730 блоков, две — 3 460 → 1 460. Пустая страница не выделяет память. Хотя отдельный слот модели вырос с 72 до 184 Б, удалены верхнеуровневые карты, ключи и индексы; указатели строки, родителей и меток сохраняются. На холодном приёме составной вариант добавляет **одно выделение 18 400 Б** для вектора со 100 строками; до изменения вектор JSON переносился без выделения на этом шаге. Тёплое заимствование из кеша по-прежнему не запрашивает память. Точный upstream сохраняет старую семантику возврата копии, но сама копия дешевле: 200 268 → 45 668 запрошенных Б при чтении 100 записей. Измерение удержания учитывает представление после приёма страницы, а не промежуточные копии при первой публикации кеша upstream. Замер двух кешей не моделирует запас ёмкости при добавлении короткой страницы в один вектор.

**Проверка:** тесты пакета 41 → 43 (upstream), 46 → 48 (составное дерево); 18 побайтно одинаковых кадров stdout (905 146 Б) и 14 GET / 0 операций записи в каждом из четырёх прогонов. Включены два журнала с проверкой 100 → 102 записей, запрос той же страницы после отказа, граф с ветвлением, метки и ошибочные поля, поиск через границы полей с переключением регистра/следующим/предыдущим результатом, исходная загрузка деталей и оба пути определения наличия родителя HEAD. Полные хеши исходников, артефактов Cargo и результаты: [checks.log](checks.log), [artifact-receipts.log](artifact-receipts.log), [measurements.log](measurements.log).

Полный workspace, нативный Desktop и упаковка здесь не запускались; это приватный модельный путь одного пакета, без изменения схемы. Счётчик не измеряет RSS, время старта, скорость, накладные расходы аллокатора или высоководную отметку всей операции.

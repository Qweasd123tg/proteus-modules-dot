# skill-pack: вернуть подготовленное тело навыка без второй копии

База: **Proteus-harness/Proteus-modules@9469e3b12529d08b1f4a76882693e2065e842c51**. Локальный commit `b2d56e28d6de0ecf81daf9969c221c1cd71e30e7`.

Тело выбранного навыка уже хранится в собственной строке, но `json!` раньше повторно копировал её при формировании успешного ответа. Теперь ответ сохраняет то же поле и порядок вставки, а строка передаётся туда по владению. Обнаружение, доступность, валидация, обработка ошибок, метаданные и текст ответа не меняются.

## Проверки

- Полный unit-suite `skill-pack`: **9/9 → 10/10** в isolated Release sorted и workspace Debug `serde_json/preserve_order`. Оба исходника собраны rustc 1.95.0 Linux x86-64 против ранее собранных locked зависимостей. Общий target не изменялся.
- **16 побайтных сравнений** (по три пары) полных ответов реального `SkillTool` на локальных fixtures: короткое, длинное, пустое и CRLF-тело; отсутствующий/отключённый навык, неверный тип аргумента и имя инструмента. Отдельно проверены тело, метаданные и порядок ключей.
- `rustfmt --check`, `git diff --check` и точное применение к базе. Поверх проверенной копии M100 применены R57–R64 (включая R62/R63/R64), затем R65. На этом составном исходнике **13/13** тестов `skill-pack` в workspace Debug, включая #341 (выбор body) и #376 (XML каталога). Полный workspace gate не запускался.

## Аллокации

Измерен активный вызов `SkillTool` с чтением тестовых файлов и сериализацией ответа, без IPC. Все случаи использовали один и тот же синтетический набор файлов. Это запросы Rust-аллокатора, не RSS или задержка.

| Sorted Release | Запрошено байтов | Запросов | Пик живых байтов |
|---|---:|---:|---:|
| Тело 143 999 B | 1 630 781 → 1 486 782 | 289 → 288 | 410 906 → 410 906 |
| Тело 43 B | 963 566 → 963 523 | 280 → 279 | 410 908 → 410 908 |
| CRLF-тело 36 B | 963 564 → 963 528 | 280 → 279 | 410 910 → 410 910 |

Те же сокращения ровно на размер строки в `preserve_order`. На пустом теле и ошибках все метрики неизменны. Ни один пик не вырос. Сырые выборки и хеши ответов в `bench.log`.

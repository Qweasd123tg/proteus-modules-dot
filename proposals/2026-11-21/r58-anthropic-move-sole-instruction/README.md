# Anthropic: повторно использовать готовый префикс инструкций

База: **Proteus-harness/Proteus-modules@9469e3b12529d08b1f4a76882693e2065e842c51**. Локальный commit `a8a3f3c8d162d699289b5147659964af6c7430ac`. Изменены только сборка запроса Anthropic и её тест.

Если в запросе есть только один вид инструкций (canonical либо legacy System), уже собранная строка становится полем `system` без повторного копирования. Если присутствуют оба вида, добавляем прежний разделитель и legacy-группу к canonical-префиксу. Приоритеты, порядок равноприоритетных блоков, пробелы, обработка пустых частей и cache-control остаются прежними. OpenAI и общий рендерер не меняются.

## Проверка

- **28 побайтных сравнений полного JSON запроса** (по три пары), охватывающих оба формата карт и cache off/on. Включены длинные и короткие canonical/legacy префиксы, смешанные группы, Unicode, равные приоритеты, пустая строка и пара пустых legacy-сообщений. Отдельно проверяется значение поля `system`, включая cache-control.
- Изолированный Release использует сортированные ключи; закреплённый граф Debug workspace tests включает `serde_json/preserve_order` (и `raw_value`). Для обоих arm использованы одни и те же ранее собранные locked Cargo-зависимости соответствующего графа, rustc 1.95.0 Linux x86-64. Тесты формирования запроса в workspace-графе: **Anthropic 4/4 → 5/5, OpenAI 3/3 → 3/3**. Общий Cargo target оставался доступен только на чтение; полный workspace gate не запускался.
- `rustfmt --check`, `git diff --check`, `git apply --check` на точной базе; оба изменённых файла не затронуты 100 выбранными патчами M100.

## Аллокации

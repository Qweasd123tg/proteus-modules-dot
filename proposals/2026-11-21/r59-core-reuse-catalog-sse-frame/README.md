# Core: переиспользовать SSE-кадр обновления каталога

Самостоятельный патч к [Proteus-core@32e56ecb](https://github.com/Proteus-harness/Proteus-core/commit/32e56ecb4cc6da324c60dd6ae2da78f3b7e46e7f). При смене каталога и при подключении после уже завершённого обновления Core отправляет одно и то же уведомление `SessionCatalogUpdated`. Оно не содержит пользовательских данных или ID сессии/запроса. Вместо повторного кодирования в каждой ветке Core один раз строит его обычным SSE-сериализатором и отдаёт неизменяемые копии `Bytes`.

Правила выбора клиентов, порядок и число событий, формат JSON/SSE, связь с watch, heartbeat и обработка ошибок остаются прежними. Обычные события и ответы продолжают кодироваться отдельно. Удерживается только один общий фиксированный кадр, не растущий кэш.

## Замер

Измерено создание и освобождение готовых `Frame<Bytes>` для этого одного события. Счётчик отражает вызовы аллокатора и запрошенные байты, включая realloc; счётчики повторов начинаются после первой выдачи. Нет измерений сетевой задержки, RSS или всего HTTP-потока.

| Выдача уведомления | Запросы аллокатору до → после | Запрошено байт до → после |
|---|---:|---:|
| Первая выдача | 3 → 3 | 328 → 328 |
| Один повтор | 3 → 0 | 328 → 0 |
| 16 повторов | 48 → 0 | 5 248 → 0 |
| 256 повторов | 768 → 0 | 83 968 → 0 |

Логическая длина сериализованного кадра — 81 байт; это не измерение полного объёма общего буфера или его служебных полей.

[Сырые счётчики](probe.log).

## Проверка

- Новый кадр побайтно совпал с прежним и разбирается обычным DTO как `SessionCatalogUpdated`. Повторная выдача и чтение четырьмя независимыми потребителями проверены.
- Пройдено **3/3** целевых тестов, включая измеритель. Штатные тесты SSE прошли, включая реальное уведомление после обновления сохранённой сводки и повторное подключение после завершения обновления. Использованы проверенные локальные process fixtures M100. Форматирование, точное прямое/обратное применение и пробелы в diff проверены. Патч применим вместе с R57 и R58 поверх M100 по проверке применения; совместного прогона не было.
- Полный workspace, внешний сетевой клиент, Windows и macOS не проверялись.

Из чистого checkout указанной ревизии, Rust 1.95, Linux x86-64:

```sh
# PROPOSAL — абсолютный путь к этому каталогу.
git apply --check "$PROPOSAL/source.patch"
cargo fetch --locked
# С process fixtures для scripts/test.py:
# PROTEUS_TEST_REFERENCE_MODULE и PROTEUS_TEST_SESSION_STORAGE_MODULE
# указывают на готовые исполняемые файлы.
python3 "$PROPOSAL/probe.py" . "${CARGO_TARGET_DIR:-target}/r59-sse-catalog"
```

Парные счётчики установлены только в тестовый бинарник во временной копии. В рабочую сборку инструментирование не добавляется.

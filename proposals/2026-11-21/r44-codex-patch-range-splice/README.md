# Codex patch: заменять блок строк одним перемещением диапазона

**Для:** `Proteus-harness/Proteus-modules@9469e3b12529d08b1f4a76882693e2065e842c51`. Самостоятельный `candidate.patch`, исходный локальный commit `f7d2f087bee66effc58cc02cdbc3371f3c420344`. Изменяются только `tool/codex-patch/src/update.rs` и тесты. Парсер, поиск (включая fuzzy match), предварительная проверка, повторное чтение и запись файла не менялись.

Внутри одного найденного блока старый код удалял каждую старую строку и вставлял каждую новую отдельно. При замене 512 строк в начале файла это сдвигало элементы оставшегося хвоста 1 024 раза за один проход. Модуль строит результат как при проверке патча, так и при его применении. Теперь один `Vec::splice` заменяет диапазон целиком; при равных длинах хвост не нужно сдвигать для каждой строки. Это не ускорение поиска совпадений.

## Сохранение поведения

Все позиции находятся на исходном файле из N строк. Для обычного совпадения поиск гарантирует `start + old_len <= N`. Пустой образец после снятия последней пустой строки возвращает текущий курсор: он начинается с нуля и обновляется только до конца найденного образца или сразу после найденной строки контекста, то есть не превышает N. Чистая вставка выбирает N или N−1 при последней пустой строке.

Перед применением список подвергается стабильной сортировке по началу, включая EOF-блоки и равные позиции. Применение по-прежнему идёт в обратном порядке. Предыдущий шаг в позиции t ≥ start оставляет как минимум t строк, даже когда всё после неё удалено. Поэтому начало текущего блока всегда допустимо; его конец ограничивается текущей длиной. Это воспроизводит прежнее поведение перекрывающихся EOF-замен. Сохраняется и порядок нескольких вставок в одну позицию.

## Измерение

Медиана времени **реального `apply_patch`** от начала разбора до возврата результата, включая filesystem verification, повторное чтение и запись на tmpfs. Подготовка патча/файла и последующая проверка байтов вне таймера. Пять сценариев; в каждом 48 000 неизменённых строк. В каждом из двух прогонов одна разогревочная пара и восемь измеренных пар; порядок baseline/candidate чередуется. Linux x86-64, rustc 1.95.0, оптимизация измеряемого crate `-C opt-level=3`, одни и те же кэшированные зависимости с закреплённым Core. Это время вызова инструмента, не Desktop или длительность агентского хода.

| Замена (старых → новых строк) | Первый прогон, мс до → после | Повтор, мс до → после |
|---|---:|---:|
| 512 → 512 в начале | 57,882 → 9,607 | 63,136 → 9,976 |
| 512 → 32 в начале | 31,678 → 6,638 | 31,060 → 7,119 |
| 32 → 512 в начале | 31,627 → 6,561 | 31,291 → 6,897 |
| 512 → 512 в конце | 6,446 → 6,526 | 6,925 → 7,385 |
| 1 → 1 в начале | 6,157 → 6,586 | 7,079 → 6,899 |

Для большой замены перед длинным хвостом выигрыш повторился. На однострочной замене выигрыш не установлен; в первом прогоне медиана была хуже на 0,429 мс. Для конца файла оба замера немного хуже; не заявляем общего ускорения всех патчей. Сырые значения и хеши файлов в `results.log` и `recheck.log`, второй прогон выполнялся при параллельной сборке.

## Проверки и воспроизведение

- Прямой Cargo на закреплённых зависимостях: `cargo test --locked -p codex-patch --lib --offline` **29/29**, включая две регрессии: перекрывающее удаление с EOF и вставки в одну позицию перед финальной пустой строкой. Результат в `suite.log`. Повторная сборка target через rustc с готовыми зависимостями также дала 29/29. `cargo fmt --all --check`, `git diff --check`, `git apply --check` на точной базе прошли.
- Побайтовая сверка 6 272 пар результатов `update::contents`: 1 012 успешных и 5 260 ошибок с одинаковым текстом. Включены пустые файлы, пустые строки, CRLF, контексты, EOF, пересечения и разные длины. В 5 сценариях полного `apply_patch` также совпали выходные файлы и текст ответа. `probe.rs` добавляется только во временную проверочную копию.
- Обёртка `scripts/test.py` остановилась на общепроектном `cargo metadata`: в офлайн-кэше не было `android_system_properties v0.1.5`. Это не затронуло успешный прямой запуск Cargo для изменённого crate. Полный workspace, сборка установочного пакета и Desktop не проверялись.
- Самостоятельно: `python3 reproduce.py /path/to/Proteus-modules` (Git, Cargo, закреплённые зависимости). Скрипт берёт точную базу, применяет патч только к кандидату, собирает обе версии и сравнивает ответы на одинаковых входах. Для проверки только модуля: `git apply candidate.patch`, затем `cargo test --locked -p codex-patch --lib`.

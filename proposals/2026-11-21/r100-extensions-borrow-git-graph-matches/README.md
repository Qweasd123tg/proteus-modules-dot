# Git Graph: не копировать все хеши из результатов поиска

Графу нужны число совпадений и позиция текущего коммита, а команде перехода нужен только один полный хеш. Раньше обе операции собирали временный список с копией каждого совпавшего хеша. Теперь граф считает совпадения по заимствованным значениям, а новый поиск и переходы копируют только выбранный хеш.

Сохраняются поиск по хешу, описанию, автору и email, точные пробелы между полями, регистр и Unicode lowercase, счётчик и кнопки при пустом результате. Если совпадений нет, выбранный коммит не сбрасывается. Для повторяющихся хешей по-прежнему берётся первое совпадение, а перемещение за край списка переносит в противоположный конец. Формат сообщений, GET-запросы, пагинация, история и панель сведений не меняются. Нового кеша и состояния нет.

## Проверка и применение

Два эквивалентных патча адаптированы к представлению записей: [source.patch](source.patch) для upstream `892f627570369ed60d7205eb0d351c753ec4305f` (JSON `Value`); [cumulative.patch](cumulative.patch) для точного M150 Extensions с 14 накладками до #422, дерево `db2430f5ca3252f22d643ef67c73396ec6b52d586a05385e25ef4d7adc9538e9` (типизированный `LogEntry`). Нужен один соответствующий патч, не оба. Меняется один файл пакета Git с собственным тестом.

[reproduce.py](reproduce.py) проверяет исходники и точный порядок накладок, Cargo.lock, применимость и обратимость патча, форматирование, release-тесты пакета, оригинальные байты stdout и отдельный пробный замер. См. `python3 reproduce.py --help`. Нужны Rust 1.95.0, локальный прогретый офлайн-кеш `CARGO_HOME`, существующая цель `--target` и общий `--lock`. Без `--admit-exclusive` только предварительная проверка. С флагом: офлайн и один job, порог допуска 512 МиБ и порог остановки 256 МиБ.

На синтетическом loopback проверены обычная история и панель сведений, первая и следующая страницы графа, переходы и их зацикливание, сброс выбора, отсутствие совпадений, выбор несовпавшего коммита, поиск на стыке полей, Unicode с греческой сигмой и турецкой İ, буквальный пробел и переключение регистра. Отдельно проверены повтор хеша после исключённой строки с тем же хешем и пустые/нестроковые исходные значения.

## Результаты

Штатные release-тесты: **41 → 42** на upstream, **48 → 49** в композиции. Во всех четырёх вариантах совпали **32 сырых кадра stdout (1 909 880 Б)**, 20 упорядоченных GET и ноль операций записи. Пять одинаковых диагностических прогонов на вариант сверили результат и счётчики в 15 сценариях.

| Синтетический сценарий | Копий хеша, до → после | Запрошено у аллокатора | Проверок совпадения |
| --- | ---: | ---: | ---: |
| Счётчик графа, 100 из 100 совпадений | 100 → 0 | 10 048 → 0 Б | 100 → 100 |
| Счётчик графа, 500 из 500 | 500 → 0 | 44 480 → 0 Б | 500 → 500 |
| Новый поиск, первое из 500 совпадений | 500 → 1 | 44 480 → 40 Б | 500 → 1 |
| Единственное совпадение на последней из 500 строк | 1 → 1 | 136 → 40 Б | 500 → 500 |
| Следующее в середине 500 совпадений | 501 → 1 | 44 520 → 40 Б | 500 → 125 |

При пустом запросе обе версии обходятся без проверок совпадения и выделений для хешей. Если непустой запрос не дал совпадений, обе версии проверяют все строки, не выделяя память для списка хешей.

Замер считает вызовы и запрошенные байты при формировании списка хешей или копировании выбранного хеша, а также обращения к существующему предикату. Нормализация запроса, временная поисковая строка, поля графа и детали, чтение истории и вывод кадра вне замера. Для счётчика графа все записи всё ещё проверяются; переход с переносом также может пройти весь список. Запрошенные байты учитывают новый размер при перевыделении и не означают удержанный объём, пиковую память или RSS. Время, полный workspace, нативный Desktop и упаковка не проверялись.

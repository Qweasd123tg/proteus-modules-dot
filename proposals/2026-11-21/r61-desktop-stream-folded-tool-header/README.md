# Desktop: один проход для заголовка свёрнутой цепочки инструментов

Заголовку свёрнутой группы нужны количество вызовов, названия с повторами и один статус. Раньше строка собирала ссылки на все вызовы во временный вектор, а заголовок повторно обходил его для статуса. Теперь один итератор передаёт ссылки прямо в расчёт заголовка. Вектор уникальных названий остаётся: он нужен для первых вхождений и их счётчиков.

Сохранились порядок и подписи, суммарное количество вызовов, приоритеты `running`/`approved` → ожидание подтверждения → ошибка/отказ → прерывание → успех. Незнакомый статус по-прежнему считается прерыванием, если ничего более приоритетного нет. Сами элементы, их раскрытие, подсказки, действия и поведение при потере связи не менялись.

База: [Proteus-desktop b6a7ec2d](https://github.com/Proteus-harness/Proteus-desktop/commit/b6a7ec2d8d7e486c8aba01291aa8c89774c4cded). SHA-256 патча: `6337a285d71509eb315125721c923b59ba754851766a070fe284ed4c68e2607b`.

## Проверка

Стенд использует штатные `Transcript::reset` и `tool_chain`, а также извлечённые из точной базы код сбора ссылок, группировку названий, выбор статуса и предикат `is_running`. Сравнивались тройки «количество, статус, упорядоченные подписи»; среди входов все сочетания десяти статусов и четырёх названий для трёх последовательных вызовов, а также пустые диапазоны и диапазоны со строками без инструментов.

Сверено **125** идентичностей зависимостей (имя, версия, источник и контрольная сумма), включая закреплённый `proteus-contracts`. Прямое и обратное применение, `git diff --check` и rustfmt прошли. Патч также применяется на M100 и на фактический сводный Desktop с правками по R60 включительно. Два изменяемых файла в обеих базах до патча побайтно совпали с исходной ревизией, новый путь был свободен.

Прошли все **42** узких теста: 41 тест исходного транскрипта и один добавленный тест заголовка. С исходным расчётом совпали все **64 028** сравнений.

## Запросы к аллокатору на один заголовок

| Синтетическая группа | Запросы, до → после | Запрошенные байты, до → после |
|---|---:|---:|
| Три одинаковых вызова `read_file` | 2 → 1 | 128 → 96 |
| Восемь разных инструментов | 4 → 2 | 384 → 288 |
| 48 вызовов трёх инструментов со смешанными статусами | 6 → 1 | 1 088 → 96 |
| Пустой контрольный диапазон | 0 → 0 | 0 → 0 |

Счётчик суммирует `alloc` и `realloc` только внутри расчёта заголовка на уже подготовленном транскрипте. Создание строк, форматирование виджетов, время и RSS не измерялись.

## Как повторить

`git apply --check /путь/source.patch` из checkout базы. Узкая проверка: `bash verify.sh /путь/Proteus-desktop`. Нужны Bash, Git, Python 3.11+, Rust 1.95 с rustfmt и локальный Cargo-кэш для `harness.lock`. Стенд собирается без сети в один Cargo job. См. [evidence.log](evidence.log). Проверялась модель заголовка, а не полная сборка и не нативное окно GPUI.

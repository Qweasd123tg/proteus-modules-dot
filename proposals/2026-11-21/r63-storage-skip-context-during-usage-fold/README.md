# Storage: не строить контекст модели при запросе только статистики расхода

Холодный ReadUsage всё так же читает и строго проверяет весь
зафиксированный префикс. Он подсчитывает usage по тем же записям,
но не строит отдельный контекст модели, который этот ответ никогда
не использует. В закреплённой семантике эта проекция только меняет
локальные структуры; она не валидирует записи, не делает I/O и
не является входом для UsageProjection.

Не меняются чтение/декодирование, SHA/EOF, проверка последовательности
и ревизии, blob или recheck версии источника. Общий код сбрасывает
курсор до чтения и выставляет verified только после полной проверки.
ReadConversation, OpenDisplaySnapshot, writer/resume и terminal page
по-прежнему используют полный путь. Частичная проекция в снимке
не хранится. Изменён только ReadUsage при фактическом чтении журнала;
Core может получить usage из уже готового view и вообще сюда не
попасть. В трассе обычного JSONL-125k restore/resume R59 ReadUsage
не наблюдался. Это **не оптимизация указанного startup-сценария**.

## Счётчики

Синтетические журналы получены штатным Commit на JSONL и SQLite:
320 обычных модельных ходов, включая три сохранённых ошибки провайдера,
20 компакций истории и 1 620 канонических записей. Один release
test-артефакт переключал прежний полный Fold и новый Fold только для
usage; две пары в обратном порядке. Измерены Rust alloc/alloc_zeroed/realloc
и запрошенные байты вокруг фактического StorageService::execute
ReadUsage. Сериализация DTO и SDK transport не входят в этот счётчик.

| Backend | Запрошенных байтов меньше в каждой паре | Вызовов аллокатора меньше |
| --- | ---: | ---: |
| JSONL | 169 440 / 134 952 (1,0–1,3%) | 335 / 306 |
| SQLite | 180 544 / 163 768 (2,8–3,1%) | 339 / 344 |

Оба режима строго декодировали те же 1 620 записей. Вызовы функции
проекции контекста в этом запросе 1 620 → 0, не все они были
дорогими. Пустой контроль не изменился. Первоначальная диагностическая
попытка слишком строго требовала побитового равенства аллокаций
между повторными воспроизведениями; сырые значения варьируют.
Сохранены начальный отказ и обе финальные пары, направление результата
совпало. Проверенные DTO-байты одинаковы внутри каждого fixture;
это не измерение сырого JSON-RPC envelope. Пиковая память, RSS,
время и итоговый размер двоичного файла не измерялись. Const generic
позволяет оставить полный проход без новой динамической ветки,
но может добавить специализированный машинный код.

## Проверки

- [candidate.patch](candidate.patch): точный Modules
  9469e3b12529d08b1f4a76882693e2065e842c51, Core SDK
  0c1b7572313230e5d123e95c722e1258a2e9ecd6.
- **64 native tests прошли, один прежний ignored**. Новый тест:
  успешная и ошибочная usage, прежняя usage и контекст после
  штатного append, новая ревизия и последняя запись старого снимка.
- Две отдельные диагностические проверки прошли. Равные
  сериализованные Usage DTO и checks на валидном journal;
  одинаковый контролируемый EOF I/O error и stale revision error
  без доверия ошибочному снимку. В journal ничего не записывалось
  при чтении.
- Прямое/обратное применение и форматирование пройдены. Тот же diff
  применим к R62 preflight плюс #372 Storage overlay, без отдельной
  compositional версии или runtime-прогона. Инструментация тестовая
  и не входит в патч.

# Core: убрать временные аллокации при восстановлении текста истории

Самостоятельный патч к [Proteus-core@32e56ecb](https://github.com/Proteus-harness/Proteus-core/commit/32e56ecb4cc6da324c60dd6ae2da78f3b7e46e7f).

При чтении сохранённой истории рендерер создавал временную строку с названием роли и отдельный вектор ссылок даже для обычного сообщения с одним текстовым блоком. Патч хранит роль как заимствованную статическую строку до создания строки ответа, а последний текстовый блок держит отдельно. Если блок один, он сразу копируется в готовую строку. Если блоков несколько, используется прежнее объединение с `\n`; ёмкость вспомогательного вектора переиспользуется между текстовыми фрагментами того же сообщения.

Порядок карточек, исходный текст (включая Unicode и пробелы вокруг непустого текста), отсечение полностью пустых блоков, привязка изображений, цитаты, timestamps и состояние незавершённых инструментов не меняются. Патч меняет только общий локальный рендерер текста: он используется, в частности, при восстановлении холодной истории; не изменены журнал, схема ответа, проверки, права, границы replay и контракты модулей. Строки с текстом и ролью в самом ответе по-прежнему имеют собственную память.

## Как измеряли

Измеряется действующий путь рендера фиксированного, уже проверенного журнала; записи подаются из памяти через штатный тестовый вход `from_records`, который вызывает production `transcript_from_scan`. В счёт входят клонирование записей при тестовой подаче, сбор индексов и полный рендер. Не входят подготовка и строгая проверка фикстуры, I/O, декодирование удалённого журнала, HTTP, GUI или сериализация результата. Счётчик аллокатора из `proteus-contracts` включает новую ёмкость при realloc. Это **не RSS, пиковая память или время ответа**; относительный выигрыш зависит от длины текста, состава истории и затрат за пределами рендерера.

| Сообщений и формат | Строк | Вызовы аллокатора до → после | Запрошено байт до → после |
|---|---:|---:|---:|
| 0, один блок | 0 | 0 → 0 | 0 → 0 |
| 1, один блок | 1 | 15 → 13 | 3 931 → 3 858 |
| 128, один блок | 128 | 1 314 → 1 058 | 328 592 → 319 248 |
| 1 024, один блок | 1 024 | 10 289 → 8 241 | 2 646 736 → 2 571 984 |
| 128, четыре блока | 128 | 2 086 → 1 958 | 558 672 → 557 520 |
| 128, текст + карточки | 640 | 9 283 → 9 155 | 2 425 660 → 2 424 508 |
| 128, только reasoning | 128 | 1 186 → 1 058 | 315 792 → 314 640 |

До изменений прошёл **51/51** тест, после **52/52** (включая измеритель); ответы на всех семи фикстурах совпали побайтно. Без измерителя кандидат отдельно прошёл **51/51** штатный тест.

Прогон сравнивает все сериализованные снимки побайтно (фиксированы идентификаторы и время) и запускает штатную группу тестов `app_server::transcript::` на базе и кандидате. Добавлен сценарий с повторными границами инструментов, Unicode-пробелом и многочастным текстом; штатные тесты покрывают изображения, reasoning, прерванные инструменты, hosted-цитаты, историю после замены и пути восстановления. Полный workspace, HTTP, реальные storage-процессы, macOS и Windows не запускались.

## Воспроизведение

Из неизменённого checkout Core указанной ревизии, Rust 1.95, Linux x86-64:

```sh
# PROPOSAL — абсолютный путь к этому каталогу.
git apply --check "$PROPOSAL/source.patch"
cargo fetch --locked
python3 "$PROPOSAL/probe.py" . "${CARGO_TARGET_DIR:-target}/r46-replay"
git apply "$PROPOSAL/source.patch"
# Штатный тестовый runner в окружении с настроенными process fixtures:
python3 scripts/test.py -p proteus-core --lib app_server::transcript::
```

`probe.py` создаёт временную копию чистого исходника и подключает только тестовые измерители; сборка `cargo test --locked --offline` использует один набор зависимостей для обеих версий и не меняет исходный checkout.

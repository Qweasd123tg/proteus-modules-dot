# Desktop: определять область чата без копирования ключей предков

При выборе чата в рабочей области Desktop проходит по сохранённым родительским связям. Раньше он заранее строил строковый ID выбранной вкладки, копировал ключ каждого посещённого предка и затем копировал ключ результата. Теперь обход использует ссылки на те же ключи и строит строковый ID результата. ID исходной вкладки отдельно нужен только тогда, когда её нет в списке сводок и приходится смотреть сохранённого владельца.

Сохранились проверка циклов, первое совпадение при дублях и приоритеты: найденный предок, указанный отсутствующий родитель, исходный ключ при цикле, затем сохранённый владелец или исходная вкладка для сессии без сводки. Код не меняет область или сохранённые данные сам по себе. Proteus и Codex по-прежнему используют разные ключи, даже если их строковые части совпадают.

База: [Proteus-desktop b6a7ec2d](https://github.com/Proteus-harness/Proteus-desktop/commit/b6a7ec2d8d7e486c8aba01291aa8c89774c4cded). SHA-256 патча: `17b951ff18359158d3922deb36d5ec62d9c67edad2b5a92188d03d9849dc4960`.

## Проверка

- **325 246** сравнений точных строковых ID с исходной версией на синтетических каталогах: обе системы ключей, циклы, отсутствующие родители, дубли, записанный владелец вкладки и его отсутствие. Отдельный тест на Unix различает исходную запись пути и запись того же пути, хранящуюся у найденного предка.
- **12/12** узких тестов: по три исходных теста резолвера в каждом варианте, новый тест пути и пять тестов сводок разговоров. Использованы исходные `ChatSpaces` и `TabLayout` из `proteus-tabs`; сверены **124** точные идентичности зависимостей.
- Прямое и обратное применение, `git diff --check` и rustfmt прошли. Затронутый файл совпадает с базой в M100 и в сводном Desktop через R61. Правки R62–R64 применились поверх этого снимка в обоих порядках, результат побайтно одинаковый.

## Запросы к аллокатору при выборе области

| Сценарий | Запросы, до → после | Запрошенные байты, до → после |
|---|---:|---:|
| Записанная корневая сессия | 5 → 2 | 86 → 33 |
| Один родитель | 7 → 3 | 254 → 85 |
| Два родителя, ключи разных драйверов | 8 → 3 | 273 → 85 |
| 47 родителей | 57 → 7 | 5 175 → 1 229 |
| Сводка родителя отсутствует | 7 → 3 | 254 → 88 |
| Циклическая связь | 9 → 3 | 284 → 88 |
| Нет сводки, есть сохранённый владелец | 4 → 4 | 85 → 85 |
| Нет сводки и владельца | 3 → 3 | 66 → 66 |

На Linux x86-64 посчитаны `alloc` и `realloc` одного вызова резолвера на готовых структурах. Сам набор посещённых ключей по-прежнему нужен для определения циклов. Полная сборка, открытие вкладки в GPUI, время и RSS не измерялись.

## Как повторить

`git apply --check /путь/source.patch` из checkout базы. Узкая проверка: `bash verify.sh /путь/Proteus-desktop`. Нужны Bash, Git, Python 3.11+, Rust 1.95 с rustfmt и подготовленный локальный Cargo-кэш для `harness.lock`. Стенд собирается без сети в один Cargo job. См. [evidence.log](evidence.log).

# Usage: сравнивать модель без временной строки на каждый запрос

«Расход» строит список моделей и фильтрует запросы по ключу `провайдер/модель`. Раньше обе операции для сравнения выделяли новую строку на каждый запрос. [Патч](source.patch) сопоставляет заимствованные части ключа, а строку создаёт только для нового пункта списка. Порядок первого появления, регистр и обработка пустых полей сохранены. Например, `a/b` + `名` и `a` + `b/名` по-прежнему дают один пункт. Агрегация по моделям, цены, поиск и сортировка не изменены.

База: [Proteus-desktop-extensions@892f627](https://github.com/Proteus-harness/Proteus-desktop-extensions/commit/892f627570369ed60d7205eb0d351c753ec4305f).

| Записей | Список моделей, байт | Фильтр модели, байт | Страница с выбранной моделью, байт |
|---:|---:|---:|---:|
| 1 | 135 → 135 | 71 → 32 | 73 951 → 73 912 |
| 20 | 576 → 167 | 704 → 224 | 234 451 → 233 562 |
| 400 | 9 696 → 167 | 13 664 → 4 064 | 456 083 → 436 954 |
| 2 000 | 48 096 → 167 | 64 352 → 16 352 | 713 711 → 617 782 |

Это запрошенные у аллокатора байты за один вызов, включая перераспределения. Синтетический журнал уже загружен; подготовка, HTTP, сериализация и весь процесс не входят в замер. Показаны и отдельные операции, и полное построение страницы. [Счётчики](measurements.log) совпали в пяти отдельных release-процессах на версию. Время и RSS не измерялись.

- Штатный `extension-usage`: **12/12** на базе, **13/13** с патчем в debug и release. Новый тест проверяет слэши, пустые и нетипизированные поля и ложные совпадения.
- **8 обычных кадров** процесса совпали побайтно, включая переключение моделей и периода, переход страницы, возврат по неизвестному ключу, а также `null`. Порядок **2 HTTP-чтений** совпал. **16** измерительных проекций и деревьев тоже совпали.
- #291 меняет порядок ходов, #309 владение снимком Analytics, #322 поиск. Оба порядка наложения дали одинаковое дерево. Проверка применения к неизменённому M100 прошла. [Журнал](checks.log).

Повтор: `python3 reproduce.py путь-к-репозиторию` (Git, Python 3, Cargo/rustfmt, TCP loopback). Входной checkout не меняется; при готовых зависимостях можно задать `CARGO_NET_OFFLINE=true`. Весь workspace, упаковка и нативное окно не проверялись.

# Анализ ходов: без промежуточных копий результата

При раскрытии результатов инструментов и итоговых ответов панель сначала глубоко копировала исходный JSON, а блок кода ещё раз копировал готовый текст. [Патч](source.patch) читает исходное значение по ссылке и передаёт подготовленную строку во владение блоку. Для готового текста остаётся та копия, которая нужна дереву виджетов; строка форматированного JSON передаётся без копии. Кэш и нативный интерфейс не меняются. Сохраняются переносы, расчёт высоты, порядок полей, начальное состояние раскрытия и различие между отсутствующим выводом, пустой строкой и явным `null`.

База: [Proteus-desktop-extensions@892f627](https://github.com/Proteus-harness/Proteus-desktop-extensions/commit/892f627570369ed60d7205eb0d351c753ec4305f).

## Замеры

Байты, запрошенные у аллокатора при построении карточек и всей страницы на готовой синтетической записи, включая перераспределения. Подготовка записи, HTTP, чтение кэша и сериализация готового дерева не измерялись.

| Вывод и ответ | Карточка инструмента | Карточка хода | Вся страница |
|---|---:|---:|---:|
| 56 байт каждый | 29 301 → 27 837 | 31 780 → 31 183 | 209 318 → 207 257 |
| 14 КиБ текста каждый | 214 173 → 167 829 | 103 180 → 74 023 | 600 230 → 524 729 (−12,6%) |
| 224 КиБ текста каждый | 3 009 693 → 2 287 509 | 1 178 380 → 719 143 | 6 498 470 → 5 317 049 (−18,2%) |
| 224 КиБ в поле объекта инструмента, 224 КиБ текста ответа | 3 928 444 → 3 171 673 | 1 178 380 → 719 143 | 7 515 957 → 6 299 949 (−16,2%) |

Это не замер RSS или задержки. [Счётчики](measurements.log) совпали в пяти отдельных release-процессах для каждой версии.

## Проверки

- `extension-analysis`: **12/12** на базе, **13/13** с патчем в debug и release. Новый тест фиксирует различие между пустым, отсутствующим, булевым и структурированным выводом.
- Побайтно совпали **21 кадр** обычных release-процессов с синтетическим HTTP на loopback и **12** измерительных деревьев. Проверены начальный показ, выбор и скрытие шага, повторный выбор, фильтр и поиск, закрытие и повторное открытие. Совпал порядок чтений HTTP.
- #292 сокращает обработку заголовков; #309 меняет владение кэшированным JSON. Оба порядка наложения этих предложений и патча дали одно дерево. Совмещённые штатные тесты Analysis, Usage и SDK прошли. [Журнал проверок](checks.log).

Повтор: `python3 reproduce.py путь-к-репозиторию` (Git, Python 3, Cargo/rustfmt, TCP loopback). Входной checkout не меняется. При готовом кэше можно задать `CARGO_NET_OFFLINE=true`. Нативное окно, упаковка и весь workspace не проверялись.

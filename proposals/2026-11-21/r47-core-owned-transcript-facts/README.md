# Core: переносить сведения об инструментах при холодном восстановлении истории

Самостоятельный патч к [Proteus-core@32e56ecb](https://github.com/Proteus-harness/Proteus-core/commit/32e56ecb4cc6da324c60dd6ae2da78f3b7e46e7f). Сканер уже отдаёт записи во владение проекции. Вместо повторного выделения памяти проекция переносит ID завершённого вызова и данные привязки дочерней сессии из записей первого скана. Во втором проходе ID запроса переносится в индекс отображаемых вызовов. Если вызов нужен ещё и индексу workflow, оставлена одна необходимая копия. Ключ привязки дочерней сессии также остаётся отдельным.

Содержимое и область действия индексов не меняются: финальный результат по-прежнему имеет приоритет над промежуточным эффектом, а разрешённая дочерняя сессия может стать известна уже после завершения хода. Привязки по-прежнему вставляются в порядке журнала; проверка повторов и полномочий выполняется прежним валидатором. Порядок сканов, проверка снимка, границы видимости/сброса, исключение активного хода и формат ответа не изменены. Уменьшается число выделений при построении индексов, а не объём хранимого журнала или число сканов.

## Измерение

Записи передаются рендереру `transcript_from_scan` через его штатный тестовый вход из уже проверенных фикстур. В полной колонке измеряется весь рендер (включая копирование записей тестовым источником перед каждым проходом, но не предварительную проверку журнальных инвариантов и не сериализацию готового ответа). Дополнительно на тех же фикстурах измерена обработка первых двух проходов без копирования входной записи; по завершении этой серии её результат сравнивается с полным рендером. Во всех случаях счётчик отражает суммарные запросы к аллокатору, включая realloc. Это не RSS, пиковая память, I/O или latency.

## Проверка и воспроизведение

- Во всех семи фикстурах полные сериализованные транскрипты до/после совпадают побайтно. Проверены обычные и workflow вызовы, приоритет финального результата, поздняя привязка дочерней сессии, пустой журнал и исключение активного хода.
- Штатная группа `app_server::transcript::` на базе и кандидате покрывает ошибки каждого прохода, сброс, видимость, вложенные вызовы и их принадлежность ходу, скрытые части, даты и поведение эффекта без финала. Добавлена проверка привязки сессии после завершения хода. Полный workspace, удалённый storage/HTTP/GUI, macOS и Windows не запускались.
- `cargo fmt --all --check`, `git diff --check` и прямое/обратное применение проверены. Дополнительно патч проходит проверку применения поверх #304 (без совместного прогона тестов).

Из чистого checkout указанной ревизии, Rust 1.95, Linux x86-64:

```sh
# PROPOSAL — абсолютный путь к этому каталогу.
git apply --check "$PROPOSAL/source.patch"
cargo fetch --locked
python3 "$PROPOSAL/probe.py" . "${CARGO_TARGET_DIR:-target}/r47-replay"
git apply "$PROPOSAL/source.patch"
# Штатный runner в окружении process fixtures:
python3 scripts/test.py -p proteus-core --lib app_server::transcript::
```

`probe.py` по умолчанию создаёт временную копию checkout и подключает измеритель только к тестовому бинарнику. Обычная сборка не содержит инструментирования. Тесты обеих версий запускаются через `cargo test --locked --offline` с одним набором зависимостей.

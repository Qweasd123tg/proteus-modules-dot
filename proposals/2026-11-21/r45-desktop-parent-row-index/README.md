# Desktop: не копировать каждый путь при получении списка сессий Proteus

При первом получении или обновлении каталога Desktop переносит серверные сводки в модель боковой панели. Для привязки дочерних чатов к родителям `from_proteus` раньше копировала путь каждой сессии в отдельную таблицу, даже если ни у одной строки не было родителя. Этот промежуточный набор путей удалялся сразу после преобразования.

Патч переносит пути в итоговые строки и запоминает номера строк с родительской ссылкой. Если такие строки есть, UUID сопоставляются с **номерами** строк; копию ключа получает только дочерняя строка с найденным родителем. Для плоского списка таблица вообще не создаётся. Входной порядок, все поля сводки, прямые и обратные ссылки по порядку списка и отсутствие родителя сохраняются. Если вход неожиданно содержит повтор UUID, по-прежнему выбирается последнее совпадение. Сохраняются и случаи ссылки на себя: как и раньше, эта функция не редактирует граф родства.

**Самостоятельный патч** к [Proteus-desktop@b6a7ec2](https://github.com/Proteus-harness/Proteus-desktop/commit/b6a7ec2d8d7e486c8aba01291aa8c89774c4cded), только `src/conversations.rs`. Не меняет Core, хранилище, API/GET, открытие чата, Codex, сортировку или рендер. Проверено применение в обоих порядках с предложением [#289](https://github.com/Qweasd123tg/proteus-modules-dot/pull/289), затрагивающим другой путь в том же файле; это не интеграционный прогон двух патчей.

## Сколько работы убрано

Синтетические входы с принадлежащими им строками и частично заполненной activity; измерен **целый вызов реальной функции** для новой модели каталога. Ни подготовка входа, ни проверка ответа, ни уничтожение выходной модели не входят в замер. Счётчик в отдельной сборке измеряет число alloc/realloc и сумму запрошенных байтов (для realloc берётся новый размер). Это не пик памяти или RSS.

| Каталог | Выделения, до → после | Запрошенные байты, до → после |
|---|---:|---:|
| Пустой | 0 → 0 | 0 → 0 |
| 16 корней | 18 → 1 | 6 240 → 3 456 |
| 4 096 корней | 4 098 → 1 | 1 593 360 → 884 736 |
| 4 096 строк, одна ссылка вперёд | 4 099 → 4 | 1 593 435 → 1 089 723 |
| 4 096 строк, половина с одним общим родителем | 6 146 → 2 060 | 1 746 960 → 1 341 360 |
| 4 096 строк, группы по восемь | 7 682 → 3 597 | 1 862 160 → 1 554 864 |
| 4 096 строк, длинная цепочка | 8 193 → 4 108 | 1 900 485 → 1 593 189 |
| 128 строк, 127 отсутствующих родителей | 130 → 8 | 49 808 → 40 112 |

У плоского каталога из 4 096 строк остаётся одно выделение под выходной вектор (на 708 624 байта меньше запросов к аллокатору). Для цепочки по-прежнему нужны 4 095 отдельных родительских ключей, а также временный список детей и позиционная таблица. Отдельный прогретый микрозамер без счётчика: в данном запуске для 4 096 корней медиана 541 → 277 мкс, для цепочки 603 → 341 мкс. Шесть процессов на версию, порядок версий чередуется, внутри процесса медиана 21 измерения после одного прогревочного; цифры времени зависят от нагрузки машины. **Не измерялись запуск Desktop, время запроса каталога, FPS или задержка первого отображения.**

## Проверки и воспроизведение

- Тесты всего модуля conversations: база 5/5, патч 6/6; новый тест сочетает дубликат UUID с разными путями, его детей, ссылку на себя и пропущенного родителя. Восемь наборов стенда проверяют все поля каждой выходной строки по входным данным; независимый обратный поиск родителя проверяет последнее вхождение UUID. Контрольные суммы порядка и родства между сборками совпали.
- Прямое и обратное применение патча, git diff --check и rustfmt изменённого файла прошли. Использованы оригинальные conversations, типы Codex и библиотека вкладок из закреплённого git-объекта и готовые совместимые зависимости. Полный workspace и нативное окно не собирались и не запускались.
- Из checkout целевой ревизии: `git apply --check /путь/source.patch`, затем `git apply /путь/source.patch`. SHA-256 патча: `36d567e2a406b69b4227a858e19c8f97cc316475f1dbbe5cd9fb6e664ee1d38a`.
- Для тестов и замеров: `bash verify.sh DESKTOP_REPO SERDE.rlib SERDE_JSON.rlib UUID.rlib PROTEUS_CONTRACTS.rlib`; передать реальные пути к совместимым rlib из кэша сборки. Нужны Rust 1.95, rustfmt, git, tar, Python 3 и lld на Linux. Полный вывод в `evidence.log`.

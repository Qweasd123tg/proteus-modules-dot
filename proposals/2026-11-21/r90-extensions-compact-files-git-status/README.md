# Files: хранить типизированный Git-статус вместо строки на каждый путь

Точный upstream Extensions: `892f627570369ed60d7205eb0d351c753ec4305f`. Изменены только `packages/files/src/git.rs` и `packages/files/src/main.rs`.

Панель уже использует Git-статус только для цвета, появления View Diff и предложения восстановления. В снимке Files теперь хранится `HashMap<String, Option<Status>>`: путь по-прежнему есть в таблице, даже если статус отсутствует, пуст, неправильного типа или неизвестен. Такой файл остаётся без цвета и действия восстановления, но с View Diff в Git-репозитории. Одна операция получает цвет и оба флага строки. Modified и renamed уже давали одинаковый цвет и возможность восстановления; Deleted по-прежнему восстанавливаемый, added/untracked/conflict — нет. Для папок применяется прежний максимум.

При повторе пути прямой статус по-прежнему берётся из последней строки, а сводка папок учитывает каждую известную строку, включая затёртые прямые статусы. Фильтр путей, последовательность запросов и смена снимка не менялись. Условия меню, точный путь, диалог подтверждения и путь выполнения восстановления не правились. В ходе проверки ни одна файловая/Git-операция не вызывается.

- `source.patch` самостоятельный для точного upstream.
- `cumulative.patch` — альтернатива для M150 + #394/#395/#397/#399/#402/#404/#406/#409/#412 (`d90b15864552a553b00b6461847e9ec0c20b9acf6546a66da90235720a0615da`), а не патч поверх `source.patch`. Он сохраняет #380 (ранний выход для предков) и проверяет его прежний независимый эталон уже через наблюдаемые цвет, наличие и восстановление для каждого порядка. #409 в этом стеке сам применяется своим составным вариантом.

## Сфокусированная проверка

Штатный Files в offline locked release, один Cargo job: **37 → 38** на upstream, **41 → 42** на составном дереве. Байты stdout настоящего Files совпали во всех четырёх ветках: пять кадров прежнего реального GET-only сценария и восемь кадров нового сценария с двумя сессиями, несколькими контекстами, переносом вида и изменением снимка. Сравнивались меню, цвет, точное значение и подтверждение Restore, идентификаторы строк, номера последовательности и порядок разрешённых GET. Вторая сессия не является репозиторием: Git-действия там по-прежнему скрыты. Все входы синтетические, реальных репозиториев и файлов нет.

## Живой объём снимка Git

Отдельный зонд вызывает настоящий `Git::parse`; после удаления исходного JSON измеряются живые запрошенные байты и блоки, раскладка элементов карты, ёмкость и число путей/папок. После подмены пустым снимком и после удаления вся измеренная память возвращалась к исходному уровню. Пять одинаковых повторов на вариант.

Проверенный x86-64: пара ключ/значение **48 → 32 байта**; ёмкость карты на предельном снимке в обеих версиях — **1 792 элементов**. Тот же снимок устраняет **1 000** отдельных блоков и **7 331** байт меток; общий выигрыш живых запрошенных байтов — **40 099**.

| Снимок | Живые байты, до → после | Живые блоки, до → после |
|---|---:|---:|
| Пустой | 0 → 0 | 0 → 0 |
| 1 путь | 401 → 329 | 6 → 5 |
| 128 путей | 17 046 → 12 011 | 267 → 139 |
| 1 000 путей (предел Core) | 131 302 → 91 203 | 2 011 → 1 011 |
| 128 путей и проверки повторов/неизвестных | 17 043 → 12 023 | 266 → 140 |

Это только удерживаемые аллокатором запрошенные байты снимка Files, не RSS/PSS и не замер запуска приложения. Размер входа 1 000 соответствует ограничению реального Core, но это синтетические пути, статусы и количество, а не статистика обычных репозиториев.

## Повторить

Используйте точный локальный git-checkout, сохранённое дерево Extensions M150, существующий target/warm offline Cargo cache, Rust/Cargo 1.95.0 и общий файл блокировки.

```bash
PYTHONDONTWRITEBYTECODE=1 python3 reproduce.py "$STOCK" "$M150_EXTENSIONS" \
  "$P394" "$P395" "$P397" "$P399" "$P402" "$P404" "$P406" "$CUMULATIVE_409" "$P412" \
  --target "$TARGET" --lock "$BUILD_LOCK" --admit-exclusive
```

Без флага — проверка входов. С флагом — один lock/job, не менее 512 MiB на обоих томах перед входом и остановка ниже 256 MiB. Cargo JSON связывает свежую сборку Files с точным исходником и ролью; отпечатки проверяются до/после запуска. Полный workspace, нативное окно, упаковка и метрики времени не проверялись.

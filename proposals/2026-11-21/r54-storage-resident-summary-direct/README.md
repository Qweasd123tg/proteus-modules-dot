# Тёплый каталог: не копировать старый дескриптор перед его заменой

[Патч](candidate.patch) для [Proteus-modules 9469e3b](https://github.com/Proteus-harness/Proteus-modules/commit/9469e3b12529d08b1f4a76882693e2065e842c51). В уже подтверждённом попадании в память возвращаемая строка использует **новый проверенный дескриптор**, а число сообщений и preview берёт из resident summary. Раньше сначала клонировался весь resident summary со старым дескриптором, затем старая копия немедленно заменялась свежей. Теперь сразу строится та же результирующая строка; лишние копии путей и locator старого дескриптора исчезают.

Все проверки остаются на исходных местах: идентичность сессии, stamp журнала/metadata, prefix cache и инвентарь blobs. Не меняются сравнение полей и recency, сортировка, выдача preview, выбытие кеша, полный проверочный replay, путь загрузки с диска или формат/запись v1. Никакого нового кеша. Это оптимизация **только реального попадания в resident cache**.

## Проверки

- Новый Rust-тест на обоих backend оставляет проверенный resident head без дискового индекса и моделирует старые timestamps только в кешированном дескрипторе. Сверяет весь свежий дескриптор, preview, число сообщений, ноль новых декодирований и отсутствие переписывания индекса. Канонический журнал и stamp не меняются.
- [64 модульных и 2 процессных теста](native-release.log) прошли в locked release scope на Linux, Rust 1.95; один ручной тест пропущен. Весь workspace и Windows не проверялись. [Наложение](composition.log) изменяет только соответствующие исходники и не выдаётся за прогон всего стека.

- [Отдельный прогон SDK без измерительной вставки](plain-parity.log) подтвердил те же ответы и индексы в четырёх сценариях обоих backend.

## Как измерялось

Два release SDK worker, включая [одинаковую тестовую вставку](instrument.py). Считается число alloc/alloc_zeroed/realloc и сумма запрошенных размеров только внутри потока выполнения `List` (realloc считается по полному запрошенному размеру). Проба не включает C SQLite, IPC-сериализацию до/после операции, создание тестового каталога или время выполнения. Сравнение порядка, timestamps, preview и всего JSON-ответа выполняется после одного и того же JSON-кодирования; v1 сверяется напрямую побайтно.

На каждом синтетическом дереве сеансы создаются обычным Commit, четыре последовательных сценария: холодный List без v1; настоящий resident List в том же процессе; новый процесс с сухим memory cache и существующим v1; resident List в первой инстанции после удаления только её тестовых v1. Холодный вызов должен подготовить v1, дисковый и resident не меняют inode/mtime/ctime/байты, последнее попадание не восстанавливает удалённые индексы. SQLite-читатель удерживает обычную транзакцию только на синтетическом журнале, чтобы пустые WAL не меняли timestamps между парными процессами.

Две серии 7 + 5 чередующихся пар, Linux CPU 6 и 7, после одной пары разогрева. Это не измерение RSS или запуска Desktop.

## Результаты

Во всех парах −4 запроса к аллокатору на строку реального resident hit. Тот же результат после удаления только синтетических индексов v1; холодный и дисковый контроль совпали по запросам и байтам во всех парах.

| Сценарий resident List | Запросы alloc до → после | Запрошенные байты до → после |
|---|---:|---:|
| jsonl, 96 обычных | 9 436 → 9 052 | 737 864 → 705 608 |
| jsonl, 128 во вложенном workspace | 16 808 → 16 296 | 1 885 398 → 1 788 630 |
| jsonl, 96 в Unicode/escaped workspace | 12 039 → 11 655 | 1 313 760 → 1 250 688 |
| sqlite, 96 обычных | 9 436 → 9 052 | 755 528 → 723 176 |
| sqlite, 128 во вложенном workspace | 16 808 → 16 296 | 1 908 950 → 1 812 054 |
| sqlite, 96 в Unicode/escaped workspace | 12 039 → 11 655 | 1 331 424 → 1 268 256 |

Обе серии повторили эти медианы точно. Для 128 вложенных сессий Rust allocator получил на 512 запросов и 96 768 запрошенных байт меньше на JSONL (96 896 на SQLite). Это не измерение времени или пикового footprint. [Серия 1](paired.csv) · [серия 2](repeat.csv).

## Повторение

На точной базе: `git apply --check candidate.patch`, затем `git apply candidate.patch`. Нативный scope: `cargo test --locked --offline --release -p session-storage -p proteus-session-storage-module` с Core harness из закреплённого `0c1b757`. Для benchmark только в одноразовых stock/candidate worktree: `python3 instrument.py CHECKOUT`, затем собрать оба `cargo build --locked --release -p proteus-session-storage-module` в разных target dirs. Запустить `python3 measure.py STOCK CANDIDATE --output samples.csv`. Для чистой проверки без инструментации добавить `--parity-only`. Нужны Linux, Python 3.11+, Rust/Cargo и закреплённые зависимости; реальные сеансы не используются.

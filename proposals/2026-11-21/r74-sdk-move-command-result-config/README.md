# SDK Extensions: не копировать конфигурацию из подтверждённого ответа

После успешного изменения настройки Mode или Model хост присылает полный `config`. SDK уже владеет разобранным ответом, но при записи в состояние ещё раз глубоко копировал весь объект. [Патч](source.patch) переносит только это поле из принятого ответа. База: [Proteus-desktop-extensions@892f627](https://github.com/Proteus-harness/Proteus-desktop-extensions/commit/892f627570369ed60d7205eb0d351c753ec4305f).

Порядок маршрутизации, подтверждения ожидающего ID, проверки сессии и обработки ошибок не меняется. Если поля нет или оно равно `null`, предыдущее состояние сохраняется. При несовпадении сессии конфигурация и сообщение об ошибке не применяются; предусмотренное подтверждение ожидающего запроса может по-прежнему пройти в другой сохранённой сессии. ID сам по себе не стал новой проверкой допуска. Код не меняет схему, транспорт, проверку прав или поведение клиента. Это сокращение работы при принятом ответе, не на каждом рендере.

| Принятый ответ, моделей / инструментов | Запросов выделения | Запрошено байт |
|---|---:|---:|
| 8 / 4 | 445 → 3 | 35 045 → 141 |
| 512 / 256 | 15 061 → 3 | 1 116 087 → 141 |
| 512 / 256 после переноса окна | 15 062 → 4 | 1 116 090 → 144 |

[Счётчики](measurements.log) учитывают успешные выделения и перераспределения на одном потоке при обработке уже разобранного ответа без открытых представлений. Подготовка, разбор JSON, HTTP, рендеринг и сериализация не измеряются. Пять повторов на вариант. Контроли (отказ с `null`, очистка ошибки без поля, подтверждение ожидающего ID без применения конфигурации в другой сессии, отсутствие подходящего окна) не изменились. Проверена передача двух строковых буферов, в том числе внутри вложенного каталога. Это не измерение RSS или задержки: перенос сохраняет возможную свободную ёмкость исходных контейнеров.

- Счётчики из таблицы повторились на точной базе и на M150 + #394 + #395 + #397. В release SDK: **60 → 61** модульный тест на базе и **66 → 67** в составе M150, по 1 doc-тесту. Mode: **4/4** на обеих базах. Model: **10/10** и **11/11** соответственно.
- Побайтно совпали **44 кадра** обычных процессов в каждом сравнении: Mode (23), Model (21). Сценарий меняет настройку, переносит представление в другой контекст, получает принятый полный ответ после закрытия старого контекста, затем проверяет отказ, очистку ошибки и изоляцию соседней сессии от опоздавшего ответа. Нормализации JSON нет. Отдельно совпали 7 записей контроля состояния диагностического теста.
- [Сборочные квитанции](artifact-receipts.log) содержат хеши исходников, наложений, lock-файлов и инструментов для четырёх запусков. В JSON Cargo подтверждены **28 свежих артефактов**: SDK, три тестовых файла, два обычных бинарника и диагностический файл в каждом варианте. Хеши исполняемых файлов проверены до и после выполнения. Повторное чтение SDK допустимо только при совпадении с уже проверенным SDK этого же варианта.
- Прямое и обратное наложение на пин и совмещение со стеком M150 проверены в обоих порядках. [Проверки](checks.log).

Повтор: `python3 reproduce.py точный-git точное-дерево-m150 патч-394 патч-395 патч-397 --target прогретый-target --lock общий-build-lock --admit-exclusive`. Нужен явный `CARGO_HOME` с доступными офлайн зависимостями. Без флага допуска проверяются только входы. Один Cargo job, locked/offline, стартовый порог 512 МиБ и остановка ниже 256 МиБ на обоих томах. Запуск не изменяет исходный checkout. Полный workspace, упаковка и нативное окно не проверялись.

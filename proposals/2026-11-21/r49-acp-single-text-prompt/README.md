# Core: передавать текст одиночного ACP-промпта без копии

[Базовая ревизия Proteus-core](https://github.com/Proteus-harness/Proteus-core/commit/32e56ecb4cc6da324c60dd6ae2da78f3b7e46e7f). Это **вход редактора**, от ACP-блоков запроса к строке перед приёмом хода; исходящие дельты ответа и история не затронуты.

Для одного блока `Text` прежний преобразователь создавал временный вектор строк, затем `join` копировал весь промпт. Теперь готовая строка с ёмкостью, равной длине, переходит из блока в результат. При избыточной ёмкости остаётся прежний путь: несколько байт текста не удержат, например, входной буфер на 64 КиБ. Для нескольких блоков, ссылок на ресурсы и неподдерживаемых типов по-прежнему используется тот же код. Общая проверка непустого текста с `trim` выполняется после обеих веток. Проверка не обрезает пробелы в принятом промпте.

| Вход | Вызовы аллокатора до → после | Запрошено байт до → после |
|---|---:|---:|
| Один текст, `hello` | 2 → 0 | 29 → 0 |
| Один текст, Unicode и крайние пробелы | 2 → 0 | 45 → 0 |
| Один текст, 64 КиБ | 2 → 0 | 65 560 → 0 |
| Один текст с аннотацией ACP | 2 → 0 | 35 → 0 |
| Только Unicode-пробелы, ошибка | 5 → 3 | 92 → 62 |
| Три текстовых блока | 2 → 2 | 80 → 80 |
| Текст, ссылка и текст | 5 → 5 | 161 → 161 |
| Пустой список, ошибка | 3 → 3 | 62 → 62 |

Измерена **только штатная функция `input::prompt_text`**: wire-фикстуры уже десериализованы в типы ACP, строка входного DTO уже выделена. Счётчик учитывает успешные запросы к системному аллокатору, включая новую ёмкость при realloc; это не peak/RSS, задержка, число аллокаций всего хода или стоимость декодирования/транспорта. Нулевые значения означают только отсутствие **новых** выделений в этом преобразовании. Таблица относится к x86-64 Linux и указанной сборке; доля таких промптов у реальных редакторов не измерялась.

## Проверка и воспроизведение

- Совпадение по байтам сериализованных строк и полных ACP-ошибок на 14 входах: обычные/аннотированные сообщения, Unicode и переводы строк, пустой ввод, разделители нескольких блоков, ссылки и неподдерживаемый тип на разных позициях. Отдельный штатный регрессионный тест охватывает владение избыточной ёмкостью.
- Прямое/обратное применение, `git diff --check` и `cargo fmt --all --check` проверены. [Результаты измерителя](probe.log) и [тесты](test-summary.log). Тест протокольной резервации, для которого нужны внешние процессные fixtures, исключён; не запускались полный workspace, настоящий редактор и сетевой провайдер, Windows/macOS.
- Патч не меняет ACP-схему, порядок допуска хода, session/config, права, политику, журнал и strict-read пути. Нет нового API, модуля или кэша.

Из чистого checkout указанной ревизии, Rust 1.95:

```sh
# PROPOSAL — абсолютный путь к этому каталогу.
git apply --check "$PROPOSAL/source.patch"
cargo fetch --locked
python3 "$PROPOSAL/probe.py" . "${CARGO_TARGET_DIR:-target}/r49-acp-prompt"
```

Скрипт создаёт временную копию, подключает счётчик только в тестовый бинарник и прогоняет базу и патч с одним набором зависимостей. Для полного ACP-набора с установленными process fixtures примените патч и выполните `python3 scripts/test.py -p proteus-core --lib app_server::acp::`.

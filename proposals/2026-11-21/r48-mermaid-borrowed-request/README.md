# Mermaid: JSON-запрос к воркеру без промежуточной копии диаграммы

Расширение строит один компактный JSON для ключа кэша и запроса к Node. Раньше оно сначала глубоко копировало исходник и тему в отдельный `Value`, затем сериализовало его; это происходило и при попадании в кэш. Preview дополнительно копировал весь объект контекста, хотя использовал только тему. [Патч](source.patch) передаёт сериализатору ссылки на исходник и тему, а для preview берёт статический пример и ссылку на тему. Единственная неизбежная полная строка этого шага остаётся.

База: [Proteus-desktop-extensions@892f627](https://github.com/Proteus-harness/Proteus-desktop-extensions/commit/892f627570369ed60d7205eb0d351c753ec4305f), [строитель запроса на базе](https://github.com/Proteus-harness/Proteus-desktop-extensions/blob/892f627570369ed60d7205eb0d351c753ec4305f/packages/mermaid-render/src/main.rs#L59-L129). По-прежнему используется `serde_json`, поля идут `source`, затем `theme`; вложенный порядок темы, экранирование и `theme:null` при отсутствии темы совпадают побайтно. Проверка языка, исходника в 50 000 байт и готового запроса в 512 КиБ остаётся в том же порядке и до работы кэша / Node. Ключ, правила попадания и вытеснения, ограничения и жизненный цикл воркера не менялись. Для стандартной сериализации добавлена прямая связь с уже закреплённым `serde`; версии зависимостей не изменены, derive-макросы не включены.

## Аллокации построения ключа

| Синтетический вход | Байт в готовом ключе | Обращений к аллокатору, до → после | Запрошено байтов, до → после |
|---|---:|---:|---:|
| Короткая диаграмма + тема | 259 | 23 → 3 | 1 902 → 896 |
| Короткая, нет темы | 163 | 11 → 2 | 1 040 → 384 |
| Диаграмма из 120 рёбер | 5 696 | 28 → 7 | 23 321 → 16 256 |
| Исходник ровно 50 000 Б | 50 126 | 25 → 4 | 201 814 → 150 429 |
| Короткая с большой вложенной темой | 116 710 | 12 028 → 11 | 1 155 426 → 262 016 |

Пять повторов на каждый вариант дали одинаковые результаты; [сырые значения](measurements.log). Счётчик измеряет только создание JSON-строки из заранее подготовленных `Content`. Сумма включает размеры при `realloc`; это не пик/RSS и не время. Не учтены устранённая копия контекста в preview, проверка кэша, отправка в Node, генерация SVG и нативная отрисовка. Результат для большой вложенной темы показывает стоимость глубокой копии, а не типичный размер темы клиента.

## Проверка и повтор

- Точный Rust-пакет в debug и release: **9 → 10** успешных unit-тестов; из двух wire-тестов в обеих версиях один прошёл, один остановился на проверке числа дочерних процессов: `/proc/<pid>/task/<tid>/children` недоступен в этом окружении, хотя предыдущая проверка ответа SVG прошла. Ничего не отключали; не заявляем зелёный пакет или проверку счёта и освобождения детей. Node-тесты воркера: **12/12** в обеих версиях.
- Обычные release-процессы вернули **14 побайтно одинаковых ответов** (15 079 Б). Сценарии: повторный рендер, смена темы, preview, другой открытый вид, отсутствующая/нулевая тема, ошибка языка, исходник 50 000 принимается / 50 001 отклоняется, запрос 524 288 принимается / 524 289 отклоняется, ошибка парсинга и следующий удачный рендер. Отдельно совпали пять строк, построенных старым и новым сериализатором (172 959 Б). [Хеши](measurements.log), [проверки](checks.log).

`python3 reproduce.py /path/to/Proteus-desktop-extensions` берёт временную копию точного коммита, проверяет прямое и обратное применение патча, формат, Rust и Node-тесты, затем запускает настоящие release-процессы и отдельные allocator probe. Нужны Python 3, Git, Cargo/rustfmt, зависимости Cargo.lock и Node.js 20+. Для готового кэша Cargo можно задать `CARGO_NET_OFFLINE=true`. Нативное окно и упаковка не проверялись.

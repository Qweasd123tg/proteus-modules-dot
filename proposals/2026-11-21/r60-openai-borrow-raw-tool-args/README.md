# OpenAI Responses: не копировать аргументы вызова дважды

База: **Proteus-harness/Proteus-modules@9469e3b12529d08b1f4a76882693e2065e842c51**. Локальный commit `181a9b6fc94ba02002e1bf9e22c0ad02509c6cbc`. Меняются только сборка OpenAI request items и её тест.

При подготовке истории OpenAI Responses raw function arguments и freeform input уже хранятся строками. Раньше код копировал их перед передачей в `json!`, который затем создавал строку результата. Теперь `json!` читает исходные строки напрямую. Если исходной строки нет и function arguments заново сериализуются из JSON, этот путь оставлен без изменений: перенос рабочего буфера сериализатора удерживал его запас ёмкости и на длинном тесте повышал пик живых байтов. Сохраняются точные байты raw (включая malformed replay), ошибки нестрокового freeform input и порядок полей.

## Проверки

- Целевые тесты OpenAI request renderer и malformed replay: **15/15 → 16/16**. Оба исходника собраны rustc 1.95.0 на Linux x86-64 против ранее собранных locked Cargo-зависимостей, без записи в общий target. Проверены графы Release с sorted keys и Debug workspace с `serde_json/preserve_order`.
- **20 полных побайтных сравнений** (по три пары). Включены обычный текст без вызовов, короткие/длинные raw, декодированные function и freeform аргументы, malformed replay, нестроковый freeform input и смешанная история вызовов/результатов. Независимо сверены строки аргументов и порядок ключей.
- `rustfmt --check`, `git diff --check`, `git apply --check` на точной базе и M100. Хеши всех 100 выбранных патчей M100 проверены; ни один не меняет эти пути. Полный workspace gate и запросы к реальному API не запускались.

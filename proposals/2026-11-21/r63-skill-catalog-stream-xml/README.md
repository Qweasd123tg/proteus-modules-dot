# skill-pack: собирать XML каталога без промежуточных строк

База: **Proteus-harness/Proteus-modules@9469e3b12529d08b1f4a76882693e2065e842c51**. Локальный commit `ccb547420fc7895705a04b799450e10a2287b1c3`.

Провайдер `skills` ранее экранировал имя, описание и путь цепочкой замен, создавая временные строки. Описание перед этим ещё собиралось из слов в отдельную строку. Теперь рендерер пишет текст и те же XML entities сразу в XML каталога. Описание использует прежний `split_whitespace()`, путь тот же `Path::display()`. Обнаружение, валидация, порядок skills и body инструмента загрузки не меняются.

## Проверки

- Полный crate `skill-pack`: **9/9 → 10/10** в обоих ранее собранных locked графах (изолированный Release sorted и workspace Debug `preserve_order`). Тесты обоих исходников скомпилированы rustc 1.95.0 на Linux x86-64 непосредственно с этими артефактами зависимостей. Общий target не менялся; полный workspace gate не запускался.
- **12 побайтных сравнений полного JSON списка context chunks** (по три пары). Независимо сверены все пять XML entities, включая уже присутствующее `&amp;`, Unicode, нормализация пробелов и отображение пути с невалидным UTF‑8. Пустой каталог, один обычный skill, 64 навыка и случаи обильного экранирования включены.
- `rustfmt --check`, `git diff --check`, `git apply --check` на точной базе и M100. Из 100 проверенных патчей M100 тот же файл менял только #341 (body загрузки). Оба порядка применения дают одинаковое результирующее дерево.

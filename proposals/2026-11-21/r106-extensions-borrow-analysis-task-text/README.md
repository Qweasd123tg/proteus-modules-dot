# «Анализ ходов»: передавать исходный текст задачи без промежуточной копии

Для длинной задачи панель строит сворачиваемый блок с полным текстом. Раньше она копировала текст во временное JSON-значение, хотя уже имела исходное. Теперь блок получает оригинальное значение по ссылке. Сам блок по-прежнему владеет полным текстом.

Тот же порог, больше 600 скалярных значений Unicode, теперь проверяется по наличию 601-го. Проверка не использует размер в байтах и не зависит от того, сколько символов показано в превью после удаления лишних пробелов. Ровно 600 символов не добавляют полный блок; 601 пробельный символ добавляет его даже при пустом превью. Копирование, необходимое самому виджету, текст, высота, переносы и закрытое начальное состояние сохраняются. Результат, конфигурация, шаги (#338/#420), API и кэш не менялись.

## Проверка и применение

Один [source.patch](source.patch), только `packages/analysis/src/summary.rs`, применяется отдельно к upstream Extensions `892f627570369ed60d7205eb0d351c753ec4305f` и M150 с 17 накладками до #428 (дерево `c1f4cbdc7c505bd0b58ca07fcb06e4f798d6499dfc4da56e762924a5622e4f25`).

[reproduce.py](reproduce.py) проверяет хеши исходников и накладок, Cargo.lock, применимость/обратимость патча, штатные release-тесты, байты stdout и отдельный диагностический замер. Нужны Rust 1.95.0, прогретый офлайн-кеш `CARGO_HOME`, существующая цель `--target` и общий `--lock`. Без `--admit-exclusive` только предварительная проверка. С флагом: `--release --locked --offline -j1`, 512 МиБ входной порог и 256 МиБ для остановки. См. `python3 reproduce.py --help`.

Проверены обычная длинная задача, 599/600/601, многобайтные и комбинируемые символы, задача из Unicode-пробелов, CRLF, экранирование, нестроковые поля, переходы между ходами и контекстами, отсутствие выбранного хода и Preview. Контроль шагов побайтно совпал с предыдущим доказательством #420.

## Результат

Синтетическая задача длиной **4 032 Б / 3 150 скалярных значений** дошла до построителя блока по исходному указателю. Готовый текст по-прежнему занимает буфер ёмкостью 4 032 Б. Логический счётчик проверки порога: **3 150 → 601**.

| Дерево | Выделения на участке, до → после | Запрошено у аллокатора |
| --- | ---: | ---: |
| Upstream | 47 → 46 | 19 926 → 15 894 Б |
| M150 + накладки через #428 | 44 → 43 | 16 026 → 11 994 Б |

В обоих случаях убрана одна копия и **4 032 запрошенных байта**. Абсолютные значения различаются, поскольку #338 уже улучшил сам построитель. При отсутствии блока этот участок по-прежнему ничего не выделяет.

Во всех четырёх release-вариантах совпали **20 сырых кадров stdout (591 898 Б)**, 13 упорядоченных синтетических GET и ноль записей. Дополнительно совпали 7 диагностических деревьев, по пять одинаковых замеров на вариант. Штатные тесты: **12 → 13** на upstream и **15 → 16** в композиции.

Замер охватывает только проверку порога и построение полного блока в синтетическом сценарии. Счётчик символов отражает логические итерации в тестовой вставке, а не машинные инструкции, реальное время или весь обход: превью, расчёт высоты и сериализация могут по-прежнему читать текст. Аллокатор не учитывает весь рендер, загрузку, нативный UI или RSS. Полный workspace, нативный Desktop и упаковка не проверялись.

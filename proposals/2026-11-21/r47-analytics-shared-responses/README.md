# Analysis и Usage: без копирования ответа кэша целиком

Страницы Analysis и Usage и общий список сохранённых сессий только читают ответ SDK, но раньше каждый вызов `Analytics::fetch` выдавал новую глубокую копию JSON, если ответ помещался в кэш. [Патч](source.patch) добавляет `Analytics::fetch_shared`: кэш и выполняющийся рендер работают с одним `Arc<Value>`. Существующий `fetch → Result<Value>` оставлен для вызывающих, которым нужен независимый, изменяемый JSON. Если ответ не попал в кэш, этот старый метод забирает исходное значение без копии JSON.

База: [Proteus-desktop-extensions@892f627](https://github.com/Proteus-harness/Proteus-desktop-extensions/commit/892f627570369ed60d7205eb0d351c753ec4305f), [SDK Analytics](https://github.com/Proteus-harness/Proteus-desktop-extensions/blob/892f627570369ed60d7205eb0d351c753ec4305f/sdk/src/analytics.rs#L53-L108). Те же ключи, TTL и LRU, до 16 записей и 8 МиБ учитываемых байтов, тот же порядок HTTP-запросов и те же правила отказа в кэшировании. Бюджет по-прежнему регулирует **только** владельцев в кэше, не пользовательские ссылки. Держатель общей ссылки может продлить жизнь объекта после вытеснения, как раньше мог хранить свою копию. Все три изменённые точки потребления держат такую ссылку только до завершения текущего рендера и не добавляют постоянного владельца. `Arc` сохраняет прежние `Send + Sync` SDK; используемый `Arc::unwrap_or_clone` стабилен с Rust 1.76, ниже минимальной версии компилятора для уже используемой редакции Rust 2024.

## Аллокации SDK

| Ответ / кодированный размер | Первый запрос, запрошено байтов | Повтор, запрошено байтов | Повтор, обращений к аллокатору |
|---|---:|---:|---:|
| Маленький · 28 Б | 269 406 → 268 858 | 423 → 43 | 9 → 4 |
| Строка · 1 048 621 Б | 6 560 049 → 5 511 170 | 1 049 015 → 48 | 11 → 4 |
| 3 072 вложенные строки · 1 208 187 Б | 11 510 517 → 8 170 955 | 3 339 695 → 45 | 36 875 → 4 |
| Свыше бюджета · 8 388 781 Б | 42 211 489 → 42 211 577 | 42 211 489 → 42 211 577 | 95 → 96 |

Инструментированный release-бинарник вызывает публичные методы SDK и полный локальный HTTP/JSON-путь на промахе; первое чтение каждого синтетического ответа и повтор без TTL. Медианы пяти прогонов на версию; для попаданий в кэш все пять значений совпали. На первом чтении маленького HTTP-ответа диапазоны 269 406–269 662 Б до и 268 858–269 114 Б после; прочие диапазоны и все сырые пары в [измерениях](measurements.log). Числа — сумма размеров обращений к аллокатору (при `realloc` учитывается новый размер), а не пик или RSS. Не включены построение виджетов, нативное окно, сборка пакетов, время и живая нагрузка. Подготовка фикстуры и печать результатов не учитываются; у тестового oversized-входа повтор снова обращается к серверу. Само оборачивание добавляет одно небольшое выделение на ответ, в том числе если он не кэшируется; на попадании остаются выделения для ключа запроса.

## Проверка и повтор

- Крейты SDK / Analysis / Usage проверены в debug и release: SDK **60 → 61** unit-тест + по одному doctest; Analysis и Usage **по 12/12**. Новый тест покрывает отсутствие копии и время жизни после вытеснения, а прежние проверки бюджета и TTL дополнены контролем освобождения. Отдельный тест через публичный `fetch` подтвердил, что изменение полученного JSON не затрагивает кэш.
- В полном `cargo test --locked --workspace --no-fail-fast` база **283 прошли, 1 упал**, кандидат **284 прошли, 1 упал**. Оба раза единственная ошибка в Mermaid lifecycle: проверка ожидает, что `/proc/<pid>/task/<tid>/children` покажет дочерний процесс после успешного SVG-ответа, а в данном окружении файла нет даже у обычного дочернего процесса. Проверку не отключали. Workspace не выдан за зелёный.
- Настоящие release-бинарники: по четыре ответа Analysis и Usage в сценарии первый рендер → повтор → обновить → выбрать сохранённую сессию. Ответы побайтно совпали (56 255 и 66 467 Б); порядок шести HTTP-запросов каждой страницы сохранён. [Лог проверок](checks.log) и [хеши ответов](measurements.log).

`python3 reproduce.py /path/to/Proteus-desktop-extensions` берёт отдельную временную копию точного коммита, проверяет применение/обратимость патча и формат, запускает тесты workspace и затронутые пакеты в release, затем сравнивает два реальных процесса и отдельный allocator probe. Нужны Git, Python 3, Cargo/rustfmt, зависимости Cargo.lock и Node.js 20+ для Mermaid-теста. При прогретом Cargo-кэше можно задать `CARGO_NET_OFFLINE=true`. Стенд работает на 127.0.0.1, не использует пользовательские файлы или живой сервер.

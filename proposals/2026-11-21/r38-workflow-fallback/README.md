# Coding workflow: не копировать мегабайты ради 2 000 символов

Кандидат к **Proteus-harness/Proteus-modules** на базе `9469e3b12529d08b1f4a76882693e2065e842c51`. Изменены только `workflow/coding-workflow/src/output_text.rs` и тесты этого crate. Когда модель возвращает пустой финальный ответ, workflow показывает начало последнего результата инструмента. Раньше он целиком копировал очищенные stdout и ошибку в одну строку, а потом брал её начало. Теперь он добавляет в конечный ответ только нужные срезы: до 2 000 скалярных значений Unicode, считая вставленный перевод строки. Обрезка пробельных символов, порядок полей, выбор последнего результата и пометка об усечении не изменились.

| Синтетический вход | Запросы alloc/realloc: байты до → после | Медиана до → после, мкс |
|---|---:|---:|
| Обычный ответ модели (fallback не нужен) | 94 → 94 | 0,046 → 0,045 |
| Только пробелы | 22 → 22 | 0,048 → 0,043 |
| Короткий вывод и ошибка | 333 → 274 | 0,247 → 0,132 |
| 2 КиБ ASCII | 7 982 → 6 358 | 4,681 → 1,362 |
| Короткий вывод и 128 КиБ ошибки с emoji | 153 406 → 24 454 | 11,439 → 4,838 |
| 2 МиБ вывода | 2 105 502 → 6 358 | 145,340 → 1,391 |
| 1 МиБ вывода + 1 МиБ ошибки | 2 105 503 → 6 358 | 145,919 → 1,411 |

**Метод.** Замер публично наблюдаемого результата функции `output_text`, а не всей сессии. До и после собраны вместе из настоящих файлов на Rust 1.95.0 с `-O`, типы `CanonicalMessage` и `ToolResult` из закреплённого Core. Один Linux x86_64 хост. 4 разогревочных пары, затем 101 пара с чередованием порядка. Вход и история готовы до запуска таймера, удаление результата после таймера. Один и тот же счётчик аллокаций текущего потока включён для обеих версий; при realloc он считает весь запрошенный новый размер. Это не замер пика RSS, вывода инструмента или стоимости модели. Хранение входного результата не меняется. Проверка `trim()` по-прежнему может просмотреть все входные пробельные символы.

**Проверка.** В чистом архиве указанной базы применили патч, скомпилировали и запустили **112/112** штатных unit-тестов `coding-workflow`, включая новый тест. Отдельный probe сравнил полные строки до и после для **6 213** сочетаний и проверил счётчик аллокаций на больших входах. Учтены ASCII, CJK, emoji, комбинируемый знак, NUL, только пробелы и разрыв прямо на разделителе. Проверены разные финальные сообщения, отсутствие истории, выбор последнего результата и литеральный placeholder. Формат и `git diff --check` прошли. Workspace/gate, установка в Desktop и живые вызовы модели не запускались.

**Повтор.** Из этой папки: `python3 reproduce.py /path/to/Proteus-modules`. Нужны Git с указанной базой, tar, Rust 1.95 с Cargo, LLD для Linux, доступ к закреплённым зависимостям. Скрипт не меняет входной checkout: распаковывает базу во временный каталог, проверяет применимость и применяет патч, запускает unit-тесты и сравнительный probe. На измерительном хосте для экономии диска использован режим `--cached-rustc flags.txt` (по одному аргументу rustc на строку: `-L` с путями зависимостей, `--extern` для зависимостей crate). Этот режим тоже компилирует весь изменённый crate в режиме unit-тестов; использованы Core `0c1b7572313230e5d123e95c722e1258a2e9ecd6`, закреплённый rand 0.9.4 и совместимый локальный кэш. Времена зависят от машины и профиля сборки; источник и полные результаты в `probe.rs` и `verification.log`.

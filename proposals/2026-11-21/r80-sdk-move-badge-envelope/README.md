# SDK Extensions: не копировать готовые данные метки при отправке

Mode, Model, Context, TPS, Quota, Git и Plan передают SDK готовые строки метки и её видимую часть. Раньше `json!` ещё раз копировал каждую строку и дерево `face` при построении отправляемого объекта. [Патч](source.patch) переносит строки и `face` в JSON. Массив элементов `Value` всё ещё создаётся; текст и структура уже готовых элементов не копируются повторно.

Порядок полей и строк не меняется: сначала обычные строки, потом ошибка команды и ошибка визуальных настроек текущего окна. Источники этих ошибок остаются на месте и по-прежнему копируются один раз для кадра. Если `face` не задан, остаётся muted icon; явный null эмитируется без преобразования. Это проверка прозрачности эмиттера, не новый допустимый вид Desktop-метки. Реальные пакеты используют прежние формы. `hidden`, выбор сессии, маршрутизация и транспорт не меняются.

Метка не добавляется в `Host.shown`: ни входные контейнеры, ни объект кадра не сохраняются между вызовами. Возможная свободная ёмкость исходных полей живёт не дольше части текущего вызова отправки. Это не изменение самих данных или границ их допуска.

| Синтетический объект метки | Запросов выделения | Запрошено байт |
|---|---:|---:|
| Пустые строки, стандартная иконка | 27 → 21 | 1 927 → 1 650 |
| Вложенный face, без строк | 27 → 15 | 2 136 → 1 269 |
| Одна строка и ошибка команды | 32 → 18 | 2 482 → 1 532 |
| Две обычные строки | 30 → 16 | 2 488 → 1 413 |
| 32 строки | 60 → 16 | 10 328 → 3 573 |
| 8 длинных строк, тот же небольшой face | 36 → 16 | 133 816 → 1 845 |

[Счётчики](measurements.log) охватывают успешные выделения и перераспределения на одном потоке в реальном построителе кадра, без сериализации, тестовой копии при отправке, подготовки или IPC. Пять одинаковых повторов на вариант. Проверены адреса первой строки и строки внутри вложенного face: новый построитель передаёт исходные буферы. Явный null без строк и пустой вход со свободной ёмкостью не изменились (15 запросов, 1 269 байт). Ёмкость выходного массива в каждой паре одинакова, включая пустой и одиночный вход с исходной ёмкостью 64. Это не измерение RSS или задержки.

- Результаты совпали на точной базе и на накопительном стеке. SDK в release: **60 → 61** и **68 → 69** модульных тестов, по одному doc-тесту. Mode: 4/4 на обеих базах, Model: 10/10 и 11/11, Context: 3/3 и 4/4.
- Побайтно совпали **53 обычных кадра** (Mode 26, Model 24, Context 3) на всех четырёх плечах. Mode/Model проверяют два окна, перенос, подтверждение/отказ и очистку; Context выдаёт стандартную иконку и кольцо на порогах warning/danger без HTTP. Отдельный тест SDK проверяет порядок двух ошибок, принадлежащих сессии и текущему окну, hidden/default, явный null и вложенную структуру; метка не становится сохранённым представлением.
- [Сборочные квитанции](artifact-receipts.log): хеши исходников, наложений, lock-файлов и инструментов, **36 свежих артефактов** Cargo JSON: SDK, четыре тестовых исполняемых файла, три обычных процесса и диагностическая программа на плечо. Четыре повторных чтения SDK сверены с уже собранной библиотекой того же плеча. Хеши исполняемых файлов проверены до и после запуска.

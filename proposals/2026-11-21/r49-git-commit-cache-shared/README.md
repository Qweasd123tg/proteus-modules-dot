# Git: открытый коммит и diff файла без повторной копии ответа

При открытии файла из графа Git читает два неизменяемых снимка: сведения о коммите (включая общий patch и список файлов) и diff выбранного файла. Кэш уже хранит их в `Arc<Value>`, но [обе функции чтения](https://github.com/Proteus-harness/Proteus-desktop-extensions/blob/892f627570369ed60d7205eb0d351c753ec4305f/packages/git/src/history.rs#L240-L259) глубоко копировали JSON. При повторном выборе даже не показываемый пользователю общий patch копировался снова. [Патч](source.patch) возвращает исходный `Arc` и передаёт его на чтение построителю виджета. Виджет по-прежнему владеет своим содержимым.

База: [Proteus-harness/Proteus-desktop-extensions@892f627](https://github.com/Proteus-harness/Proteus-desktop-extensions/commit/892f627570369ed60d7205eb0d351c753ec4305f). Правка только в пакете Git. Те же HTTP-запросы, тот же формат вывода. Не меняются лимит в 16 записей / 8 МиБ, политика вытеснения, обработка слишком большого ответа без записи в кэш, полные и короткие хеши и обычный working-tree diff. Ссылки существуют только пока строится текущий вид или строка сообщения Amend; долговременного владельца не добавлено.

## Затраты при попадании в кэш

Полный вызов `Git::document` на готовых синтетических данных. Счётчик считает обращения к системному аллокатору и сумму запрошенных байтов, включая новый размер при `realloc`. Вход уже в кэше. Запись результата в stdout, десериализация HTTP, окно Desktop, RSS и время не входят. Размеры в первой колонке: общий и выбранный patch.

| Fixture | Вид | Аллокации, до → после | Запрошено байтов, до → после |
|---|---|---:|---:|
| 1 файл, 256 Б / 256 Б | Выбранный файл | 275 → 244 | 21 631 → 18 401 |
| 24 файла, 24 / 3 КиБ | Весь коммит | 583 → 354 | 97 444 → 49 415 |
| 24 файла, 24 / 3 КиБ | Выбранный файл | 482 → 244 | 73 171 → 21 217 (−71%) |
| 160 файлов, 480 / 192 КиБ | Граф с инспектором | 10 195 → 8 742 | 1 567 770 → 925 033 |
| 160 файлов, 480 / 192 КиБ | Весь коммит | 2 759 → 1 306 | 1 223 620 → 580 883 |
| 160 файлов, 480 / 192 КиБ | Выбранный файл | 1 706 → 244 | 1 054 951 → 214 753 (−79,6%) |

В пяти отдельных запусках каждой сборки результаты совпали. Все девять сериализованных деревьев виджетов совпали побайтно. Сложность самого виджета никуда не исчезает: например, инспектор по-прежнему строит дерево файлов. [Данные и хеши](measurements.log).

## Проверки

- Обычные release-бинарники с синтетическим loopback API: открытие и повторный рендер коммита, выбор коммита и файла из графа, возврат ко всем файлам, 404 неизвестного коммита, восстановление и обновление `run_settled` при том же HEAD. Проверяются реальные кадры и порядок HTTP GET, включая короткий и полный алиас, путь файла, номера действий, тексты, diff и отсутствие лишнего чтения.
- Тесты штатного `extension-git` из точной базы и с патчем, debug и release: по **41/41**. Две существующие проверки усилены: полная и короткая формы должны возвращать один и тот же immutable объект, не просто равные значения. Проверка со слабыми ссылками после каждого синтетического сценария подтверждает: после рендера на снимок есть только одна сильная ссылка, после смены сессии не остаётся ни одной.
- [Предложение #283](https://github.com/Qweasd123tg/proteus-modules-dot/pull/283) меняет только построители массивов в `sdk/src/ui.rs`. Оба порядка наложения на точную базу дают одно и то же дерево; совмещённые debug-тесты Git и SDK прошли. Измерения выше сравнивают только исходную базу с этим патчем, а не с #283. [Подробнее](checks.log).

Для повтора: `python3 reproduce.py /path/to/Proteus-desktop-extensions` (Git, Python 3, Rust/Cargo/rustfmt, локальный TCP). Сценарий делает временный checkout базы, проверяет применение и обратимость, выполняет тесты, собирает и сравнивает процессы; измеритель подключается только к отдельной сборке в этом временном checkout. При заполненном кэше можно задать `CARGO_NET_OFFLINE=true`. Для проверки файлов предложения: `sha256sum -c SHA256SUMS`. Полный workspace, нативное окно и упаковка не проверялись.

# Desktop: не собирать дерево панелей ради одного ответа

У окна с четырьмя панелями поиск вкладки больше не выделяет временный список из четырёх ссылок. Это касается поиска панели по ID, определения панели вкладки и проверки закрепления. Первые две операции используются, в частности, при анимации панелей (`src/ui/tabs/view.rs`) и сравнении старых и новых вкладок (`src/ui/tabs/motion.rs`).

**Изменение.** В headless-крейте `proteus-tabs` дерево теперь ищет первый результат в прежнем порядке чтения и сразу останавливается. Внутри панели проверка закрепления смотрит лишь на закреплённый префикс вкладок. Постоянного индекса и дополнительного состояния нет. В худшем случае поиск по ID остаётся линейным по числу узлов; поиск вкладки может также проверить все вкладки. Публичный API, формат сохранения и методы, действительно возвращающие список всех панелей, не меняются.

**Замер.** Один поток, Linux x86_64, Rust 1.95.0, release с исходным Cargo.lock. В каждой панели две вкладки, одна закреплена. На любой реальный ID и один отсутствующий выполняются шесть запросов через публичные методы: панель по ID, активная вкладка, панель по вкладке, наличие и две проверки закрепления. Все ответы проверяются. Построение и проверка дерева, генерация ключей и печать не учитываются.

| Панелей | Запросов к модели | Вызовов alloc/realloc, до → после | Сумма запрошенных байтов, до → после |
|---:|---:|---:|---:|
| 1 | 12 | 12 → 0 | 384 → 0 |
| 4 | 30 | 30 → 0 | 960 → 0 |
| 32 | 198 | 792 → 0 | 95 040 → 0 |

Это запросы к аллокатору внутри выбранных методов, не RSS и не пиковая память. Время кадра, запуск приложения и производительность GPU не измерялись; окно GPUI не собиралось и не запускалось.

**Проверка и применение.** База: `Proteus-harness/Proteus-desktop` @ `b6a7ec2d8d7e486c8aba01291aa8c89774c4cded`. Пакет содержит патч только для трёх файлов в `crates/tabs`. Из корня чистой базы выполните `git apply --check /путь/к/source.patch`, затем `git apply /путь/к/source.patch`. Весь набор `cargo test --locked -p proteus-tabs --lib` прошёл до и после (72/72 в каждой версии). Повторить независимую проверку обеих версий в одноразовой копии: `bash verify.sh /путь/к/Proteus-desktop`. При заполненном кэше Cargo можно задать `CARGO_NET_OFFLINE=true`. Результаты приведены в `evidence.log`.

# Analysis: не копировать текст сообщения при объединении одной части

При показе записанного запроса модели и ответа Analysis форматирует каждое сообщение. Если сообщение состоит ровно из одного обычного `Text`, прежний путь создавал строку, временный список и ещё одну копию строки при объединении списка. Теперь такой текст обрезается по краям тем же `trim` и копируется сразу в итоговую строку. Если после обрезки ничего не осталось, как и раньше, форматируется JSON всего сообщения.

Условие требует ровно одну исходную часть, ровно один тег `Text` и строковое поле `text`. Несколько частей, отсутствующие или нетипизированные поля, вывод инструментов, ссылки на файлы и незнакомые типы остаются на прежнем пути. Порядок, пробелы внутри текста, подписи, размеры и раскрытие виджетов не меняются. Нет изменений в доступе, запросах, кэше или лимитах.

## Проверка

Один точный патч применим к upstream `892f627570369ed60d7205eb0d351c753ec4305f` и M150 с изменениями Extensions через #448. Релизные unit-тесты Analysis: 12 → 13 и 17 → 18. Реальные релизные бинарники на обеих базах выдали побайтно одинаковые 11 stdout-кадров (789 687 байт); совпали семь GET к синтетическому loopback по методу, маршруту, сессии и статусу. Проверены одно и двенадцать обычных сообщений, повторное открытие представления на тёплых данных, обновление после события, записанный и частичный ответы, Preview, пустые и некорректные записи. Записи, action-кадры, stderr и реальные сервисы не использовались. ToolCall, ToolResult и FileRef в фикстурах только данные для форматирования.

Отдельный пробник измеряет только возвращаемую строку `message_text` на уже разобранном JSON. Для сообщения в 2 048 байт: 3 запроса к аллокатору / 4 192 запрошенных байта → 1 / 2 048. Для двенадцати сообщений длиной 2–8 КиБ: 36 / 117 888 → 12 / 58 368. Содержимое и ёмкость итоговых строк те же, как и все метрики шести контрольных групп: пустой текст, нетипизированные поля, пустые или reasoning-only части, неизвестные теги, форматируемые части и несколько частей. Это не измерение времени, RSS, сети или всей отрисовки.

Для воспроизведения: `reproduce.py STOCK_REPO THROUGH_443_REPO --context-446 EXACT_446_PATCH --tps-448 EXACT_448_PATCH --target EXISTING_TARGET --lock COMMON_LOCK`. Без `--admit-exclusive` проверяются только локальные входы. Один релизный package gate, одна offline locked задача Cargo, два отдельных экспорта и общий lock. Требуются Rust/Cargo 1.95.0 и ранее подготовленный отдельный Cargo target/home с точными зависимостями. Прежние пороги остаются: 512 MiB на входе, 256 MiB stop на обеих файловых системах, плюс резервы 32 MiB для исходников и 48 MiB для target перед экспортом. Все артефакты Analysis привязаны к точным исходникам, профилю и свежим Cargo-результатам. Полный workspace и нативный UI не запускались.

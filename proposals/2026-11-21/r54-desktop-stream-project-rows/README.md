# Desktop: показать строки проекта без временных списков

Панель сессий уже получает дерево проектов. Перед отрисовкой каждой открытой папки она ещё раз делила корневые строки на два списка, собирала из них два списка ссылок, а при показе всех строк создавала ещё один список. Теперь строки основного блока передаются отрисовщику по очереди. Для закрытой секции «Показать ещё» считается лишь число скрытых строк; ссылки на них сохраняются только пока проигрывается её анимация.

Сохраняются первые пять корней, место активного чата или его предка, относительный порядок явно показанных и анимируемых строк и скрытый счётчик. При полном показе и поиске общий порядок остаётся исходным: лишнее определение принадлежности строки к сокращённому списку больше не нужно. Места фокуса и прокрутки, разметка анимации, переход к следующей странице Codex, закреплённые и архивные строки не менялись. Кешей и дополнительных правил фильтрации нет.

База: [Proteus-desktop b6a7ec2d](https://github.com/Proteus-harness/Proteus-desktop/commit/b6a7ec2d8d7e486c8aba01291aa8c89774c4cded). SHA-256 файла `source.patch`: `feee77987619f015516aeae6c09d1d702b3a2dc426ea9bed330a503578720c0c`. Этот патч работает **после** построения исходного дерева сессий, в отличие от [#258](https://github.com/Qweasd123tg/proteus-modules-dot/pull/258) и [#282](https://github.com/Qweasd123tg/proteus-modules-dot/pull/282).

## Замер на дереве из штатного кода Desktop

Проекты для замера созданы исходным `SessionMarks::arrange` из синтетических сессий, с двумя уровнями потомков. Время включает только разбор уже готовых корневых строк, счётчик и передачу строк; не сортировку истории, реальную отрисовку или создание дерева. Три коротких режима показывают, где осталась реальная работа: выбор ветки с активным потомком проверяется в сокращённом списке, а анимация по-прежнему сохраняет ссылки на свои строки.

| Сценарий | Запросы аллокатору, до → после | Запрошенные байты, до → после | Медиана, мкс |
|---|---:|---:|---:|
| 5 корней, сокращённый список | 2 → 0 | 192 → 0 | 0,306 → 0,020 |
| 8 корней, сокращённый список, выбран вложенный чат | 6 → 3 | 280 → 24 | 0,376 → 0,246 |
| 8 корней, показ всех | 7 → 0 | 344 → 0 | 0,450 → 0,018 |
| 8 корней, анимация «Показать ещё» | 6 → 4 | 280 → 56 | 0,467 → 0,182 |
| 40 корней, сокращённый список, выбран вложенный чат | 42 → 35 | 2 456 → 280 | 2,967 → 1,897 |
| 40 корней, показ всех | 43 → 0 | 2 776 → 0 | 2,839 → 0,037 |
| 200 корней, показ всех (стресс) | 205 → 0 | 11 480 → 0 | 10,630 → 0,185 |

Запросы включают alloc и realloc, это не пиковая память или RSS. Время снято отдельным бинарником без счётчика на Linux x86-64, восемь чередующихся прогретых пар на одном логическом CPU. Нулевые аллокации относятся только к подготовке списка в ветке полного показа, не ко всему интерфейсу.

## Проверка

- **3 585** сравнений с блоком из исходного рендера: совпали ключи и порядок основного и анимируемого списков, число скрытых строк. Корни построил тот же штатный проектор. Покрыты выбранный вложенный чат, отсутствующая активная строка, поиск, архив/закрепление, открытие/закрытие и пустой вход.
- Исходные модули `sessions` и `conversations`: 16/16 штатных тестов. С новым модулем: 17/17, отдельный тест удерживает предка активного потомка перед анимируемыми строками.
- Все 124 внешние идентичности зависимостей совпали с Desktop Cargo.lock, включая Git-коммит контрактов; используется точный исходный `proteus-tabs`. Прямое и обратное применение, git diff --check и rustfmt прошли. Патч также применяется после #258 и согласованного варианта #282 из 50-й сборки предложений. Журнал: [evidence.log](evidence.log).

## Как повторить

Из checkout базы: `git apply --check /путь/source.patch`; для отдельного воспроизведения: `bash verify.sh /путь/Proteus-desktop`. Нужны Git, Bash, Python 3.11+, Rust 1.95.0 с rustfmt и локальный кеш для `harness.lock`. Временная сборка не правит checkout и работает в режиме `--offline --locked`. Для повторения микрозамера закрепите прогон на одном доступном логическом CPU. Полный workspace и GUI не запускались.

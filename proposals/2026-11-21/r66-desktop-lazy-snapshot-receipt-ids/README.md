# Desktop: не собирать UUID всех сообщений ради квитанций отправки

Во время получения снимка чата Desktop проверяет, какие локальные отправки уже подтвердил сервер. Раньше код заранее собирал UUID всех сообщений снимка во временный вектор, даже если локальных отправок не было. Теперь исходный список проверяется только для квитанции с известным UUID, если её ещё не подтвердил идентификатор запуска.

Порядок сопоставления и его признаки не меняются: активный или последний запуск проверяется первым, затем точный UUID, а не текст. Удаление подтверждённых квитанций, активность инструмента, обработка повтора и поздней ошибки HTTP сохраняются. Если известных ожидающих UUID много, поиск проходит по строкам снимка для каждого из них вместо прохода по плотному вектору UUID. Это обмен локальности на отсутствие копии; время не измерялось.

База: [Proteus-desktop b6a7ec2d](https://github.com/Proteus-harness/Proteus-desktop/commit/b6a7ec2d8d7e486c8aba01291aa8c89774c4cded). SHA-256 патча: `bb4a72c4254f5b423a9cfd308f39ba7c52a9aaf6a558e3a0a4c53d565b614e49`.

## Проверка

- **233 280** сравнений состояния квитанций: первый синтетический снимок и его повтор, совпадающий и несовпадающий UUID, повторяющийся текст, активный или завершённый запуск, поздний сбой и статус подготовки инструмента.
- **10/10** исходных тестов обратной связи, **11/11** после правки. Новый тест проверяет, что UUID, уже сопоставленный по запуску, и отправка без известного UUID не запускают поиск. Стенд использует точный код `Feedback` и участок вызова из `Session::apply_snapshot` с настоящим типом `AppSessionSnapshot`; сверены **125** идентичностей зависимостей.
- Прямое и обратное применение, `git diff --check` и rustfmt прошли. Изменённые файлы совпадают с базой в M100 и фактическом сводном Desktop через R61. Два порядка применения R62–R66 поверх этого снимка дают побайтно одинаковый результат.

## Запросы к аллокатору на одну синхронизацию квитанций

| Готовый синтетический снимок | Запросы, до → после | Запрошенные байты, до → после |
|---|---:|---:|
| 50 сообщений, нет квитанций | 5 → 0 | 1 984 → 0 |
| 200 сообщений, нет квитанций | 7 → 0 | 8 128 → 0 |
| 50 сообщений, UUID квитанции пока неизвестен | 5 → 0 | 1 984 → 0 |
| 50 сообщений, подтверждение по запуску | 6 → 1 | 1 987 → 3 |
| 50 сообщений, есть или нет строки с известным UUID | 5 → 0 | 1 984 → 0 |
| 200 сообщений, несколько квитанций с известными UUID | 7 → 0 | 8 128 → 0 |
| Пустой снимок | 0 → 0 | 0 → 0 |

Учтены только `alloc` и `realloc` в участке обратной связи на Linux x86-64. Это не пик памяти, RSS или размер фактической страницы сервера. Нативная отрисовка, работа сети, применение истории и время не измерялись.

## Как повторить

`git apply --check /путь/source.patch` из checkout базы. Узкая проверка: `bash verify.sh /путь/Proteus-desktop`. Нужны Bash, Git, Python 3.11+, Rust 1.95 с rustfmt и локальный Cargo-кэш для `harness.lock`. Стенд собирается без сети в один Cargo job. См. [evidence.log](evidence.log).

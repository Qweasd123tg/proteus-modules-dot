# Core: не собирать reasoning, который уже отфильтрован из показа

Патч к [Proteus-core@32e56ecb](https://github.com/Proteus-harness/Proteus-core/commit/32e56ecb4cc6da324c60dd6ae2da78f3b7e46e7f). Если уже прошла анонимная сводка reasoning и у этого элемента нет потока с его ID, действующее правило не публикует отдельное завершение reasoning. Раньше перед проверкой этого правила Core всё равно склеивал текст элемента и затем выбрасывал строку. Теперь он собирает её только в ветке, где результат может быть использован.

Сама проверка не изменилась. Анонимный прогресс по-прежнему передаётся, reasoning с ID публикуется отдельно, а reasoning без предварительного прогресса может выйти в завершении. Канонические события передаются дальше без изменений; тексты ответов, порядок, отмена, ошибки и правила записи истории не затронуты.

## Измерение

Сравниваются две реализации штатного `present_stream` на одинаковых уже созданных событиях, с реальным Core emitter и локальным тестовым получателем событий. Счётчик включает обработку потока, сбор возвращённых событий и получения UI-событий тестовым получателем. Входные DTO и сериализация результатов вне замера. Это аллокации и запрошенные байты, включая realloc, **не** задержка UI, RSS, сеть или стоимость всего хода.

| Сценарий | Запросы аллокатору до → после | Запрошено байт до → после |
|---|---:|---:|
| Анонимный прогресс, короткий блок | 11 → 9 | 2 797 → 2 741 |
| Анонимный прогресс, 32 элемента по 4 блока | 273 → 145 | 85 558 → 74 102 |
| Анонимный прогресс, синтетический блок 64 КиБ | 11 → 9 | 133 813 → 2 741 |
| Поздно появившийся поток с ID | 18 → 16 | 4 037 → 3 858 |
| Анонимный прогресс и ранний поток с ID | 18 → 18 | 4 037 → 4 037 |
| Итоговый ответ без предварительного прогресса | 9 → 9 | 2 758 → 2 758 |

[Все результаты](probe.log). Число, размер и распределение реальных ответов не измерялись.

## Проверка

- **11** парных сценариев: побайтно совпали сериализованные выходные канонические события и события получателя. Проверены анонимный прогресс, видимое reasoning с ID, разные ID в одном ответе, позднее появление ID, итог без прогресса, пустой блок, повтор завершения на терминальном ответе, подавление потока и отмена.
- В итоговом запуске с процессными фикстурами M100 прошли **14/14** тестов. В том же исполняемом наборе пройдены проверки BoundModel на сбои/дедлайн и проверка выдачи reasoning через ACP. Форматирование, обычное и обратное применение, пробелы в diff прошли. Проверено применение поверх состава M100, но полный совместный прогон с этим патчем не выполнялся.
- Полный workspace, сетевой провайдер, реальный GUI, Windows и macOS не проверялись.

Из чистого checkout указанной ревизии, Rust 1.95, Linux x86-64:

```sh
# PROPOSAL — абсолютный путь к этому каталогу.
git apply --check "$PROPOSAL/source.patch"
cargo fetch --locked
# С процессными фикстурами Core: PROTEUS_TEST_REFERENCE_MODULE и
# PROTEUS_TEST_SESSION_STORAGE_MODULE должны указывать на готовые исполняемые файлы.
python3 "$PROPOSAL/probe.py" . "${CARGO_TARGET_DIR:-target}/r57-presentation"
```

Скрипт работает во временной копии и добавляет исходные функции и счётчик только в тестовый бинарник. Штатная сборка не содержит инструментирования.

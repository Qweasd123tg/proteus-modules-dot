# Core: считать размер JSON истории без сборки временной строки

`source.patch` отдельно применяется к `Proteus-harness/Proteus-core@32e56ecb4cc6da324c60dd6ae2da78f3b7e46e7f`. При подсчёте приблизительного числа токенов в истории Core превращал в полную JSON-строку metadata, аргументы и содержимое инструментов, цитаты и активность hosted tools, брал длину и сразу выбрасывал строку. Это срабатывало и для `null` в каждом обычном сообщении. Оценку используют карта контекста и сохранённая проекция сессии.

Патч отправляет тот же компактный JSON в считающий writer. Экранирование остаётся обязанностью Serde; округление, роли и состав учитываемых полей не меняются. Для этого на уровень session store поднят уже существующий счётчик размера страниц; два прежних локальных счётчика cache теперь заменены одним. Числовые лимиты, отказ от неполной сериализации, хеширование содержимого и порядок проверок перед публикацией не изменены. Это не смена токенизатора и не устранение полного прохода истории.

## Фактические измерения

Дифференциальный Rust-тест вызывает полную production-функцию исходной ревизии и патча на одних и тех же заранее созданных сообщениях. Счётчик из `proteus-contracts/src/test_alloc.rs` считает в потоке аллокации **только во время вызова**, включая новый размер при realloc.

| Фикстура | Оценка до и после | Запрошено у аллокатора, байт | Вызовы аллокатора |
|---|---:|---:|---:|
| 1 000 обычных текстовых сообщений | 6 750 | 8 000 → 0 | 1 000 → 0 |
| Структурированный результат, 1 024 повторения | 8 321 | 102 461 → 0 | 50 → 0 |
| Та же смесь, 131 072 повторения | 1 048 705 | 12 977 213 → 0 | 71 → 0 |

Смесь содержит JSON с экранированием и Unicode, текст, изображение и binary-содержимое инструментов, metadata, цитату и hosted activity. Ноль относится к этим входам, не ко всем возможным сообщениям: например, форматирование путей не менялось. Пиковая память процесса, RSS, скорость работы сервера и частота таких входов у пользователей не измерялись.

В `probe.log` прошли 3/3 проверки: сравнение целых сводок на пустой и смешанной истории и на границах округления, измерение аллокаций, точный лимит JSON в байтах и отказ на один байт ниже. `typecheck.log` относится ко всему библиотечному test target (rustc, emit=metadata), это не запуск всего workspace.

Дополнительно прошли **7/7 существующих тестов Core** на границы страниц, старые/новые окна после append, repair индекса инструментов и отказ при повреждённых или завышенных packed pages. Имена и результаты в `cache.log`. Чтобы обойти перелинковку всех тестов при нехватке диска, `verify_cache.py` вызывает неизменённые тела выбранных тестов на их штатных production-модулях и внутрипроцессном тестовом storage. Временная копия открывает функции runner-у; рабочее дерево не меняется. Отдельный backend-процесс, HTTP и Desktop не запускались.

## Воспроизведение

```sh
git apply --check "$PROPOSAL/source.patch"
# На неизменённой копии с доступным base и единственным набором собранных зависимостей:
python3 "$PROPOSAL/probe.py" . "${CARGO_TARGET_DIR:-target}/debug/deps"
git apply "$PROPOSAL/source.patch"
# Опционально: тот же компактный прогон семи cache-тестов (Python 3.11+):
python3 "$PROPOSAL/verify_cache.py" . "${CARGO_TARGET_DIR:-target}/debug/deps"
# Обычный Cargo-прогон в рабочей среде:
cargo test --locked -p proteus-core --lib core::session_store::
```

Скрипту сравнения нужны Python 3, Git, Rust 1.95 и lld; он извлекает исходники через git show и применяет изменения во временной директории. Целостность содержимого каталога: `sha256sum -c SHA256SUMS`.

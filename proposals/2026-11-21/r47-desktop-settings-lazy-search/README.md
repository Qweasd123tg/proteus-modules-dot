# Desktop: не готовить описание в поиске настроек, если хватило названия

Боковая панель настроек ищет по названию, описанию и ключевым словам. Для каждой строки поиск раньше собирал и приводил дополнительные поля к нижнему регистру, даже когда все слова нашлись в названии. Даже одно поле сначала копировалось через `join`, а затем копировалось снова при смене регистра.

Теперь первое слово, которого нет в названии, инициирует подготовку дополнительных полей. Последующие слова используют готовую строку. Одиночное дополнительное поле приводится к нижнему регистру напрямую, без промежуточной копии. При нескольких полях сохраняются тот же разделитель и то же Unicode-преобразование.

Слова могут, как и раньше, находиться в разных полях. Порядок совпадений, стабильность внутри ранга, разделы, раскрытия и якоря не меняются. Список совпадений **не обрезается раньше**: режим JSON по-прежнему правит всю хронологическую порцию совпадений нужного модуля, до итоговой сортировки и ограничения в 60 результатов.

**База:** [Proteus-desktop@b6a7ec2](https://github.com/Proteus-harness/Proteus-desktop/commit/b6a7ec2d8d7e486c8aba01291aa8c89774c4cded). SHA-256 патча: `6fe23da75aa51e17ef378b7316bca0d6eba8fb0bc6ae18a1b258c6cbf0e9def1`. Меняется только `src/ui/settings/search.rs`. Никаких изменений CLI, транспорта, API или настроек пользователя.

## Измерение

В измеряемый вызов входят разбор запроса, создание совпадений, ранжирование и формирование результата. В первых пяти строках таблицы используются **реальные 20 строк** из Desktop «Внешний вид» и «Чат», с оригинальными заголовками и описаниями. Остальные разделы UI не включены. Последние две строки это стресс-контроль из 2 048 синтетических полей: несколько дополнительных текстов на поле и около 2 КБ общего описания. Тела описаний подготовлены до замера.

| Запрос | Alloc/realloc, до → после | Запрошено байт, до → после |
|---|---:|---:|
| «АВТОПРОКРУТКА», слово в названии | 142 → 123 | 8 234 → 5 767 |
| «сообщения диалога», слова в описании | 143 → 125 | 8 240 → 5 857 |
| «РАЗМЕР ввода», название и описание | 143 → 125 | 8 230 → 5 847 |
| `qxmiss`, ничего не найдено | 140 → 122 | 7 158 → 4 775 |
| Пустой после разбора | 0 → 0 | 0 → 0 |
| Стресс: 60% названий покрывают все слова | 16 398 → 13 938 | 11 892 014 → 5 364 814 |
| Стресс: запрос отсутствует, все поля нужны | 16 386 → 16 386 | 11 112 586 → 11 112 586 |

Число и сумма запрошенных байтов измерены отдельно от времени. При realloc считается новый размер. Это **не пик памяти и не RSS**. Прогретый микрозамер без счётчика, восемь процессов на версию, чередование порядка на одном логическом CPU: на реальных строках медианы практически одинаковы (например, 36,52 → 35,87 мкс для «АВТОПРОКРУТКА»); значительный выигрыш по времени виден только в стресс-запросе, где часто достаточно названия (47,11 → 20,12 мс). Для промаха по длинным описаниям работа по подготовке полей остаётся. Скорость целого поиска в окне не измерялась.

## Проверки

- 3/3 на базе, 4/4 после патча. Собраны извлечённые из точного git-объекта `Finder`, `Hit`, типы назначения, статические строки Desktop и их вызовы поиска. Сработал исходный тест точного названия среди 60 префиксов и новый тест разных рангов, нескольких полей и якорей. Проверены реальные названия, описание, частичное совпадение, пустой запрос, отсутствие ответа и то, что JSON-замена меняет только якоря добавленной группы, не ранее найденные совпадения.
- На семи нагрузках и 66 вариантах запросов/размеров совпали контрольные суммы **порядка и всех полей** результата. Варианты включают порог 60, кириллицу и Unicode-контекст сигмы.
- Прошли прямое и обратное применение, `git diff --check` и проверка форматирования файла. Это изолированные проверки без GPUI; полное приложение, остальной набор Settings и нативная навигация не запускались.

Из checkout указанной ревизии: `git apply --check /путь/source.patch`, затем `git apply /путь/source.patch`. Для воспроизведения: `bash verify.sh PROTEUS_DESKTOP_CHECKOUT`. Нужны Rust 1.95.0 с rustfmt, Python 3, git, tar и bash; сеть не требуется, checkout не изменяется. Фактический вывод в `evidence.log`.

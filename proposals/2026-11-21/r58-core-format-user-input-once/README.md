# Core: собирать ответ на вопрос в один буфер

Патч к [Proteus-core@32e56ecb](https://github.com/Proteus-harness/Proteus-core/commit/32e56ecb4cc6da324c60dd6ae2da78f3b7e46e7f). Форматтер результата `request_user_input` строил временную строку для каждого списка вариантов и строки вопроса, а затем копировал сводку вместе с заголовком. Теперь он считает длину по уже отсортированным ссылкам и записывает итог в одну строку нужной ёмкости. Временный список ссылок для сортировки остаётся.

Прежние сортировка ключей, порядок выбранных ответов, разделители, текст для отсутствующих ответов, пустые варианты, пробелы и Unicode не меняются. Проверка вопроса, структура ответа, очередь, права и завершение хода остаются прежними.

## Замер

Измерена только реальная функция форматирования над уже заполненной картой. Построение дерева запроса, разбор ответа, пересылка и сериализация снимков вне замера. Счётчик показывает запросы аллокатору и суммарные запрошенные байты, включая realloc; это не RSS или задержка хода.

| Вход | Вызовы аллокатора до → после | Запрошено байт до → после |
|---|---:|---:|
| Нет ответов | 1 → 1 | 29 → 29 |
| Один ответ | 7 → 2 | 160 → 93 |
| Ключ с пустым списком | 6 → 2 | 152 → 89 |
| Три вопроса, обычные варианты | 15 → 2 | 536 → 163 |
| Unicode и переносы строк | 16 → 2 | 549 → 154 |
| Длинный ответ, стресс-фикстура | 8 → 2 | 380 159 → 95 085 |

[Полные счётчики](probe.log). Размеры входов синтетические; длинный ответ и карта на 64 ключа являются стресс-фикстурами, не статистикой использования.

## Проверка

- На **1 088** фикстурах итог совпал побайтно с исходной функцией. Проверены сортировка, порядок ответов, пустые карты/списки/значения, строки с переносами, NUL, Unicode и длинное поле. Ёмкость итоговой строки равна её длине в проверенных сценариях.
- В целевом прогоне прошли **11/11** тестов. Прогнаны штатные тесты инструмента и идентичности запросов, плюс реальный HTTP-сценарий ответа на вопрос с моделью и хранилищем из локальных process fixtures M100. Форматирование, пробелы в diff и прямое/обратное применение прошли. Патч применим поверх Core из M100 вместе с R57 по проверке применения, не совместному запуску.
- Полный workspace, сеть с настоящей моделью, GUI, macOS и Windows не проверялись.

Из чистого checkout указанной ревизии, Rust 1.95, Linux x86-64:

```sh
# PROPOSAL — абсолютный путь к этому каталогу.
git apply --check "$PROPOSAL/source.patch"
cargo fetch --locked
# С process fixtures, как для scripts/test.py:
# PROTEUS_TEST_REFERENCE_MODULE и PROTEUS_TEST_SESSION_STORAGE_MODULE
# указывают на готовые исполняемые файлы.
python3 "$PROPOSAL/probe.py" . "${CARGO_TARGET_DIR:-target}/r58-answer-format"
```

Измеритель компилирует прежний и новый форматтеры в одном тестовом бинарнике временной копии. Штатная сборка не включает инструментирование.

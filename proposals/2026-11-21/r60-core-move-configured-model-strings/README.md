# Core: переносить имена моделей в локальный список

Самостоятельный патч к [Proteus-core@32e56ecb](https://github.com/Proteus-harness/Proteus-core/commit/32e56ecb4cc6da324c60dd6ae2da78f3b7e46e7f). Локальный список вариантов уже получает собственные `ModelConfig` из действующих преобразований профиля. До изменения он ещё раз копировал имя провайдера и модели при построении `ModelRef`. Теперь готовые строки переходят во владение `ModelRef`, в том числе перед прежней проверкой повторов.

Преобразования и обработка ошибок остаются теми же. Активная модель идёт первой, остальные идут в порядке профилей, совпадающие пары исключаются. Исходная конфигурация и снимки остаются неизменными. Убрана только вторая копия двух строк; первая копия из профиля, другие поля и сетевое обнаружение модели не меняются.

## Замер

Измерен реальный `configured_model_options` над уже подготовленной конфигурацией. Учтены преобразования профилей и сбор результирующего списка. Подготовка конфигурации, заголовки моделей, сериализация HTTP, обращения к процессам и сеть не измерялись. Счётчик показывает число запросов аллокатору и суммарные запрошенные байты, включая realloc; это не RSS или задержка выбирающего интерфейса.

| Локальная конфигурация | Запросы аллокатору до → после | Запрошено байт до → после |
|---|---:|---:|
| Профилей нет | 1 → 1 | 72 → 72 |
| Один профиль по умолчанию | 9 → 5 | 268 → 230 |
| 4 псевдонима, 3 уникальные модели | 26 → 16 | 316 → 264 |
| 4 псевдонима, отсутствует активный | 23 → 15 | 454 → 417 |
| 128 профилей, синтетический стресс | 651 → 393 | 17 180 → 14 896 |

## Проверка

- **154** входа: сериализованные результаты совпали побайтно. Проверены активная модель не первой в порядке профилей, повторяющиеся псевдонимы, отсутствующий и пустой выбор, пустые/не-ASCII строки, вложенные настройки профиля и исходные строки с запасом ёмкости. Исходная конфигурация не меняется; ёмкость итоговых строк в контролях одинакова.
- Пройден **1/1** изолированный нативный тест с 154 случаями: прежняя и новая функции взяты из точных исходников и скомпилированы в одном небольшом тестовом бинарнике против реальных `AppConfig`, `ModelConfig` и `ModelRef` из уже собранной базовой библиотеки Core. Точное прямое/обратное применение, проверка пробелов и форматирование прошли. Применение поверх M100 вместе с R57–R59 проверено без повторного запуска всего состава.
- Целую библиотеку Core после патча не пересобирали из-за доступных ресурсов. Полный workspace, HTTP-путь, внешний провайдер, интерфейс, Windows и macOS не проверялись.

Из чистого checkout указанной ревизии, Rust 1.95, Linux x86-64:

```sh
# PROPOSAL — абсолютный путь к этому каталогу.
git apply --check "$PROPOSAL/source.patch"
cargo build --locked -p proteus-core --lib
# CORE_RLIB, CONTRACTS_RLIB и SERDE_JSON_RLIB — артефакты этой сборки
# из одного target/debug/deps; RING_NATIVE — каталог build/ring-*/out
# той же сборки. Нужны тот же rustc и доступный lld.
python3 "$PROPOSAL/probe.py" . --core-rlib "$CORE_RLIB" \
  --contracts-rlib "$CONTRACTS_RLIB" --serde-json-rlib "$SERDE_JSON_RLIB" \
  --native-dir "$RING_NATIVE"
```

Измеритель собирает прежнюю и новую функции из временной копии вместе; штатная сборка не получает дополнительных зависимостей или счётчиков.

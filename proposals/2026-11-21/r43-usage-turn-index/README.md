# Usage: номера ходов без повторного поиска по всей истории

Вкладка «Расход» строит список ходов для фильтра и подписывает номером хода каждую видимую карточку запроса. Раньше для каждого запроса приходилось искать его ID по всему накопленному вектору. Если все 8 192 запроса относятся к разным ходам, только для сбора этого списка выполняется 33 550 336 сравнений идентификаторов. Ещё до 20 поисков требовались для карточек.

[Патч](source.patch) хранит заимствованные строки ID в упорядоченном `IndexSet<&str>` на время одной проекции. Позиция первого появления даёт исходный номер даже после фильтрации и сортировки. Прежний порядок выпадающего списка, пустые и некорректные ID («Вне хода»), протокол, тарифы и формат карточек не меняются. Индекс использует память пропорционально числу разных ходов и не переживает текущий снимок; зависимость `indexmap` уже есть в пакете. Вместо квадратичного перебора получаем ожидаемый линейный проход по запросам. При малом числе разных ходов хеширование может стоить дороже простого перебора.

База: [Proteus-desktop-extensions@892f627](https://github.com/Proteus-harness/Proteus-desktop-extensions/commit/892f627570369ed60d7205eb0d351c753ec4305f). Потребитель: [Usage view](https://github.com/Proteus-harness/Proteus-desktop-extensions/blob/892f627570369ed60d7205eb0d351c753ec4305f/packages/usage/src/view.rs#L43-L104).

## Что изменилось в замере

| Запросов / разных ходов | Только сбор ID, мс, до → после | Вся `view::render`, мс, до → после |
|---|---:|---:|
| 32 / 2 | 0,0010 → 0,0019 | 0,387 → 0,363 |
| 2 048 / 16 | 0,130 → 0,149 | 4,57 → 4,28 |
| 2 048 / 512 | 1,31 → 0,20 | 6,08 → 4,87 |
| 8 192 / 2 048 | 22,08 → 1,84 | 41,78 → 19,99 |
| 8 192 / 8 192 | 78,70 → 1,62 | 113,94 → 29,54 |

Медианы восьми пар прогретых release-прогонов, с чередованием первого бинарника. Готовый синтетический снимок подаётся до начала замера; для полной проекции учитывается построение и освобождение всех узлов страницы. Это не время открытия вкладки, сетевого запроса, сериализации или нативной отрисовки; для коротких журналов ускорение не заявляется. Оба бинарника дали **побайтно одинаковый JSON** на 24 комбинациях: шесть размеров/вариантов повторения (в том числе пустой журнал) и четыре режима фильтрации/порядка/страницы. Вывод: 3 104 462 байта, [SHA-256 и все измерения](timings.log).

## Проверка и перенос

* `cargo test --locked -p extension-usage`: 12/12 на базе, **13/13** с патчем. Добавлен тест первого появления, повторов, Unicode и отсутствующего/некорректного ID.
* Полный `cargo test --offline --locked --workspace --no-fail-fast`: 284 прошли, 1 упал. Единственное падение, Mermaid wire на Linux, воспроизведено и на чистой базе в отдельном target. Среда не предоставляет `/proc/<pid>/task/<tid>/children`, по которому тест проверяет число процессов. Продукт и проверка Mermaid не менялись. Python suite и нативное окно Desktop не запускались. [Итоги проверок](checks.log).
* Повтор: `python3 reproduce.py /path/to/Proteus-desktop-extensions`. Нужны Git с объектом базы, tar, Python 3, Rust/Cargo/rustfmt и зависимости Cargo.lock. Для автономной проверки с кэшем используйте `CARGO_NET_OFFLINE=true`. Скрипт создаёт временные исходники и свой target, проверяет патч, запускает изменённый пакет и сравнивает обе версии [на настоящей проекции](probe.rs). Для переноса в чистой базе: `git apply --check /path/to/source.patch && git apply /path/to/source.patch`.

# Core: читать описание терминала из существующего JSON

Самостоятельный патч к [Proteus-core@32e56ecb](https://github.com/Proteus-harness/Proteus-core/commit/32e56ecb4cc6da324c60dd6ae2da78f3b7e46e7f). При восстановлении истории рендерер копировал каждый JSON-объект `tool_terminal`, чтобы извлечь из него типизированную ссылку на терминал. Теперь тот же `ToolTerminalRef` десериализуется из ссылки на существующее значение, один раз до выбора ветки «обновить карточку» или «создать карточку результата». Сохранение исходных метаданных у карточки по-прежнему требует отдельную копию; убрана только промежуточная копия для парсера.

Схема терминала, обработка неизвестных полей, очистка ссылки при отсутствии/некорректном значении, полномочия терминала, strict validation журнала и сериализованный контракт не меняются. Live-проекция, включая её собственное сохранение уже опубликованного терминала, не затронута.

## Измерение

Штатный тестовый вход подаёт в настоящий холодный рендер фиксированный, предварительно проверенный канонический журнал. Измеряется весь рендер, в том числе копирование входных записей тестовым источником между сканами; подготовка фикстуры, строгая проверка журнала и сериализация готового DTO находятся вне замера. Штатный счётчик аллокатора отражает количество обращений и сумму запрошенных байтов, включая realloc. Это не RSS, не пик живых данных и не замер задержки. В синтетической фикстуре ошибки присутствует одно неизвестное поле с вложенным содержимым около 4 КиБ; этот случай проверяет сохранение необработанных метаданных и не представляет размер обычного описания терминала.

| Число результатов и описание терминала | Вызовы аллокатора, до → после | Запрошено байт, до → после |
|---|---:|---:|
| 0, без описания | 5 → 5 | 178 → 178 |
| 1, без описания | 117 → 117 | 10 636 → 10 636 |
| 1, обычное описание | 164 → 158 | 13 239 → 12 829 |
| 64, обычное описание | 9 401 → 9 017 | 725 032 → 698 792 |
| 512, обычное описание | 74 833 → 71 761 | 5 815 992 → 5 606 072 |
| 16, неизвестное вложенное поле | 3 401 → 3 145 | 728 472 → 631 112 |
| 64, неизвестное вложенное поле | 13 497 → 12 473 | 2 921 384 → 2 531 944 |

База с измерителем прошла **51/51**, кандидат **52/52**. Все семь полных снимков до/после совпали побайтно.

## Проверка

- Встроенный регрессионный тест сверяет новый путь со старым `serde_json::from_value` для обычного объекта, позиционного массива, лишнего, отсутствующего или неверно типизированного поля, ошибки UUID, `null` и отсутствия ключа. Проверены оба пути карточки: старый терминал очищается при невалидном/отсутствующем значении, а необработанные метаданные и статус сохраняются. Измеритель отдельно сравнивает полную сериализацию семи проверенных журналов.
- Набор тестов `app_server::transcript::`, форматирование, прямое и обратное применение прошли. Изолированная проверка индекса подтвердила, что патч применяется поверх #304 и #308; объединённый исполняемый набор не запускался. Полный workspace, HTTP, GUI, настоящие процессы storage/терминала, Windows и macOS не проверялись.

## Воспроизведение

Из чистого checkout Core указанной ревизии, Rust 1.95, Linux x86-64:

```sh
# PROPOSAL — абсолютный путь к этому каталогу.
git apply --check "$PROPOSAL/source.patch"
cargo fetch --locked
python3 "$PROPOSAL/probe.py" . "${CARGO_TARGET_DIR:-target}/r48-replay"
git apply "$PROPOSAL/source.patch"
# Штатный runner в окружении с настроенными process fixtures:
python3 scripts/test.py -p proteus-core --lib app_server::transcript::
```

Скрипт создаёт временную копию исходников, добавляет измеритель только в тестовую сборку и запускает обе версии через `cargo test --locked --offline` на одном наборе зависимостей.

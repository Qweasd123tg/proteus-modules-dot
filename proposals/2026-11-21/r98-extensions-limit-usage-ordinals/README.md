# «Расход»: номера запросов только для текущей страницы

При каждом показе панели карта номеров хранила ID всего журнала, хотя число видно не более чем на 20 карточках. Теперь карта содержит только отображаемые ключи. Обратный проход по исходному журналу останавливается, когда для каждого из них найден номер. При пустой странице этого прохода нет. Это временная таблица одного построения, не новый кеш и не ограничение на число записей API.

Номер по-прежнему равен **последней позиции ID во всём исходном журнале**, считая с единицы. Даже если последняя запись с таким ID исключена фильтром, обе показанные карточки сохраняют прежний номер. Пустая строка, отсутствующий, null и нестроковый ID по-прежнему делят один номер; значение кнопки и раскрытие не меняются. Патч не меняет подсчёты токенов, сортировку, фильтры, номера ходов или запросы к серверу.

## Измерение

Для синтетического журнала из 2 000 различных ID на проверенном Rust 1.95.0/x86-64:

| Страница | Ключей в таблице, до → после | Запрошено у аллокатора | Просмотрено строк исходного журнала |
| --- | ---: | ---: | ---: |
| Первые 20 в исходном порядке | 2 000 → 20 | 102 416 → 816 Б | 2 000 → 2 000 |
| Последние 20 или 20 новейших | 2 000 → 20 | 102 416 → 816 Б | 2 000 → 20 |
| Фильтр без совпадений | 2 000 → 0 | 102 416 → 0 Б | 2 000 → 0 |
| Единственный результат в конце | 2 000 → 1 | 102 416 → 116 Б | 2 000 → 1 |

В непустом случае добавляется проход по ключам видимой страницы (до 20). На первой странице поиск всё ещё линейный. При 20 исходных записях и полной странице объём не меняется (816 Б); при одной записи оба варианта запрашивают 116 Б, при пустом журнале 0 Б. На длинной полной странице по-прежнему одно выделение, но на **101 600 Б меньше**; фактическая ёмкость карты 3 584 → 28. Лимит 20 относится к числу ключей, не к ёмкости.

[Измерения](measurements.log) получены через тестовую вставку в реальное место построения карты: System считает вызовы и запрошенные байты в одном потоке, одновременно считаются обращения к исходным и видимым ключам. Вход подготовлен вне замера, пять одинаковых результатов каждого случая на каждом из четырёх вариантов. Не измерялись весь render, память самого журнала, RSS, задержка или выигрыш всего приложения.

## Проверка и применение

Один [source.patch](source.patch) применим отдельно к upstream Extensions `892f627570369ed60d7205eb0d351c753ec4305f` и к M150 с 13 накладками Extensions до #420 (составное дерево `cffc586029afcf517ab3f112ec0309f5889d961d18bf802ede177e847fc23ac7`). Установка и протокол не меняются. Патч затрагивает только реализацию списка и тест пакета Usage.

У всех четырёх release-бинарников совпали побайтно **21 кадр stdout, 252 934 Б**. На каждый пришлось ровно шесть синтетических GET к `/sessions` и `/usage`, без записей. Проверены два контекста одной сессии, закрытие и новое открытие, Preview, порядок, страницы (включая выход за границы), период, модель, проблемные запросы, поиск, раскрытие и сворачивание дубликатов и нестроковых ID. Отдельный probe сверил номера и исходные значения кнопок в 11 случаях. Штатные тесты пакета: 12 → 13 на upstream и 15 → 16 в композиции. [Проверки](checks.log) и [точные артефакты Cargo](artifact-receipts.log).

Для воспроизведения запустить [reproduce.py](reproduce.py) с локальным Git upstream, деревом M150 и 13 накладками в проверяемом по SHA-256 порядке (точные хеши в начале скрипта), существующей прогретой целью `--target` и общим файлом `--lock`. Нужны Rust 1.95.0 и прогретый офлайн-кеш Cargo в `CARGO_HOME`. Без `--admit-exclusive` выполняется только предварительная проверка. С флагом: эксклюзивная блокировка, `--release --locked --offline -j1`, пороги свободного места 512 МиБ на входе и 256 МиБ для остановки. См. `python3 reproduce.py --help`.

Полный workspace, нативный Desktop, упаковка и нагрузка реальных сессий не запускались.

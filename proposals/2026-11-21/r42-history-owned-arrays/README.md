# Git History: не копировать готовые строки списка и графа

Штатная вкладка истории передаёт строки в `ui::list`, документ графа коммитов передаёт колонки и строки в `ui::lanes`. Оба конструктора уже владеют этими массивами. В исходной версии `json!` сериализует их элементы в новые `Value`, повторно выделяя память в том числе под меню, подписи и метаданные каждой строки. Независимая копия здесь не нужна. Патч переносит исходные массивы в объект через `Value::Array`, как уже делают `tree` и `fill`. Публичные сигнатуры, порядок ключей, набор полей, обработчики выбора и протокол не меняются.

База: [Proteus-desktop-extensions@892f627](https://github.com/Proteus-harness/Proteus-desktop-extensions/commit/892f627570369ed60d7205eb0d351c753ec4305f). Потребители: [построители истории Git](https://github.com/Proteus-harness/Proteus-desktop-extensions/blob/892f627570369ed60d7205eb0d351c753ec4305f/packages/git/src/history.rs). Патч: [source.patch](source.patch), SHA-256 `304154dd50500366fa9b6f076ad15dac6c3ddcdaa564aa12b4a07d67947b8794`.

## Что измерено

Синтетические 1 000 строк с вложенным меню; входные массивы готовы **до** начала счёта. Проверяется только сборка внешнего виджета, а не создание самих строк, запись JSON в канал, скорость Desktop или RSS процесса.

| Конструктор | Запросов выделения/переразмещения, до → после | Дополнительный пик живых байтов, до → после |
|---|---:|---:|
| Список истории | 24 012 → 11 | 1 530 732 → 842 |
| Граф коммитов | 28 026 → 12 | 2 053 453 → 858 |

[Стенд](probe.rs) считает запрошенные байты через глобальный аллокатор Rust. Пиковая величина отсчитывается от уже живого входа, без накладных расходов системного аллокатора. Обе версии выдали побайтно одинаковый JSON на 0, 1, 100 и 1 000 строках (включая Unicode и пустые массивы). Полные счётчики: [до](stock.tsv) и [после](candidate.tsv); порядок столбцов: виджет, строки, число запросов, сумма запрошенных байтов, дополнительный пик живых байтов.

## Проверка и перенос

* Новый regression-тест сравнивает wire и исходные буферы строк и колонок. На базе с добавленным тестом падает проверка адреса, с патчем проходит. `rustfmt --check`, прямой и обратный `git apply --check` прошли.
* На исходниках точной ревизии прошли 61/61 тест SDK и 41/41 тест Git-расширения (включая синтетический loopback API, граф, меню и навигацию). Цели собраны напрямую через `rustc --test` с готовыми зависимостями. Пять тестов модуля UI уже входят в 61. Полный Cargo workspace, Python wire suite и окно Desktop не запускались. [Журнал](evidence.log).
* Чтобы повторить узкий замер, нужен Git, Rust и совместимый с ним `serde_json` 1.0.152 с `preserve_order` плюс его скомпилированные зависимости в соседнем каталоге `deps`. Команда: `bash verify.sh /path/to/upstream/sdk/src/ui.rs /path/to/deps/libserde_json-HASH.rlib`. Скрипт проверит точный исходный blob и сравнит весь вывод побайтно в отдельном временном дереве, не меняя checkout.
* В чистом checkout базы: `git apply --check /path/to/source.patch && git apply /path/to/source.patch`; для штатной полной проверки: `cargo test --locked --workspace`.

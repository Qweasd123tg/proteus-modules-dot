# SDK Extensions: не копировать пути сессий при очистке

После обработки большинства кадров SDK очищает припаркованные состояния, а цикл `run` отдельно очищает экземпляры пакета. Обе операции раньше строили временное множество и копировали пути всех живых контекстов, даже если удалять нечего.

[Патч](source.patch) оставляет прежний `HashMap::retain` и объединяет проверку принадлежности. Для пустой карты проверок нет. Если окно или проверяемая запись одна, новые структуры не выделяются. Если обе стороны содержат несколько записей, остаётся временный `HashSet` с заимствованными ключами, без копий строк. Контекст без сессии отличается от контекста с пустым путём и от отсутствия окна. В ветке одного окна ключ извлекается один раз, независимо от числа припаркованных записей. Для нескольких окон и записей остаются один проход по контекстам и проверки принадлежности в множестве (обычная линейная стоимость, без двойного вложенного поиска).

Время очистки не сдвигается; новые кеши или ссылки за пределами вызова не появляются. Если второе окно ещё держит сессию, конфигурация, ошибка команды, ожидающие настройки и экземпляр пакета сохраняются. После закрытия последнего окна они освобождаются; повторное открытие такого же пути не наследует старое состояние. Маршрутизация, rehost, допуск и доставка кадров не меняются.

| 1 000 циклов обеих проверок | Запросов выделения | Запрошено байт |
|---|---:|---:|
| Нет окон и записей | 0 → 0 | 0 → 0 |
| Один контекст, один экземпляр | 4 000 → 0 | 300 000 → 0 |
| 8 контекстов одной сессии, один экземпляр | 18 000 → 0 | 1 376 000 → 0 |
| 8 разных сессий, 7 припаркованных состояний | 18 000 → 2 000 | 1 376 000 → 576 000 |
| 128 разных сессий, 127 припаркованных состояний | 258 000 → 2 000 | 21 592 000 → 8 736 000 |

[Счётчики](measurements.log) считают успешные выделения и перераспределения на одном потоке при двух реальных вызовах очистки на заранее подготовленных данных. Для нескольких сессий остаются два временных множества за цикл. Подготовка, рендеринг, HTTP и IPC вне счётчика. Пять одинаковых повторов на вариант. Не замер задержки, RSS или частоты очистки всего приложения.

- Побайтно совпали **50 обычных кадров** (Mode 26, Model 24) на каждой паре, в том числе перенос представления, успешный ответ и отказ, первое и последнее закрытие контекстов одной сессии и свежее открытие того же пути без устаревшего значка до снимка. Отдельные SDK-контроли проверили ошибку и ожидающий ID в припаркованной сессии, освобождение по последнему контексту и различие None и пустой строки.

Четыре повторных чтения SDK разрешены только после проверки совпадения с уже собранным артефактом той же версии. Хеши исполняемых файлов сверены до и после запусков.

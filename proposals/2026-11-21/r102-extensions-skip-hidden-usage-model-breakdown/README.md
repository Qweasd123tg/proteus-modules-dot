# «Расход»: не считать разбивку по моделям, когда таблица скрыта

Панель и раньше показывала разбивку только при двух и более группах, но считала её даже в сессии с одной моделью и при явном выборе модели. Теперь сводка пропускает группировку, только когда уже известно, что таблица не может появиться. Общая стоимость, токены, уведомления о неизвестных сведениях и карточки запросов считаются как раньше.

После сброса устаревшего выбора остаются те же точные ключи моделей, включая варианты со слешами. Две записи могут иметь одинаковый ключ разбивки, хотя тариф известен только для одной из них; общий расчёт по-прежнему проверяет каждую. Если в доступной выборке возможны разные модели, используется прежний расчёт, даже когда поиск или фильтр статуса скрыл их карточки. Пагинация, сортировка, номера запросов, протокол, доступ и кэш не меняются.

## Проверка и применение

Выберите один патч: [source.patch](source.patch) для upstream Extensions `892f627570369ed60d7205eb0d351c753ec4305f`, или [cumulative.patch](cumulative.patch) для M150 с 15 накладками Extensions до #424, дерево `f02907b8618ee5e86ff650edb606598287a77038e358e99baa0fd42c9120c880`. Меняется только файл представления Usage со встроенным тестом.

[reproduce.py](reproduce.py) проверяет исходные хеши, порядок накладок, Cargo.lock, прямую и обратную применимость патча, штатные release-тесты, байты реального stdout и отдельный диагностический прогон. Нужны Rust 1.95.0, прогретый офлайн-кеш `CARGO_HOME`, существующая цель `--target` и общий `--lock`. По умолчанию выполняется предварительная проверка. С `--admit-exclusive`: один offline locked job, 512 МиБ на входе и порог остановки 256 МиБ. См. `python3 reproduce.py --help`.

Проверены 20 обычных запросов одной модели, 50 запросов с одним ключом разбивки и частично известной стоимостью, равный расход двух групп (прежний порядок), ошибочные/отсутствующие данные модели, сброс неизвестного выбора, поиск и фильтр с сохранением групп сводки, периоды с одной моделью или одной строкой, закрытие и повторное открытие, Preview и недоступный журнал. Контроль номеров карточек сравнивается также с точным выводом предыдущего пакета #422.

## Результат

Штатные release-тесты: **12 → 13** на upstream, **16 → 17** в композиции. Во всех четырёх вариантах совпали **41 кадр stdout побайтно (472 128 Б)**, 14 упорядоченных GET, ноль операций записи и отдельно 11 диагностических деревьев сводки. По пять одинаковых диагностических прогонов на вариант.

| Сценарий | Вызовы расчёта стоимости в сводке, до → после | Форматирование ключа группы | Запрошено при группировке |
| --- | ---: | ---: | ---: |
| Одна модель, 20 строк | 40 → 20 | 20 → 0 | 1 480 → 0 Б |
| Одна модель, 50 строк | 100 → 50 | 50 → 0 | 2 290 → 0 Б |
| Явно выбран один ключ с 50 строками | 100 → 50 | 50 → 0 | 2 140 → 0 Б |
| Смешанный отчёт, 52 строки | 104 → 104 | 52 → 52 | 2 175 → 2 175 Б |

На пустом журнале выделений при группировке не было и нет. В смешанной сессии без выбранной модели прежний обход сохранён, даже если текущий период из 50 строк в итоге содержит только одну модель.

Счётчики сняты на реальном построении сводки тестовой вставкой. Объём памяти относится только к запрошенным выделениям/перевыделениям при группировке; не учитываются карточки, фильтрация, список моделей, ввод-вывод, весь рендер или RSS. Время, полный workspace, нативный Desktop и упаковка не проверялись.

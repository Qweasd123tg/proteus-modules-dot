# Files: не хранить вторую копию имени записи

Точный upstream: `892f627570369ed60d7205eb0d351c753ec4305f`. Изменены только `packages/files/src/tree.rs` и его штатные тесты.

`Project` хранит типизированные листинги между отрисовками. Для обычного ответа Core строка относительного пути уже заканчивается точным UTF-8 именем записи. Храним только путь и смещение начала имени, рассчитанное один раз при разборе. Смещение допустимо, только когда имя совпало целиком байт в байт и префикс пуст либо заканчивается разделителем. Если отображаемое имя отличается, отдельный `Box<str>` хранит именно исходную строку. Пустые и некорректно типизированные поля по-прежнему проходят прежние значения по умолчанию; исключение проверяет сырое имя до преобразования. Существующая нормализация пути, его идентичность, порядок, тип, флаги неполного списка, запросы, кэш, инвалидация и протокол не менялись. Чтение по смещению не сканирует путь заново.

- `source.patch` применяется самостоятельно к указанному upstream. Старый обход владеет копией строки листинга: имя, взятое из пути, копируется только для видимой строки, а отдельный `Box<str>` передаётся в уже требуемый `String` строки без второй копии.
- `cumulative.patch` является **альтернативой**, а не вторым патчем поверх `source.patch`. Применяется к сохранённому дереву M150 с #394/#395/#397/#399/#402/#404/#406 (`d6eed9c15d556bc6b26589da37edd340327215322f31f02508390eecfd2fc5f7`). Здесь #267 уже перевёл обход на `Rc<Listing>`: та же запись заимствуется и копируется только собственная строка метки видимой строки. Не откатывает существующий fold/collapse или проекцию Git-статусов. Оба варианта проверены отдельно.

## Сфокусированная проверка

Штатный `extension-files`, offline locked release, один Cargo job: **37 → 38** тестов на upstream и **40 → 41** на составном дереве. Новый тест фиксирует границы UTF-8, Windows-разделитель, буквальный обратный слеш в имени, псевдоним, совпадение без разделителя, пустые/отсутствующие поля, тип записи и прежнее исключение имён. Остальные штатные тесты не удалены.

В каждой паре исходные байты stdout **13 кадров** настоящего бинарника совпали. Синтетический loopback получил 18 разрешённых GET в том же порядке: складывание, раскрытие, выбор и сворачивание дерева (9 кадров), раскрытие усечённого списка на 1 000 полученных записей с обычными/нестандартными именами (2), пустой список и ошибка ответа (по 1). Идентификаторы, порядок, этапы видимости, текст меток, сохранённые флаги и номера последовательности проверяются без пересериализации stdout. Нет обращений к Git-репозиторию пользователя, внешней сети или записи в его рабочую папку.

Отдельный зонд снял **живые запрошенные байты аллокатора** только пока заполненный `Project` удерживал листинги. Он использует настоящий `Project::listing` и `Listing::parse`; входные JSON и временные строки уже освобождены, UI не создаётся. Складывает отдельно именованные блоки, ёмкость путей и буферов `Vec<Entry>`, проверяет сопоставимое число слотов, общий live счётчик и возврат к исходному уровню после `drop`. По пять идентичных наблюдений на вариант, 28 байт в каждом имени.

Entry на проверенном x86-64: **56 → 48 байт**. Для 1 000 записей вектор сохраняет 1 024 слота, сокращая их общий буфер на 8 192 байта; для обычного имени удаляется ещё один блок из 28 байт на запись.

Это не RSS/PSS, не пик процесса и не число папок, обычно открытых пользователем. Одна папка из примера экономит около 35 KiB; 64 таких уже удерживаемых листинга дают 2.21 MiB, но их наличие при старте здесь не измерялось. Расход аллокатора на округление, системные страницы, отрисовка и производительность по времени не измерялись. Полный набор Extensions, упаковку, нативное окно и память всего Proteus этот тест не проверяет.

## Повторить

Укажите локальный git-checkout, содержащий upstream, сохранённое дерево Extensions M150, упорядоченные семь предыдущих патчей, существующий Cargo target и общий файл блокировки. Используйте Rust/Cargo 1.95.0 из проверенного toolchain и уже подготовленный offline кэш Cargo.

```bash
PYTHONDONTWRITEBYTECODE=1 python3 reproduce.py "$STOCK" "$M150_EXTENSIONS" \
  "$PATCH_394" "$PATCH_395" "$PATCH_397" "$PATCH_399" "$PATCH_402" "$PATCH_404" "$PATCH_406" \
  --target "$TARGET" --lock "$BUILD_LOCK" --admit-exclusive
```

Без `--admit-exclusive` только проверка входов. С флагом: один общий lock, границы свободного места 512 MiB при входе и 256 MiB для остановки на каждом используемом томе. Cargo JSON подтверждает свежий точный исполняемый файл Files каждой ветки и роли; отпечатки проверяются до/после запуска, SDK свежий при первом артефакте каждой ветки либо доказанно переиспользован только внутри неё. `checks.log` содержит итоги, `measurements.log` строки замера, `artifact-receipts.log` ревизии/деревья/инструменты/артефакты.

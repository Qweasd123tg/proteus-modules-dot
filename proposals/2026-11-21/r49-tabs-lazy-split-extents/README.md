# Desktop: геометрия разделённых панелей без временного списка на каждый узел

При перерисовке области вкладок Desktop вычисляет целевые прямоугольники панелей через [`render_tabs → rects_spaced`](https://github.com/Proteus-harness/Proteus-desktop/blob/b6a7ec2d8d7e486c8aba01291aa8c89774c4cded/src/ui/tabs/view.rs#L29-L44). Раньше для каждого разбиения создавался `Vec<f32>` с ширинами или высотами всех детей, затем он один раз читался по порядку и выбрасывался. Теперь геометрия получает размеры по одному через итератор. Итоговый список прямоугольников по-прежнему создаётся. В раскладке из одной панели временного списка не было и раньше.

Формулы для фиксированных пикселей, весов, сжатия и зазоров не меняются. Порядок обхода и операций с `f32` тот же, кеширования нет. При изменении ширины перетаскиванием, блокировке панелей и слиянии вложенных разбиений остаётся прежний снимок размеров там, где код обращается по индексу или меняет модель. Это не поиск панели по идентификатору и не кеш высот чата.

База: [Proteus-desktop `b6a7ec2d`](https://github.com/Proteus-harness/Proteus-desktop/commit/b6a7ec2d8d7e486c8aba01291aa8c89774c4cded), исходное дерево `crates/tabs`: `30e619947f49f2f70735a7d21c5aa536b319ffa7`. SHA-256 файла `source.patch`: `16c9eb4e0df982f3fc2cd5021fb578a67d863cbdc517f82e81c51efe3042f691`.

## Аллокации одного расчёта геометрии

| Раскладка | Запросы аллокатору, до → после | Запрошено байтов, до → после | Медиана, нс/вызов |
|---|---:|---:|---:|
| Одна панель (контроль) | 1 → 1 | 80 → 80 | 32,70 → 35,17 |
| Две панели рядом | 2 → 1 | 88 → 80 | 39,08 → 33,52 |
| Сетка 2 × 2 | 4 → 1 | 104 → 80 | 89,54 → 59,47 |
| Восемь панелей в ряд | 3 → 2 | 272 → 240 | 120,84 → 112,46 |
| 64 панели, вложенное бинарное дерево (стресс) | 68 → 5 | 2 984 → 2 480 | 1 732,44 → 1 098,02 |

Счётчик охватывает ровно один вызов `rects_spaced` на готовой синтетической раскладке: по одному запросу меньше на каждый узел разбиения и по четыре запрошенных байта меньше на каждого его ребёнка. У `realloc` учитывается запрошенный новый размер; это не байты, одновременно находящиеся в памяти. Время замерено отдельным бинарником без счётчиков, с прогревом и освобождением результата, восемь процессов на версию, с чередованием порядка на одном логическом CPU. Для одной панели улучшения не видно; это контроль, где проход по разбиениям не выполняется. Абсолютные времена шумны.

## Проверка

Собран весь исходный крейт `proteus-tabs` с оригинальным манифестом отдельно от GPUI. Все внешние зависимости зафиксированы по имени, версии, registry и checksum из Desktop Cargo.lock. Профиль probe: `opt-level=3`, ThinLTO, одна единица кодогенерации, как у крейта вкладок в Desktop release.

- **72/72 штатных теста на каждой версии**: в том числе размеры, перетаскивание разделителя, блокировка, нормализация, навигация, восстановление и перенос вкладок.
- Побайтово совпали все **1 632 комбинации**: 128 валидных раскладок плюс восемь намеренно невалидных состояний в памяти, по 12 сочетаний размеров окна и зазора. Сверялись идентификаторы, порядок и точные биты четырёх координат каждого прямоугольника (всего 26 304). Есть обе оси, разные веса и фиксированные панели, тесные и нулевые размеры, отрицательные значения, NaN и бесконечности. Невалидные контрольные значения не меняют правил допуска настройки.
- Прямое и обратное применение патча, `git diff --check`, rustfmt и сверка всех 11 внешних зависимостей прошли. Журнал выбранных проверок и все исходные замеры: [evidence.log](evidence.log).

Полный native workspace и окно приложения не запускались: локальная попытка `cargo metadata --locked --offline` для исходного workspace остановилась на отсутствующем в кеше `gpui-kit`. Здесь не измерялись время кадра, FPS или RSS приложения.

## Воспроизведение

Нужны Linux x86-64, Git, Bash, Python 3.11+, Rust 1.95.0 с rustfmt и кеш зависимостей `harness.lock`. В checkout базы сначала можно проверить `git apply --check /путь/source.patch`, а затем применить `git apply /путь/source.patch`. Отдельно запустите `bash verify.sh /путь/Proteus-desktop` из каталога пакета. Скрипт извлекает крейт из указанного коммита во временную директорию, не правит checkout, сверяет lock, применимость в обе стороны и форматирование, запускает тесты, сравнение и замеры. Для стабильности замеров закрепите процесс на одном доступном логическом CPU через `taskset`. В упаковке нет исходников пользовательских сессий, готовых бинарников или изменений upstream.

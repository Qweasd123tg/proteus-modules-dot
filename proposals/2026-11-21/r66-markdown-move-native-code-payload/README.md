# Markdown: переносить исходник нативного блока без повторной копии

При построении нативного блока кода расширение уже владеет строками текста и языка. Прежнее построение JSON через сериализатор ещё раз копировало обе строки. [Патч](source.patch) переносит их в готовый узел в прежнем порядке полей. Если у строки от парсера есть запас ёмкости, он не остаётся в сохранённом узле.

Окончания строк, идентификаторы, сырой текст закрытого блока и результат разбора незакрытого блока сохраняются. Маршрутизация в зарегистрированные расширения, разбор Markdown, обновление потокового префикса и независимость возвращённого дерева от кэша не меняются. База: [Proteus-desktop-extensions@892f627](https://github.com/Proteus-harness/Proteus-desktop-extensions/commit/892f627570369ed60d7205eb0d351c753ec4305f).

| Синтетический документ | Запрошено байт за построение до → после | Экономия, байт |
|---|---:|---:|
| Один закрытый нативный блок, 320 байт кода | 53 711 → 53 387 | 324 |
| Два закрытых нативных блока, 80 КиБ кода | 9 042 818 → 8 960 890 | 81 928 |
| Один открытый нативный блок, около 10 КиБ кода | 1 129 202 → 1 118 959 | 10 243 |
| Блок с отступом и без завершающего перевода строки | 32 804 → 32 589 | 215 |

[Счётчики](measurements.log) охватывают `Document::render` на готовом тексте, включая перераспределения. Для 80 КиБ кода экономия составляет около 0,9% всех запрошенных байтов разбора и построения дерева. Запрошенные байты и число выделений для зарегистрированного блока, повторного рендера из кэша и прозы совпали. Длина и ёмкость сохранённого текста совпали во всех парных случаях. Это не замер задержки или RSS.

- На пине штатный `extension-markdown-render`: **48/48** до патча, **49/49** после в debug и release. Новый тест сверяет закрытый блок с CRLF и незакрытый блок с Unicode.
- **6 кадров** обычного процесса и **7 измерительных деревьев** совпали побайтно. В том числе закрытие блока при потоковом обновлении, смена регистрации языка, переход к простому тексту, закрытие и повторное открытие.
- Прямое и обратное наложение на пин проверены. Все 21 ранее опубликованный патч Extensions, включая #299 про границу потокового префикса и #383, совмещаются с этим патчем в обоих порядках с одинаковым деревом; на совмещённом источнике 50/50 тестов Markdown в debug. [Проверки](checks.log).

Повтор: `python3 reproduce.py путь-к-репозиторию` (Git, Python 3, Cargo/rustfmt). При готовых зависимостях можно задать `CARGO_NET_OFFLINE=true`. Входной checkout не меняется. Упаковка, нативное окно и полный workspace не проверялись.

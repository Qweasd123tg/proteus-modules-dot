# Core: читать оценку входных токенов из имеющегося JSON

Самостоятельный патч к [Proteus-core@32e56ecb](https://github.com/Proteus-harness/Proteus-core/commit/32e56ecb4cc6da324c60dd6ae2da78f3b7e46e7f). Поставщик может сохранить оценку токенов для непрозрачных частей сообщения в метаданных. При чтении этой подсказки (`ModelInputEstimate::from_metadata`, в том числе для workflow replay) код клонировал весь соответствующий JSON-объект, чтобы сразу его десериализовать. Теперь тот же тип `ModelInputEstimate` строится из ссылки на значение.

Правила Serde для структуры, UUID и `u32`, ручная проверка дубликатов ID, порядок записей и результат `None` при неправильных данных остаются прежними. Входной JSON, соседние метаданные, история и исходный запрос модели не изменяются. Патч не затрагивает формирование/валидацию запроса к провайдеру, strict-read пути или права. Выходной список и множество ID всё ещё выделяют память.

## Измерение

Измерена только функция чтения оценки из **уже готового `serde_json::Value`**. Создание входного JSON, запись метаданных, сериализация снимка, файловый replay, модель и сеть не входят в замер. Счётчик отражает вызовы аллокатора и запрошенные байты, включая realloc; это не RSS или время полного replay. Размеры входов синтетические.

| Оценка | Вызовы аллокатора до → после | Запрошено байт до → после |
|---|---:|---:|
| Поле отсутствует | 0 → 0 | 0 → 0 |
| Пустой список | 2 → 0 | 637 → 0 |
| 1 часть | 9 → 2 | 1 454 → 104 |
| 16 частей | 72 → 5 | 13 449 → 1 404 |
| 128 частей | 523 → 8 | 103 209 → 11 308 |
| 1 024 части, стресс-фикстура | 4 110 → 11 | 820 953 → 90 204 |
| Два совпадающих ID, отклонено | 13 → 2 | 2 187 → 124 |

[Полные показатели](probe.log). Неверные типы, переполнение и неизвестные поля не начинают приниматься ради выигрыша.

## Проверка

- На **1 315** фикстурах сериализованные результаты до/после совпали побайтно. Матрица покрывает обычный объект и позиционную форму Serde, разные представления UUID, границы `u32`, пустые и отсутствующие подсказки, лишние/отсутствующие поля и дубликаты ID. В измеряемых сценариях отдельно проверено, что весь исходный JSON остаётся неизменным.
- Полный набор библиотечных тестов `proteus-contracts` на обеих версиях вместе с измерителем: 161/161 на каждой версии. Чистый кандидат отдельно прошёл 4/4 теста `input_estimates::`. Форматирование, проверка пробелов и прямое/обратное применение прошли. Патч также применим поверх первой 50-патчевой композиции; это только проверка применения.
- Полный workspace, настоящее исполнение workflow replay, провайдер, macOS и Windows не проверялись.

Из чистого checkout указанной ревизии, Rust 1.95, Linux x86-64:

```sh
# PROPOSAL — абсолютный путь к этому каталогу.
git apply --check "$PROPOSAL/source.patch"
cargo fetch --locked
python3 "$PROPOSAL/probe.py" . "${CARGO_TARGET_DIR:-target}/r53-estimates"
```

Измеритель запускается во временной копии. В обычной сборке нет нового кода измерения или зависимостей.

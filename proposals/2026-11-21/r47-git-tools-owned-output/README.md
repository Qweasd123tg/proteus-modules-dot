# Git tools: переиспользовать буфер результата для JSON-ответа

База: **Proteus-harness/Proteus-modules@9469e3b12529d08b1f4a76882693e2065e842c51**. Локальный commit `dd848a06bb7f34c397948fe5d17c4b9ec505f366`. Меняется только `tool/git-tools`; новый код запуска Git не добавлен.

При обычном валидном UTF-8 прежний код копировал захваченный stdout при преобразовании в `String`, ещё раз при построении итогового текста и ещё раз при подготовке JSON-объекта. Теперь `String::from_utf8` принимает исходный буфер, а `Value::String(output)` принимает готовую строку без копирования. stderr декодируется как `Cow`: валидный stderr не требует отдельной строки. Некорректный UTF-8 и обрезанная посередине буква по-прежнему восстанавливаются через стандартный `from_utf8_lossy`. Финальная сериализация JSON сохраняется.

Тот же набор полей, порядок вставки полей, разделитель stdout/stderr, ошибки и метаданные обрезки. Патч не меняет чтение потоков, лимиты, таймаут, Git-аргументы, фильтры, проверки путей или разрешения. Изменения затрагивают только этап после получения вывода и сборку результата.

## Проверки

* `cargo test --locked -p git-tools --lib`: исходник **4/4**, кандидат **5/5**; `cargo fmt -p git-tools -- --check` и `git diff --check` прошли. Новый тест проверяет пустые и смешанные каналы, прежний разделитель при уже закрывающем LF, неверные байты и усечённую многобайтную последовательность UTF-8. Существующие проверки read-only Git и запрета совпавших внешних фильтров без изменений прошли.
* Стандартная обёртка `scripts/test.py` остановилась до сборки при offline all-platform `cargo metadata`: отсутствует `android_system_properties 0.1.5`. Нативный locked Cargo-test прошёл. Установка, полная workspace/CI и Desktop не запускались.
* Пробник сравнивает байты всего JSON, независимо сверяет ответ с сырым локальным `git diff` при обрезке и подстановке UTF-8. Для проверки: `python3 reproduce.py /путь/к/Proteus-modules`. Он собирает два временных checkout, не меняя ваш. Применение: на указанной базе запустить `git apply --check /путь/candidate.patch`, затем `git apply /путь/candidate.patch`.

## Измерение

Linux x86-64, Git 2.56.1, Rust 1.95.0; обе версии собраны `cargo test --locked --release`. Обычные реальные вызовы `GitStatusTool::invoke_json` и `GitDiffTool::invoke_json` на одном временном Git-репозитории, новый тестовый процесс для каждого вызова. Чередующийся порядок в каждой серии, одна незачётная разогревочная пара и девять пар на сценарий. Счётчик глобального аллокатора действует во время одного вызова, включая потоки захвата, но не процесс Git. Он суммирует размеры успешных alloc/alloc_zeroed/realloc (realloc учитывает весь запрошенный размер); это **объём запросов к аллокатору**, а не RSS, не пиковая память и не реально скопированные байты. Старт подготовки контракта/фикстуры и чтение результата не входят в измерение.

В обоих прогонах одинаковые медианы запросов к аллокатору и побайтовое совпадение полных JSON-ответов во всех семи сценариях:

| Сценарий | Запрошено байт, до → после | Запросов, до → после |
|---|---:|---:|
| git diff, stdout обрезан до 200 КиБ | 1 729 312 → 1 114 514 | 904 → 891 |
| Небольшой diff | 76 035 → 75 205 | 889 → 876 |
| Обрезанная буква UTF-8 | 76 292 → 75 638 | 891 → 879 |
| Неверный байт в diff | 76 369 → 75 669 | 890 → 878 |
| Нет изменений | 75 501 → 75 094 | 887 → 876 |
| git status | 75 082 → 74 394 | 882 → 869 |
| Ошибка Git вне репозитория | 75 344 → 74 642 | 884 → 871 |

На большом diff на 614 798 байт (35,6%) меньше суммарных запросов к Rust-аллокатору. Медианы времени большого вызова 24,58 → 23,92 и 23,84 → 23,93 мс: устойчивого выигрыша задержки нет. Сырые значения, включая задержку, и хеши полных ответов: `probe.log`, `recheck.log`.

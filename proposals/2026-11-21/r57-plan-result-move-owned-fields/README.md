# update_plan: переносить строки в готовые карты ответа

База: **Proteus-harness/Proteus-modules@9469e3b12529d08b1f4a76882693e2065e842c51**. Локальный commit `737815d0ff7c6d8e20e367478c1fe294140044df`. Меняется только `tool/plan-tool/src/lib.rs`. Эта версия заменяет первый локальный вариант; их не нужно применять вместе.

В успешном ответе `json!` повторно выделял память под уже проверенные строки шагов и пояснения. Карты результата теперь получают эти строки по владению, с нужной ёмкостью и в прежнем порядке вставки. Без временных значений и изменяемой индексации. Статусы сериализуются прежним serde-энумом; валидация, ошибки, JSON-поля и счётчики не меняются.

## Совместимость

Изолированный пакет использует алфавитный порядок ключей. Полный закреплённый workspace включает `serde_json/preserve_order` через `agent-client-protocol` и `agent-client-protocol-schema` в графе dev-зависимости от Core. Поэтому сохранили прежний порядок вставки, а не выбрали один фиксированный порядок сериализации. Детали графа в `feature-and-dedup.log`. [#183](https://github.com/Qweasd123tg/proteus-modules-dot/pull/183) уже переносит входные аргументы в валидатор; этот патч меняет только сборку выхода и не пересекается с выбранными 100 патчами M100: ни один не меняет этот файл.

## Проверки и измерение

- База **6/6**, кандидат **7/7** в каждом из двух режимов. Локальные Release тестовые бинарники собраны rustc 1.95.0 (x86-64 Linux) с артефактами зависимостей из предыдущего `cargo test --locked --release -p plan-tool --lib`. Точные отпечатки зависимостей в `direct-locked-deps.log`; общую директорию Cargo не меняли. Полный workspace gate не запускался. `rustfmt --check`, `git diff --check` и применение патча в режиме проверки на точную базу прошли.
- **24 побайтных сравнения** полных ответов и ошибок: 12 сценариев на каждый режим карты, включая длинный и пустой план, Unicode, экранирование, нестроковый/дублированный ID, отсутствующие поля, невалидные шаги и ошибку контекста. Пробник отдельно проверяет порядок ключей.
- Rust-аллокатор вокруг всего вызова обработчика без транспорта: по три пары процессов, медианы. Считаются запрошенные байты alloc/realloc, число этих запросов и пиковое приращение живых байтов. Ни один из 24 сценариев не показал роста этих величин. Это не системный RSS и не замер задержки.

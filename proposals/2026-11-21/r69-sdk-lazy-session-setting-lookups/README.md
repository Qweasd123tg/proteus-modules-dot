# SDK Extensions: искать настройку без временного списка

Mode и Model несколько раз читают отдельные настройки для одного значка или всплывающего окна. Раньше каждый поиск создавал список всех select-строк и затем искал по нему ID. [Патч](source.patch) читает строки по одной и останавливается на первом подходящем контроле. Метод `session_settings()` сохраняет прежний возвращаемый тип и полный порядок. Отдельного кэша и нового состояния нет.

Учитываются только select-контролы, первый подходящий дубликат по-прежнему выигрывает. Не меняются обработка отсутствующих значений, приоритет последней неподтверждённой команды (включая `null`), проверки действия, адресация сессии и порядок сообщений. База: [Proteus-desktop-extensions@892f627](https://github.com/Proteus-harness/Proteus-desktop-extensions/commit/892f627570369ed60d7205eb0d351c753ec4305f).

| Штатная поверхность, 64 строки входа | Проверок типа строки | Сборок всего списка SDK |
|---|---:|---:|
| Значок Mode с разделом поведения | 320 → 9 | 5 → 0 |
| Окно Mode | 256 → 8 | 4 → 0 |
| Значок Model с выбранным усилием | 320 → 16 | 5 → 0 |
| Окно Model с двумя дополнительными настройками | 512 → 91 | 8 → 1 |

[Результаты](measurements.log) включают и сценарий из 8 строк. При промахе или совпадении в конце все строки всё ещё проверяются, но промежуточный список не собирается. При ответе из очереди неподтверждённых изменений ни одна версия список не читает. Это счётчики работы в отдельных release-сборках на синтетических данных, не измерение выделений памяти, времени или RSS.

- На точной базе в debug и release: SDK **60 → 62** модульных теста и 1 doc-тест, Mode **4/4**, Model **10/10**. На точном M150 в release: SDK **62 → 64** и 1 doc-тест, Mode **4/4**, Model **11/11**.
- В обоих сравнениях побайтно совпали **23 обычных кадра** Mode/Model. Проверены preview, отказ при неизвестном выборе, подтверждённая к отправке настройка, перенос окна, поздняя ошибка и изоляция второго чата. В отдельной сборке совпали ещё **8 кадров** проверки счётчиков.
- Независимо восстановлены все 22 патча Extensions в M150. Наложение нового патча первым или последним даёт одно дерево; обратное наложение восстанавливает состав точного M150. [Проверки](checks.log).

Повтор: `python3 reproduce.py путь-к-репозиторию [путь-к-точному-дереву-M150-Extensions]` (Git, Python 3, Rust/Cargo/rustfmt и уже доступные зависимости). Для повтора с прогретым таргетом задайте `R69_EXT_TARGET`. Входные checkout не меняются. Полный workspace, упаковка и нативное окно в этом раунде не проверялись.

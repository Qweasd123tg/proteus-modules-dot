# Mermaid: передать декодированную строку SVG без копирования

Точный upstream Extensions: `892f627570369ed60d7205eb0d351c753ec4305f`. Единственный изменённый файл — `packages/mermaid-render/src/worker.rs`. Тот же `source.patch` независимо проверен на upstream и на сохранённом M150 + #394/#395/#397/#399/#402/#404/#406/#409 (`72a172bc775db7fdf72a448c9d20b41128a3b0f56d16b63a7c0502da0ba283d7`, для #409 нужен его составной вариант).

Результат Node уже владеет строкой SVG. Раньше проекция брала ссылку, а SDK-билдер сначала создавал `String` и затем копировал его в JSON-узел. Теперь закрытый код Mermaid после **всех** прежних проверок перемещает готовое значение в поле `source` узла, построенного существующим билдером. Порядок полей и экранирование остаются теми же. Публичный SDK, вызов и окружение воркера, декодирование/границы кадров, ошибки и порядок проверок, кэш, маршрутизация, последняя успешная отрисовка и fallback не менялись. Изменение не убирает отдельные копии корня в кэше или Desktop.

## Что проверено

- Штатные Rust unit-тесты пакета в offline locked release, один Cargo job: **9 → 11** на upstream и **10 → 12** на составном дереве. Новый тест сравнивает точный JSON и указатель на декодированную строку. Другой проверяет приоритет ошибок и границу ровно 1 MiB / на один байт больше.
- Штатный Node-набор: **12/12** на каждой из четырёх веток с тем же Node v24.22.3 и сверенными SHA-256 `worker.mjs`, темы и Pele. **Канонический Rust wire остаётся 1 pass / 1 fail** на всех четырёх ветках: прежний тест дочернего процесса доходит до первого успешного SVG, затем падает на `0 != 1` в `wire.rs:155:5`. Независимая проверка с живым дочерним процессом подтвердила ENOENT у task-children procfs. Тест не изменяли и не пропускали; ниже отдельная проверка обмена, не замена lifecycle-проверки.
- Настоящие uninstrumented Rust-бинарники запускали настоящий packaged Node worker, без сервера/внешней сети. **14** обычных кадров совпали байт в байт, включая старый SHA R48. Ещё **4** кадра большего сценария совпали между всеми ветками, с повтором и второй сессией. Их декодированные SVG и размеры совпали с прямыми ответами ровно того Node worker. Реальные синтетические диаграммы: 97 рёбер → **42 313** UTF-8 байт, 96 сообщений → **35 281**. Никакой подмены Node для больших измерений.

## Изолированная стоимость проекции

Отдельный тестовый вызов берёт уже разобранный ответ из того же `serde_json::from_slice`, исключает подготовку input, JSON parse, сериализацию, очередь, UI и кэш. Считает успешные запросы к аллокатору в одном потоке и проверяет ссылку на результат и ёмкость строки; по пять одинаковых наблюдений на ветку.

| Вход | SVG, Б | Обращения до → после | Запрошенные байты до → после |
|---|---:|---:|---:|
| UTF-8 и JSON-экранирование | 35 | 11 → 9 | 1 274 → 1 204 |
| Реальный ответ Pele, 97 рёбер | 42 313 | 11 → 9 | 85 830 → 1 204 |
| Синтетический предел 1 MiB | 1 048 576 | 11 → 9 | 2 098 356 → 1 204 |
| Больше предела | 1 048 577 | 1 → 1 | 72 → 72 |
| Некорректные размеры | 35 | 1 → 1 | 72 → 72 |
| Ошибка воркера | 0 | 2 → 2 | 101 → 101 |

Это измерение **запрошенных байтов при построении узла**, не RSS/PSS, не удерживаемая память, не пик процесса и не выигрыш по времени. На каждом проверенном корректном ответе входная ёмкость была равна длине, а ёмкость окончательной строки не выросла. Синтетическая граница 1 MiB не означает, что обычный Pele создаёт SVG такого размера.

## Повторить

Укажите локальный git-checkout, содержащий upstream, сохранённое дерево M150 Extensions, предыдущие восемь патчей в порядке применения, существующий Cargo target и общий файл блокировки. Используйте Rust/Cargo 1.95.0, сверенный Node v24.22.3 и подготовленный offline Cargo cache.

```bash
PYTHONDONTWRITEBYTECODE=1 python3 reproduce.py "$STOCK" "$M150_EXTENSIONS" \
  "$PATCH_394" "$PATCH_395" "$PATCH_397" "$PATCH_399" "$PATCH_402" "$PATCH_404" "$PATCH_406" "$COMPOSED_409" \
  --target "$TARGET" --lock "$BUILD_LOCK" --admit-exclusive
```

Без флага стартует только проверка входов. С флагом используются один lock и один job; минимум 512 MiB на каждом томе до входа, остановка при <256 MiB. Cargo JSON привязывает исполняемые файлы к точному checkout, роли и target; отпечатки перепроверяются до/после запуска. `checks.log`, `measurements.log` и `artifact-receipts.log` содержат результаты, исходные хеши и выбранные артефакты. Нативное окно и полный workspace не запускались.

# SDK Extensions: не копировать готовые варианты выбора

`select` и `picker` уже строят список вариантов, но раньше при завершающем `json!` копировали каждую готовую строку ещё раз, включая вложенное значение варианта. [Патч](source.patch) переносит этот список в итоговый объект. Входные сигнатуры и порядок полей и вариантов не меняются; правило сравнения значения остаётся прежним, в том числе для совпадающих дубликатов и `null`. Первое построение строк из входных данных остаётся.

Usage строит варианты всех доступных ходов ещё до ограничения списка запросов на странице. Model строит варианты каталога выбранных моделей. Это отдельная от #395 работа над готовыми списками вариантов, а не изменение общих контейнеров. База: [Proteus-desktop-extensions@892f627](https://github.com/Proteus-harness/Proteus-desktop-extensions/commit/892f627570369ed60d7205eb0d351c753ec4305f).

| Конструктор, число вариантов | Запросов выделения | Запрошено байт |
|---|---:|---:|
| Select, 8 | 127 → 70 | 9 252 → 5 244 |
| Select, 512 | 7 183 → 3 598 | 516 092 → 258 664 |
| Select, 2 048 | 28 687 → 14 350 | 2 063 406 → 1 032 321 |
| Picker, 512 | 7 181 → 3 596 | 516 074 → 258 646 |
| Picker, 2 048 | 28 685 → 14 348 | 2 063 388 → 1 032 303 |

[Счётчики](measurements.log) охватывают успешные выделения и перераспределения памяти на одном потоке при построении конструктора; подготовка вариантов, HTTP и сериализация результата не входят в измерение. Пустой выбор и `fill` не изменились. Ёмкость результирующего массива совпала во всех парных проверках, но это не утверждение про RSS, удерживаемую память всего процесса или задержку.

- На точной базе в release: SDK **60 → 61** модульный тест и 1 doc-тест, Usage **12/12**, Model **10/10**. На M150 + #394 + #395: SDK **65 → 66** и 1 doc-тест, Usage **15/15**, Model **11/11**.
- В каждом сравнении совпали **5 обычных кадров** побайтно: Usage с 512 ходами и 128 сессиями до/после выбора периода, Model с 512 вариантами двух провайдеров при открытии и закрытии каталога. Те же **два GET** в Usage. Отдельные **11** измерительных выходов совпали побайтно, счётчики повторились пять раз на каждую версию.
- [Сборочные квитанции](artifact-receipts.log) фиксируют точные исходники, наложения, lock-файл и инструменты в каждой из четырёх сборок. В JSON Cargo проверены **28** свежих артефактов: SDK, три тестовых исполняемых файла, два обычных бинарника и измерительная программа на каждую сборку. Выбранные пути и хеши проверены перед запуском и после. Повторное чтение SDK разрешено только при совпадении с уже проверенным SDK этой же сборки. Хеш исполняемого файла служит квитанцией конкретной сборки, а не обещанием идентичной сборки на другом пути.
- Прямое и обратное наложение на пин и совмещение с #394 и #395 поверх точного M150 проверены в обоих порядках. [Проверки](checks.log).

Повтор: `python3 reproduce.py точный-git точное-дерево-m150 патч-394 патч-395 --target прогретый-target --lock общий-build-lock --admit-exclusive`. Нужен явный `CARGO_HOME` с уже доступными зависимостями. Без флага допуска только проверка входов. Один Cargo job, locked/offline, стартовый порог 512 МиБ и остановка ниже 256 МиБ на обоих томах. Исходный checkout не изменяется. Полный workspace, упаковка и нативное окно не проверялись.

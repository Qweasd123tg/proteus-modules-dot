# Context Pack: разбирать свой JSON-конфиг без глубокой копии

База: **Proteus-harness/Proteus-modules@9469e3b12529d08b1f4a76882693e2065e842c51**. Локальный commit `fe115291f26fbe8a0b46b95aa155743ab17efe6e`.

Три входа Context Pack уже владеют разобранным JSON. Раньше они клонировали `config` перед передачей в типизированный десериализатор. Теперь исходное поле передаётся по владению через `Value::take`. Остальная обработка использует типизированный конфиг и явные DTO для провайдеров; исходный JSON им не передавался. Настройки по умолчанию, строгая схема, порядок вызовов и лимиты как прежде.

## Проверки

- Полный unit-suite `context-pack`: **25/25 → 26/26** в двух ранее собранных locked графах (Release sorted, workspace Debug `serde_json/preserve_order`). Оба исходника скомпилированы rustc 1.95.0 Linux x86-64 против одних и тех же артефактов каждого графа, без записи в общий Cargo target.
- **16 полных побайтных сравнений** (по три пары), включая результат или диагностический текст и точные строки callback. Пробник также проверяет порядок/содержимое вызовов. Проверены все три builder'а, null/пустой конфиг, короткие/расширенные настройки, неизвестное поле и неверный тип. На невалидном конфиге провайдеры не вызываются.
- `rustfmt --check`, `git diff --check` и точное применение к базе. На проверенную копию M100 применены checksum‑проверенные R57–R65 и R66. **28/28** тестов накопительного `context-pack` в workspace Debug, включая #261/#334; не полный workspace gate.

## Аллокации

Измерен полный `build_json` с локальным mock host, без IPC и настоящих провайдеров. Измеритель отключён для отдельного захвата callback‑байтов. Rust‑аллокации, не RSS и не задержка.

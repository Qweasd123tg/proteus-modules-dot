# Git: открывать рабочие diff без глубокой копии кэшированного ответа

Раньше Git глубоко копировал JSON рабочей разницы при чтении из кэша и при сохранении пригодного для кэширования HTTP-ответа. [Патч](source.patch) передаёт рендереру ссылку на тот же неизменяемый снимок. Готовый виджет по-прежнему владеет своим текстом. Не меняются токен ревизии, сброс по пути и экрану, порядок LRU и пределы 16 записей / 8 МиБ. История отдельных коммитов не затронута.

База: [Proteus-desktop-extensions@892f627](https://github.com/Proteus-harness/Proteus-desktop-extensions/commit/892f627570369ed60d7205eb0d351c753ec4305f).

| Синтетический вызов | Запрошенные у аллокатора байты, до → после |
|---|---:|
| Повторно показать один рабочий diff, 2 КиБ | 18 058 → 15 146 |
| Повторно показать один рабочий diff, 64 КиБ | 145 034 → 78 634 |
| Повторно показать один рабочий diff, 384 КиБ | 800 394 → 406 314 (−49,2%) |
| Повторно показать «Все изменения», 8 × 256 КиБ | 12 340 263 → 10 236 199 (−17,1%) |
| Первый показ, 11 200 байт, есть токен ревизии | 30 620 → 18 404 |
| Первый показ, 11 200 байт, `revision: null` | 18 151 → 18 239 (+88) |

Для первых показов счётчик начинается сразу после декодирования синтетического HTTP-ответа; для повторных чтений кэш уже заполнен. Запрошенные байты включают перераспределения, но не сериализацию готового дерева. При `revision: null` новая версия создаёт одну временную аллокацию на 88 байт и по-прежнему не записывает ответ в кэш. [Счётчики](measurements.log) совпали в пяти отдельных release-процессах. Это не замер времени, RSS или всего Desktop.

- Штатный `extension-git`: **41/41** на базе, **42/42** с патчем в debug и release. Новый тест подтверждает, что повторные чтения возвращают один объект, а после удаления из кэша и освобождения временных ссылок владельцев не остаётся.
- Побайтно совпали **6** обычных кадров и **10** измерительных деревьев. При обычном запуске совпали порядок чтений, повторное использование diff после закрытия, сброс при изменении ревизии и повторное чтение при `null`.
- #319 меняет снимки истории коммитов, #330 меняет выбор подсказки коммита. Оба порядка наложения с ними дают одинаковое дерево; сухая проверка на запечатанном M100 прошла. Нативное окно, упаковка и весь workspace не проверялись. [Журнал](checks.log).

Повтор: `python3 reproduce.py путь-к-репозиторию` (Git, Python 3, Cargo/rustfmt, TCP loopback). При готовых зависимостях можно задать `CARGO_NET_OFFLINE=true`. Входной checkout не меняется.

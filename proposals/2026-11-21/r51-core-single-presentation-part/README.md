# Core: убрать промежуточный вектор при выводе одного текстового блока

Самостоятельный патч к [Proteus-core@32e56ecb](https://github.com/Proteus-harness/Proteus-core/commit/32e56ecb4cc6da324c60dd6ae2da78f3b7e46e7f). `CanonicalMessage::display_text` и `reasoning_text` используются при публикации завершённых частей ответа. Раньше даже один видимый непустой блок проходил через временный вектор ссылок перед сборкой строки. Теперь пустая проекция по-прежнему не выделяет память, для одного блока создаётся только возвращаемая строка, а для нескольких сохраняется склейка в строку известной длины.

Текст ответа и доступный для показа reasoning остаются раздельными. Сигнатуры и непрозрачные записи провайдера не попадают в эти строки. Прежняя проверка `trim().is_empty()` отбрасывает только полностью пустые блоки, а непустые сохраняются без обрезки. Пробелы, табуляция, переводы строк, порядок, `\n` между блоками и исходные канонические сообщения остаются неизменными. Это не патч холодного рендера или ACP-ввода; публичный API, типы, журнал и проверки не меняются.

## Замер

Измерены реальные функции проекции на уже созданных сообщениях. Построение входных DTO, модель, поток событий и сериализация снимков вынесены за границу измерения. Счётчик учитывает запросы к аллокатору, включая realloc; это не замер RSS, задержки ответа или памяти всего хода.

| Видимый результат в одном канале | Вызовы до → после | Запрошено байт до → после |
|---|---:|---:|
| Ничего, либо только пробельные блоки | 0 → 0 | 0 → 0 |
| Текст `hello` | 2 → 1 | 69 → 5 |
| Reasoning `thought` или его summary | 2 → 1 | 71 → 7 |
| Одиночный текст 64 КиБ | 2 → 1 | 65 600 → 65 536 |

На контрольных сообщениях с двумя/тремя и 64 видимыми блоками на канал вызовы аллокатора и запрошенные байты не изменились. [Все результаты](probe.log).

## Проверка

- Сериализованный результат обоих каналов до/после совпал побайтно на 3 136 фикстурах. В них проверены смешанные последовательности типов, пустой и пробельный текст, порядок, Unicode, управляющие байты и непроецируемые данные.
- Полный библиотечный набор `proteus-contracts` на обеих версиях, включая измеритель; прямое и обратное применение, `git diff --check` и форматирование. Отдельная проверка применения поверх первой 50-патчевой композиции не заменяет её повторный прогон.
- Чистый кандидат прошёл 7/7 тестов `app_server::acp::`, в том числе настоящий путь BoundModel → исходящие текст/читаемый reasoning и повторное завершение потокового Unicode. Использованы уже собранные локальные process fixtures; полный workspace, сетевой провайдер, настоящий редактор, macOS и Windows не запускались. [Отчёт о тестах](test-summary.log).

Из чистого checkout указанной ревизии, Rust 1.95, Linux x86-64:

```sh
# PROPOSAL — абсолютный путь к этому каталогу.
git apply --check "$PROPOSAL/source.patch"
cargo fetch --locked
python3 "$PROPOSAL/probe.py" . "${CARGO_TARGET_DIR:-target}/r51-presentation"
git apply "$PROPOSAL/source.patch"
# С настроенными process fixtures:
python3 scripts/test.py -p proteus-core --lib app_server::acp::
```

Измеритель работает во временной копии на одном Cargo-кэше, новых production-зависимостей не добавляет.

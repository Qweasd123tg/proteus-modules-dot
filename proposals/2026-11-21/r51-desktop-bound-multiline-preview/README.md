# Desktop: не собирать невидимый хвост подписи инструмента

Desktop соединяет непустые строки аргумента через « ↵ », чтобы показать его краткое содержание. Раньше он копил ссылки на **все** непустые строки, собирал всю строку целиком и только потом обрезал её. Теперь построение останавливается, когда видимый фрагмент заполнен. Это общий путь для заголовков с текстовым аргументом (например, `exec_command`), массива с одним строковым значением и строковых параметров в раскрытой карточке.

Для заголовка осталось 300 Unicode-скаляров, для аргумента 160. Сохранились Unicode-обрезка пробелов на границах строк, пропуск пустых строк, LF/CRLF и обработка отдельного CR. Если на границу попадает часть разделителя, эта часть по-прежнему видна. Многоточие не добавляется; символы управления направлением текста не фильтруются и не преобразуются. Выбор ключа и специальный формат массивов из нескольких строковых элементов не изменились. Аргументы, транспорт, валидация, подтверждение и полные карточки не меняются. Оптимизация прекращает **сборку** невидимого хвоста; чтобы найти конец длинной первой строки, её всё ещё надо просканировать.

База: [Proteus-desktop `b6a7ec2d`](https://github.com/Proteus-harness/Proteus-desktop/commit/b6a7ec2d8d7e486c8aba01291aa8c89774c4cded). Это другая ветка форматирования, не подпись прогресса [#314](https://github.com/Qweasd123tg/proteus-modules-dot/pull/314). SHA-256 патча: `b249421598296f7563dda56d37fe91b503f55bd0fdb9f23458d6c5b378a40724`.

## Замер на уже разобранных аргументах

| Сценарий | Вызовы аллокатора, до → после | Запрошенные байты, до → после | Медиана, мкс |
|---|---:|---:|---:|
| Короткая команда | 4 → 3 | 97 → 33 | 0,194 → 0,179 |
| Три строки | 4 → 3 | 106 → 44 | 0,272 → 0,270 |
| 64 строки | 9 → 4 | 4 108 → 945 | 3,995 → 1,121 |
| Одна длинная строка (132 000 Б, стресс) | 5 → 3 | 132 979 → 915 | 19,424 → 16,537 |
| Многострочная команда (стресс) | 16 → 4 | 441 756 → 945 | 545,745 → 2,075 |
| Строковый параметр в раскрытии (стресс) | 17 → 5 | 486 506 → 630 | 441,512 → 1,155 |

Считаются запросы `alloc/realloc` и запрошенные байты, а не пиковая память. Отдельный прогретый release-бинарник без счётчика измеряет только `headline` или `other_args`, не рендер или разбор JSON. Восемь чередующихся пар процессов на одном логическом CPU Linux x86-64. Короткий многострочный сценарий практически не изменился по времени. Стресс-строки проверяют масштабирование форматирования и не означают, что такой размер разрешён на любом входе.

## Проверки

- Полный исходный модуль с существующими тестами: 10/10 до, 11/11 после, отдельно в обычном и сохраняющем порядок ключей режиме `serde_json 1.0.152`. Идентичности зависимостей, включая checksums, сверены с Desktop `Cargo.lock`.
- Для обеих версий и обоих режимов: 1 523 значения, для каждого сверены полные результаты четырёх путей, плюс пять отдельных случаев массивов. Проверены в том числе пустые строки, очистка пробелов Unicode, разрыв разделителя, CR/LF, управляющие символы и Unicode-границы.
- Прямое и обратное применение патча, `git diff --check`, rustfmt прошли. При локальной проверке два порядка применения с #314 дали одинаковые исходники. Результаты: [evidence.log](evidence.log).

## Как проверить

Из checkout базы: `git apply --check /путь/source.patch`, затем `git apply /путь/source.patch`. Для отдельного воспроизведения: `bash verify.sh /путь/Proteus-desktop`. Нужны Git, Python 3.11+, Bash, Rust 1.95.0 с rustfmt и кеш зависимостей из `harness.lock`. Скрипт извлекает исходный модуль в отдельный временный каталог, проверяет закреплённые зависимости и запускает Cargo с `--offline --locked`. При повторении микрозамера закрепите процесс на одном доступном логическом CPU через `taskset`. Основной checkout не меняется. Полный workspace, GPUI и окно приложения не запускались.

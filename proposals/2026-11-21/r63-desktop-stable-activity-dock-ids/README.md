# Desktop: не копировать неизменившиеся ID в панели активности чата

При каждой отрисовке панели над композером Desktop передавал в `DockState` новый вектор ID. Это копировало и строки ID ожидающих запросов, даже если набор, порядок и выбранный элемент остались прежними. Теперь панель сначала сравнивает заимствованные ID с сохранёнными и использует прежнее состояние, если список совпадает, а выбранный элемент не устарел.

Порядок остаётся частью сравнения. Для новых, завершённых, переставленных запросов и для устаревшего выбранного ID выполняется прежняя логика. Если выбранный элемент исчез при неизменном списке, клавиатурная цель и запасной выбор по-прежнему восстанавливаются. Раскрытие, анимация, действия пользователя, отправка ответов и правила подтверждения не менялись.

База: [Proteus-desktop b6a7ec2d](https://github.com/Proteus-harness/Proteus-desktop/commit/b6a7ec2d8d7e486c8aba01291aa8c89774c4cded). SHA-256 патча: `642cab53418adaabdd58efdc4a60214cb5b6cf0a758494fc7f097fe33489898d`.

## Проверка

- **603 729** сравнений с исходной реализацией: все упорядоченные списки до трёх элементов из шести ID, выбор из разных типов, повторы, пустой список и устаревшие значения. Сверены порядок ID, открытый элемент, клавиатурная цель и присутствие панели для всех комбинаций дополнительных элементов.
- **5/5** штатных тестов в исходной версии и **6/6** после изменения. Для стенда извлечён точный `DockState` из исходника, исключён только неизменённый метод форматирования ID для GPUI. Повторный синтез состояния не требует сторонних зависимостей.
- Прямое и обратное применение, `git diff --check` и rustfmt прошли. Файл совпадает с базой на M100 и последнем сводном Desktop через R61. Поверх этого рабочего снимка правки R62 и R63 применяются в обоих порядках с побайтно одинаковым результатом.

## Запросы к аллокатору в одном обновлении состояния

| Синтетическое обновление панели | Запросы, до → после | Запрошенные байты, до → после |
|---|---:|---:|
| То же расширение | 1 → 0 | 32 → 0 |
| Те же два ожидающих запроса и расширение, панель закрыта или открыта | 3 → 0 | 108 → 0 |
| Поменялся только порядок | 3 → 3 | 108 → 108 |
| Пришло подтверждение или закончился запрос | 3 → 3 | 76 → 76 |
| Устаревший выбор при прежнем списке | 4 → 4 | 114 → 114 |
| Пустой список | 0 → 0 | 0 → 0 |

Измерен узкий участок синхронизации по готовым ID на Linux x86-64; счётчик суммирует `alloc` и `realloc`. Создание элементов, нативная сборка, отрисовка, время и RSS не измерялись.

## Как повторить

`git apply --check /путь/source.patch` из checkout базы. Узкая проверка: `bash verify.sh /путь/Proteus-desktop`. Нужны Bash, Git, Python 3.11+ и Rust 1.95 с rustfmt; Cargo-кэш и сеть не нужны. См. [evidence.log](evidence.log).

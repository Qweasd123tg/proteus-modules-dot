# Storage: проверять ASCII-границы имени cache без преобразования в текст

Во время обхода квоты worker ищет имена с точными границами
.storage-cache- и .json. Этим двум ASCII-проверкам не нужен
полный lossy Unicode-разбор имени. Патч проверяет их на локальном
представлении OsStr. Имя защищённого файла берётся один раз
на обход, а не заново для каждого кандидата.

Не тронуты read_dir, stat, получение mtime, суммирование, бюджет
128 МиБ, сортировка и выбор при совпадающем mtime, неприкосновенность
только что записанного файла, удаление, ошибки и порядок публикации.
Замена не добавляет новый формат имени или файлов, зависимости,
unsafe или архитектурное кеширование квоты.

Rust 1.95 описывает кодирование OsStr как платформенное, но с
самосинхронизирующейся надстройкой над UTF-8/ASCII. На Windows тот
же pinned Rust хранит Windows OsStr как WTF-8; границы ASCII не
меняются от lossy замены непарного суррогата на символ U+FFFD.
Мы проверяем только локально, не сохраняем raw представление.
Это вывод из исходников, **не Windows runtime-прогон**.
[Rust 1.95 OsStr](https://raw.githubusercontent.com/rust-lang/rust/1.95.0/library/std/src/ffi/os_str.rs),
[реализация Windows WTF-8](https://raw.githubusercontent.com/rust-lang/rust/1.95.0/library/std/src/sys/os_str/wtf8.rs).

## Счёт работы

Обе ветки release-теста обходили свой приватный каталог после
копирования каждого из 320 проверенных cache-файлов R59 и
держали три обычных посторонних имени. Не копировали личные
сессии. Получилось по 320 обходов, ниже квоты, два чередующихся
набора, конечные файлы побайтно неизменны.

| В этом обходе | До → после |
| --- | ---: |
| Имен просмотрено | 52 320 → 52 320 |
| Имен, переданных полному lossy-разбору | 52 320 → 0 |
| Байтов этих входных имён | 4 326 080 → 0 |
| Вызовы получения basename в измеренном исходном потоке | 51 360 → 320 |
| Metadata calls | 51 360 → 51 360 |
| Запросы аллокатору, обычные ASCII-имена | 107 324 → 107 324 |
| Запрошенные аллокатором B, обычные ASCII-имена | 15 954 784 → 15 954 784 |

Это входы операции, не чтения с диска, числа машинных инструкций
или ускорение. Компилятор потенциально мог уже вынести часть
лексической работы сам. В отдельном Unix-контроле с двумя
обычными старыми Latin-1 именами ожидаемо исчезли аллокации lossy
строки: 11 → 7 вызовов, 417 → 321 запрошенных B. Этот результат
не распространяется на стандартные ASCII-имена.

## Проверка

- Точный Modules 9469e3b12529d08b1f4a76882693e2065e842c51,
  Core SDK 0c1b7572313230e5d123e95c722e1258a2e9ecd6.
- Одна scoped locked release-сборка: 66 тестов прошли (65
  обычных + измеритель), 1 прежний ignored. Проверены ASCII,
  Unicode и Unix legacy имя; ровно 128 МиБ не удаляет,
  переполнение удаляет старейшее, защищённый ключ остаётся,
  временные/чужие имена и каталог игнорируются.
- Две реализации возвращают той же ошибкой NotFound на ранее
  существовавший приватный каталог после обычного перемещения.
  Не меняется родительский guard cache writer.
- Прямое/обратное применение и scoped format пройдены. Тот же
  исходный diff применим к R62 preflight с #372/#377; отдельной
  composed сборки, elapsed, RSS и Windows тестов не было.

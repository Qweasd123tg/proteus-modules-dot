# Desktop: краткий заголовок плана без копирования всех шагов

В строке инструмента `update_plan` Desktop показывает число выполненных и всех шагов и текст первого шага в работе. Для этого заголовка раньше создавался полноценный вектор шагов со своими строками. Если активный шаг выходил за пределы подписи, сначала форматировалась вся строка, а уже потом отрезался лишний текст.

Теперь заголовок проходит по существующему JSON один раз, считает шаги и берёт ссылку на первый активный текст. Копируется только часть текста, которая входит в подпись из 300 Unicode-скаляров. Раскрытая карточка по-прежнему получает полный список с исходными строками. Никаких изменений аргументов инструмента, отправки, загрузки журнала или ограничений Core. Это другой путь, чем [#288](https://github.com/Qweasd123tg/proteus-modules-dot/pull/288), где менялось создание серверного превью JSON.

Сохраняются обработка невалидного массива и шагов, пропуск отсутствующего или нестрокового статуса, статус ожидания для незнакомой **строки**, первый активный шаг даже с пустым текстом, пробелы и переносы. Ограничение применяется к подписи вместе с числовым префиксом, без добавления многоточия. Формат и порядок раскрытия не меняются.

**База:** [Proteus-desktop@b6a7ec2](https://github.com/Proteus-harness/Proteus-desktop/commit/b6a7ec2d8d7e486c8aba01291aa8c89774c4cded). SHA-256 патча: `3a2273b44332673f25b629f6d3b951b7a37729abb2accb14f3a5b45a969f2946`.

## Аллокации при построении заголовка

Измерен целый вызов оригинального `headline("update_plan", args)` с уже разобранными аргументами. Подготовка синтетического JSON и раскрытая карточка не входят в измерение. Счётчик считает alloc/realloc и сумму запрошенных байтов (для realloc учитывается новый размер). Это **не RSS, не пик памяти и не измерение FPS**.

| План | Запросы к аллокатору, до → после | Запрошенные байты, до → после |
|---|---:|---:|
| Пустой | 1 → 1 | 11 → 11 |
| Три коротких шага, один активен | 9 → 3 | 275 → 53 |
| Три коротких шага, нет активного | 6 → 2 | 202 → 19 |
| Первый активный шаг пуст | 5 → 2 | 160 → 19 |
| Один активный шаг, 132 000 байтов UTF-8 | 8 → 3 | 397 055 → 908 |
| 1 024 шага, один активен | 1 038 → 4 | 254 119 → 231 |

Последние две строки намеренно стрессовые. Они проверяют масштабирование работы на входе, а не предполагают, что любой такой план проходит через внешний транспорт. Прогретый микрозамер без счётчика на Linux x86-64, восемь процессов на версию с чередованием на одном логическом CPU: 0,321 → 0,193 мкс для трёх шагов, 10,536 → 0,540 мкс для длинного текста, 51,200 → 17,149 мкс для 1 024 шагов. Это время самого построения заголовка, не интерфейса или провайдера.

## Проверки и воспроизведение

- Полный модуль `tool_display` с исходным парсером и соседними тестами: 10/10 до, 11/11 после, в двух сборках с обычной и сохраняющей входной порядок картой `serde_json`. Зависимости совпадают с закреплённым lock по версии, источнику и checksum, включая `serde_json` 1.0.152.
- 196 дифференциальных случаев на каждой версии и шесть нагрузок сверяют **полный заголовок и полный список** с независимым оракулом. Включены пустой и отсутствующий статус, числовой и незнакомый статус, пустой первый активный шаг и отличающийся второй, Unicode и граница отсечения. Штатный тест отдельно проверяет точный результат около 300 скаляров.
- Прошли прямое и обратное применение, `git diff --check`, rustfmt. Полный workspace, GPUI и окно чата не запускались.

Из checkout указанной ревизии: `git apply --check /путь/source.patch`, затем `git apply /путь/source.patch`. Для тестов, оракула и замеров: `bash verify.sh PROTEUS_DESKTOP_CHECKOUT`. Нужны Linux, Python 3.11+, Rust 1.95.0 с rustfmt и загруженные зависимости из `harness.lock`. Скрипт использует временную папку, не меняет checkout и запускает Cargo с `--offline --locked`. Результаты в `evidence.log`.

# Каталог blobs: один буфер абсолютного пути на каталог

[Патч](candidate.patch) для [Proteus-modules 9469e3b](https://github.com/Proteus-harness/Proteus-modules/commit/9469e3b12529d08b1f4a76882693e2065e842c51). В `blob_stamps` абсолютный путь к текущему каталогу выделяется один раз. Для каждой записи к нему добавляется её имя, штатная `symlink_metadata` заново проверяет тот же путь, и буфер возвращается к каталогу. Относительный ключ для карты меток строится как раньше. Отказ от временного полного пути уменьшает число аллокаций при обходе; на ускорение полного List этот эксперимент не даёт основания рассчитывать.

## Что проверено

- Та же последовательность вызовов `read_dir` и `symlink_metadata`, тот же запрет следовать дочерним symlinks, те же проверки глубины и числа меток. `DirEntry::metadata` не используется. Никаких изменений replay, повторных сверок, source stamps, JSON v1, лимитов, checksum и записи sidecar. Проверка числа вызовов по исходнику (492 metadata / 1 read_dir на плоской fixture, 500 / 9 на вложенной); это не заявление о числе системных вызовов ядра. В песочнице `ptrace` недоступен, трассировки ядра не проводились.
- [Rust 1.95 Unix](https://github.com/rust-lang/rust/blob/59807616e1fa2540724bfbac14d7976d7e4a3860/library/std/src/sys/fs/unix.rs) и [Windows](https://github.com/rust-lang/rust/blob/59807616e1fa2540724bfbac14d7976d7e4a3860/library/std/src/sys/fs/windows.rs) строят `DirEntry::path` как `root.join(file_name)`. Вариант с `push/pop` использует тот же basename из перечисления файла. Перед первым дочерним доступом `PathBuf::push` одинаково обрабатывает verbatim-строку. Последующие обращения добавляют обычное имя и убирают только этот компонент, не меняя выбранный UNC share или корень. Эту часть проверяли по исходникам Rust; Windows-замеров и прогона Windows не было. Нативный Linux-тест проверяет также хвостовой разделитель и `/./`, разные длины имён, Unicode, одинаковое имя на разной глубине и равенство байтов digest.
- Настоящий SDK worker через stdio: для каждого backend пары процессов чередуются AB/BA на одном дереве из 10 сессий, 8 записей по 512 B и 492 обычных файла в 8 вложенных каталогах **на сессию**. Перед каждым cold List индекс удалён. Совпали полные строки и порядок, все десять sidecar побайтно. Следующий fresh-process List с существующими индексами не меняет их байты/метки. Обычное добавление файла во вложенный каталог заставило обе версии одинаково заменить устаревший индекс. Поведения в гонках не симулировали; checks/rechecks остались на исходных местах.
- Прямой locked suite: **65 unit + 2 process passed**, 1 штатный ручной тест пропущен. После добавления двух вариантов записи пути оба сценария inventory отдельно прошли снова. [Лог](validation.txt). Обёртка тестов не завершила офлайн cargo metadata из-за недоступного Android-пакета; тест всего workspace не запускали.
- [#296, запись](https://github.com/Qweasd123tg/proteus-modules-dot/pull/296) и [#303, чтение](https://github.com/Qweasd123tg/proteus-modules-dot/pull/303) накладываются с этим патчем в любом из шести порядков; сравнение итоговых файлов байт-в-байт. [Лог наложения](composition.log). Это проверка патчей, не совместная runtime-сборка.

## Микрозамер инвентаризации

Linux x86‑64 tmpfs, Rust 1.95, `session-storage` opt-level=3, зависимости test profile. 40 пар на случай, порядок ABBA, один логический CPU через taskset (не эксклюзивный). Реализованные функции stock и candidate в одном test binary; копия stock извлечена из исходного Git-объекта, её карта и digest проверены на каждом образце. Счётчик суммирует alloc/realloc и запрошенные байты, а не физический RSS. Тайминг проходит отдельно, без активной записи аллокатора.

| Файлы | Аллокации на обход | Запрошенные байты | CPU мкс, медиана |
|---|---:|---:|---:|
| 492 в одном каталоге | 2548 → 1565 (−38,6%) | 148 066 → 114 642 (−22,6%) | 564 → 540 |
| 492 в восьми вложенных каталогах | 3617 → 2625 (−27,4%) | 186 100 → 140 488 (−24,5%) | 825 → 827 |
| Каталог отсутствует | 5 → 5 | 140 → 140 | 1,32 → 1,29 |

Пик логически живых байтов **выше на 68–84 B** в наполненных fixtures: переиспользуемый буфер остаётся до конца обработки каталога; остальной пик занимает карта меток. Экономия относится к трафику аллокатора, не к пиковому RSS.

## SDK wall time и CPU

Здесь полный SDK List, а не время одной инвентаризации. Обычные dev binary, по 7 пар на backend и фазу, 56 полных измеренных List за прогон, всего 168. В первом прогоне параллельно шла компиляция; второй использует те же бинарники после компиляции; третий дополнительно измеряет user+system CPU дочернего процесса (включая initialize и shutdown). Второй прогон показал, например, SQLite cold +40,5% по медиане попарного wall time (диапазоны 113–209 мс против 114–247), но соответствующая задержка **не повторилась**: в третьем прогоне SQLite cold 179,6 → 175,9 мс wall и 184,4 → 180,8 мс CPU (попарно −2,2% CPU). Остальные попарные изменения полного worker CPU третьего прогона: JSONL cold −1,6%, JSONL disk +0,2%, SQLite disk −0,9%. Ни одного устойчивого преимущества или регрессии полного List эти небольшие шумные выборки не устанавливают; эффект на реальном диске и на таймаут пользователя неизвестен. Нужный результат здесь — снижение трафика аллокатора при обходе, а не ускорение RPC.

## Воспроизведение

1. На точном пине применить `candidate.patch` и запустить `python3 scripts/test.py -p session-storage -p proteus-session-storage-module`. Для host-only offline кэша использовать `cargo test --offline --locked -p session-storage -p proteus-session-storage-module`, с `PROTEUS_TEST_HARNESS_ROOT` на закреплённый локальный Core 0c1b757.
2. В одноразовом checkout с применённым патчем выполнить `python3 instrument.py /original/repo /disposable/checkout`, затем там же `cargo test --locked --config 'profile.test.package.session-storage.opt-level=3' -p session-storage --lib r47_measure_blob_inventory -- --ignored --test-threads=1 --nocapture > inventory.log`. Для сопоставления времён можно закрепить test process на одном доступном CPU через taskset.
3. Собрать два настоящих модуля `cargo build --locked -p proteus-session-storage-module` с разными target dirs. `python3 rpc_parity.py /path/to/stock /path/to/candidate > rpc.jsonl`. `python3 summarize.py inventory.log rpc.jsonl --extract raw.csv`. Все входы синтетические; пользовательские пути и данные не нужны.

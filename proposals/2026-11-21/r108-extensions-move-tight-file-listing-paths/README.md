# Files: передавать готовые пути из ответа сервера без копирования

При загрузке папки пакет уже владеет разобранным ответом сервера. Раньше он копировал каждый путь в список, а разобранный ответ затем освобождался. Теперь путь переходит в список без выделения, если он уже нормализован и ёмкость равна длине. При префиксе `./` или лишней ёмкости остаётся прежнее копирование; это сохраняет объём удерживаемых путей.

Не меняются исходные имена и псевдонимы, `./`-нормализация, порядок, исключения по исходному имени, типы, поведение некорректных полей, сворачивание папок и флаг неполного списка. Подсветка, меню, пути и подтверждения операций остаются прежними. Кэш и границы доступа, запросы и лимит Core не меняются. Списки для панели, раскрытия, «Развернуть всё» и Preview принимают ответ во владение.

## Проверка и применение

Выберите [source.patch](source.patch) для upstream Extensions `892f627570369ed60d7205eb0d351c753ec4305f` или [cumulative.patch](cumulative.patch) для M150 с 18 накладками Extensions до #430, дерево `f577f32ab08f57859a72eafc50114fb3559c78c2f7cea6d64c90f7e40125b4be`. Накладки отдельно, не одна поверх другой. В составной версии сохраняется существующее совместное хранение суффикса имени (#409).

[reproduce.py](reproduce.py) проверяет точные исходники, порядок накладок, Cargo.lock, прямое/обратное применение, штатный release-набор пакета, реальный протокол по синтетическому loopback и отдельный замер. Нужны Rust 1.95.0, прогретый офлайн-кеш `CARGO_HOME`, существующая цель `--target` и общий файл `--lock`. Без `--admit-exclusive` только предварительная проверка. С флагом: `--release --locked --offline -j1`, 512 МиБ допуска и 256 МиБ порог остановки. См. `python3 reproduce.py --help`.

Проверены первый и тёплый показ, папка на 64 записи и вложенная на 32, раскрытие и повторная загрузка, Preview, Unicode и экранированные пути, псевдонимы, исключение по имени и неполный список. Составной контроль #414 совпал с прежними точными кадрами и запросами.

## Результат

В обоих исходных деревьях указатели путей из уже разобранного обычного ответа совпали с указателями в итоговом списке. В одной строке на 48 Б удалено одно выделение; в списке из **32 строк удалены 32 выделения и 1 760 запрошенных байт**, в списке из **64 строк 64 выделения и 3 072 байта**. Ёмкости итоговых строк и векторов не выросли. В смешанном контроле перенесены ровно три подходящих пути (36 Б), остальные сохранили прежнее копирование или пустое значение. Пустой ответ не выделяет память в обеих версиях.

Штатные release-тесты: **37 → 38** на upstream и **42 → 43** в композиции. Во всех четырёх вариантах совпали **20 сырых кадров stdout (593 341 Б)**, 35 упорядоченных GET, ноль операций записи и отдельно 6 диагностических деревьев. По пять одинаковых пробных прогонов на вариант.

Замер относится только к превращению уже разобранного ответа в список, не учитывает чтение HTTP, JSON-декодирование, построение виджетов, рендер, время или RSS. Длины и ёмкости проверены отдельно, их значения не оценивают память всего процесса. Полный workspace, нативный Desktop и упаковка не проверялись.

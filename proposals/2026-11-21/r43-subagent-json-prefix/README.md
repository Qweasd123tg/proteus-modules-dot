# Core: не строить мегабайты JSON ради превью фонового инструмента

Отдельный патч к `Proteus-harness/Proteus-core@32e56ecb4cc6da324c60dd6ae2da78f3b7e46e7f`. При `ToolCallRequested` и `ToolFinished` родитель формирует карточку вложенного инструмента фонового агента. Превью аргументов и metadata ограничено 8 000 байтами, но проекция сериализовала в строку *весь* JSON под блокировкой live view. При большом выводе память тратилась на хвост, который пользователь никогда не увидит в этой карточке.

Патч направляет тот же компактный JSON в ограниченный буфер. Если значение помещается целиком, в карточке остаётся исходный типизированный JSON, а не строка. Если не помещается, результат как раньше: `{"truncated":true,"preview":"…"}` с тем же префиксом, включая JSON-экранирование и отсечение незаконченного UTF-8 символа. Пробелы/многоточие в префикс не добавляются. Зависимостей, изменений контракта, лимитов или формата wire нет. Не меняет корневые инструменты, foreground-дочерние инструменты или обработку `effective_args`. Это ограничение памяти превью, не всего события или состояния.

## Измерено на пути событий

Одинаковые события проходят через настоящие версии `TurnProgress::apply` до/после. Счётчик аллокатора из репозитория включён только при обработке конкретного события, а не на создание входов, чтение snapshot или проверку. Полные снимки сравнены. Числа — суммарно запрошенные байты, включая новый размер при realloc; это **не RSS и не время ответа**.

| Компактный JSON, байт | Аргументы: до → после | Metadata результата: до → после |
|---:|---:|---:|
| 30, обычный объект | 1 943 → 1 951 | 451 → 459 |
| 8 000, точная граница | 33 503 → 25 818 | 32 011 → 24 326 |
| 65 538, плоская строка | 206 499 → 26 240 | 205 007 → 24 748 |
| 4 194 306, плоская строка | 12 592 803 → 26 240 | 12 591 311 → 24 748 |
| 1 507 338, вложенные строки с JSON-экранированием | 4 204 176 → 26 240 | 4 202 684 → 24 748 |

У небольшой карточки суммарный размер вырос на 8 байт, а число аллокаций уменьшилось на две. У большой плоской строки число отдельных аллокаций выросло (аргументы 13 → 19), зато больше не выделяется строка размером с вход. Serde всё ещё может просмотреть большую строку в поисках экранируемых символов до первой записи, поэтому постоянное время или ускорение всего сервера не заявляются.

## Проверки и воспроизведение

- 15 штатных тестов проекции на базе, 16 на патче (включая новый тест каждой границы многобайтного и экранированного JSON), 1 дифференциальный тест пути событий с семью входами: **32/32**. В том числе 8 000 / 8 001 байт, обрыв четырёхбайтного символа, аргументы и metadata. Полные результаты — в `probe.log`.
- Весь библиотечный test target Core прошёл типизацию (`rustc --test --emit=metadata`; не полная линковка). `cargo fmt --all --check`, `git diff --check`, применение и обратное применение с `--check` прошли. Весь workspace и end-to-end транспорты не запускались.
- Скрипт не меняет checkout: извлекает точные исходники двух версий в temp и компилирует исходный модуль проекции целиком, его настоящий модуль text, все штатные тесты и тестовую обвязку со штатными типами контрактов. Нужны Python 3, rustc 1.95, lld и каталог с одной согласованной сборкой зависимостей.

```sh
# В каталоге чистого Core указанной ревизии; PROPOSAL — абсолютный путь к пакету.
git apply --check "$PROPOSAL/source.patch"
python3 "$PROPOSAL/probe.py" . "${CARGO_TARGET_DIR:-target}/debug/deps"
git apply "$PROPOSAL/source.patch"
# Обычный выборочный test target в полноценной рабочей среде:
./scripts/test.py -p proteus-core --lib app_server::turn_progress::tests
```

# Analysis: список шагов за один проход

Панель «Анализ ходов» повторно читала тип каждого шага для каждой показанной кнопки-фильтра, приводила один и тот же запрос к нижнему регистру для каждой строки и несколько раз определяла состояние одного шага. Теперь один проход по шагам считает кнопки и проблемы, отбирает совпадения и строит первые 400 строк. Список всех совпавших ссылок больше не выделяется. Полные счётчики по-прежнему учитывают шаги за пределом отображения.

Сохраняются порядок шагов и фильтров, обычное trim/Unicode lowercase поведение, исходный текст в поле поиска, видимый фильтр выбранного отсутствующего типа, пустые состояния, число совпадений и предел 400 строк. Условия ошибки и отсутствия результата, раскрытие выбранного шага, запросы к API и Preview не меняются. Нет нового кеша, состояния на сессию или изменения схемы/прав. Счётчики видов используют `usize`, как прежний результат `Iterator::count()`.

## Применение

Один и тот же [source.patch](source.patch) отдельно применим к точному upstream `892f627570369ed60d7205eb0d351c753ec4305f` и к M150 с накладками Extensions включительно #418 (`8359cad19f033e36d3208f284c5735cbbac20b8263760f1100174d9a5759ede7`). #338 (сокращение временных копий содержимого раскрываемых карточек) остаётся независимым. SDK, API, протокол и конфигурация сборки не затронуты.

## Воспроизведение

[reproduce.py](reproduce.py) сначала проверяет точные исходные деревья, Cargo.lock и 12 пакетов накладок в заданном порядке. Без `--admit-exclusive` останавливается после предварительной проверки. Для прогона: Rust 1.95.0, локальный офлайн-кеш Cargo с заданным `CARGO_HOME`, существующая прогретая цель `--target` и общий `--lock`; один release job, `--locked --offline`, входной порог свободного места 512 МиБ на каждом из двух томов, порог остановки 256 МиБ. См. `python3 reproduce.py --help`.

Сначала запускаются штатные тесты пакета и реальный release-бинарник с ограниченным GET-only loopback. Строки stdout сравниваются побайтно до повторного кодирования; проверяются оба контекста, поиск по Юникоду, пустые результаты, фильтр проблем, строки за пределом 400, раскрытие/скрытие и смена хода. Отдельная тестовая вставка затем считает вызовы **самого** `step_list` и его помощников по реальным веткам этого кода и сравнивает побайтно все построенные деревья. Она не учитывает итоговую карточку, загрузку сети, другие панели или время работы.

## Результат

На отдельной выборке из 420 шагов и четырёх видов:

| Проверенный счётчик списка | До | После |
| --- | ---: | ---: |
| Чтение вида для чисел фильтров | 3 360 | 420 |
| Приведение запроса к нижнему регистру | 420 | 1 |
| Определение состояния, все шаги | 820 | 420 |
| Определение состояния, только проблемы | 997 | 420 |
| Посещения вложенных строк hooks, только проблемы | 2 265 | 963 |
| Построение заголовка при поиске 105 инструментов | 210 | 105 |
| Временные ссылки на совпадения без фильтра | 420 | 0 |

В последнем случае по-прежнему рисуются ровно 400 из 420 совпадений. Пустой список не нормализует запрос, длинный «не найдено» не строит строки. Состояние на 420 шагах может потребовать посещений внутри отдельного шага; счётчик вида измеряет только проходы чисел фильтров, не все операции над JSON.

Штатные release-тесты: **12 → 13** на upstream, **14 → 15** на составном дереве. Во всех четырёх вариантах совпали **13 сырых кадров stdout** (514 764 Б), пять упорядоченных GET, ноль записей и отдельно **11 измерительных деревьев** (559 562 Б). Проверки и точная идентификация: [checks.log](checks.log), [measurements.log](measurements.log), [artifact-receipts.log](artifact-receipts.log).

Замера RSS, аллокатора, запуска или задержки нет. Полный workspace, нативный Desktop и упаковка не запускались.

# Desktop: один поиск по карте высот на окно истории

При перестроении геометрии полосы прокрутки Desktop складывает высоты строк загруженного окна. Раньше для каждой строки выполнялся отдельный поиск от корня дерева диапазонов. Например, пересчёт окна из 200 строк требовал 200 поисков, даже когда все строки имели одну и ту же оценку высоты.

Патч находит первый нужный диапазон один раз и читает следующие по порядку. Начало посреди диапазона, нулевая высота свёрнутых строк, дробные оценки и запасная высота за концом карты сохраняются. Изменён только пересчёт префиксов высот. Обработка пользовательского перехода, загрузка страниц, привязка прокрутки, форматы дисковых данных и протоколы не меняются.

**База:** [Proteus-harness/Proteus-desktop, b6a7ec2](https://github.com/Proteus-harness/Proteus-desktop/commit/b6a7ec2d8d7e486c8aba01291aa8c89774c4cded). SHA-256 `source.patch`: `b39b5efb427d3fcc2c44390b40a87efb6294e77e582c9b9925bc2dca6299d189`. Прямое и обратное применение проверены; в целевом checkout: `git apply --check /путь/source.patch`, затем `git apply /путь/source.patch`.

**Что измерено.** Синтетический тёплый замер самого цикла построения префикса, извлечённого из настоящего `Geometry::rebuild`, с настоящей `HeightMap` и тем же деревом сумм. Прочие поля окна не нужны: координаты в стенде хранятся в f32, как в нативном типе Pixels. На каждый случай медиана шести процессов для каждой версии, порядок версий чередовался; в процессе один прогрев, 11 серий по 128 вызовов, использована медиана серий. Создание карты и построение UI не входят в таймер. Контрольные суммы всех накопленных высот и поправки к длине документа совпали для каждого случая.

| Запрошенное окно | База, мкс | Патч, мкс |
|---|---:|---:|
| 200 строк внутри одного диапазона, миллион логических строк | 1,244 | 0,560 |
| 200 строк с разными высотами в карте на 16 384 строки | 4,395 | 2,090 |
| 50 строк в той же карте | 1,091 | 0,587 |
| Одна строка в той же карте | 0,025 | 0,113 |
| 50 строк, большая часть за концом короткой карты (проверка запасной высоты) | 0,233 | 0,190 |

В коротком окне на одну строку установка курсора **дороже** прямого поиска, примерно на 0,088 мкс. Для 200 разноразмерных строк выигрыш около 2,3 мкс за один пересчёт. Это не измерение FPS, RSS или времени отображения чата.

**Проверено:** тесты настоящего модуля карты: 11/11 на базе, 12/12 после патча. Новый тест сравнивает последовательный результат с независимыми точечными поисками для каждого возможного начала, в том числе в пустой, частично измеренной и уплотнённой картах. Отдельно выполнена проверка типов полных модулей геометрии, карты, кэша и его хранилища и их тестов с настоящим gpui_kit (база и патч). Нативное окно, полный бинарник и весь набор GUI-тестов не запускались.

**Воспроизведение:**

- `bash verify.sh DESKTOP_REPO SUM_TREE.rlib`: юнит-тесты, прямое/обратное применение, замеры и сверка результатов.
- `bash typecheck.sh DESKTOP_REPO SUM_TREE.rlib GPUI_KIT.rlib SHA2.rlib LIBC.rlib ASYNC_CHANNEL.rlib UUID.rlib`: отдельно проверить типы владельца изменённого цикла и его тестов.
- Скрипты используют временную папку и совместимые Rust-библиотеки из кэша зависимостей Desktop. Нужны Linux, rustc, git, tar, Python 3 и lld. Фактический вывод в `evidence.log`.

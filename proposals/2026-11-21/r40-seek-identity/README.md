# Desktop: разные сообщения не должны получать одинаковые ключи при переходе по истории

При прыжке ползунком к далёкой странице чат открывал пустой `Transcript` со счётчиком ключей, снова начинавшимся с 1. Если в двух разных окнах было по 50 строк, ключи могли полностью совпасть. Расчёт изменений для виртуального списка тогда сообщал «ничего не изменилось», хотя поменялись все 50 сообщений. Когда архив и актуальный хвост снова соединялись, разные сообщения могли оказаться под одним ключом уже внутри одного окна. Содержимое сохранённой истории не затронуто.

Патч даёт новому окну **тот же генератор уникальных ключей**, что у текущего чата, не копируя строки, состояние активного треда или индексы. Штатная подгрузка по-прежнему сохраняет ключи сообщений, совпавших по настоящей идентичности в живом хвосте. Та же конструкция уже использовалась в `external_prepend`; теперь оба места вызывают один метод. Формат хранилища, запросы страниц, ограничения кэша и правила отбрасывания устаревших ответов не меняются.

### Что воспроизведено

Синтетический чат из 1000 строк, в актуальном окне 950–999. На одних входах проверены фактические `History::accept_seek`, `accept_page`, `latest` и `Transcript`.

| Переход | Без патча | С патчем |
|---|---|---|
| Хвост → строки 475–524 → строки 75–124 | Обе смены окна: ни одной операции замены | Каждый раз заменены все 50 строк |
| После этого пришло одно новое сообщение; возврат к хвосту | Добавлена одна строка; первые 50 сочтены прежними | Архивные 50 заменены на 51 актуальную |
| Переход к строке 920 и подгрузка вперёд | В окне из 100 разных сообщений только **55** уникальных ключей | **100 из 100** уникальны; 45 настоящих совпадений с хвостом сохранили свои ключи; при возврате удалено 55 архивных строк и добавлено 5 новых для окна |

Это проверка корректности списка изменений и идентичности строк. Отрисовка в нативном окне, положение в пикселях, FPS, задержка и RSS не измерялись.

### Проверка и применение

База: `Proteus-harness/Proteus-desktop` @ `b6a7ec2d8d7e486c8aba01291aa8c89774c4cded`. SHA-256 `source.patch`: `e6c68a0ab16597b670671114ea531b18ad7ce3cd22a8db092f4fcef7b0e59d5d`. Из корня этой базы: `git apply --check /path/to/source.patch`, затем `git apply /path/to/source.patch`. Проверены применение в чистый индекс и обратимость, отсутствие ошибок пробелов и rustfmt для четырёх изменённых файлов.

`evidence.log`: один и тот же набор из 60 проверок на обеих версиях. На базе 58 прошли и ровно две новые регрессии упали, с патчем **60/60**. Это все 41 тест модели транскрипта и 19 тестов модели истории, включая новые. Из набора в `history/tests.rs` исключены два теста с GPUI ListState. Полный Desktop, GUI и отдельные тесты других модулей здесь не собирались.

Воспроизведение в Linux с Rust 1.95.0, LLD, Python 3 и готовыми зависимостями закреплённого checkout:
`bash verify.sh /path/to/Proteus-desktop /path/to/target/debug/deps`.
Скрипт извлекает только нужные файлы и не меняет переданный checkout. Использует исходные модули транскрипта, типы и тела методов истории, без реализации-дубля и сетевого сервера. Для другого совместимого набора артефактов укажите точные пути в `CONTRACTS_RLIB`, `JSON_RLIB`, `UUID_RLIB`. Если готовых библиотек нет, в отдельном полном checkout с патчем обе регрессии входят в штатную команду `cargo test --locked --no-default-features -p proteus-native --bin proteus-native ui::chat::history::tests::`.

# Analysis: заголовок сообщения без копии всего тела

Когда в Analysis открывают шаг модели, расширение создаёт для каждого сообщения заголовок по первым 90 символам и отдельный блок с полным текстом. Раньше построение одного заголовка требовало собрать **все** слова сообщения в вектор, соединить их в строку, а затем обрезать и скопировать результат. [Патч](source.patch) сворачивает пробельные символы в один ASCII-пробел и прекращает обход после видимого префикса. Лимит по-прежнему задан в Unicode scalar values (`char`), а не в байтах; начальные и конечные пробелы в вывод не попадают. Длинный участок пробелов до следующего видимого символа в некоторых случаях всё равно нужно прочитать. Полный текст доступен в карточке как прежде.

База: [Proteus-desktop-extensions@892f627](https://github.com/Proteus-harness/Proteus-desktop-extensions/commit/892f627570369ed60d7205eb0d351c753ec4305f). Производственный путь: [заголовки сообщений в карточке шага](https://github.com/Proteus-harness/Proteus-desktop-extensions/blob/892f627570369ed60d7205eb0d351c753ec4305f/packages/analysis/src/details.rs#L63-L80). Тот же helper используют заголовок задачи и строки списка ходов. Схема, лимиты и выбор текста не меняются.

| Вход | Только заголовок, выделено байтов, до → после | Вся карточка шага, выделено байтов, до → после | Вся карточка шага, мс, до → после |
|---|---:|---:|---:|
| 122 Б, короткое сообщение | 892 → 248 | 45 601 → 44 957 | 0,028 → 0,027 |
| 64 КиБ текста со словами | 584 709 → 248 | 1 495 047 → 910 586 | 0,377 → 0,224 |
| 1 МиБ текста со словами | 9 353 435 → 248 | 23 279 315 → 13 926 128 | 5,46 → 4,95 |
| 1 МиБ, одно слово из `界` | 1 049 542 → 1 016 | 13 677 439 → 12 628 913 | 4,05 → 3,24 |
| 64 КиБ пробелов | 0 → 0 | 898 408 → 897 413 | 0,498 → 0,519 |

Счётчик суммирует размеры запросов к аллокатору, включая новые размеры при `realloc`. Это не пик памяти и не RSS. Время включает создание и уничтожение объекта; медианы семи пар прогретых release-запусков с чередованием первой версии. Создание синтетических данных, сериализация готовой карточки, IPC и нативная отрисовка в таймер не входят. Для обычных коротких сообщений или одних пробелов выигрыш во времени страницы не заявляется. Для всего экрана стоимость зависит от числа сообщений, формирования полных тел и других виджетов.

## Проверка и повтор

- Точный пакет `cargo test --locked -p extension-analysis`, debug и release: база **12/12**, патч **13/13**. Новый тест сравнивает прежнее правило и результат на всех границах пяти строк, включая пустую, Unicode-пробелы, emoji и комбинируемый знак.
- Для шести входов (также пустое сообщение) два release-бинарника вернули **побайтно одинаковые** заголовки и JSON `details::step_card`; 4 738 375 байт с префиксами длин. [Хеш, все случаи и сырые измерения](measurements.log); [проверки](checks.log).
- `python3 reproduce.py /path/to/Proteus-desktop-extensions` извлекает точную базу, проверяет прямое и обратное применение патча, формат, release-тесты и запускает [один probe](probe.rs) в двух версиях. Нужны git, tar, Python 3, Cargo, Rust с rustfmt и зависимости Cargo.lock; для прогретого Cargo-кэша можно задать `CARGO_NET_OFFLINE=true`. Изменяется только временная копия репозитория. Полный workspace, нативное окно, пакетирование и живой сервер не проверялись.

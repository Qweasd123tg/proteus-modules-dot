# Desktop: не собирать подсказки тегов за пределами восьми кнопок

Редактор тегов в настройках показывает до восьми подсказок. Раньше он копировал строки для каждого кандидата, искал дубликаты линейно во всё более длинном списке, а после этого отбирал все совпадения, хотя рисовал только первые восемь. Теперь источники обходятся лениво, дубликаты отсеиваются по заимствованным строкам, а копии создаются для первых восьми совпадений. При редком запросе может понадобиться прочитать весь список, но скрытые строки не копируются в результат.

Владелец схемы и порядок источников прежние: варианты перечисления, значения по умолчанию, затем инструменты или экспорты (слоты, модели, хуки, плагины). Для одинакового значения остаётся первая подпись, даже если по запросу совпала бы только более поздняя. Не меняются Unicode-регистр при поиске, пробелы запроса, исключение уже выбранных строк, идентификаторы кнопок и действие по клику. Правила добавления, проверки и записи профиля не менялись.

База: [Proteus-desktop b6a7ec2d](https://github.com/Proteus-harness/Proteus-desktop/commit/b6a7ec2d8d7e486c8aba01291aa8c89774c4cded). SHA-256 файла `source.patch`: `fbc10e207fb115bec4ca4c0088315f6de316404eeaedda53166a1281c4eb50d1`.

## Что измерили

| Синтетический список | Вызовы аллокатора, до → после | Запрошенные байты, до → после | Медиана, мкс |
|---|---:|---:|---:|
| 24 инструмента, открытие без запроса | 85 → 21 | 4 267 → 1 206 | 2,958 → 1,471 |
| 24 инструмента, поиск «helper» | 126 → 44 | 3 913 → 2 662 | 4,634 → 4,760 |
| 80 инструментов, ни одного совпадения | 347 → 94 | 14 592 → 5 033 | 15,830 → 9,310 |
| 512 инструментов, открытие без запроса (стресс) | 1 071 → 21 | 123 401 → 1 206 | 299,978 → 1,655 |

Это построение видимых пар «значение, подпись» на уже готовых типизированных данных, без рисования, работы GPUI и сетевой загрузки. Запросы к аллокатору включают `alloc` и `realloc`, байты суммируются, это не пиковая память и не RSS. Микрозамер без счётчика: оптимизированный бинарник, восемь чередующихся пар прогретых запусков на одном логическом CPU Linux x86-64. Для поискового запроса на 24 инструментах меньше аллокаций, но ускорения не показано.

## Проверка

- Полностью совпали видимые пары, порядок и количество в **16 128** сравнениях на исходных типах `ConfigField` и `ConfigBuilderSnapshot`. Проверены разные источники и порядки, пустой запрос, Unicode, совпадения в заголовках и значениях, дубли и исключение выбранного. Сравнение использует исходный сборщик и выражение фильтра из закреплённой ревизии. Отдельный новый Rust-тест защищает предел и выбор первой подписи.
- **124 идентичности зависимостей** совпадают с Desktop Cargo.lock, включая закреплённый коммит `proteus-contracts`. Прямое/обратное применение, git diff --check и rustfmt прошли. Журнал и исходные значения: [evidence.log](evidence.log).

## Как повторить

Из checkout базы: `git apply --check /путь/source.patch`; для отдельной проверки `bash verify.sh /путь/Proteus-desktop`. Требуются Git, Bash, Python 3.11+, Rust 1.95.0 с rustfmt и локальный кеш зависимостей из `harness.lock`. Проверка берёт исходные функции из Git, не меняет checkout и запускает Cargo в режиме `--offline --locked`. Для замера лучше закрепить процесс на одном доступном логическом CPU через `taskset`. Полный workspace и GUI не собирались и не запускались; нативные тесты редактора не объявляются пройденными.

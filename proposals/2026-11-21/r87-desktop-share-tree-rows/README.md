# Desktop: share accepted extension tree rows with the native tree

Applies to Proteus Desktop `b6a7ec2d8d7e486c8aba01291aa8c89774c4cded` and to the verified M150 Desktop stack through #410. This is one production patch with no protocol, dependency, limit, or permissions change.

Files and Git declare a tree of owned rows: IDs, row text and optional menu payloads. The decoded widget view used to keep one full row vector while the native tree retained its own deep copy. Even a value-equal refresh cloned the whole vector before the equality early return. The existing required array is still decoded as a `Vec<Row>`, then moved into an immutable shared owner. Native mount and refresh pass an Arc handle instead of cloning its row contents.

Equality is still value-based and still preserves the native tree's current snapshot on a no-op. An independently decoded, equal new declaration can therefore keep its own separate backing alongside the existing native tree. The change avoids the throwaway handoff clone in that case; it does not intern across incoming messages. Open menus still carry per-row snapshots with their original ordered payloads. Closing branches still copy only disappearing children into `Fold.gone`, not the whole old row owner. The new owner itself has a small header; freshly decoded vectors retain their original capacity.

## Focused verification

The same patch applied and reversed cleanly on stock and on the sealed cumulative source. The verifier checked 44 predecessor patch hashes, 125 locked dependency identities, and unchanged menu, validation, and navigation source neighborhoods. Four newly compiled Cargo JSON-identified arms executed the exact Tree decoding/validation, row handoff, reconcile/navigation/fold methods, menu item snapshot statement and menu fill/ask logic. The carrier substitutes native effects and tests the declared fixture icon names through the real lookup algorithm. It does not execute native rendering, actual right-click/focus/input, dialogs, live ingress or a full app build. One fixture explicitly decodes on a reader thread and moves the actual typed wire result across it.

* At mount, the synthetic 1,001-row Files/Git-style fixture had 1,001 fewer duplicated native row slots (216,216 bytes in row slots only on the checked build). The 1,000 nested menu buffers and representative nested strings alias the original instead of being cloned. These observations do not count total tree footprint.
* In a separately decoded value-equal refresh of the same rich fixture, the measured handoff alone went from 36,004 allocation requests and 3,770,240 requested bytes to zero. Counting starts after decode and excludes render and the rest of the app. These temporary requests are not resident memory, are not additive with the mount result, and vary with row/menu contents.
* The four behavior traces are byte-identical, SHA-256 `792cbe62e8e8c5749c3d067847f39c261ed12774ca1ed020083a415d1a619aa5`. Required, null, malformed, duplicate and unknown fields retain exact errors. Row/icon/menu validation retains the original panel error versus localized content error. The checks preserve row ordering, duplicate IDs, layout, splices, selection/reveal, header-only keyboard navigation, and equal-row action rebinding without extra notification. An old right-click snapshot keeps its original JSON key order and signed zero after a new action/controller snapshot. Replacing/closing rows frees the obsolete full owner while the two child ghosts remain available until the modeled fold settles.

No native GUI, frame-rate, latency, RSS, or full Desktop-suite claim. This packet does not modify app instrumentation.

## Reproduce

Run `sha256sum -c SHA256SUMS` here. Then `bash verify.sh --prepare WORKSPACE_WITH_PINNED_INPUTS` checks the exact source tiers, lock and formatting without compiling. Use `--run` only with the admitted offline warm target/cache and shared compiler lock (`CARGO_HOME`, `CARGO_TARGET_DIR`, `R87_BUILD_LOCK`, and a fresh private `R87_RAW_CARGO_DIR`). The verifier checks minimum disk reserves, bounds additional disk consumption and uses offline locked Cargo with one job. `cargo-provenance.json` binds the executed fresh non-test binary to a source arm and hashes the exact projected files and included local dependency. `behavior.trace` and `work.log` record the deterministic outputs.

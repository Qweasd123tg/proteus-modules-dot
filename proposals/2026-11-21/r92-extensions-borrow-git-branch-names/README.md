# Git: кэшировать имена веток и читать список без копии

Точный upstream Extensions: `892f627570369ed60d7205eb0d351c753ec4305f`. Один и тот же `source.patch` проверен на upstream и на M150 + #394/#395/#397/#399/#402/#404/#406/#409/#412/#414 (`ecbf209a01b6915f70c55928a1895574215dd0a717ae8082fb504056d94821b0`; #409 и #414 в этом слепке применяются своими составными вариантами).

Обычная панель Git строит меню веток даже на первой вкладке Changes, а всплывающее окно строит полный список. Оба читают только имя. Раньше снимок удерживал все JSON-объекты веток и глубоко копировал весь список при каждом чтении. Теперь он перемещает уже декодированные строки имён в `Vec<String>` и отдаёт срез по ссылке. Последний коммит, автор, upstream и ключи декодированных объектов больше не удерживаются каталогом. Метаданные отдельного статусного снимка, SDK и сервер не меняются.

Сохраняются исходные порядок/повторы, Unicode и пустое имя для отсутствующей или некорректной записи. Пустые записи считаются в прежних первых 60 элементах меню; popup по-прежнему показывает весь список. Текущая ветка и запасной символ «—» берутся из прежнего источника, а не из заголовка каталога. Успешный пустой ответ кэшируется, неудачный запрос — нет. Код сброса на изменении ветки/refs, обновлении, смене сессии и успешных операциях, условия checkout/create, значения действий и обработка ошибок не менялись.

## Точная проверка

- Только штатный Git, offline locked release, один Cargo job: **41 → 43** теста на upstream и **44 → 46** на составном дереве. Новые тесты проверяют передачу указателя, прежнюю пустую подстановку, тёплый срез, пустой кэш и повтор после ошибки.
- Реальный бинарник Git, синтетический локальный сервер, **GET only**, 12 исходных stdout-кадров побайтно совпали во всех четырёх ветках. Меню / полный popup, 60-й элемент, пустые/повторяющиеся имена, тёплый черновик, перенос popup в другой контекст, явное обновление и отдельное изменение refs при той же ветке. Отдельная сессия с «—» и не-репозиторий. **9** GET изменений/каталога в строго том же порядке, ни одного POST, checkout или обращения к пользовательскому Git.

## Изолированный удерживаемый каталог и тёплое чтение

Зонд измеряет живые запрошенные блоки/байты после исчезновения декодированного ответа (до построения UI) и отдельно считает запросы к аллокатору на тёплом вызове `branch_list`. Сравниваются ёмкость/слоты, указатель на первое декодированное имя, указатель при повторном чтении и полный сброс. По пять одинаковых наблюдений на вариант. Данные повторяют штатный Core DTO с 20-байтным именем и 96-байтным описанием последнего коммита.

| Веток | Живые байты до → после | Живые блоки до → после | Запрошенные байты на тёплом чтении |
|---:|---:|---:|---:|
| 0 | 0 → 0 | 0 → 0 | 0 → 0 |
| 8 | 8 800 → 352 | 89 → 9 | 8 800 → 0 |
| 64 | 70 400 → 2 816 | 705 → 65 | 70 400 → 0 |
| 1 000 | 1 100 000 → 44 000 | 11 001 → 1 001 | 1 100 000 → 0 |

На x86-64 размер слота **72 → 24 байта**, ёмкость в каждом наборе не изменилась. При 1 000 строках тёплое чтение устраняет все **11 001** прежних запросов к аллокатору; разбор уже готового ответа в каталог запрашивает **24 000** байт под вектор вместо **1 100 000** байт старой проекции. Передача указателей подтверждена на непустых наборах.

1 000 — граница из Core, а не измерение обычного числа веток. Это запрошенные байты и аллокации, не RSS/PSS, не замер запуска или задержки; построение меню и форматирование его JSON сохраняются.

## Повторить

Нужны точный локальный git-checkout, сохранённое дерево Extensions M150, десять предыдущих патчей, подготовленный offline Cargo cache, Rust/Cargo 1.95.0 и общий lock.

```bash
PYTHONDONTWRITEBYTECODE=1 python3 reproduce.py "$STOCK" "$M150_EXTENSIONS" \
  "$P394" "$P395" "$P397" "$P399" "$P402" "$P404" "$P406" "$CUMULATIVE_409" "$P412" "$CUMULATIVE_414" \
  --target "$TARGET" --lock "$BUILD_LOCK" --admit-exclusive
```

Без флага проверяются входы. С флагом — один lock, одна задача компиляции, минимум 512 MiB на обоих томах перед входом, остановка ниже 256 MiB. Cargo JSON доказывает точное происхождение исполняемых файлов, их хеши сверяются до/после запуска. Не запускались нативное окно, упаковка и полный workspace.

# Desktop: обход родителей в списке чатов без временного вектора пути

При подготовке боковой панели `SessionMarks::arrange` проверяет родительские связи: если в истории есть цикл, одного разрыва достаточно, чтобы все сессии оставались доступны. Раньше обход графа создавал временный вектор даже для строки без родителя. Теперь код сначала отмечает текущий путь, затем ещё раз проходит по тем же связям, записывает завершённые метки и только после этого разрывает то же ребро.

Порядок обхода и выбор ребра сохраняются, поэтому структура веток, поиск, архив и закрепления не меняются. Обход остаётся итеративным с линейной сложностью. Вторая фаза читает родительские связи вместо последовательного чтения временного вектора; на длинных цепочках это может изменить локальность чтения. Время не измерялось.

База: [Proteus-desktop b6a7ec2d](https://github.com/Proteus-harness/Proteus-desktop/commit/b6a7ec2d8d7e486c8aba01291aa8c89774c4cded). SHA-256 патча: `26450c411d908c9696c2a2fb9e9892b19d91f1c470b5be288f4a94210f447dbc`.

## Проверка

- Взяты исходные модули сессий и разговоров, типы Codex и `proteus-tabs`. Сверены **124** идентичности зависимостей (имя, версия, источник и контрольная сумма), включая `proteus-contracts`.
- С исходной функцией совпали **126 126** полных массивов родителей. Это все графы с 0–6 строками и не более одной исходящей связью на строку, включая петли, циклы и сходящиеся ветки.
- **1 400** списков штатного `SessionMarks::arrange` совпали побайтно. В синтетических данных есть обе системы идентификаторов, пустой и Unicode-поиск, отметки, отсутствующие родители и разные формы деревьев. Штатные тесты: **16/16** до правки и **17/17** после.
- Прямое и обратное применение, `git diff --check` и rustfmt прошли. Патч применяется поверх M100; прямой и обратный порядки с R57–R59 дают побайтно одинаковые файлы. Проверка применения к независимо составленному Desktop через R59 тоже прошла. Это не #345 (поиск текущей строки в готовом дереве) и не оптимизация сортировки проектов из M100.

## Запросы аллокатору при подготовке списка

| Синтетический список | Запросы, до → после | Запрошенные байты, до → после |
|---|---:|---:|
| Пустой | 0 → 0 | 0 → 0 |
| 64 отдельные сессии в одной папке | 218 → 154 | 26 003 → 23 955 |
| Цепочка из 64 сессий | 276 → 271 | 33 691 → 32 699 |
| 64 сессии небольшими ветками, четыре папки | 247 → 183 | 23 571 → 21 523 |
| 64 смешанные сессии с поиском, архивом и закреплениями | 331 → 273 | 21 896 → 20 040 |

Это весь вызов `SessionMarks::arrange` на готовых синтетических данных. В отдельно измеренном обходе графа таких 64 корней запросы сократились с 65 до 1: остался только 64-байтный вектор меток. Счётчик суммирует `alloc` и `realloc`; это не пиковая память, RSS или стоимость отрисовки.

## Как повторить

`git apply --check /путь/source.patch` из checkout базы. Узкая проверка: `bash verify.sh /путь/Proteus-desktop`. Нужны Bash, Git, Python 3.11+, Rust 1.95 с rustfmt и локальный Cargo-кэш для `harness.lock`. Стенд собирается без сети в один Cargo job. См. [evidence.log](evidence.log). Полная сборка Desktop и окно GPUI не проверялись.

# Git: распределять изменения по разделам за один проход

Раньше Git-панель трижды перебирала один и тот же список изменений, по проходу для каждого раздела. [Патч](source.patch) распределяет строки по прежним разделам за один проход. Внутри каждого раздела строки остаются в исходном порядке. Конфликты не получают лишних копий, а частично добавленный в индекс файл по-прежнему виден и в Staged, и в Unstaged.

| Обычный синтетический список | Посещения строк | Чтения статуса | Чтения флагов индекса |
|---|---:|---:|---:|
| 32 файла, по статусу | 96 → 32 | 152 → 32 | 0 → 0 |
| 64 файла, по статусу | 192 → 64 | 304 → 64 | 0 → 0 |
| 32 файла, по индексу | 96 → 32 | 96 → 32 | 56 → 56 |
| 64 файла, по индексу | 192 → 64 | 192 → 64 | 112 → 112 |

[Счётчики](measurements.log) измеряют только построение групп из готового списка: пять одинаковых отсчётов на вариант. Выделения System, запрошенные байты, ёмкость внешнего вектора и суммарная ёмкость разделов совпали. Это не замер задержки или RSS. Сами строки не копируются: проверены точные ссылки на исходные записи, в том числе записи с одинаковыми путями. Политика выбора файлов и ограничения не меняются; порядок подходящих строк для действий проверен как чистое вычисление, сами действия не выполнялись.

- Release-пакет `extension-git`: **41 → 42** теста на [upstream](https://github.com/Proteus-harness/Proteus-desktop-extensions/commit/892f627570369ed60d7205eb0d351c753ec4305f), **50 → 51** на M150 с дополнениями по #435. Один и тот же патч накладывается и снимается на обеих базах.
- Проверка реального процесса: **9** побайтно одинаковых кадров (420 372 байт), **8** GET в одинаковом порядке и без команд действий, записей, реального репозитория или внешнего сервера. Пустая панель, отсутствие репозитория и ошибка каталога веток также совпали с предыдущей проверкой R112. [Проверки](checks.log), [происхождение исполняемых файлов](artifact-receipts.log).

[Воспроизведение](reproduce.py): закреплённые исходники, предыдущие патчи, общий подготовленный target, offline Cargo 1.95.0. Один release job под общим lock, прежние пороги свободного места. GUI и полный workspace не запускались.

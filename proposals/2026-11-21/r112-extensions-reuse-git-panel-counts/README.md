# Git: один подсчёт статусов для панели изменений

Панель изменений раньше дважды обходила один и тот же снимок Git: для меню Stage/Unstage и для редактора коммита. [Патч](source.patch) передаёт обоим уже рассчитанные счётчики. Новый кэш не нужен: подсчёт выполняется заново для каждого показа панели.

Порядок загрузки, ошибка каталога веток, группировка, доступность кнопок и подписи не изменились. Проверка при выполнении коммита по-прежнему считает статусы отдельно из актуального для действия снимка. HTTP-запросов меньше не стало: ускоряется только обход уже полученных данных.

| Случай | Вызовы подсчёта | Посещения записей |
|---|---:|---:|
| 32 изменённых файла | 2 → 1 | 64 → 32 |
| 64 изменённых файла | 2 → 1 | 128 → 64 |
| Пустой список в репозитории | 2 → 1 | 0 → 0 |
| Ответ не является репозиторием | 0 → 0 | 0 → 0 |
| Ошибка каталога веток, 32 файла | 1 → 1 | 32 → 32 |

В [замерах](measurements.log) проверяли реальный `Git::panel` с готовым синтетическим снимком, в обоих режимах группировки и после смены снимка. Вывод совпал, а число запросов System на выделение памяти и число запрошенных байтов не изменились внутри каждой пары «до / после». На каждый вариант пришлось пять одинаковых отсчётов. Это не измерение задержки или RSS.

Штатный release-пакет `extension-git`: **41/41** на [upstream](https://github.com/Proteus-harness/Proteus-desktop-extensions/commit/892f627570369ed60d7205eb0d351c753ec4305f), **50/50** на точном составе M150 через #433, с патчем и без. Один патч накладывается и снимается на обеих базах. Реальный процесс вернул **15** одинаковых побайтно кадров (707 330 байт) и сделал **8** одинаковых GET к синтетическому loopback на вариант, без записей или реального рабочего дерева. Покрыты повторные показы, две панели одной сессии, конфликт, частичный индекс, скрытый редактор и ошибка чтения веток. См. [проверки](checks.log) и [происхождение исполняемых файлов](artifact-receipts.log).

[Воспроизведение](reproduce.py) требует закреплённые локальные исходники, предыдущие патчи и подготовленный target для offline Cargo 1.95.0; параметры доступны в `--help`. Один release job под общим lock, с прежними порогами свободного места. GUI, упаковка и полный workspace не запускались.

# Skill Pack: сохранять только тело запрошенного навыка

База: **Proteus-harness/Proteus-modules@9469e3b12529d08b1f4a76882693e2065e842c51**. Локальный commit `341d2dff82d6030b7410028e417093c5025d885e`. Патч меняет только `tool/skill-pack/src/lib.rs` и `discovery.rs`.

Раньше вызов `skill` копировал в отдельные строки тела всех найденных файлов, хотя возвращает тело только одного навыка. Теперь загрузчик сохраняет тело только у кандидата с точным запрошенным ID. Для пакетов проверяется именно префикс `id_пакета:`, а затем прежнее локальное имя. Два источника с одним ID могут ещё оба сохранить тело до разрешения приоритета. В режиме каталога и контекстного провайдера тела по-прежнему не сохраняются.

Это не ленивое чтение файлов и не ранний выход из обхода. По-прежнему читаются и целиком валидируются все прежние кандидаты, в том же порядке, с теми же лимитами размера и проверками UTF-8, frontmatter и границ workspace. Ошибка в постороннем файле остаётся видимой; приоритет проектов, порядок настроек и отключение навыков не меняются. Вместо изменения проверок пропускается только ненужная копия тела после успешной проверки.

## Проверки

- Штатный `python3 scripts/test.py -p skill-pack --lib --release` на точной базе с закреплёнными зависимостями: база **9/9**, кандидат **11/11**. Две регрессии проверяют user→project override и прежнюю ошибку на постороннем испорченном файле, а также точное имя пакета с вложенным префиксом через реальный `skill`. Прошли `cargo build --locked --release -p skill-pack --lib` (без test-only варианта), `rustfmt --check`, `git diff --check` и `git apply --check`.
- [#60](https://github.com/Qweasd123tg/proteus-modules-dot/pull/60) уже добавляет прежний режим пропуска тела для каталога; здесь отдельно устраняется удержание остальных тел при загрузке одного. [#166](https://github.com/Qweasd123tg/proteus-modules-dot/pull/166) посвящён дублирующим Python-фикстурам, не этому обработчику. В проверенных новых пакетах до #337 совпадающего изменения нет.
- Полный workspace gate, сборка Desktop и CI не запускались.

## Дифференциальная проверка и измерение

Два независимых прогона сравнили полные ответы настоящего Rust-обработчика `skill` и полный ответ контекстного провайдера на синтетических файлах в рабочей папке. Во всех десяти сценариях ответы побайтно совпали. Независимые ожидания проверяют конкретное тело и метаданные, точный plugin ID, пользовательский/project override, отключённый и неизвестный навык, ошибки UTF-8/размера в постороннем файле и контроль каталога. В публикуемых SHA-256 путь временной папки нормализован после сравнения полных байтов. Сеть и процессный транспорт не используются.

Linux x86-64, rustc 1.95.0, locked Release. Метрики охватывают весь вызов с прогретым файловым кэшем. Для времени отдельно собраны бинарники без измерителя, основные сценарии идут по девять пар процессов, порядок чередуется. Запрошенные байты учитывают полный размер каждого успешного alloc/realloc; пик — максимальное приращение логического размера живых Rust-аллокаций, не RSS.

| Сценарий | Запрошенные байты | Вызовы alloc/realloc | Пик живых байтов |
|---|---:|---:|---:|
| 96 файлов примерно по 128 КиБ, одно совпадение | 70 363 156 → 57 913 121 | 6 426 → 6 331 | 12 903 548 → 523 042 |
| Та же папка, навык отсутствует | 69 838 193 → 57 257 105 | 6 417 → 6 321 | 12 903 552 → 391 993 |
| 8 файлов по 3 КиБ, одно совпадение | 681 648 → 660 249 | 533 → 526 | 100 322 → 81 980 |
| Один файл по 3 КиБ | 102 061 → 102 061 | 112 → 112 | 75 134 → 75 134 |
| Контрольный контекстный провайдер, 8 файлов | 656 155 → 656 155 | 656 → 656 | 78 275 → 78 275 |

На большом успешном вызове пик живых байтов ниже **на 95,9%**, запрошено на **17,7%** меньше. **Стабильного ускорения полного успешного вызова не подтверждено**: на большом наборе медианы 16,45 → 11,22 мс и 13,28 → 15,42 мс, на восьми файлах 156 → 197 мкс и 145 → 136 мкс. При отсутствии навыка на большом наборе в двух прогонах 19,92 → 15,53 и 13,65 → 12,20 мс; на одном файле аллокации не меняются. Сырые данные в `bench.log` и `recheck.log`. Выигрыш предложения относится к объёму тел, которые удерживаются одновременно, не к количеству чтений.

Воспроизведение на Linux: `python3 reproduce.py /путь/к/Proteus-modules`. Нужны Python, Git, Rust и закреплённые Cargo-зависимости. Скрипт использует отдельные временные checkout; его Cargo target не стоит делить с одновременно выполняемыми сборками того же пакета. На указанной чистой базе: `git apply --check /путь/candidate.patch`.

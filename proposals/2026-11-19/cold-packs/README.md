# Proteus: быстрее первое открытие архива без экранного кеша

Патч предназначен для Proteus-core на коммите 2aad0ba29311f0dbf7c107efc281abc1202ce4c4. Это каталог предложения; он не меняет исходники основного репозитория. Для проверки перед применением: git apply --check /путь/core-cold-packs.patch. Внешний worker и формат журнала менять не нужно.

## Зачем

На тесте холодного восстановления 125 000 отображаемых сообщений (100 активных) обработка тысяч отдельных записей производного кеша занимала основную часть времени даже после отдельной оптимизации строгой проверки ID. Исходные сообщения и ACK журнала для этого изменения остаются каноническими; новый формат затрагивает только заново создаваемую экранную проекцию.

## Как проверяли

Один и тот же внешний JSONL worker с ранее доставленной оптимизацией R10 в обоих вариантах. Core и пакеты собраны с одинаковыми настройками; в варианте candidate только patch упаковки плюс диагностический тест, не меняющий поведение рабочего пути. Свежий процесс хранилища, новый синтетический архив, без сохранённой экранной проекции; системный page cache не сбрасывали. Время prepare + launch начинается после наполнения журнала/подъёма storage worker, заканчивается до первого send. Это не тайминг клиентского окна, байтовое сжатие или полный CI проекта.

## Воспроизведение

Используйте синтетическую фикстуру R11 (в том числе её run.py и verify_cold.py), скомпилируйте тот же focus-тест из двух чистых копий Core: указанная база и база плюс патч. Используйте одинаковый бинарник reference/model и одинаковый JSONL worker во всех запусках, R9_FRESH_STORAGE=1, по одному размеру за запуск и тот же CPU. Публикации измерены как число WriteCache в период восстановления до ввода; промежуток между первым запросом и последним ответом уже входит в launch.

## Формат и совместимость

До восьми логических страниц по 50 сообщений в одном объекте, максимум 256 КиБ JSON на объект. Страницы, пересекающие последние 50 сообщений, хранятся отдельно, включая случай частичной последней страницы. Большая одиночная страница остаётся одиночной. Ревизия, логические SHA, проверка принадлежности источнику, лимиты backend и порядок публикации head сохранены. Обычная маленькая допись не перекладывает старые блоки. Новый Core понимает прежние одноуровневые кеши. Старый Core при понижении версии может перестроить такой производный кеш; это не миграция журнала.

Архивная страница из блока может потребовать чтения соседних строк того же объекта; на границе возможны два объекта. Ускорение старой прокрутки не заявляется. Продакшен меняется только в Core. Ни Desktop, ни код Modules storage не надо обновлять ради самого wire-формата этого патча.

## Проверки

- Реальные Core AppServer + JSONL worker: 3 003 → 3 005 строк; два полных прохода по 61 странице, произвольные смещения на границе групп, сохранённая предыдущая ревизия после append. Полный HTTP-экспорт до/после закрытия живого хэндла и открытия свежим воркером побайтово совпал (1 016 840 байт). В отдельном воркере чтения нет acquire/commit/release writer; байты журнала не менялись.
- Три сфокусированных Rust-теста фактического кода страниц с памятью вместо транспорта: точные ссылки на логические SHA, старый header, пропавший/испорченный блок, malformed typed leaf и бюджет байт, горячий хвост. Отдельный четвёртый тест целой перепроекции включён в патч, но не запускался. Полный workspace gate и AppServer с SQLite не запускались.

## Замер холодного открытия

| Видимых сообщений | Пара | Prepare + launch до → после | Записи кеша до → после |
|---:|---|---:|---:|
| 50 000 | A | 6,675 → 4,012 с | 1 006 → 132 |
| 125 000 | A, без патча затем с патчем | 17,524 → 9,287 с | 2 506 → 320 |
| 125 000 | B, обратный порядок | 22,415 → 10,433 с | 2 506 → 320 |

На 125 000 записей примерно на 87% меньше; открытие в этих двух парах на 47–53% быстрее. В обеих версиях 20 ответов с display records (52 843 542 байта), то есть экономия идёт из публикации кеша, не с чтения или из-за урезанной истории. Все шесть холодных тестов прошли сверку активного контекста, префикса журнала и видимого количества. Числа сильно зависят от хоста, размера строк и состояния файлового кеша. См. evidence/cold-phases.jsonl и evidence/verified.jsonl; это не замер GUI и не медиана флота.

# Полный ход с фиксированным запросом к модели

Core `8ea2cdaf4195ae24e941354f68d4e97335d139d7`, Modules `37b3d9c4db0b8cb5c4ca6cec690ebf7ce64c1979`, реальный AgentAppServer и отдельный релизный JSONL worker. Это дополнение к #219: вместо вызова компонента проекции напрямую действительно отдан пользовательский ход штатному тестовому workflow с локальной fake-моделью. Никаких реальных учетных данных и сессий. Окно Desktop не запускалось.

Стенд валидным API пишет архив порциями по 100 строк; затем для длинных случаев корректная compaction оставляет только последние 100 сообщений для модели. В измеряемую часть не входят построение фикстуры, возобновление runtime и построение его начального снимка. В каждом первом ходе запрос действительно содержит 101 сообщение, старые строки архива в него не попадают. Проверены сохранность исходного префикса журнала, завершение хода, общая длина отображаемого transcript и ответ в нём.

| Размер архива | Только подготовка истории в закрытии хода | Пагинированные проходы Core с начала в закрытии |
|---:|---:|---:|
| 100 | 50,7 / 50,4 мс | 5 × 7 записей, 1 страница за проход |
| 2 000 | 433,0 / 1 108,8 мс | 5 × 27 записей, 1 страница |
| 5 000 | 1 075,1 / 1 388,2 мс | 5 × 57 записей, 1 страница |
| 50 000 | 23,18 с, одна серия | 5 × 507 записей, 8 страниц |

Это исходные измерения, не обещание прироста или задержки на машине пользователя. 50 000 строк составляют ~21,2 МБ записанного JSONL до хода, а «запись» здесь содержит сотню сообщений. Первый проход строго собирает валидированное каноническое состояние. Следующие четыре — разные этапы полного преобразования событий в UI, включая видимость, ссылки на инструменты и временные метки. Лог считает только явные ReadRecords в Core; дополнительные проверки в worker не отслеживаются этим счётчиком. Тайминги варьируют в общей среде, поэтому наследовать конкретную константу нельзя.

[Проба](probe-first.rs) добавляется в `crates/proteus-core/src/app_server/http/tests/session_reads.rs`. Обозначения `SETTLE` и `SCAN` дают минимальные диагностики вокруг `runs.rs::completed_transcript` и `RemoteJournalSnapshot::scan_from`. Измеренный тестовый исполняемый файл Rust 1.95.0 собран с opt-level=1 (opt-level=3 для этого тестового файла получил SIGKILL вместе с другими сборками), codegen-units=64 и ранее подготовленными release-зависимостями. Релизный worker штатный. Это один выбранный тест, не полный набор штатных проверок Core.

Приложены [патч наблюдений](observe.patch), [сырые основной](run.log) и [повторный](repeat.log) логи и [воспроизведение через Cargo](reproduce.sh) для Linux. `PERF7_CASES=100,2000,5000,50000` воспроизводит форму повторного теста; сильные различия в абсолютных задержках возможны. Для измерения испытание изолировано от посторонних сетевых сервисов. [Почему не взят штатный пример history-scale](../runner/README.md).

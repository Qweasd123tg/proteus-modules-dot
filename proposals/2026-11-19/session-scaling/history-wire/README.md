# History paging on a real headless Core/Desktop route (baseline; no production patch)

Core 8ea2cdaf, Desktop 210cc9f2 (DTOs 105f8253), Modules 37b3d9c4, Linux x86_64. The real authenticated Core GET /history/page is served by Hyper over TCP loopback. A separate process runs the Desktop methods Api::new, initial_history_page, history_page, get and get_with, real proxy/idle transport, ureq 3.4.2, serde_json 1.0.152 and the pinned AppTranscriptPage DTO. No GPUI, compositor, real user history, credentials or model. The worker providing JSONL is the standalone release proteus-session-storage-module (sha256 faaec56c3e9b0cf54abaaf5910a78fca8b98a525a3b3ad25c04aee183fe3d336); an otherwise idle reference-module fixture is available to the stock test server. Inputs are short synthetic alternating user/assistant messages, 64 'q' plus identifier & Unicode prefix, submitted in canonical history batches of 100 outside timed reads. The full display cache was prepared on the local temporary filesystem before timed reads. A corpus size is not the number of rows displayed at once.

The client checks each row including position/text, total, top-of-page index and matching revision. By design there are no tools, blobs, variable-width storage pages or concurrent edits. Each HTTP response carries at most 50 rows. Single-call time is from immediately before the real client call to receiving the deserialized page (excluding comparison). For the sweep: sum of those request intervals for a complete backwards traversal, excluding checks and cursor construction. This isn't a timing of actual scrolling, which need not request every page. No model, GPU, complete UI, cold-cache claim, RSS or projected speedup.

The read counter wraps real process storage transparently in a separate run, not during TCP timings. On a known revision with these evenly sized pages: one Open, one revision-header read, one display-data read; no journal record read. The application validates both the header and the referenced content. HEAD lookup (no revision) additionally checks current source. Looking only at an individual data page hides the cost: metadata contains all page refs for all three sections. A sweep of P regular data pages repeats a manifest with O(P) refs P times. This is quadratic **index bytes**, not a claim that measured whole-app time obeys an exact quadratic. Whole-document header bytes are from compact JSON of the actual cached header value (excludes all RPC framing/source/etag). Per run there are two identical-sized persisted headers: the current pointer and the named revision. A single request consumes one, not both.

**Interpretation:** For the active 20,000-row synthetic case there are 400 even pages and 400 reads of the 81,611-byte revision manifest (32,644,400 B); all returned HTTP bodies total 5,491,467 B. Compare content-addressed / bounded, revision-linked index buckets or validated per-reader metadata reuse, with strict invalidation/fallback. Preserve behavior on edited/deleted, absent/stale/corrupt caches, changes of locator incarnation, variable-width pages and malformed content/hash; don't assume an unconstrained global memo is correct. No A/B change was tested here.

## Reproduction with complete Cargo sources

1. Use release binaries for the standalone pinned session-storage module and a matching test reference-module. Use a local Linux Rust 1.95 toolchain, loopback TCP and a fresh working directory. No settings, user session or external model needed.
2. Run `python3 prepare.py /path/Proteus-core /path/Proteus-desktop /new/work`. In `/new/work/client` run `cargo build --release` (the pruned workspace resolves its Desktop-locked dependencies).
3. In the prepared Core checkout export `PROTEUS_TEST_REFERENCE_MODULE`, `PROTEUS_TEST_SESSION_STORAGE_MODULE`, and `PERF6_CLIENT` (absolute paths; the latter `.../client/target/release/proteus-perf6-history-client`). Run `PERF6_CASES=1000,5000,20000 PERF6_REPS=5 cargo test --release --locked -p proteus-core --lib perf6_paged_history_over_route -- --test-threads=1 --nocapture`. Set `PERF6_COUNTS=1` only for separate structural verification. Cases must be multiples of 100 and at least 100. `PERF6_SKIP_SWEEP=1` omits the full traversal. Each invocation uses fresh synthetic temporary data.
4. Here the unmodified complete Cargo dependency builds for both Core and Desktop contracts were killed under pressure. The measurement used a Rust opt-level 3 headless test executable linked against prebuilt pinned release Core dependencies, with unrelated test registration disabled; the matched production HTTP/reader implementations were not changed. The separate Cargo release client compiled just those exact Desktop API, canonical-origin/transport, tracing, transcript and nested DTO definitions from the specified sources, without unrelated contracts. This is not a full Desktop build or a full Cargo test suite. Native GUI preflight failed: no fontconfig.pc/freetype2.pc/xkbcommon.pc, no DISPLAY or /dev/dri, and AF_UNIX bind denied. TCP loopback succeeded. No Windows/macOS data or presented-frame timing.

**Largest measured case (50k messages, 1,000 pages).** The actual revision manifest is 201,612 B, reread 1,000 times in a complete sweep (201,612,000 B internal metadata values versus 13,745,667 B of HTTP bodies for all pages). The no-window Desktop API traversal took 9.764 s; median of 18 warm individual requests targeting the newest/middle/oldest pages: 10.86 ms. At 1k/5k it was 46/313 ms for the 20/100 requests respectively. This does not measure the initial display time; the stable metadata overhead is an opportunity, not a measured saving. Synthetic fixture creation and initial projection excluded. See raw logs and `python3 summarize.py`.

A second, fresh process/data series at 50k rows took 10.614 s for the transport sweep. The repeated 201,612,000 bytes and total HTTP-body bytes were identical. The narrower client used for both series can alternatively be reconstructed with `prepare_narrow_client.py` and its included pruned lockfile; it extracts the exact upstream methods and types used without pulling in the unexercised code. This **does not** start a native window.

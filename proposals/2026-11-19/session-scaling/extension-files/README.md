# Файловая панель: два раза строили поддерево, которое SDK уже получил во владение

[Files::panel](https://github.com/Proteus-harness/Proteus-desktop-extensions/blob/a35cea08be83ee8e5ecbfce9ef5050a1c00eb247/packages/files/src/main.rs#L215-L242) строит строки с командами меню, передаёт массив в [tree](https://github.com/Proteus-harness/Proteus-desktop-extensions/blob/a35cea08be83ee8e5ecbfce9ef5050a1c00eb247/sdk/src/ui.rs#L266-L268), а весь результат в [fill](https://github.com/Proteus-harness/Proteus-desktop-extensions/blob/a35cea08be83ee8e5ecbfce9ef5050a1c00eb247/sdk/src/ui.rs#L62-L64). В обоих конструкторах старый `json!` превращает уже принадлежащие им Values в новые Values через serde: строки, вложенные массивы и поля объекта создаются повторно. Это две лишние реконструкции в памяти, **не** два разбора JSON с провода. В [кандидате](move-widget-arrays.patch) только эти два помощника перемещают готовый массив через `Value::Array`. Порядок ключей сохранён даже при `preserve_order`.

### Что измерено

Реальная `Files::panel` на уже загруженной синтетической директории с обычными файлами и их реальными меню. Каждая сборка выдаёт идентичную компактную JSON запись вплоть до последнего байта. Новая и прежняя панели измерены в отдельных свежих процессах, один прогрев, 7 чередующихся A/B пар на CPU 1, потом 7 на CPU 3 (общий Linux-хост; не частная машина). Время средней операции внутри процесса (построение и drop корня, включая создание строк, учет выбранной строки и меню), затем медиана процессов; это настенные времена, не измерение аппаратных CPU cycles. Heap записан отдельным бинарником: это запрошенные у allocator байты выше прогретого состояния сразу до одного построения. Не RSS и не число байт на проводе.

| Файлов без корня | Построение + drop, мс, первая серия | Вторая серия | Добавочный пик, байты | Живые байты сразу после получения результата |
|---:|---:|---:|---:|---:|
| 0 | 0,021 → 0,011 | 0,022 → 0,011 | 13 060 → 10 702 | 6 610 → 7 170 |
| 16 | 0,592 → 0,341 | 0,572 → 0,275 | 256 212 → 140 448 | 124 051 → 131 339 |
| 128 | 4,21 → 2,18 | 4,25 → 1,75 | 1 973 396 → 1 032 192 | 949 491 → 1 003 371 |
| 512 | 20,76 → 8,78 | 14,93 → 5,14 | 7 860 884 → 4 089 600 | 3 779 571 → 3 993 195 |

**Оговорка важна:** пока результат жив, перемещённые собственные Value сохраняют резерв ёмкости строителей (около +5,7% на 128 и 512). Штатный [Host::show_with_keys](https://github.com/Proteus-harness/Proteus-desktop-extensions/blob/a35cea08be83ee8e5ecbfce9ef5050a1c00eb247/sdk/src/host.rs#L383-L392) сохраняет одно выданное дерево на view. Значит, в состоянии простоя оно может стоить больше, хотя пик во время построения одного результата меньше. Здесь нет прежнего корня в Host, пересылки в Desktop, собственно сетевого чтения каталога, GUI или запуска плагина на пользовательском проекте. После `drop` возвращение к прежнему числу байтов точное во всех восьми запусках. При желании оптимизировать **только** steady RAM эту правку брать не стоит.

Полные исходные [числа](results.json), [метод](measure.py), [обвязка](panel_probe.rs). Rust 1.95.0 x86_64 Linux, release opt-level=3, codegen-units=4. Для исходного замера обе копии SDK и две версии штатного files собирались rustc с общими закреплёнными release-зависимостями; счётчики отсутствуют в измерении времени. `reproduce.py` делает аналогичную переносимую сборку через Cargo в новом каталоге. На чистом checkout Extensions `a35cea08be83ee8e5ecbfce9ef5050a1c00eb247`:
```sh
python reproduce.py "$EXTENSIONS" "$NEW_OUTPUT_DIR" 1 3 > results.local.json
```
Выберите доступные CPU. Для точной проверки ownership можно добавить [этот тест](ownership.rs) в конец sdk/src/ui.rs после применения патча; он проверяет адрес массивов и строки и точный JSON. [Тест прошёл](ownership-test.log). Штатный `tests/wire.py --wire` для Files на обеих версиях прошёл, все 16 сообщений идентичны (44 525 байт). [Комплект тестов](checks.txt): 277 штатных тестов прошли, один тест жизненного цикла Mermaid увидел в `/proc` 0 детей вместо 1. Тот же тест отдельно не прошёл с той же ошибкой на **неизменённой** исходной версии. Полный комплект зелёным не заявляется.

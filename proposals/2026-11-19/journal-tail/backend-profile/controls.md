## Воспроизведение: diagnostic-only

Использовать **отдельные** рабочие копии: основой A служит Modules `37b3d9c4` с патчем Compare из раунда 7, для B поверх него применяется патч seek. Код Core в обеих сборках один и тот же, путь реального хода описан в [стенде #220](https://github.com/Qweasd123tg/proteus-modules-dot/blob/0752bb0f96ff12575d394c066f94cebef76ccc93/proposals/2026-11-19/journal-settlement/real-turn/README.md); воспользоваться версией с одной проверкой Compare. Загрузить запущенный в обычном режиме рабочий модуль недостаточно: надо пересобрать worker для наблюдения.

1. Отдельно для каждого из A и B применить `instrument-modules.patch` к указанной копии Modules. Установить при сборке `PERF8_STORAGE_TRACE` равным абсолютному пути нового TSV-файла (директория должна существовать). Собрать `cargo build --locked --release -p proteus-session-storage-module` и сохранить worker. Это ограниченная диагностика: принудительный сброс счётчиков в каждом RPC не предназначен для обычных тестов.
2. Для отнесения времени к слоям SDK: отдельно наложить `instrument-worker-sdk.patch` на зависимость **worker** `proteus-module-sdk` из Core `4c032eeb`; дать worker эту локальную сборку вместо изначального SDK, с остальными идентичными зависимостями. При сборке задать `PERF8_SDK_TRACE` абсолютный путь нового TSV-файла. SDK не нужен для счётчиков декодирования. В опубликованных результатах worker, SDK и service собирались отдельно с `opt-level=3` и линковались с закреплёнными release-зависимостями, Core – ранее собранный probe с `opt-level=1`.
3. Для каждого worker из каталога Core с доступными ресурсами выполнить `python3 capture.py /abs/core-test /abs/worker /abs/proteus-reference-module /new/host.log --cpu N`. Сравнивать одинаковые affinity, варианты и размеры. Конкретный UUID/локатор генерируется заново, длина и форма синтетических данных совпадают.
4. В host.log за `CASE display=N` взять интервал от `SETTLE_BEGIN` до `SETTLE_END`, сравнивая с эпохой первой колонки worker TSV. Фактическое время закрытия – внутренний таймер Core в `SETTLE_END`, время всего хода – `total_ms` из `TURN`. Дополнительное чтение записей **после** закрытия для проверки результата исключается. Метки наблюдаются в Python после чтения stderr; служебная асинхронная операция на границе может попасть на другую сторону. Обязательные полные и хвостовые чтения, их counts и offsets проверяются по окнам и `SCAN`. Схема service TSV в заголовках приложенных CSV. В SDK TSV колонки start_epoch_ns, elapsed_ns, stage, operation-or-request-id, frame_bytes, pid, invocation_thread. На проводе считаются байты уже проверенной канонической сериализации вместе с LF; не измеряются memcpy/пропускная способность диска. Ни один обработанный payload в профили не пишется.

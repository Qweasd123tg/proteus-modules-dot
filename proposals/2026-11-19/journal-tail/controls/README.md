# Независимые контроли

На двух реальных release worker (общее основание CompareSnapshots) прошли 27 пар «сценарий × backend», 15 предыдущих плюс 12 новых. Дополнения: UTF-8 и линии длиннее внутреннего буфера, точный/посторонний курсор, непоследовательные и повторные страницы, независимый writer на фиксированном снимке, изменение/восстановление размера, неполный хвост и ограничение с внешним payload. Сравнивались последовательности, байты, ответы и ошибки. Потеря/изменение внешнего payload отдельно проходит штатное каноническое чтение, а не угадывается по метке файла. [Тест границы](boundary_controls.py), [основные тесты](worker_controls.py), [штатный лог](logs/stock-boundary.log), [candidate](logs/candidate-boundary.log).

Кандидат Core (малый суффикс) отдельно проверен на порогах 1/16/17/65 записей и точном 256 КиБ ±1 байт, коротких страницах, ошибке поздней страницы/неподходящем snapshot, reset и конкурентном продвижении ревизии перед publish. Сравнение с независимой полной проекцией целиком; на конкурирующей записи старый валидный вид не подменяет новый HEAD. Устранённая физическая повторная загрузка сама по себе больше не может сигнализировать об ошибке, которая появилась уже после успешного фиксированного чтения. Удаление внешнего payload после чтения не было атомарно согласовано с публикацией и в прежнем варианте.

Исходник дополнительных проверок Core: [core_controls.rs](core_controls.rs), [малый стенд](core_fixture.py), [сборка небольшого test-crate](test_root.rs); [stock](logs/stock-focused-all.log) 60/60, [candidate](logs/candidate-focused-all.log) 61/61 с дополнительным тестом границы.

На варианте с дополнительным ограничением по геометрии границы снова прошли 27/27 сценариев: [граница](logs/guarded-boundary.log), [базовые контроли](logs/guarded-r7.log).

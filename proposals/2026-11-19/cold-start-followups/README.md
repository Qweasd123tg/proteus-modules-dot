# Proteus: холодное восстановление, первый ход и прокрутка архива

Это набор предложений для исходных репозиториев, а не изменения их рабочих веток. В `r14` лежат проверенные кандидаты, в `experiments` — стенды и эксперименты, которые пока не стоит включать. Трассы построены на синтетических данных. Время до кадра GUI не измеряли.

| Изменение | Результат | Проверка |
|---|---|---|
| [JSONL: один проход декодирования payload](r14/storage/README.md) | На 125 000 сообщений строгий `OpenDisplaySnapshot` 3,901 → 2,965 с (−24%), CPU −22,9%; пиковая память примерно та же | 4 пары, 49 тестов; ещё 1 пропущен. SHA исходника, состояние и порядок записей совпали |
| [Архив: ограниченные сжатые группы поверх #222](r14/archive/README.md) | Старое окно 135,6 → 7,9 КБ; обход назад 19,29 → 1,15 МБ, 738/920 → 103/105 мс (JSONL) | 5/5, включая JSONL AppServer; компонентный SQLite A/B |
| [Desktop + Core: сразу нужная вкладка](r14/desktop/qualification.md) | При сохранённой B и последней A открывается только B, а не A+B. Папка новых чатов и поведение при устаревшем адресе те же | 14 тестов Core, 68 headless Desktop, 1 пропущен |
| [Одна ревизия на выдачу](r14/revision/README.md) | Ранее доставленный фикс R9 в отдельной версии для #222. Не переносить одновременно оба варианта | Детерминированный красный тест и 63/63 со стеком R13 |

Архивные группы не бесплатны: на плохо сжимаемой фикстуре число запросов создания кеша выросло с 40 до 150. Уже сохранённые группы #222 читаются как есть; ускорение появляется после обычной повторной материализации. Не увеличивать размер групп вслепую.

## Базы и применение

Из чистой ветки нужного исходного репозитория: `git apply --check /путь/к/патчу`, затем `git apply /путь/к/патчу`. Проверять следующий diff только после наложения предыдущих. Не применять патч вторично по другому имени.

- **Core `2aad0ba29311f0dbf7c107efc281abc1202ce4c4`:** для экранной части сначала [#222](../cold-packs/core-cold-packs.patch), затем нужные `r13/patches`, `r14/archive/framed-packs.patch`; версию исправления гонки из `r14/revision` выбирать вместо исходной R9 из `earlier/r9/core-revision`. Патч startup-hint `r14/desktop/core-preferred.patch` независим, для эффекта требуется Desktop-половина. После изменений SDK/семантики обновить зависимость Core и пересобрать используемый внешний worker.
- **Modules `2c2cee47ea76df12c6e208839594e32470a2c3f1`:** `r14/storage/storage-single-pass-payload.patch`. Тестовая фикстура R9 находится отдельно в `earlier/r9/storage-fixture`. Старый i686 diff уже [опубликован здесь](../journal-tail/seek/portable-prefix-chunk.patch) и не продублирован.
- **Desktop `fcc30413b12374d622abbba5a8832e10b62fdf3f`:** `r14/desktop/desktop-preferred.patch`, затем при необходимости независимый `earlier/r9/desktop-codex/capped-preview.patch`. Старый Core отработает как прежде и просто проигнорирует подсказку.
- **Extensions `9752f9a16889c9cee2f1f83476a42cbc4724ef03`:** независимые патчи для [меню моделей](earlier/r9/extensions-model/model-picker.patch) и [Git-значка](earlier/r10/extensions-git-status-ownership.patch).
- **Сравнение R10:** [инкрементальный индекс](earlier/r10/core-incremental-active-history-ids.patch) на той же базе Core альтернативен [старой линейной проверке](../journal-settlement/active-ids/active-ids.patch), а не дополняет её. [R11](earlier/r11/phase-results.jsonl) содержит измерения масштабирования до #222.

## Что пока не включать

[Ограниченная выдача старых окон](experiments/bounded-window/README.md) читает один блок для последних 50 строк, два для произвольного старого окна. Это прототип на уже проверенных записях, не готовое включение в AppServer. [Проект передачи одной ревизии](r14/revision/READY-DESIGN.md) закрывает следующий шаг: отдавать первую страницу до фоновой записи без повторного разбора на первом scroll/send. Диагностические 4,705 с R13 не включали запись производного кеша, чтение старой страницы или send. [Изменения RPC](experiments/rpc/README.md) показали меньше аллокаций на IPC, но не подтвердили сквозного ускорения; не включать их в рекомендуемый стек.

Контрольные суммы: `sha256sum -c SHA256SUMS` из этой папки. В Git включена компактная проверяемая подборка замеров; крупные сырые трассы отдельно в рабочем архиве.

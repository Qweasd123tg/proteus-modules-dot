# Состояние макета перед idle и после него

Проверка прошла через настоящие `TextView`, `TextViewState`, GPUI window draw/layout/prepaint/paint и очередь в официальном `TestAppContext`. Контейнер шириной 320 логических пикселей содержит HTML и отдельный цветной элемент-индикатор высотой 7. Мы сравнивали не только текст: записывали выставленные виджету границы, вертикальную позицию индикатора, число подложек и подчёркиваний в сцене, is_ready, выделение. Платформа тестовая (`NoopTextSystem`), без шрифтов рабочего стола, графического backend и предъявленного кадра. Это не визуальный скриншот и не время до первого читаемого кадра.

У обеих версий полностью совпали **8 снимков**. Заголовок, текст и ссылка дали высоту 100,5, индикатор на y=100,5 и одно подчёркивание ещё до обработки очереди и те же значения после. Select-all вернул текст и сменил число прямоугольников с 1 на 4. Замена таблицей очистила выделение: высота 79, индикатор y=79 до и после idle. После трёх быстрых замен остался только `red` (высота 26); отдельный последующий push оставил обе части (высота 64). Конкретные величины зависят от тестового текстового backend; проверялось их равенство. [Весь вывод](layout.jsonl), контрольная SHA-256 `9841aedeb6a481a0d81190d6102a9ea56d5b905d1dde44015d4f56089a60fda3`.

В первой сборке виджет создан стандартным HTML-конструктором, в изменённой — тем же `html_for_replacements`, который выбирает shipped RichText. Это проверка выбранной ветки. Для повтора: `python3 reproduce.py /path/to/Proteus-desktop ../candidate/defer-rich-text-only.patch ../host/Cargo.lock [--offline]`. Скрипт проверяет исходные Git blob, отдельно помечает реально выполненную ветку каждой сборки и исключает чтение предыдущего бинарника Cargo. Для обоих запусков используются один Rust 1.95, одно окно TestPlatform в процессе и одинаковые входы; вывод между версиями сравнивается целиком.

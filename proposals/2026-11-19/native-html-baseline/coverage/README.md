# До каких принятых ответов из предыдущей трассы доходит порог 4 096 байт

Это повторный анализ [сырых доказательств #217](https://github.com/Qweasd123tg/proteus-modules-dot/blob/8f785d2d6865533101834ce7c2376657139c328a/proposals/2026-11-18/repeated-text-parsing/transport/proofs.json), а не замер окна или профилирование приложения. Для каждого управляемого режима известны реально полученные деревья и SHA-256 HTML. Выбираются только **актуальные** ответы по правилам проводившегося опыта, один retained view с неизменным контекстом и без слотов. Затем исключаются повторы того же HTML. Изменившийся HTML размером до 4 096 байт включительно мог бы попасть в синхронную ветку, если виджет смонтирован. Отдельная проверка числа принятых ответов совпадает с результатами настоящей очереди во всех 13 режимах.

| Текст 53 762 Б из #217, отправка в одном и том же view | Получено / принято деревьев | Коротких новых/изменившихся HTML |
|---|---:|---:|
| Один полный текст | 1 / 1 | 0 |
| 16 редакций, подтверждать каждую | 16 / 16 | 1 (3 911 Б) |
| 64 редакции, подтверждать каждую | 64 / 64 | 4 (978, 1 961, 2 936, 3 911 Б) |
| 64 редакции, группами по 8 | 16 / 8 | 0 |
| Все 64 до первого подтверждения | 2 / 1 | 0 |
| Поздняя ссылка, 64 редакции, подтверждать каждую | 64 / 64 | 4 (1 004, 1 962, 2 945, 3 921 Б) |

На длинных текстах из #217 это гипотеза про **первые короткие части**, а не ещё одно ускорение всех 64 редакций. Для статического маленького сообщения картина принципиально иная. Результаты искусственного темпа не описывают размер и темп сообщений пользователя. Без исполнения GPUI в этой трассе неизвестно, запустился ли фоновый запрос, успела ли его заменить новая версия и изменилось ли время кадра.

Воспроизведение: `python3 coverage.py /path/to/proofs.json` (проверяется хеш исходного опубликованного файла). [Результаты всех режимов](results.json).

# Ленивая фоновая база только в retained RichText Desktop

**Итоговый патч** для [Desktop 210cc9f2](https://github.com/Proteus-harness/Proteus-desktop/tree/210cc9f274ffe40533b390a0d9e940f251a9fa22): [defer-rich-text-only.patch](defer-rich-text-only.patch). Он **заменяет** прежний общий эксперимент: добавлять их друг за другом нельзя. В поставляемом каталоге один полный патч.

Почему общий вариант отвергнут: обычный публичный HTML-клиент вправе вызвать первый `push_str` после простоя и ожидать, что baseline уже подготовлен. Перенос парса на критический путь append ухудшал именно этот сценарий. У существующего конструктора `TextViewState::html(text, cx)` прежняя стратегия сохранена: успешная маленькая полная замена отправляет обычный BaselineAck; worker его немедленно разбирает при обработке. У `markdown` всё также остаётся в прежнем режиме. «Прежнем» здесь означает ту же работу парсера и семантику, а не идентичность машинного кода или обещание наносекундного равенства.

Введён отдельный `TextViewState::html_for_replacements(text, cx)`. Единственное его применение в поставляемом приложении — создание приватного [нативного RichText для декларативного виджета](https://github.com/Proteus-harness/Proteus-desktop/blob/210cc9f274ffe40533b390a0d9e940f251a9fa22/src/ui/extensions/declarative/rich_text.rs#L19-L52). Этот владелец обновляет полную строку исключительно через `set_text`. Обычные public HTML/Markdown constructors передают `false` закрытому конструктору; только новый передаёт `true`. Неизменяемое решение принято **до** первого синхронного разбора. Нет глобальной настройки, опционального параметра публичных обновлений или зависимости общей библиотеки от идентификатора Proteus-виджета.

В opt-in варианте:
* Короткая успешная замена без пользовательских HTML parser hooks по-прежнему синхронно заполняет видимое дерево. После обычного coalescing worker может сохранить до 4 096 входных байт вместо второго дерева. Большие замены, Markdown, неуспехи и HTML parser hooks не используют этот shortcut.
* Если кто-то всё же вызовет публичный `push_str` на Opt-in состоянии, поведение разметки не меняется: припаркованная база и следующая дельта будут разобраны раздельно, а уже объединённое штатным coalescing обновление останется объединённым. Такой первый поздний **opt-in** append может стоить дороже. Публичный `html` не получает этого компромисса.
* Остались исходные приоритет replace/supersede, бюджет 64 сообщений, защита ревизий и восстановление после ошибок. Дерево видимой стороны не передаётся worker через clone. Фоновый worker всё ещё просыпается, чтобы обработать небольшой запрос; не заявляется устранение самого потока, JSON, layout или paint.

Проверка файлов: `python3 verify_scope.py /path/to/Proteus-desktop`; Git blob-идентичности в [blobs.json](blobs.json). Этот аудит не заменяет независимого нативного теста работы очереди/выделения на обоих конструкторах и не означает показ окна. Не приписывайте узкому патчу процент от полного Desktop GUI по временам общего эксперимента.

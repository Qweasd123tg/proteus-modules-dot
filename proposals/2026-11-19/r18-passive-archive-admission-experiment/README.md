# Эксперимент Core: очередь восстановления холодной страницы

Не рекомендация включить по умолчанию. Два патча на Proteus-core
2aad0ba29311f0dbf7c107efc281abc1202ce4c4: сначала
bounded-passive-recovery.patch, затем http-saturation-test.patch.
Проверять git apply --check перед каждым шагом. Не требует #224
и не меняет Modules/SDK pin, форматы архива или канонический журнал.

Только холодный промах пассивного /history/page на одном HTTP-сервере:
одно восстановление одновременно, ещё до восьми запросов ждут, при
переполнении 503. Разрешение удерживает фактическая блокирующая работа,
даже если HTTP-обработчик уже отменён; ожидающий при отмене освобождает
место. После допуска кеш перепроверяется: другой запрос мог уже подготовить
нужную страницу.

В управляемом тесте драйвер проходит настоящий аутентифицированный HTTP
диспетчер и настоящий JSONL storage. С первым восстановлением на барьере
и восемью ожидающими два запроса получили 503. Отмена ожидания не пустила
второе восстановление раньше завершения первой работы; после снятия
барьера новые восемь запросов получили 200, те же страницы и ревизию,
с сохранением byte-for-byte канона и без активации архива. Это не обрыв
сокета TCP, не замер PSS и не репликация 4×125 000 с кандидатом.

Существующие read-model, HTTP history и отдельный тест допуска также прошли.
Повтор: cargo test --locked -p proteus-core --lib archive_saturation.

Границы: активный чат, /resume, полный /history, кеш-хиты и предварительные
чтения проходят вне этой очереди. Тёплая latest-страница всё ещё может
ждать блокировку storage на OpenSnapshot, закреплённая ревизия проверяется
иначе. Нельзя обещать независимость активной отправки от тяжёлого чтения
или улучшение памяти/скорости всего приложения. Для полного внедрения
нужен release A/B на одних журналах со всеми четырьмя корректными страницами,
PSS и окном реальной отправки.

В evidence описана независимая 4×125 000 диагностика **stock**, где три
страницы вернули ошибку и соседний send не завершился. Она показывает,
зачем нужен следующий системный шаг, но не результат этого патча.

Исходный и повторные целевые тесты: 9/9 различных тестов на
451fb32521dd32c382b0de726c05f4a2a09ed884, сценарий диспетчера 6/6.

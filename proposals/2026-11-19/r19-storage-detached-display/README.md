Открытие JSONL fd + physical ceiling или read-only транзакции SQLite, хеширование, строгая валидация всех записей, сборка временного файла и сериализация resume-state — вне общего mutex. Между вычислением и регистрацией сравниваются locator, lifecycle, метки источника; bounded inventory blobs требуется для обновления кеша головы. Допуск один на detached display/catalog **на экземпляр сервиса**, staging-бюджет 512 MiB совместно для retained и in-flight записей. Canonical `OpenSnapshot` не перенесён за блокировку.

Форматирование и `git diff --check` прошли.

**Функциональная проверка в сервисе:** в тестах обоих backend остановка сразу после freeze и до первого хеша. Синхронный durable ACK прогретого A приходит до снятия барьера B. После этого state, revision, hash, номера отображаемых записей B сверяются с последовательным контролем с той же историей (есть невидимое событие). Другие тесты: append и удаление/повторное создание, materialization пустой reservation, два захвата при бюджете одного файла, eviction и release, повреждение при исчерпанном staging. Это тест `StorageService::execute`, не HTTP и не SDK subprocess.

**Отдельная проверка реального SDK-процесса:** Linux/Python, `sqlite-wire.py` и `rpc.py` рядом. В одном живом module worker создать и подготовить A и B. Внешним соединением SQLite удерживать EXCLUSIVE-транзакцию на B и убедиться через независимый read-only SELECT, что чтение действительно заблокировано. Отправить по SDK `OpenDisplaySnapshot(B)`, увидеть реальное открытие SQLite-файла через inotify, отправить `Commit(A)` через тот же процесс. В течение 1 секунды до снятия внешней блокировки проверяется наличие сопоставленного по ID durable ACK A. После снятия блокировки проверяется точный snapshot B и сообщение A из ACK. Скрипт выводит SHA-256 бинарника и JSON; результаты `false` на контролях ожидаемы, не считаются успехом кандидата. Этот тест проверяет возможность движения при занятой чужой БД, не измеряет throughput или p95.

## Ограничения для выпуска

- Если изменяется **сама B**, возвращается ошибка конфликта, не смешанный handle и не тихое переснятие N+1. Текущий Core (`RemoteValidatedRead::open_projected_display`) не повторяет такой запрос; UI может увидеть ошибку. Нужен отдельный контракт типизированного конфликта/ограниченного повтора либо проверенное обслуживание прежнего N. По этой причине эксперимент — не готовый новый default.
- При сохранении current head проверка инвентаря blobs и индекс sidecar всё ещё могут выполнять ограниченный I/O под общим mutex. Устранена блокировка на полном холодном hash/fold, не вся блокировка.
- На Unix метки включают inode/device/ctime; не переносить доказательство Linux на Windows с иной моделью файловых меток. Нет общей квоты между exports/процессами, приводимого heap-бюджета для всех Fold или доказательства end-to-end скорости из unit-теста.

Проверенный результат wire-контроля: на stock и промежуточном варианте ACK A не получен в течение удержания блокировки B (1 с); на финальном `714ef623bc198beefe0fd74ea06220ed9cc1062f428af2cabcff913362527a5b` корректный ACK пришёл до разблокирования B. После освобождения блокировки все три варианта вернули ожидаемое состояние B. Это один функциональный опыт на вариант, не оценка задержки в production.

## Контрольный HTTP/SSE A/B, затем B/A

Изменён только внешний JSONL worker: A — upstream Modules `cf99937`; B — патч `final.patch`. Core везде upstream `048378d` с тем же SHA-256 бинарника, фиксированным fake model и одинаковыми timeout/config. Стенд: один активный чат, 100 архивов, по 125 000 исторических строк в четырёх открываемых; в конце каждой длинной истории есть compaction до 100 текущих сообщений. Это не 4 × 125 000 **активных** сообщений модели, не настоящий Desktop и не интернет-модель. Холодный означает новый процесс и отсутствие прикладных cache/sidecars, а не очищенный OS page cache.

| Метрика | Stock A, два запуска | Эксперимент B, два запуска |
|---|---:|---:|
| Первый непустой SSE-текст A при четырёх ожидающих запросах истории | 9 253 / 8 678 мс | 98 / 95 мс |
| Законченный успешный синхронный `/send` | 13 938 / 13 980 мс | 183 / 174 мс |
| Четыре холодные страницы (мин–макс в запуске) | 18,89–20,33 / 17,76–19,98 с | 13,04–15,91 / 13,41–16,86 с |
| Измеренный пик PSS дерева в холодной фазе | 734 / 780 МиБ | 1 081 / 970 МиБ |
| Медиана PSS короткой фазы после прогонов | 391 / 402 МиБ | 624 / 676 МиБ |

Архивы: 4/4 HTTP 200 во всех четырёх запусках. Для каждого проверены 50 строк, ID, роль, текст, закреплённая ревизия и повторное latest-открытие. Проверены неизменные SHA журнала/blob-корпуса, один правильный model request и исход запроса активного чата в каноническом журнале. Момент SSE TurnStarted служит **верхней оценкой** времени durable открытия, не таймингом wire ACK. PSS измерен по дереву реальных процессов без Desktop, выборочный пик — нижняя граница; два парных запуска не измеряют p95. Во время прогона остановлены другие сборки. Полные компактные summary и сравнения в `evidence/http/`.

Рост PSS — блокер для default, независимо от выигрыша в задержке: на снимке пика вклад storage worker вырос с 172 до 521 МиБ в первой паре, с 245 до 424 МиБ во второй. В точности это вклад процесса *в момент пика дерева*, не его собственный максимум. Замер не разделяет живые объекты и удержанную память allocator. Следующий эксперимент: развести большой detached replay и полный canonical fallback по общему бюджету, не ставя короткие ACK за тяжелыми операциями; отделить живой heap от удержания allocator до выбора лечения. См. `ARCHITECTURE.md`.

### Повторить на Linux

Собрать release Core на указанном коммите, release stock/final worker в отдельных checkout и сохранить их точные SHA-256; для fake workflow использовать отдельно собранный штатный `proteus-reference-module`. Генератор ниже создаёт один синтетический набор; используйте его неизменённым для всех вариантов. Новый набор может иметь другой digest канонических байтов (ID записей), сравнивайте контроль и эксперимент по одному набору.

```sh

  --worker "$STOCK_WORKER" --archives 100 --rows 125000

  --core-commit 048378da7cbe890d8bf8a0152e55eb28ecb5013d \
  --core-sha256 "$CORE_SHA" --worker "$WORKER_BIN" --worker-sha256 "$WORKER_SHA" \
  --reference "$REFERENCE_BIN" --golden /path/to/generated-fixture --out "$OUT"
python3 stand/compare.py results-stock/summary.json results-final/summary.json --axis worker
```

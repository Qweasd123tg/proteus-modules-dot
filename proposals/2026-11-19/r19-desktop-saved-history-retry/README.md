# Desktop: повторное чтение сохранённой истории в той же вкладке

**База:** Proteus-harness/Proteus-desktop `7ccb6c8634c40f450d83bb6e9eff891dc776ee6b`. Проверен диапазон от `fcc30413` до этого main: доставка и холодный старт обновлены; обработчик сохранённой дочерней истории и его заголовок не менялись. `repositories.json`, Cargo.lock, Cargo.toml, HTTP-контракт и зависимости патч не меняет.

**До правки.** Запрос сохранённого хвоста потребляет флаг `dirty` до запроса. Завершённые сессии не опрашиваются: после первой ошибки GET видна её подпись, но сообщений нет и самой подписью повторить запрос нельзя. Это не потеря данных: выбор вкладки или повторная навигация из родителя уже разрешали новую попытку.

**После.** Только на хвосте с ошибкой, вне текущего запроса и чтения архива, заголовок предлагает «Повторить». Это тот же штатный путь восстановления, что используется при повторном открытии: одна явная попытка при отрисовке вкладки, без немедленных повторов, второго writer, SSE или `/resume`. Ошибка последующего чтения не очищает ранее показанные строки. На успешном или пустом результате кнопки нет. Если перед обработкой нажатия уже началось чтение хвоста, второе чтение не ставится в очередь. Для работающих чатов не меняется существующий опрос. Сам механизм чтения, логическая ревизия, защита закрытой вкладки по identity и ограничение физического HTTP-запроса не изменены. Изменение интерфейса описано в DESIGN.md.

**Проверка в checkout указанной базы** (Rust 1.95.0):

```sh
git apply --check desktop-saved-history-retry.patch
git apply desktop-saved-history-retry.patch
cargo fmt --all --check
python3 scripts/check_licenses.py .
cargo test --locked --no-default-features -j 1 -p proteus-native --bin proteus-native ui::chat::readonly::
```

Тесты используют настоящий GPUI TestAppContext / VisualTestContext, точный запрос `GET /history/page?session_dir=…` и loopback HTTP: 503, отсутствие опроса у завершённой сессии, нажатие кнопки в том же представлении и получение сохранённой строки. Отдельно проверяются дедупликация повторного действия, закрытие вкладки до обработки ответа и устаревший ответ после смены поколения. Это не полноценный прогон GUI с физическим дисплеем и не измерение производительности.

**Статус.** На указанной базе собран нативный Linux test binary (Rust 1.95, один Cargo job, no default features). Все 5 тестов readonly прошли, отдельно 23 соседних теста API, навигации и истории прошли тем же бинарником. Логи: [readonly](evidence/readonly-tests.log), [соседние](evidence/adjacent-tests.log). Физический экран/GPU и полный Desktop suite не проверялись. Применимость, форматирование и лицензии проверены.

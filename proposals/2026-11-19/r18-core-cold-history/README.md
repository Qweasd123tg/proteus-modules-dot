# Core: использовать отпечаток уже проверенной холодной истории

База патча: Proteus-core 2aad0ba29311f0dbf7c107efc281abc1202ce4c4.
Это предложение для исходного репозитория, не изменение его ветки.

Когда к последней странице нет производного кеша, текущая версия сначала
выполняет обычный OpenSnapshot, затем всё равно валидирует и рендерит
ту же историю. Патч для запроса **последней, не именованной** страницы
переиспользует отпечаток, с которым строго проверена и спроецирована
история. Перед выдачей остаётся конечная сверка текущего источника.
Обычный fallback на каноническое чтение сохраняется. Применимые ошибки
источника не заменяются общим сообщением о неудачном fingerprint.

Для именованной ревизии сохраняется раннее отбрасывание чужой ревизии;
если исходник меняется между ранней сверкой и строгой проекцией,
отличающаяся проекция не публикуется под видом восстановления этой
ревизии. Проекция не становится полномочием на запись и не заменяет
проверку журнала. Коммит, требования storage и контракт HTTP не меняются.

Для повторения на чистой базе:
1. git apply --check core-history-recovery.patch
2. git apply core-history-recovery.patch
3. cargo test --locked -p proteus-core --lib app_server::read_model::tests

Не обещает устранить конкуренцию четырёх холодных архивов, справедливость
планировщика или сокращение общего пика памяти. Не меняет формат данных и
не требует изменения Modules/SDK pin. Замеры времени и целевой тест
перегрузки оцениваются отдельно от этой проверки корректности.

Проверено: 4/4 read_model tests на Rust 1.95.0. Новая фикстура
не разрешает обычный OpenSnapshot до строгой проекции; последняя страница
из 51 строки возвращает нужные 50 и прежнюю ревизию. Отдельный контроль
возвращает исходную типизированную MissingSession при конечной сверке.
Границы пустой и неполной страницы, повреждённый канон и отсутствие
подмены именованной ревизии также прошли. Это целевая проверка, не полный CI.
